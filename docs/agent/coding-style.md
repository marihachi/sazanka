# コードの書き方

整形（インデント、行長、クォート、末尾カンマなど）は Prettier に任せる。ここに書くのは、Prettier が判断しない事柄だけ。

ここの取り決めと Prettier の結果がぶつかったら、Prettier を優先する。`npm run format` をかけ直しても形が変わらない状態が正しい形で、この文書に合わせるために整形をやり直したり、Prettier の設定を変えたりはしない。取り決めの方が、Prettier の出力の中で選べる範囲に収まっていないだけなので、その箇所は Prettier が出した形のままにする。

## 制御構文

- 制御構文 (`if` や `for`、`while` など) の本体は、1 行で済む場合でも波括弧を付ける（開発者の方針）。後から行を足したときに、括弧の付け忘れで意図しない範囲になるのを防ぐ。

  ```ts
  if (!selection) {
    return;
  }
  ```

- 例外として、本体が `break;` `continue;` `return;` のように、その場で抜けるだけの短い文なら、括弧を省いて同じ行に書いてよい。

  ```ts
  if (h.past.length === 0) return h;
  ```

- ただし、オブジェクトを組み立てて返す早期 return は、短くても括弧を付ける（開発者の方針）。`{` が並んで、ブロックなのか返す値なのかが読み取りにくくなるため。

  ```ts
  if (!raw) {
    return { project: emptyProject() };
  }
  ```

## オブジェクトリテラル

- メンバが 2 つ以上あるオブジェクトは、メンバ毎に改行する（開発者の方針）。

  ```ts
  return {
    past: [...h.past, h.present].slice(-LIMIT),
    present: next,
    future: [],
  };
  ```

- ただし、省略記法（`{ a, b }`）やスプレッド（`{ ...v, x }`）を含むものと、座標の `{ x, y }` は 1 行のままでよい。

  ```ts
  return { ...h, present: next };
  return { x: c.x - GRID, y };
  ```

- この使い分けができるのは、Prettier の `objectWrap` が既定の `preserve` だから。`{` の直後で改行しておけば `npm run format` でも 1 行に詰め直されず、1 行に書いたものは 1 行のまま残る。
- ただし `printWidth`（120 桁）に収まらないものは、1 行に書いても Prettier が必ず折り返す。省略記法やスプレッドを含んでいても、そういうものは折り返された形のままにする。
- 1 行にしたいオブジェクトの中に、改行するオブジェクトが入っている場合は、内側の改行を優先して外側も改行する。外側を 1 行に詰めると内側も巻き込まれて、両方は立てられないため。
