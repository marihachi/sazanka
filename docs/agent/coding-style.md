# コードの書き方

コードは人が読む前提で書く。テストの用意（フィクスチャ）も同じ。

## Biome

整形（インデント、行の長さ、クォート、末尾のカンマなど）と Lint は Biome に任せる。設定は `biome.json`。

- 1 行は 100 桁（`lineWidth`）。
- Lint は推奨の規則（`preset: recommended`）をすべて有効にしている。
- import の並べ替え（`organizeImports`）は使わない。
- SVG は Lint の対象から外している。アイコンは CSS の `mask` で形を切り抜くための素材で、画像として表示したり読み上げたりするものではないため（[アイコンとロゴ](icons.md)）。
- このドキュメントの取り決めと Biome の整形の結果がぶつかったら、Biome を優先する。`npm run format` をかけ直しても変わらない形が正しい形。取り決めに合わせるために、整形をやり直したり Biome の設定を変えたりしない。

### 指摘を抑えるとき

- `biome-ignore`（Lint）と `biome-ignore format`（整形）には、必ず理由を書く。規則がその場面に当てはまらないときに限って使う。
- 今抑えている主なもの:
  - `useEffect` などの依存配列を、意図して絞っているもの（依存を足すと動きが変わる）。
  - ピンの番号を `key` にしているもの（ピンは番号そのものが識別子）。
  - シートを描画面として扱っているもの（マウスとタッチで操作し、キーボードでの操作は用意していない）。

### React を import できるファイル

- React を使うのは `.tsx` と `use*.ts` だけ。それ以外の `.ts` では、`react`、`react-dom`、Chakra UI、Emotion の import を `noRestrictedImports` で禁じている（`biome.json` の `overrides`）。理由は[ソースの構成](structure.md)の「画面と計算の分け方」。
- `ui/theme.ts` だけは禁止から外している。Chakra のテーマの設定で、JSX も状態も持たない画面の側のファイルのため。
- Biome が見るのは import するパッケージだけ。`.ts` から `.tsx` のコンポーネントを import することは止められないが、これもしない。

## 制御構文

`if`、`for`、`while` などの本体は、1 行でも波括弧で囲む（Biome の `useBlockStatements`）。あとから行を足したときに、括弧の付け忘れで意図しない範囲になるのを防ぐため。早期 return や `break;` も同じ。

```ts
// 書かない
if (!raw) return value;

// 書く
if (!raw) {
  return value;
}
```

## 必ずあるはずの値

非 null アサーション（`!`）は使わない（Biome の `noNonNullAssertion`）。「ここでは必ずある」値は、なければ何が壊れたかを書いた例外にして取り出す。あとで分かりにくいエラーになる前に、その場で止めるため。

- `Map` から、あるはずのキーの値を取り出すときは `src/util.ts` の `mustGet` を使う。
- それ以外（要素の ref など）は、その場で `if (!x) { throw new Error(...) }` と書く。同じ取り出しが何度も出てくるなら、小さな関数にまとめる（例: `Sheet.tsx` の `sheetSvg`）。
- `useEffect` の中で使う ref は、例外にせず `if (!svg) { return; }` で何もしない。

## オブジェクトと配列の改行

- オブジェクトを 1 行に書くか、メンバごとに改行するかは、読みやすい方を選ぶ。
  - 同じ形のものが並ぶとき（テストの部品の一覧など）は、1 行ずつ書いて縦にそろえる。違いを目で追えるため。
  - 意味のまとまりを見せたいときや、1 行では追えないときは、メンバごとに改行する。
- Biome は、オブジェクトの `{` の直後の改行を保つ。`{` の直後で改行すれば縦のまま、1 行に書けば（100 桁に収まる限り）1 行のまま残る。100 桁を超えると Biome が折り返す。
- 配列は改行が保たれず、100 桁に収まると 1 行に詰められる。1 行に 1 要素ずつ並べて比べたい配列（テストの部品や配線の一覧など）は、直前に `// biome-ignore format: 表形式を維持するため` を付けて整形から外す。
  - 付けるのは、要素が 2 つ以上あり、並べて比べたいものだけ。
  - 整形から外した配列は折り返されないので、行が長くなりすぎないよう手で整える。

```ts
// 並べて比べるもの
const comps: Component[] = [
  { id: 'a', kind: 'INPUT', x: 0, y: 0, on: a },
  { id: 'b', kind: 'INPUT', x: 0, y: 0, on: b },
];

// まとまりごとに見せるもの
return {
  past: [...h.past, h.present].slice(-LIMIT),
  present: next,
  future: [],
};
```

## テスト

- テストは Vitest。対象のファイルと同じフォルダに、同じ名前で置く（`sim.ts` なら `sim.test.ts`）。対象のファイルを分けたり改名したりしたら、テストも合わせる。
- `sim.ts` のように 1 つのファイルのテストが大きいものは、観点で分けてよい（例: `simDetail.test.ts` は細かい動きと不変条件）。

### 開発者からの指示

- テストは、React に依存しない処理について書く。
- localStorage などの外部の環境に依存する部分（`file/storage.ts` の `load*` / `save*`）はテストしない。ブラウザで確かめる（[ブラウザでの動作確認](browser-check.md)の「保存の確かめ方」）。その中の環境に依存しない検証や変換（文字列を受け取って結果を返す `readStored` など）はテストする。
