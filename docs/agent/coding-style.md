# コードの書き方

このプロジェクトのコードは、人が読む前提で書く。テストの用意（フィクスチャ）も同じ。

整形（インデント、行長、クォート、末尾カンマなど）と Lint は Biome に任せる（設定は `biome.json`）。ここに書くのは、Biome が判断しない事柄と、Biome の規則を選んだ理由。

ここの取り決めと Biome の整形の結果がぶつかったら、Biome を優先する。`npm run format` をかけ直しても形が変わらない状態が正しい形で、この文書に合わせるために整形をやり直したり、Biome の設定を変えたりはしない。取り決めの方が、Biome の出力の中で選べる範囲に収まっていないだけなので、その箇所は Biome が出した形のままにする。

## Lint

- 推奨の規則（`preset: recommended`）をすべて有効にしている（開発者の方針）。
- 指摘を抑えるとき（`biome-ignore`）は、理由を必ず書く。規則の方が当てはまらない場面に限る。今抑えているのは次のようなもの。
  - React の効果の依存を、意図して絞っているもの（依存を変えると動きが変わる）
  - ピンの番号を `key` にしているもの（ピンは番号そのものが識別子）
  - シートを描画面として扱っているもの（マウスとタッチで操作し、キーボードでの操作は用意していない）
- SVG のアセット（`src/assets/`、`public/`）は Lint の対象から外している。アイコンは CSS の `mask` で切り抜きに使う素材で、画像として読み上げられることがないため（[アイコンとロゴ](icons.md)）。
- import の並べ替え（`organizeImports`）は使っていない。

## 制御構文

- 制御構文 (`if` や `for`、`while` など) の本体は、1行で済む場合でも波括弧を付ける（開発者の方針）。後から行を足したときに、括弧の付け忘れで意図しない範囲になるのを防ぐ。早期 return や `break;` も例外にしない。Biome の `useBlockStatements` で守らせている。

  変更前:
  ```ts
  if (!raw) return value;
  ```
  変更後:
  ```ts
  if (!raw) {
    return value;
  }
  ```

## 必ずあるはずの値

- 非 null アサーション（`!`）は使わない（Biome の `noNonNullAssertion`）。「ここでは必ずある」値は、なければ何が壊れたかを書いた例外にして取り出す。後で分かりにくいエラーになる前に、その場で止めるため。
  - `Map` から、あるはずのキーの値を取り出すときは `engine/util.ts` の `mustGet` を使う。
  - それ以外（要素の ref など）は、その場で `if (!x) { throw new Error(...) }` と書くか、同じ取り出しが何度も出てくるなら小さな関数にまとめる（例: `Sheet.tsx` の `sheetSvg`）。
  - React の効果の中の ref は、例外にせず `if (!svg) { return; }` で何もしない。

## オブジェクトリテラル

- 1 行に書くか、メンバ毎に改行するかは、書き手が読みやすい方を選ぶ。一律の規則は置かない。
  - 同じ形のものが並ぶとき（テストの部品の一覧など）は、1 行ずつにして縦にそろえると、違いが目で追える。
  - 意味のまとまりごとに見せたいときや、メンバが増えて 1 行では追えないときは、メンバ毎に改行する。

  ```ts
  // 並べて比べるもの
  const comps: Component[] = [
    { id: 'a', kind: 'INPUT', x: 0, y: 0, on: a },
    { id: 'b', kind: 'INPUT', x: 0, y: 0, on: b },
  ];

  // まとまりごとに見せるもの
  return {
    past: [...h.past, h.present].slice(-LIMIT),
    present: next,
    future: [],
  };
  ```

- Biome の整形は、オブジェクトの `{` の直後の改行を保つので、どちらの形も保たれる。`{` の直後で改行しておけば 1 行に詰め直されず、1 行に書いたものは（`lineWidth` の 80 桁に収まる限り）1 行のまま残る。
- 80 桁に収まらないものは、1 行に書いても Biome が折り返す。長いオブジェクトは結局メンバ毎に縦に並ぶので、迷う必要はない。
