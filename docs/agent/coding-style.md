# コードの書き方

このプロジェクトのコードは、人が読む前提で書く。テストの用意（フィクスチャ）も同じ。

整形（インデント、行長、クォート、末尾カンマなど）は Prettier に任せる。ここに書くのは、Prettier が判断しない事柄だけ。

ここの取り決めと Prettier の結果がぶつかったら、Prettier を優先する。`npm run format` をかけ直しても形が変わらない状態が正しい形で、この文書に合わせるために整形をやり直したり、Prettier の設定を変えたりはしない。取り決めの方が、Prettier の出力の中で選べる範囲に収まっていないだけなので、その箇所は Prettier が出した形のままにする。

## 制御構文

- 制御構文 (`if` や `for`、`while` など) の本体は、1行で済む場合でも波括弧を付ける。後から行を足したときに、括弧の付け忘れで意図しない範囲になるのを防ぐ。
- 制御構文の本体が次の行に渡るなら、括弧を付ける。

  変更前:
  ```ts
  if (!raw) return value;
  ```
  変更後:
  ```ts
  if (!raw) {
    return value;
  }
  ```

- 例外として、本体が `break;` `continue;` `return;` のように、その場で抜けるだけの短い文なら、括弧を省いて同じ行に書いてよい。

  ```ts
  if (h.past.length === 0) return h;
  ```

- ただし、オブジェクトを組み立てて返す早期 return は、短くても括弧を付ける。`{` が並んで、ブロックなのか返す値なのかが読み取りにくくなるため。

  ```ts
  if (!raw) {
    return { project: emptyProject() };
  }
  ```

## オブジェクトリテラル

- 1 行に書くか、メンバ毎に改行するかは、書き手が読みやすい方を選ぶ。一律の規則は置かない。
  - 同じ形のものが並ぶとき（テストの部品の一覧など）は、1 行ずつにして縦にそろえると、違いが目で追える。
  - 意味のまとまりごとに見せたいときや、メンバが増えて 1 行では追えないときは、メンバ毎に改行する。

  ```ts
  // 並べて比べるもの
  const comps: Component[] = [
    { id: 'a', kind: 'INPUT', x: 0, y: 0, on: a },
    { id: 'b', kind: 'INPUT', x: 0, y: 0, on: b },
  ];

  // まとまりごとに見せるもの
  return {
    past: [...h.past, h.present].slice(-LIMIT),
    present: next,
    future: [],
  };
  ```

- Prettier の `objectWrap` は既定の `preserve` なので、どちらの形も保たれる。`{` の直後で改行しておけば 1 行に詰め直されず、1 行に書いたものは（`printWidth` の 80 桁に収まる限り）1 行のまま残る。
- 80 桁に収まらないものは、1 行に書いても Prettier が折り返す。長いオブジェクトは結局メンバ毎に縦に並ぶので、迷う必要はない。
