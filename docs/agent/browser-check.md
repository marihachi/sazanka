# ブラウザでの動作確認

ヘッドレスブラウザでこのアプリの動きを確かめるときの、このアプリ固有の事柄。確かめる方針は[作業の進め方](workflow.md)、進め方は Skill の `browser-check` にある。何を確かめるかは、各ドキュメントの「触ったら確かめること」にある。

## 起動と開く先

- 開発サーバーは `npx vite --port 5199 --strictPort` で起動し、`http://localhost:5199/sazanka/` を開く（`vite.config.ts` の `base` の下に置かれる）。
- ビルドしたものでしか確かめられないもの（`licenses.txt` など。[ライブラリとライセンス](licenses.md)）は、`npx vite build` のあと `npx vite preview --port 5199 --strictPort` で開く。

## 状態の用意

- 確かめるための回路は、画面で組み立てるより、保存データ（localStorage の `sazanka.project`）に直接書いて用意する方が速い。形は[保存データ](persistence.md)と `docs/format/v3.md` にある。
  - アプリはプロジェクトが変わるたびに自動で保存するので、書いた値が上書きされることがある。書き方は Skill の `browser-check` の「ハマりやすい点」に従う。
  - 例（INPUT → AND → OUTPUT）。配線の点は、ピンの先の位置（`docs/format/v3.md` の「ピンの先の位置」）に合わせる:

    ```js
    const project = {
      version: 3,
      project: {
        circuits: [
          {
            id: 'main',
            name: 'メイン',
            parts: [
              { id: 'part-1', kind: 'input', x: 2900, y: 1960 },
              { id: 'part-2', kind: 'and', x: 3020, y: 1940 },
              { id: 'part-3', kind: 'output', x: 3180, y: 1960 },
            ],
            wires: [
              { id: 'wire-1', points: [{ x: 2960, y: 1980 }, { x: 2980, y: 1980 }, { x: 2980, y: 1960 }, { x: 3000, y: 1960 }] },
              { id: 'wire-2', points: [{ x: 3100, y: 1980 }, { x: 3160, y: 1980 }] },
            ],
          },
        ],
      },
    };
    ```

- ほかのキー: 環境設定は `sazanka.preferences`、パレットの折り畳みは `sazanka.paletteCollapsed`、シートの表示は `sazanka.views`（`file/storage.ts`）。
- 部品の座標は、シート（6000×4000、真ん中は (3000, 2000)）の中に置く。部品同士が重ならないよう、`GRID`（20）の何倍かずつ離す。
  - 表示（`sazanka.views`）を保存していない回路は、部品があれば回路全体が見える表示で開き、部品がなければシートの真ん中を等倍で開く（[シートの表示](view.md)）。
- 発振する回路が要るときは、NOT の出力を自分の入力へつなぐ。
- 部品の座標を読み書きして操作するときは、シートの `<g transform="translate(x y) scale(s)">` から、回路の座標を画面の座標に直す（画面の座標 = 回路の座標 × s + (x, y) + シートの左上）。
- 配線モード（`W`）で何もないところや部品の上をクリックすると、配線の点を置く。選択の確認をするときは、選択モード（`V`）に戻っているかを確かめる（ツールバーのボタンの `aria-pressed`）。
- INPUT の ON/OFF は保存データから読まない。ON にしたいときは、開いてからクリックする。
- 保存データが空のときは、メイン回路だけの空のプロジェクトで開く。

## 表示言語

- 保存した環境設定がなければ、ブラウザの言語で表示言語が決まる（日本語なら日本語、それ以外は英語）。ヘッドレスの Chrome は、たいてい英語になる。
- 言語を決めて開くときは、`sazanka.preferences` の `language`（`'ja'` / `'en'`）を書くか、読み込む前に `navigator.languages` を差し替える（Puppeteer なら `page.evaluateOnNewDocument(() => Object.defineProperty(navigator, 'languages', { get: () => ['ja'] }))`）。
- ボタンを `aria-label` で探すときは、その言語の文言で探す（例: 日本語は `環境設定`、英語は `Preferences`）。

## 要素の探し方

- シート（配線や部品）は CSS Modules なので、クラス名にハッシュが付く。部分一致で探す（例: 配線は `wire` を含み、`wire-hit` を含まないクラス。分岐の印は `junction`、出力のぶつかりは `conflict` を含む）。
- Chakra UI の部品は、役割の属性で探せる。
  - ダイアログは `[role="dialog"]`、確定ボタンのある確認は `[role="alertdialog"]`。
  - タブは `[role="tab"]`、開いているタブは `aria-selected="true"`。
  - ツールチップの文字は、`[data-scope="tooltip"][data-part="content"]` のうち `data-state="open"` のもの。ポインターを載せてから 400ms で出る。
- ヘッダーなどのボタンは `aria-label`（ボタンの名前）で探せる。削除エリアの丸は `aria-label="ここへドラッグで削除"`。

## 気を付けること

- ステータスバーのヒントの切り替えは、ヒントが 2 文以上ある状態（何もない回路で、何も選んでいないとき）で試す。ドラッグ中や配線中などは 1 文だけなので切り替わらない（[UI](ui.md)の「ステータスバーのヒント」）。
- パレットからシートへ部品を置く操作は、ブラウザのドラッグ＆ドロップ（`dataTransfer`）を使う。Skill の「人の操作をまねる」の例外に当たるので、合成イベントで確かめる。落とす先はシートの `svg`。
- CLOCK が動いている間は、ヘッダーのボタンのツールチップが消える既知の不具合がある（[UI](ui.md)の「ツールチップ」）。ツールチップを確かめるときは、何もない回路で行う。

## 保存の確かめ方

localStorage の読み書き（`file/storage.ts` の `load*` / `save*`）は単体テストを書かず、ここで確かめる（[コードの書き方](coding-style.md)の「テスト」）。保存の処理を触ったら、次を確かめる。

- 保存: 回路、環境設定、パレットの折り畳み、シートの表示（拡大縮小や移動）を変えて再読み込みすると、同じ状態で開く。
- 壊れた値: 各キーに、壊れた JSON や形の違う値（項目が欠けている、型が違う、範囲外の数）を書いてから再読み込みする。
  - 環境設定・折り畳み・表示は、例外を出さずに開き、読めないところだけ既定値になる（環境設定は項目ごと、表示は回路ごと、折り畳みはグループの ID ごと）。
  - プロジェクトは、空のプロジェクトで開き、ダイアログで知らせる。

## フレームレートを測る

測り方は Skill の `browser-check` の「フレームレートを測る」にある。ここには、このアプリで測る条件と目安を書く。

- 測るのは、React で描画するコード（`.tsx` と `use*.ts`。[ソースの構成](structure.md)の「画面と計算の分け方」）を変えたとき。それ以外の `.ts`（純粋な計算処理）だけの変更では測らない。重くなりやすいのは描き直しの方だから（[描画の重さ](performance.md)）。
- CPU は 4 倍遅くする。
- CLOCK を十数個置いた回路（保存データに直接書く）で、CLOCK が動いているだけのときと、部品をドラッグしているときを測る。
- 目安（ビルドしたもの）: どちらも 60 fps。開発用のサーバーでは、ドラッグ中は 50 fps 台まで下がる。
- 下がっていたら、まず描き直しが増えていないかを疑う（[描画の重さ](performance.md)）。

## 荒い操作で試すもの

Skill の「荒い操作を試す」の種類ごとの、このアプリでの例。触った範囲に当てはまるものを選ぶ。

- 連打: タブバーの「+」、元に戻す・やり直し（ボタンと Ctrl+Z / Ctrl+Y）、1 tick 進める・戻す、ダイアログの確定ボタンと Enter、すべて折りたたむ、拡大・縮小。
- 割り込み: ダイアログが開く途中の Esc。タブや部品のドラッグ中の Esc・右クリック・ホイール・Ctrl+Z。
- はみ出し: タブや部品を画面の外までドラッグして離す。
- 入力: タブやモジュールの名前（空、とても長い、改行入り）、tick の間隔と CLOCK の周期（全角の数字、負の数、`1e3`、とても大きな数）、読み込みに貼る文字列（とても大きい、壊れた JSON）。
- 画面: ダイアログを開いたまま、またはタブのドラッグ中に幅を変える。幅 320px。
- 速さ: パレットの部品やタブを 3 回続けてクリックする。
- 二重にできていないかは、モジュールの数（タブの数）と部品の数で見る。

## Claude Code

- バックグラウンドで起動した開発サーバーは、タスクを止めても（`TaskStop`）、Windows では vite の node が残ってポートをふさぐことがある。次に起動すると `--strictPort` で失敗し、確認のスクリプトは残った古いサーバーにつながってしまう。止めたら、ポート（5199）で待ち受けているプロセスが残っていないかを確かめ、残っていれば止める。
