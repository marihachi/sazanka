# ブラウザでの動作確認

このアプリをヘッドレスブラウザで動かして確かめるときの、このアプリ固有の事柄。確かめる方針は[作業の進め方](workflow.md)、進め方は Skill の `browser-check` にある。何を確かめるかは、各実装のドキュメントの「触ったら確かめること」にある。

## 起動と開く先

- 開発サーバーは `npx vite --port 5199 --strictPort` で起動し、`http://localhost:5199/sazanka/` を開く（`vite.config.ts` の `base` の下に置かれる）。
- ビルドしたものでだけ確かめられるものがある（`licenses.txt` は、ビルドで書き出すので開発サーバーにはない。[ライセンス](licenses.md)）。そのときは `npx vite build` のあと `npx vite preview --port 5199 --strictPort` で開く。

## 状態の用意

- 回路を用意するときは、画面で組み立てるより、保存データ（localStorage の `sazanka.project`）に直接書く方が速い。形は[保存データ](persistence.md)にある。
  - 最初のページ読み込みが終わるのを待ってから書き、書いたら再読み込みする。待たずに書くと、アプリの自動保存に上書きされる。
  - CLOCK が動いている回路では tick ごとに保存されるので、書いてから再読み込みするまでの間に上書きされる。そのときは次の読み込みの最初（アプリのスクリプトが動く前）に書き換える（Puppeteer なら `page.evaluateOnNewDocument`）。
  - 保存データの例（INPUT → AND → OUTPUT）:

    ```js
    const project = {
      version: 1,
      project: {
        circuits: [
          {
            id: 'main',
            name: 'メイン回路',
            components: [
              { id: 'part-1', kind: 'INPUT', x: 2400, y: 1900 },
              { id: 'part-2', kind: 'AND', x: 2560, y: 1900 },
              { id: 'part-3', kind: 'OUTPUT', x: 2720, y: 1900 },
            ],
            wires: [
              { id: 'wire-1', from: { comp: 'part-1', pin: 0 }, to: { comp: 'part-2', pin: 0 }, points: [] },
              { id: 'wire-2', from: { comp: 'part-2', pin: 0 }, to: { comp: 'part-3', pin: 0 }, points: [] },
            ],
          },
        ],
      },
    };
    ```

- ほかの保存データ: 環境設定は `sazanka.preferences`、パレットの折り畳みは `sazanka.paletteCollapsed`、シートの表示は `sazanka.views`（`app/storage.ts`）。
- 部品の座標は、シートの表示範囲に合わせる。シートは横 300 マス・縦 200 マスあり、開いた直後はその真ん中（`x` が 2500 前後、`y` が 1900 前後）が見えている（`components/view.ts` の `centerView`）。原点に近い座標に置くと画面の外になる。部品同士が重ならないよう、`GRID`（20）の何倍かずつ離す。
- 発振する回路が要るときは、NOT の出力を自分の入力へつなぐ。
- 新しいプロファイルで開くと保存データは空（メイン回路だけ）になる。スクリプトを分けて走らせると、前の確認の状態は残らない。

## 要素の探し方

- CSS Modules のクラス名にはハッシュが付くので、部分一致で探す（`wire` を含み `wire-hit` を含まない、など）。
- Chakra UI の部品は、役割の属性で探せる。
  - ダイアログは `[role="dialog"]`、取り返しのつかない操作の確認は `[role="alertdialog"]`。
  - タブは `[role="tab"]`、開いているタブは `aria-selected="true"`。
  - ツールチップの文字は `[data-scope="tooltip"][data-part="content"]` のうち `data-state="open"` のもの。ポインターを載せてから 400ms で出る。
- ヘッダーなどのボタンは `aria-label`（ボタンの名前）で探せる。

## 気を付けること

- ステータスバーのヒントの切り替えは、ヒントが 2 文以上ある状態（何もない回路など）で試す。発振中や、部品にポインターが載っている間は 1 文だけなので切り替わらない。
- パレットからシートへ部品を置く操作は、ブラウザのドラッグ＆ドロップ（`dataTransfer`）なので、ヘッドレスブラウザの実際のポインター操作では起こせない。`DataTransfer` を持たせた `DragEvent` を `dragstart` → `dragover` → `drop` の順に送り、報告にそう書く。
- CLOCK が動いている間は、ヘッダーのボタンのツールチップが消える既知の不具合がある（[UI](ui.md)）。ツールチップを確かめるときは、何もない回路で行う。

## 荒い操作で試すもの

Skill の「荒い操作を試す」の種類ごとの、このアプリでの例。触った範囲に当てはまるものを選ぶ。

- 連打: タブバーの「+」、元に戻す・やり直し（ボタンと Ctrl+Z / Ctrl+Y）、1 tick 進める・戻す、ダイアログの確定ボタンと Enter、すべて折りたたむ、拡大・縮小。
- 割り込み: ダイアログが開く途中の Esc。タブや部品のドラッグ中の Esc・右クリック・ホイール・Ctrl+Z。
- はみ出し: タブや部品を画面の外までドラッグして離す。
- 入力: タブやモジュールの名前（空、とても長い、改行入り）、tick の間隔と CLOCK の周期（全角の数字、負の数、`1e3`、とても大きな数）、読み込みに貼る文字列（とても大きい、壊れた JSON）。
- 画面: ダイアログを開いたまま、またはタブのドラッグ中に幅を変える。幅 320px。
- 速さ: パレットの部品やタブを 3 回続けてクリックする。
- 二重にできていないかは、モジュールの数（タブの数）と部品の数で見る。
