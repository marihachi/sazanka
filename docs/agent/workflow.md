# 作業の進め方

## 言語

開発者とのやりとり、UI の文言、コードのコメント、ドキュメントは日本語で書く。

### 開発者からの指示

- 開発者の画面に出るものは、すべて日本語にする。返答の本文だけでなく、ツールを呼ぶときの説明や、確認用のスクリプトが出す文言も含む。

## 変更したあとの確認

1. `npm run format` で整形する（Biome）。
2. `npm run lint`、`npx tsc -b`、`npm test`、`npx vite build` を通す。

- `npm run build` は、型チェックとビルドをまとめて行う。`npm run check` は整形と Lint をまとめて確かめ、`npm run format:check` は整形されているかだけを確かめる。
- Markdown は Biome の対象外。ドキュメントは手で整える。
- 改行コードは LF にそろえている（`.gitattributes` と `biome.json`）。`core.autocrlf=true` の環境でも、`.gitattributes` があるので CRLF にならない。
- Windows では、`npm test` がまれに全テストファイルの読み込みに失敗し、「no tests」で終わることがある。原因は分かっていない（作業フォルダのドライブ名が `c:` と `C:` で切り替わった直後に起きやすい）。個々のテストが失敗したのではなく、全ファイルがまとめて読めなかったときは、まず再実行する。たいていは通る。

### 開発者からの指示

- 変更したら、上の確認をひととおり通す。
- 画面や操作に関わる変更をしたら、ヘッドレスブラウザで動きを確かめる。テストとビルドが通るだけで済ませない。やり方は Skill の `browser-check`、このアプリ固有のことは[ブラウザでの動作確認](browser-check.md)にある。
  - クリック、ダブルクリック、ドラッグ、文字の入力は、人の速さと間隔でする。一瞬で操作すると、人の操作では起きない失敗をしたり、人の操作でだけ起きる不具合を見逃したりするため。
  - フレームレートが下がっていないかも毎回測る。重さは機能の確認では気付けず、あとから原因を探すのが難しいため。
  - 作業の区切り（一連の置き換えや機能の追加が終わったとき）と、開発者に頼まれたときは、荒い操作のテスト（連打、ドラッグ中の割り込み、画面の外へのドラッグ、おかしな入力など）もする。対象は、その作業で触った範囲。
  - 確かめられなかったものは、報告にそう書く。

## コミット

### 開発者からの指示

- コミットは、開発者に頼まれたときだけ行う。

## 合意してから進める

判断が要るものは、案を示して開発者の合意を得てから始める。

- 示すもの: 案（複数あれば候補と、推す案とその理由）、影響が及ぶ範囲、選ばなかった案の理由。名前は候補を複数挙げる。
- 進めている途中で案を変えたくなったら、勝手に変えずにもう一度示す。
- 迷ったら、決め打ちせずに聞く。
- 計画を立てる手順は Skill の `plan` にある。

### 開発者からの指示

- 合意が要るのは、構成やファイルの分け方の変更、保存データや共有用 JSON の形式、画面の作りや操作の割り当て、ライブラリの追加、名前の付け方、Skill の追加・変更・削除。
- 取り決め（ドキュメントに書く方針や決まり）の変更は、案を示さずにその場で直してよい。ただし「開発者からの指示」の規則は、開発者が意向を示したとき（「〜しましょうか」でもよい）だけ直す。

## 実装を始める合図

実装を進める手順は Skill の `implement` にある。

### 開発者からの指示

- 実装（ソースコード、画面、ファイル名など、アプリの実装の変更）は、開発者から始めることをはっきり指示されてから始める。計画や調査を頼まれたときは、実装を始めない。
- 合図にするのは、始めることを直接言っている指示だけ。例: 「開始して」「実装を始めて」「作ってください」「その内容で実装して」。
- 曖昧な答えは合図にしない。例: 「その内容でいいよ」「OK です」「それでいきましょう」「いいですね」「〜しましょうか」。これらは計画への合意で、実装を始める指示ではない。
- 「進めて」のように、何を進めるのかが文脈で分かれるものも、実装を始めることがはっきりしなければ合図にしない。
- ファイル名の変更も実装に含む。名前への合意だけでは改名しない。
- 段階に分けた実装では、各段階の区切りで止め、次の段階も合図を待つ。
- 合図を待つときは、結果、次にすること、決めてほしいことを示して返答を終える。
- 合図があるか迷ったら、始めずに聞く。
- 合図が要るのは実装の変更だけ。取り決めの変更には要らない（上の「合意してから進める」）。ただし、Skill を新しく作るときは合図が要る。

## Claude Code

- Edit / Write でファイルを編集するたびに、フック（`.claude/settings.json` → `.claude/hooks/format.mjs`）が Biome で整形する。Lint の指摘は直さないので、`npm run lint` で確かめる。
- シェルからの書き込み（sed、スクリプトなど）にはフックが効かない。その場合は自分で整形する。
