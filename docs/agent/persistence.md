# 保存データ

プロジェクトの保存データと共有用 JSON、利用者ごとの設定の保存。形式の仕様は `docs/format/` にある（今は [version 1](../format/v1.md)）。

## 前提

アプリは公開済み。利用者の手元には、それぞれの版で保存したデータと、書き出した共有用 JSON が残っている。共有用 JSON は他人の手元にも渡るので、保存データ以上に古い版が回ってくる。

## 形式を変えるとき

- 版を上げるのは、今の版で古いデータを読むのに変換が要る変更（項目の意味や形が変わるなど）のとき。部品の種類や、省略できる項目を足すだけなら上げない。
  - 上げなくてよいのは、公開しているのが最新版だけで、新しいデータが古い版で開かれることがほぼないため。古い版を開けるようにする（版ごとの URL を残す、オフラインで動かすなど）なら、この判断を見直す。そのときは、追加だけでも版を上げることと、古い版が新しいデータを上書きしないようにすることが要る。今は、古い版のアプリで新しいデータを開くと、「壊れている」か「新しい版のデータ」として断り、空のプロジェクトを自動保存で上書きしてしまう。
- 保存データは `file/storage.ts` の `STORAGE_VERSION` を上げ、`readStored` に古い版を読む分岐を足す。
- 共有用 JSON は `file/share.ts` の `SHARE_VERSION` を上げ、`parseProject` に古い版を読む分岐を足す。
- どちらも、今より新しい版のデータは読み込まずに断る。
- 部品の種類や項目を足したら、検証（`project.ts` の `checkProject`）も合わせる。置ける種類の判定（`component.ts` の `isPlaceableComponentKind`）は `PARTS` と `SPECIAL_KINDS` を見るので、`PARTS` に足した種類はそのまま検証を通る。

### 開発者からの指示

- 保存データと共有用 JSON の形式を、古いデータがそのままでは読めなくなる形に変えるときは、必ず版を上げ、古い版を読み込む処理を足す。
- 形式の仕様は、版ごとに 1 つの文書で書く（`docs/format/v1.md` など）。
  - 形式を変えたら、今の版の文書も直す。版を上げずに足したもの（部品の種類など）は、その文書の「version 1 の中で変えたもの」に書き足す。
  - 版を上げたら、新しい版の文書（例: `v2.md`）を作り、古い版の文書は `docs/format/archive/` に移す。移した文書は、古い版を読む処理を書くときに参照するので書き換えない。
  - 保存データと共有用 JSON の版は別々の番号。片方だけ上げることになったら、文書の分け方を開発者に相談する。
- モジュールをファイルとして保存し、パスで参照する案を[検討中](../design/module-files.md)。まだ何も決まっていないので、実装しない。保存形式やモジュールの参照を変えるときは、この検討とぶつからないかだけ見て、進め方は開発者に聞く。

## 保存データ

- プロジェクトは、変わるたびに localStorage の `sazanka.project` に自動で保存する（`App.tsx` の `useEffect` から `storage.ts` の `saveProject` を呼ぶ）。形は `{ version, project }`。
- 読み込むときは、共有用 JSON と同じ検証（`checkProject`）を通す。壊れていたら空のプロジェクトで開き、ダイアログで利用者に知らせる。壊れたデータをそのまま使うと、表示や計算の途中で例外が起きて画面が出なくなるため。
- localStorage を使えない環境では、保存データなしとして扱い、保存の失敗は無視する。
- 読み込みの処理は、localStorage に触る `loadProject` と、文字列を受け取って結果を返す `readStored` に分けている。`readStored` はテストできる。

### 開発者からの指示

- 壊れたデータは退避しない。空のプロジェクトを自動保存で上書きする。

## 共有用 JSON

- ヘッダーの「書き出し」「読み込み」で使う（`file/share.ts`、操作は `file/useProjectFile.ts`）。形は `{ app: 'sazanka', version, project }`。
- 書き出すときは、部品と配線の ID を回路ごとに `part-1`、`wire-1` からの連番に付け直す（読みやすくするため）。読み込むときは、アプリの中と同じランダムな ID に付け直す。回路の ID はモジュールの参照に使うので、どちらでも変えない。
- 他人から受け取る文字列なので、読み込むときは形を検証してから使う（`checkProject`）。
- 書き出すときに作者名を付けられる（`Project.author`。空なら含めない）。作者名の入ったものを読み込むと、お知らせを出す。

## 保存しないもの

- INPUT と CLOCK の ON/OFF（部品の `on`）は、保存データにも共有用 JSON にも含めない（`project.ts` の `withoutSwitchStates`）。
  - アプリの中では部品に `on` を持ち、シミュレーションで使う。外すのは保存・書き出し・読み込みのときだけ。
  - 初めのころのデータには `on` が入っている。読み込むときに外すので、検証には足さない。形式の仕様にも書かない。
- フリップフロップの状態など、シミュレーション中の状態も保存しない。開き直すと、回路は初めの状態から動く。
- 元に戻すの履歴も保存しない。

### 開発者からの指示

- INPUT と CLOCK の ON/OFF は保存しない。動かしている間のほかの状態も保存しないので、それとそろえる。

## 消さないもの

- モジュールのピンが減って、存在しないピンを指すようになった配線も、削除せずにデータに残す。表示と計算から除くだけ（`Sheet.tsx`、`flatten.ts`）。ピンが元に戻れば配線も戻る、という前提なので、勝手に削除する処理を入れない。

## 利用者ごとの設定

回路とは別のキーに置く。読めなければ既定値で動かし、エラーにはしない。版は付けていない。

| キー                       | 中身                                                      | 読めないとき                         |
| -------------------------- | --------------------------------------------------------- | ------------------------------------ |
| `sazanka.preferences`      | 環境設定（tick の間隔、方眼、角の丸め、アクセントカラー） | 項目ごとに既定値                     |
| `sazanka.paletteCollapsed` | パレットで折り畳んでいるグループの ID                     | 空（すべて開く）。知らない ID は無視 |
| `sazanka.views`            | 回路 ID ごとの表示（位置と倍率）                          | 回路ごとに捨て、既定の表示で開く     |

- パレットの折り畳みは、グループの ID（`parts/view.ts` の `PaletteGroupId` と、モジュールのグループの `'module'`）で保存している。見出しの文字（`Palette.tsx` の `GROUPS`）は変えてよいが、ID は変えない。変えると、利用者が折り畳んでいた状態が失われる。
- 表示は回路 ID ごとに保存している。モジュールを削除したら、その ID の分を消す。新規作成と読み込みでは、ID が同じでも中身は別の回路なので、すべて消す。
