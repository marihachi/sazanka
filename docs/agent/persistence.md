# 保存データ

- 回路は localStorage に自動で保存している。利用者の手元の保存データを壊さないよう、形式を変えるときは古い形式を読み込めるようにしておくこと。
  - ただし未リリースの間は、開発者の判断で移行処理を省くことがある。リリース後は必ず移行処理を用意する。
  - 読み込むときは、共有用 JSON と同じ検証（`project.ts` の `checkProject`）を通し、壊れていたら空のプロジェクトで開いて利用者に知らせる。壊れたデータをそのまま使うと、表示や計算の途中で例外が起きて画面が出なくなる。
  - 壊れたデータの退避はしない（開発者の判断）。空のプロジェクトを自動保存で上書きする。
  - 形式を変えるときは `STORAGE_VERSION` を上げ、古い版を読み込む分岐を足す。新しい版のデータは読み込まずに断る。
- モジュールのピンが減って、存在しないピンを指すようになった配線も、削除せずにデータとして残している（表示と計算からは除いているだけ）。
  - ピンが元に戻れば配線も復活する、という前提。勝手に削除する処理を入れないこと。
- 共有用の JSON（ツールバーの「書き出し」「読み込み」、`src/engine/share.ts`）も保存データと同じく、利用者の手元に残り、他人に渡るデータとして扱う。
  - 形式を変えるときは `SHARE_VERSION` を上げ、古い版も読み込めるようにする。新しい版のデータは読み込まずに断る。
  - 他人から受け取る文字列なので、読み込むときは形を検証してから使う（`project.ts` の `checkProject`）。部品の種類や項目を足したら、検証も合わせて直す。
- 利用者ごとの表示の設定（パレットの折り畳みなど）は、回路とは別のキーに置く。読めなければ既定値で動かし、エラーにはしない。
