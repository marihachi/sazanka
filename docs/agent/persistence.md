# 保存データ

このアプリは公開済み（GitHub Pages）。利用者の手元には、それぞれの版で保存されたデータが残っている。
**保存データと共有用 JSON の形式を、古いデータがそのままでは読めなくなる形に変えるときは、必ず版を上げ、古い版を読み込む処理を足すこと。**
省いてよいのは未リリースの間だけだったので、その判断はもう使えない。

- 版を上げるのは、今の版で古いデータを読むのに変換が要る変更（項目の意味や形が変わるなど）のとき。部品の種類や省略可能な項目を足すだけなら上げなくてよい。
  - 公開しているのが最新版だけで、新しいデータが古い版で開かれることがほぼないため。古い版を開けるようにする（版ごとの URL を残す、オフラインで動かすなど）なら、この判断を見直す。そのときは、追加だけでも版を上げることと、古い版が新しいデータを上書きしないようにすることが必要になる（今は、古い版は新しいデータを「壊れている」か「新しい版のデータ」として断り、空のプロジェクトを自動保存で上書きする）。

- 形式の仕様は `docs/format/` に、版ごとに1つの文書で書いている（今は [version 1](../format/v1.md)）。
  - 形式を変えたら、今の版の文書も合わせて直す。版を上げずに足したもの（部品の種類など）は、その文書の「version 1 の中で足したもの」に書き足す。
  - 版を上げたら、新しい版の文書（例: `v2.md`）を作り、古い版の文書は `docs/format/archive/` に移す（開発者の方針）。古い版を読み込む処理を書くときに参照するので、移した文書は書き換えない。
  - 保存データと共有用 JSON の版は別々の番号。片方だけ上げることになったら、文書をどう分けるかを開発者に相談する。
- 回路は localStorage に自動で保存している。
  - 読み込むときは、共有用 JSON と同じ検証（`project.ts` の `checkProject`）を通し、壊れていたら空のプロジェクトで開いて利用者に知らせる。壊れたデータをそのまま使うと、表示や計算の途中で例外が起きて画面が出なくなる。
  - 壊れたデータの退避はしない（開発者の判断）。空のプロジェクトを自動保存で上書きする。
  - 形式を変えるときは `STORAGE_VERSION`（`app/storage.ts`）を上げ、`readStored` に古い版を読み込む分岐を足す。新しい版のデータは読み込まずに断る。
- モジュールのピンが減って、存在しないピンを指すようになった配線も、削除せずにデータとして残している（表示と計算からは除いているだけ）。
  - ピンが元に戻れば配線も復活する、という前提。勝手に削除する処理を入れないこと。
- 共有用の JSON（ツールバーの「書き出し」「読み込み」、`src/engine/share.ts`）も保存データと同じく、利用者の手元に残り、他人に渡るデータとして扱う。
  - 形式を変えるときは `SHARE_VERSION`（`engine/share.ts`）を上げ、`parseProject` に古い版を読み込む分岐を足す。新しい版のデータは読み込まずに断る。書き出した JSON は他人の手元にも残るので、保存データ以上に古い版が回ってくる。
  - 他人から受け取る文字列なので、読み込むときは形を検証してから使う（`project.ts` の `checkProject`）。部品の種類や項目を足したら、検証も合わせて直す（置ける種類の一覧は `component.ts` の `PLACEABLE_KINDS`）。
- 利用者ごとの表示の設定（パレットの折り畳み、シートの表示位置と倍率など）は、回路とは別のキーに置く。読めなければ既定値で動かし、エラーにはしない。版は付けていない。
  - シートの表示位置と倍率は、回路 ID ごとに保存している。モジュールを削除したら、その ID の分を消す。新規作成と読み込みでは、ID が同じでも中身は別の回路なので、すべて消す。
