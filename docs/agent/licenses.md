# ライブラリとライセンス

ライブラリを足すときの考え方と、ライセンスの表示。

## 今の依存

- 実行時: React、React DOM、UI の部品の Chakra UI（と、それが使う Emotion）。
- 開発用: Vite、TypeScript、Vitest、Biome、ライセンスを集める rollup-plugin-license。
- 回路のデータ、シミュレーション、シートの描画、状態の管理は、ライブラリを使わずに自前で書いている。

## ライブラリを足すとき

- 使った方が良いライブラリに気付いたら、開発者に提案する（勝手に入れない。[作業の進め方](workflow.md)の「合意してから進める」）。提案するのは、次の 2 つをどちらも満たすもの。
  - 実装のコストが下がる。自分で書くより、書く量と考えることが減る。
  - 長い目で見て、拡張の妨げにならない。作りたいものがライブラリの想定から外れたときに、書き直しや回避策が要らない。
- 提案には、何が楽になるか、代わりに増える制約（できなくなること、合わせ込みが要る箇所）、自分で書く場合との比較を含める。どちらかの条件が怪しいなら、その懸念も出す。
- ライセンスが MIT と両立するか（GPL などで、このアプリのライセンスに影響しないか）と、表示以外の条件がないかを確かめる。迷ったら開発者に相談する。
- アプリの実行時に使うものは `dependencies`、開発やビルドの道具は `devDependencies` に入れる。

## 同梱しているライブラリのライセンス

- 公開しているアプリは、同梱しているライブラリの複製を配っていることになる。MIT などは、配布物にライセンス文（著作権表示と許諾表示）を含めることを条件にしている。ビルドで JS を圧縮すると、ライブラリの中のライセンスのコメントは消えるので、それだけでは条件を満たさない。
- ライセンス文は、ビルドで `dist/licenses.txt` に書き出し、「このアプリについて」からリンクしている。
  - 一覧は手で書かず、`rollup-plugin-license` で集める（`vite.config.ts` の `licensesText`）。ビルドに実際に入ったモジュールが対象なので、依存に挙がっているだけのパッケージは載らない。
  - 実際に入ったものはビルドが終わるまで分からないので、JS に埋め込まず別のファイルにしている。開発用のサーバーではファイルができないので、リンク先は開けない。
  - ライセンス文のファイルがないパッケージは、`package.json` の `license`（種類）だけを載せ、本文の代わりに同梱されていない旨を出す。種類も分からないパッケージは載せない。どちらもビルドのログに `[licenses]` で始まる警告を出す。

### 開発者からの指示

- ライブラリや素材のライセンスが求める表示を、配布物に必ず含める。
- 同梱しているライブラリのライセンス文は `licenses.txt` に書き出し、「このアプリについて」からリンクする。
- ライセンスの種類も分からないパッケージは、一覧に載せない。

### 触ったら確かめること

依存を足したり、ライセンスの集め方（`vite.config.ts`）を触ったりしたら、次を確かめる。

- `npx vite build` のログに `[licenses]` の警告が出ていない。出ていたら、そのパッケージのライセンスを確かめる。
- `dist/licenses.txt` に、足したライブラリが載っている。
- ビルドしたものを `npx vite preview` で開き、「このアプリについて」のリンクから `licenses.txt` が文字化けせずに開ける。

## 素材

- アイコン（`src/assets/icons/` と `src/parts/<種類>/icon.svg`）は、このプロジェクトで描いたもの。外から素材を持ってくるときは、ライセンスを確かめ、必要な表示を「このアプリについて」に足す。
- ロゴの文字は、Inter SemiBold（SIL OFL）の字形をパスにしたもの（[アイコンとロゴ](icons.md)）。今は念のため、README と「このアプリについて」にフォント名とライセンスを書いている。
- ロゴのフォントは、フォントのファイル自体を配っていないので、ライセンスの表示は必須ではないと考えている。
