# UI

回路を描く領域は「シート」（コンポーネントは `Sheet`）と呼ぶ（ユーザーの指定）。コメントやドキュメントでも「キャンバス」とは呼ばない。

## アイコン

- アイコンは `src/assets/icons/` に SVG のアセットとして置く（ユーザーの指定）。コンポーネントの中にインラインで書かない。
- アイコンの SVG は CSS の `mask` として使い、形を切り抜いて文字色（`currentColor`）で塗っている。そのため、SVG の中で指定した色は表示に反映されない。塗る部分は不透明な色（`#000`）で描き、透明な部分が背景になる。色分けしたアイコンが必要になった場合は、この方式を見直す必要がある。
- ヘッダーのロゴ（`src/assets/logo.svg`）も同じ方式で、アクセントカラーで塗っている。ロゴの「sazanka」は、環境によって字形が変わらないよう、Inter SemiBold（SIL OFL）の字形をパスに変換して埋め込んでいる。文字やフォントを変えるときは、opentype.js などでパスを作り直す（大きさ 17px、ベースライン y=20、x=30 から、字間 0.5px）。文字の幅が変わったら、SVG の `viewBox` と `Header.module.css` の `.logo` の幅も合わせる。

## ダイアログ

- ブラウザの `prompt` / `confirm` / `alert` は使わない。ユーザーは VS Code 内のブラウザで動かしていて、そこではこれらが何もせずに終わる（`prompt` は null、`confirm` は false を返す）。
  - 代わりに `src/components/Dialogs.tsx` の画面内 UI（`Dialog`、`InlineInput`）を使う。

## ドラッグ

- 部品のドラッグでは、シート（svg）にポインターキャプチャを設定している。削除エリアなど、シートの外まで動きを追うため。
  - キャプチャ中は click や dblclick がシートに届き、部品には届かない。そのため、キャプチャは押した位置から少し動いてから設定する。押した時点で設定すると、ダブルクリック（ラベル編集、モジュールを開く）が動かなくなる。

## ステータスバーのヒント

- 分かりにくい操作や仕様に気付いたら、ステータスバーのヒントに適宜追加する（ユーザーの指示）。機能を追加・変更したときも、ヒントが必要か考える。
- ヒントの文言は `src/app/hints.ts` にまとめている。
- ヒントは短い文に分けて、時間で順に切り替えて表示する。操作の途中（配線中、ドラッグ中、編集中）は、そのとき必要な1文だけを出す。
