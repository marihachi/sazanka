# UI

回路を描く領域は「シート」（コンポーネントは `Sheet`）と呼ぶ（プロジェクトの方針）。コメントやドキュメントでも「キャンバス」とは呼ばない。

## アイコン

- アイコンは `src/assets/icons/` に SVG のアセットとして置く（プロジェクトの方針）。コンポーネントの中にインラインで書かない。
- アイコンの SVG は CSS の `mask` として使い、形を切り抜いて文字色（`currentColor`）で塗っている。そのため、SVG の中で指定した色は表示に反映されない。塗る部分は不透明な色（`#000`）で描き、透明な部分が背景になる。色分けしたアイコンが必要になった場合は、この方式を見直す必要がある。
- ヘッダーのロゴ（`src/assets/logo.svg`）も同じ方式で、アクセントカラーで塗っている。ロゴの「sazanka」は、環境によって字形が変わらないよう、Inter SemiBold（SIL OFL）の字形をパスに変換して埋め込んでいる。文字やフォントを変えるときは、opentype.js などでパスを作り直す（大きさ 17px、ベースライン y=20、x=30 から、字間 0.5px）。文字の幅が変わったら、SVG の `viewBox` と、ロゴを表示している場所の大きさ（`Header.module.css` の `.logo`、「このアプリについて」の `Dialogs.module.css` の `.about-logo`）も合わせる。
- ブラウザのタブのアイコン（`public/favicon.svg`）は、ロゴの花だけを抜き出したもの。マスク方式ではなく、アクセントカラー（`#2dd4bf`）を直接書いている。ロゴの花やアクセントカラーを変えたら、こちらも合わせて直す。

## ダイアログ

- ブラウザの `prompt` / `confirm` / `alert` は使わない。VS Code 内のブラウザなど、これらが何もせずに終わる環境がある（`prompt` は null、`confirm` は false を返す）。どの環境で開かれても動くようにするため。
  - 代わりに `src/components/Dialogs.tsx` の画面内のダイアログを使う。

## ドラッグ

- シートには `touch-action: none` を付けている。付けないと、スマホで指を動かし始めた時点でブラウザがスクロールとして扱い、pointercancel が来てドラッグが止まる。シートの上の操作はすべて Pointer Events で受けているので、タッチ専用の処理は持っていない。
- 部品のドラッグでは、シート（svg）にポインターキャプチャを設定している。削除エリアなど、シートの外まで動きを追うため。
  - キャプチャ中は click や dblclick がシートに届き、部品には届かない。そのため、キャプチャは押した位置から少し動いてから設定する。押した時点で設定すると、ダブルクリック（ラベル編集、モジュールを開く）が動かなくなる。
  - 何もないところから始める範囲選択は、クリックで何かをすることがないので、押した時点でキャプチャしている。
- 選択中の部品を押してドラッグすると、選択中の部品をまとめて動かす。移動量は、どの部品もシートからはみ出さない範囲に縮める（`layout.ts` の `clampMove`）。全体の形を崩さないため、部品ごとには止めない。

## シートの表示（スクロールと拡大縮小）

- シートは横 300 マス・縦 200 マスの有限の大きさ（`layout.ts` の `SHEET_WIDTH` / `SHEET_HEIGHT`）。左上が回路の座標の原点で、部品はシートの中にだけ置ける（`clampPosition`）。座標は負にならず、保存データの形は変わらない。
  - 表示はシートの外まで自由に動かせる（開発者の方針）。シートの外は色（`--outside`）を変え、境目に線を引いている。シートの大きさを変えるときは、この表示（`Sheet.tsx` の `sheetStart` / `sheetEnd` を使う部分）も合わせて確かめる。
  - シートより外にある部品（大きさを決める前に作った回路など）も、そのまま表示・計算する。動かしたときに初めてシートの中へ戻る。
- 表示の位置と倍率（`components/view.ts` の `View`）は、回路の座標を描く `<g>` の transform と、方眼の patternTransform の両方に掛けている。ポインターの位置は `toWorld` で回路の座標に直してから使う。ラベルの入力欄のような HTML の要素は拡大縮小せず、位置だけ `toScreen` で合わせる。
- 操作は、ホイール（トラックパッドのピンチも Ctrl 付きのホイールとして届く）で拡大縮小、中ボタンか Space を押しながらのドラッグで移動、スマホでは2本指で移動と拡大縮小（開発者の方針）。何もないところのドラッグは、パソコンでもスマホでも範囲選択のまま。
  - ホイールは `addEventListener` で `passive: false` を付けて登録している。React の `onWheel` は passive になり、`preventDefault` が効かずにページごと拡大されてしまうため。
  - 移動と2本指の操作は `onPointerDownCapture` で子要素より先に受け取り、そこで止める。部品の上から始めても、部品のドラッグや配線が始まらないようにするため。
  - 2本目の指が触れたら、1本目で始めていた部品のドラッグや範囲選択は打ち切る。2本指の操作の後は、指がすべて離れるまで1本目の操作を再開しない。
- 表示は回路ごとに覚え、localStorage に保存する（[保存データ](persistence.md)）。元に戻す対象にはしない。
  - 表示を保存していない回路は、開いた時点の表示をすぐに保存して固定する（`App.tsx`）。固定しないと、部品を置くたびに表示が計算し直され、画面が勝手に動く。
- 表示を保存していない回路の開き方（`view.ts` の `overview`）:
  - 部品のない回路は、シートの中央を画面の真ん中に置いた等倍の表示で開く（開発者の方針）。
  - 部品のある回路は、回路全体が見える表示で開く。既存の回路はシートの左上の近くに部品があるので、中央を表示すると隠れてしまうため。
  - 「回路全体を表示」も同じ関数を使う。シートの外が映る場合は、シートの端を画面の端に合わせる。

## ステータスバーのヒント

- 分かりにくい操作や仕様に気付いたら、ステータスバーのヒントに適宜追加する（プロジェクトの方針）。機能を追加・変更したときも、ヒントが必要か考える。
- ヒントは短い文に分けて、時間で順に切り替えて表示する。操作の途中（配線中、ドラッグ中、編集中）は、そのとき必要な1文だけを出す。
