# UI

画面の配置と、ボタン・ダイアログ・ヒントの決まり。どの操作に何を割り当てているかは[画面操作](interaction.md)、アイコンとロゴは[アイコンとロゴ](icons.md)、シートのスクロールと拡大縮小は[シートの表示](view.md)にある。

## 画面の配置

- 操作は、効く範囲で置き場所を分けている（開発者の方針）。操作を足すときも、どちらに効くかで置き場所を決める。
  - プロジェクト全体に効く操作（新規作成、書き出し、読み込み、元に戻す、やり直し）は、ヘッダー（`Header.tsx`）。元に戻すの履歴はすべての回路で1本なので、全体の操作として扱う。
  - 回路（タブ）の切り替えと、モジュールの追加は、タブバー（`TabBar.tsx`）。追加はタブの末尾の「+」。追加できるのはモジュールだけで、メイン回路は 1 つだけ。
  - 部品の一覧はシートの左のパレット（`Palette.tsx`）。
  - 開いている回路に効く操作（シミュレーションの一時停止・1 tick 送り、モジュールの削除）は、タブの下のシートのツールバー（`SheetToolbar.tsx`）。選択中のタブと同じ色（`bg.panel`）にして、そのタブの中の操作だと見せている。タブは Chakra の `Tabs`（`outline`）で、ドラッグでの並べ替えと名前の変更は `TabBar.tsx` が自前で足している。
  - シートの表示の拡大縮小は、シートの右下に重ねる（`ZoomControls.tsx`）。
  - 部品を消す削除エリアは、ズームのパネルの上に重ねる（`TrashZone.tsx`。開発者の方針）。ふだんは丸いごみ箱のアイコンだけで、部品をドラッグし始めると丸の下（外）に「削除」と出し、上に載せると丸が赤くなる。丸の位置と大きさは、ドラッグの前後で変えない（開発者の方針。運ぶ先が動くと狙いにくいため）。そのため「削除」の文字の場所はふだんから空けておき、ドラッグ中だけ見せる。ドラッグ中だけ出すのではなくいつも出しておくのは、ここへ運べば消せることに気付けるようにするため。
    - 部品を落としたかは、丸の画面上の位置で判定している（`Sheet.tsx` の `trashRef`。「削除」の文字の上は含まない）。エリアを動かしても判定は付いてくる。ステータスバーのヒントに場所（「右下の」）を書いているので、置き場所を変えたら `hints.ts` も直す。
  - 選んだ部品の項目（CLOCK の周期、INPUT / OUTPUT のラベルなど、部品ごとのプロパティ）は、シートの右側のプロパティ欄（`PropertyPanel.tsx`）で編集する（開発者の方針）。狭い画面（Chakra の `md` 未満）では、部品を選んでいる間だけ出す。部品に項目を足すときは、ここに入力欄を足す。
  - 環境設定のウィンドウ（`dialogs/PreferencesDialog.tsx`）を開くボタンは、ヘッダーの右端（このアプリについての隣）。環境設定は利用者ごとの値で、プロジェクトには含めない（型と選択肢は `components/preferences.ts`）。
- 取り消しにくい危険な操作のボタン（モジュールの削除など）は、`ToolButton` の `danger` で赤（Chakra の `colorPalette="red"`）にする。
- ボタンは `ToolButton.tsx`（Chakra の `Button` / `IconButton` の `ghost`）を使う。文字はアクセントカラーにせず灰色（`colorPalette="gray"`）で出す。パレットの部品と見出しのボタンも同じ。ページ全体の既定のパレットはアクセントカラーなので、指定しないと Chakra のボタンは青緑になる。狭い画面（Chakra の `md` 未満）では文字を隠してアイコンだけにし、文字はツールチップと読み上げ用のラベルに残す。
- ボタンなどの説明は、`title` ではなく `HintTooltip.tsx`（Chakra の `Tooltip`）で出す。見た目を Chakra にそろえるため。
  - 押せないボタン（`disabled`）はポインターのイベントを出さないので、そのままではツールチップが出ない。`span` などで包み、包んだ要素をツールチップの対象にする（`ToolButton` の押せないとき、パレットの置けないモジュール）。
  - 指で触る画面では、ツールチップは出ない（`title` のときと同じ）。説明が要る情報は、ツールチップだけに頼らない。
  - 既知の不具合: CLOCK が動いている（シミュレーションで回路の値が変わり続けている）間、ヘッダーのボタンのツールチップが、出てもすぐ消えたり、出たり消えたりする。ズームのボタンのツールチップでは起きない。原因は未特定。
    - 再現した手順: 環境設定で tick の間隔を変えて閉じ、パレットから CLOCK を置き、シートの何もない所をクリックしてから、ヘッダーのボタンにポインターを載せる。同じ条件に近づけた別の手順では再現しないことがあり、条件を絞り切れていない。
    - 違ったもの: Chakra（zag）のツールチップはボタンの祖先がスクロールすると閉じる（`closeOnScroll`）が、これを止めても直らず、スクロールも起きていなかった。
    - 違ったもの: CLOCK の tick ごとに App（画面全体）を描き直していたのをやめても直らなかった（今は tick ごとに描き直すのはシートだけ）。

## ダイアログ

- ブラウザの `prompt` / `confirm` / `alert` は使わない。VS Code 内のブラウザなど、これらが何もせずに終わる環境がある（`prompt` は null、`confirm` は false を返す）。どの環境で開かれても動くようにするため。
  - 代わりに `src/components/dialogs/` の画面内のダイアログを使う。ダイアログは 1 つずつ別のファイルにする（開発者の方針）。確認とお知らせは `ConfirmDialog`、名前の入力は `PromptDialog`、書き出し・読み込みは `TextDialog`、このアプリについては `AboutDialog`、環境設定は `PreferencesDialog`。
- ダイアログは Chakra の `Dialog` で、外枠は `dialogs/DialogFrame.tsx` にまとめ、各ダイアログから使う。Esc・外側のクリックで閉じること、フォーカスを中に閉じ込めることは Chakra に任せる。開いたときにフォーカスする要素は、各ダイアログが `initialFocus` で渡す（確認なら確定ボタン、入力なら入力欄）。
- 開くかどうかは、`App.tsx` がダイアログのコンポーネントを置くかどうかで決める（Chakra の `open` は常に true）。
- 取り返しのつかない操作の確認は `role="alertdialog"` にし、確定ボタンを赤（`colorPalette="red"`）にする。
- ダイアログは同時に 1 つだけ出す。閉じるダイアログと入れ替わりに別のダイアログを開くと、Chakra（中の zag）は後から開いた方を入れ子とみなし、前のものを外したときに一緒に閉じてしまう。そのため、お知らせ（`Dialog`）は、入力のダイアログ（`PromptDialog`・`TextDialog`）が閉じてから出している（`App.tsx`）。ダイアログから続けて別のダイアログを出す流れを足すときは、同じようにする。

## ステータスバーのヒント

- 分かりにくい操作や仕様に気付いたら、ステータスバーのヒントに適宜追加する（プロジェクトの方針）。機能を追加・変更したときも、ヒントが必要か考える。
- ヒントは短い文に分けて、時間で順に切り替えて表示する。操作の途中（配線中、ドラッグ中、編集中）は、そのとき必要な1文だけを出す。
- 発振の警告は、ステータスバーの右端に赤い `Badge` で出す。

## 触ったら確かめること

ヘッダー、タブバー、シートのツールバーのボタン（`ToolButton.tsx`）を触ったら、ヘッドレスブラウザで次を確かめる。

- 幅の広い画面では、ボタンにアイコンと文字が出る。
- 狭い画面（Chakra の `md` 未満。例: 幅 600px）では、アイコンだけになり、並びが崩れない。
- 元に戻す・やり直しなど、押せないときのボタンが薄く出る。
- モジュールを開いているとき、「モジュールを削除」が赤で出る。

ダイアログ（`dialogs/`）を触ったら、次を確かめる。

- 開いたときのフォーカス: モジュールの追加では名前が全選択、確認では確定ボタン、環境設定とこのアプリについてでは「閉じる」。
- Esc と外側のクリックで閉じる。開いている間は Ctrl+Z などのショートカットが効かない。
- モジュールの追加: すでにある名前ではエラーが出て確定できない。Enter で確定すると、モジュールが作られて開く。
- モジュールの削除の確認: `alertdialog` で確定ボタンが赤い。キャンセルでは消えず、確定で消える。
- 書き出し: 文字列は読み取り専用で、作者名を入れると文字列に反映される。「コピー」で閉じずに結果が出る。
- 読み込み: 読めない文字列ではエラーを出して閉じない。作者名の入ったものを読み込むと、お知らせが出る（入れ替わりに開くダイアログが閉じてしまわないか）。
- 環境設定: tick の間隔の範囲外の値でエラーの文が出て、使える値は反映される。方眼の表示の切り替えがシートに効く。色見本でアクセントカラーが変わる。
- 狭い画面（例: 幅 400px）でも、ダイアログが画面に収まる。

パレット（`Palette.tsx`）を触ったら、次を確かめる。

- グループの見出しで、そのグループだけが折り畳まれる。「すべて折りたたむ」「すべて展開」が効き、ボタンの名前が入れ替わる。折り畳みの状態は再読み込みしても残る。
- 部品のボタンのクリックで部品が置かれる。シートへのドラッグ（HTML のドラッグ＆ドロップ）でも置ける。ヘッドレスブラウザでの再現の仕方は[ブラウザでの動作確認](browser-check.md)にある。

削除エリア（`TrashZone.tsx`）を触ったら、次を確かめる。

- ふだんは丸いアイコンだけで、ズームのパネルの上にあり、重ならない。
- 部品をドラッグし始めると、丸の下（外）に「削除」と出る。丸の位置と大きさは変わらない。上に載せると赤くなり、離すと部品が消え、元の丸に戻る。元に戻すで部品が戻る。
- エリアの外で離すと、部品は消えずに動く。エリアの上から押してドラッグしても、シートの範囲選択が始まらない。
- 狭い画面（例: 幅 400px）でも画面に収まる。

プロパティ欄（`PropertyPanel.tsx`）を触ったら、次を確かめる。

- 部品を選ぶと種類と項目が出て、何も選んでいないときは案内の文が出る。
- CLOCK の周期: 範囲外の値ではエラーの文が出て、使える値は反映され、秒の説明も変わる。
- INPUT / OUTPUT のラベル: 入れるとシートの部品に出る。
- 狭い画面（例: 幅 600px）では部品を選んでいる間だけ出て、`md` 以上（例: 幅 800px）では選んでいなくても出る。

ツールチップ（`HintTooltip.tsx`、それを使うボタン）を触ったら、次を確かめる。ツールチップは、ポインターを載せてから 400ms ほど待つと出る。

- ヘッダー・シートのツールバー・ズームのボタンに説明が出る。押せないボタン（例: 履歴がないときのやり直し）にも出る。
- パレットの部品には部品の説明が出る。置けないモジュール（例: そのモジュール自身を開いているとき）は押せず、置けない理由が出る。パレットの下の方の部品は、スクロールして見える位置に出してから試す。
- モジュールのタブには操作の説明が出て、メイン回路のタブには出ない。

ステータスバー（`StatusBar.tsx`）とズーム（`ZoomControls.tsx`）を触ったら、次を確かめる。

- ヒントは時間で切り替わり、ポインターを載せている間は止まる。ヒントが 1 文しかない状態（発振中など）では切り替わらないので、何もない回路で試す。
- 発振する回路（例: NOT の出力を自分の入力へつなぐ）では「発振しています」が出る。保存データに直接書いて用意できる。
- 拡大・縮小で倍率が変わり、倍率のボタンで 100% に戻る。ボタンを押してもシートの範囲選択が始まらない。狭い画面でもボタンが画面に収まる。
