# 編集と元に戻す

- 元に戻す仕組みは、プロジェクト全体の状態をそのまま履歴に積む方式（`src/app/history.ts`）。差分は持たない。
- 新しい編集操作を足すときは、元に戻す対象かどうかを決めて使い分ける。
  - 回路の編集（部品・配線・ラベル・モジュールの追加や変更や削除）は `history.commit`（App の `setCircuit` / `setProject` の既定）。
  - 回路の編集ではない変更（INPUT の ON/OFF、CLOCK の切り替わり）は `history.replace`（`setCircuit(..., false)`）。元に戻しても、INPUT / CLOCK の ON/OFF は今の値を引き継ぐ（`keepSwitchStates`）。
  - ドラッグのように連続する変更は、動き始めに `history.checkpoint()` を1回呼び、以降は `replace` で更新して、1回の操作として戻せるようにする。移動してから削除エリアで削除した場合も、移動と削除で1回。
- モジュールのタブの並べ替えも `commit`（元に戻せる）。タブの並びは保存データの回路の順そのもので、パレットのモジュールの並びも変わるため。メイン回路は先頭に固定（データの決まり）なので、動かさず、その前にも置かない（`project.ts` の `moveCircuit`）。
- 配線の折れる点（`Wire` の `points`）は、配線中に何もないところをクリックして置く（開発者の方針）。自動で経路を探す方式は、配線が多いと計算が重く、経路が勝手に変わるので採らなかった。
  - 配線中の仮の線（`Sheet.tsx` の `pendingPath`）は、クリックで確定したときと同じ形に描く。何もないところでは折れる点を置いたときの形（横→縦）、入力ピンの上ではそのピンへ入る形（縦→横）。形がずれると、クリックした後に線が違う位置へ動いて見える。`wireRoute` の曲がり方を変えるときは、ここも合わせる。
  - 片方の端の部品だけを動かすと、その配線の折れる点は消して、中間で1回折れる形に戻す（開発者の方針）。両端の部品を同じだけ動かしたとき（まとめて移動、貼り付け）は、形が崩れないので、折れる点も一緒に動かす（`edit.ts` の `moveComponents` / `cloneComponents`）。
  - 折れる点を置いていない配線（中間で1回折れる形）は、中央の縦線をドラッグで左右に動かせる。動かした位置は、出力ピンと同じ高さに置いた折れる点1つとして保存する（線の形が同じになるため）。ドラッグ全体で1回の操作として元に戻せる。
  - 部品と配線、配線どうしが重ならないようにするのは利用者に任せている。
  - 配線の角は、描くときに丸める（`Sheet.tsx` の `wirePath`、環境設定で切れる）。見た目だけで、データの折れる点は角のまま。
- プロパティ欄での部品の項目の変更（CLOCK の周期、INPUT / OUTPUT のラベルなど）は、使える値になったらすぐに反映する（開発者の方針）。ドラッグと同じく、欄を触っている間の最初の変更の直前に `history.checkpoint()` を1回呼び、以降は `replace` で更新する。欄を離れるか Enter を押すまでの変更を、1回の操作として元に戻せる（打つたびに履歴が増えないように）。
- コピーと貼り付け:
  - コピーするのは、選んだ部品と、その部品同士をつなぐ配線だけ（`edit.ts` の `extractComponents`）。クリップボードはアプリの中だけに持ち、保存しない。別の回路のタブにも貼れる。
  - Ctrl+V では、まだ回路を変えない。部品がポインターについて動き、シートをクリックした位置で確定する（開発者の方針）。確定した時点で1回の編集として `commit` する。Esc や回路の切り替えで取り消す。
  - モジュールを、それ自身の中や、それを含む回路に貼ると循環するので、貼り付けを始める時点で断る。
- 元に戻すと、選択・配線中・名前の編集中の状態は解除する。戻した先に対象が存在しないことがあるため。
- 履歴は保存しない。ページを開き直すと元に戻せなくなる。
