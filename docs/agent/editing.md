# 編集と元に戻す

回路の編集と、元に戻す / やり直しの仕組み。どの操作に何を割り当てているかは[画面操作](interaction.md)にある。

## 編集の流れ

- 編集の処理は `editing/edit.ts` にある。どれも新しい回路を返し、元の回路は書き換えない。元に戻す対象にするかどうかは、ここでは決めない。
- 状態を変えるのは `App.tsx`。開いている回路は `setCircuit(update, record)`、プロジェクト全体は `setProject` で変える。`record` を `false` にすると、元に戻す対象にしない。
- モジュールの操作は `modules/useModules.ts`、コピーと貼り付けは `editing/useClipboard.ts`、新規作成・書き出し・読み込みは `file/useProjectFile.ts` にある。どれも、`App.tsx` から受け取った更新の関数で状態を変える。

## 元に戻す

- プロジェクト全体の状態をそのまま履歴に積む（`editing/history.ts`）。差分は持たない。履歴は 100 回分まで（`LIMIT`）。
- 履歴はすべての回路で 1 本。どのタブで編集しても、同じ履歴に積む。
- 履歴は保存しない。ページを開き直すと元に戻せなくなる。
- 使い分け（`useProjectHistory.ts`）:
  - `commit` … 今の状態を履歴に積んでから変える。元に戻せる編集。
  - `replace` … 履歴に積まずに変える。
  - `checkpoint` … 今の状態だけを履歴に積む。このあとの `replace` を、まとめて 1 回の操作として戻せる。
- 新しい編集を足すときは、元に戻す対象かどうかを決めて使い分ける。

| 操作                                             | 使うもの                                          |
| ------------------------------------------------ | ------------------------------------------------- |
| 部品・配線の追加や削除、貼り付け                 | `commit`                                          |
| モジュールの追加・改名・削除、タブの並べ替え     | `commit`                                          |
| 新規作成、読み込み                               | `commit`（元に戻せる）                            |
| 部品と配線のドラッグ                             | 動き始めに `checkpoint`、以降は `replace`         |
| プロパティ欄での変更（CLOCK の周期、ラベル）     | 最初の変更の直前に `checkpoint`、以降は `replace` |
| INPUT の ON/OFF、書き出しの作者名                | `replace`（元に戻す対象にしない）                 |

- 部品や配線を動かしてから削除エリアで離した場合は、移動と削除をまとめて 1 回の操作にする（動かしていれば、削除も `replace` で行う）。
- プロパティ欄の変更は、欄を離れるか Enter を押すまでを 1 回の操作にする。打つたびに履歴が増えないようにするため。
- タブの並べ替えを元に戻せるのは、タブの並びが保存データの回路の順そのもので、パレットのモジュールの並びも変わるため。
- 元に戻しても、INPUT の ON/OFF は今の値を引き継ぐ（`switchStates.ts` の `keepSwitchStates`）。CLOCK の ON/OFF はプロジェクトに書かないので、履歴とは関わらない（[シミュレーション](simulation.md)）。
- 元に戻すと、選択・配線中・名前の編集中の状態を解除する。戻した先に、その対象がないことがあるため。
- 部品のドラッグ中は、元に戻す・やり直しを受け付けない。ドラッグの開始時に積んだ履歴との整合が崩れるため。

## 配線

- 配線は部品とは別のデータで、部品を指さない（`circuit.ts` の `Wire`）。何とつながっているかは、位置から計算する（`geometry/net.ts` の `computeNets`）。決め方は形式の仕様（[version 2](../format/v2.md) の「つながりの決め方」）にある。
- 配線の点はグリッドに乗り、どの区間も縦か横。描く操作は[画面操作](interaction.md)の「配線」にある。
- 部品を消しても、つながっていた配線は残す。部品を動かしても、配線は動かさない（`edit.ts` の `removeParts` / `moveParts`）。配線は部品と同じく単体で存在できるものとして扱うため。
- 1 つのネットに出力ピンが 2 つ以上あると、出力のぶつかり（エラー）。そのネットの配線を赤く描き、ステータスバーに警告を出す。つながる入力ピンは OFF として計算する。
- 部品と配線、配線どうしが重ならないようにするのは、利用者に任せている。配線の端が意図せずほかの配線に乗ると、つながってしまう。
- 配線の角を丸めるのは描くときだけ（`sheet/wirePath.ts`、環境設定で切れる）。データの折れる点は角のまま。

### 開発者からの指示

- 配線は、クリックした点からクリックした点まで、縦か横の 1 方向に伸ばす。途中で曲げるときは、途中でクリックし、その点から別の向きへ伸ばす。
- 配線は、部品と同じように単体で存在できる。部品につながっている必要はない。
- 配線は、別の配線の途中から分岐できる。
- 配線の端が、折れる点や部品のピンと同じ位置にあれば、つながっているとみなす。
- 配線どうしは、重なっていても、つながっている（途中から分岐している）場合と、つながっていない（交差しているだけの）場合がある。
- 1 つのネットに出力ピンが 2 つ以上つながったら、エラーにする。
- 部品を動かしても、配線はついてこない（つながりは切れる）。

## コピーと貼り付け

- コピーするのは、選んだ部品と配線（`edit.ts` の `extractParts`）。部品だけを選んだときは、配線は含めない。切り取りは、コピーしてから削除する。
- クリップボードはアプリの中だけに持ち、保存しない。別の回路のタブにも貼れる。
- Ctrl+V では、まだ回路を変えない。部品と配線がポインターについて動き、クリックした位置で確定する。確定した時点で、新しい ID を付けて（`cloneParts`）`commit` する。
- 貼り付けを取りやめるのは、Esc を押したときと、回路を切り替えたとき。押したまま大きく動かしてから離したときは、確定せずに貼り付け中のまま残る。
- モジュールを、それ自身の中や、それを含む回路に貼ると循環するので、貼り付けを始める時点で断る（`circuit/module.ts` の `dependsOn`）。パレットからモジュールを置くときも、同じ理由で置けないものを押せなくしている。

## モジュール

- 追加は、名前を入れるダイアログで確定してから作る。既定の名前は「モジュール<n>」。空の名前と、すでにある回路と同じ名前は断る。
- 改名で空の名前にしたときは、変えない。改名では、ほかの回路と同じ名前を断っていない（追加とは違う）。
- ほかの回路に置かれているモジュールは削除できない。理由をダイアログで知らせる。
- メイン回路は先頭に固定。動かさず、その前にも置かない（`project.ts` の `moveCircuit`）。
