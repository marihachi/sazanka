# 用語

このアプリで使う言葉と、コードでの名前の対応。ドキュメント、UI の文言、コードのコメントは、ここの言い方にそろえる。英語の UI の文言は、下の「英語の UI での言い方」にそろえる。

## 人

- 開発者: エージェントに指示する人。複数人いる。
- 利用者: できあがったアプリを使う人。

## 回路のデータ

| 言葉           | コードでの名前           | 意味                                                                                                                                                         |
| -------------- | ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| プロジェクト   | `Project`                | メイン回路とすべてのモジュールをまとめたもの。保存と書き出しの単位                                                                                           |
| 回路           | `Circuit` / `CircuitDef` | 部品と配線の集まり。`CircuitDef` は ID と名前が付いたもの（タブ 1 つ分）                                                                                     |
| メイン回路     | `MAIN_ID`（`'main'`）    | プロジェクトに必ず 1 つある、いちばん外側の回路。追加も削除もできない                                                                                        |
| モジュール     | 種類 `module`            | 部品としてほかの回路に置ける回路。メイン回路以外の回路はすべてモジュール                                                                                     |
| 部品           | `Part`                   | シートに置くもの（ゲート、フリップフロップ、INPUT、モジュールなど）                                                                                          |
| 動作の分類     | `PartSpec.behavior`      | 部品の種類の仕様が、どう動くか。`logic`（入力から出力を求める）、`flipFlop`（記憶素子）、`display`（表示するだけ。出力なし）                                 |
| 部品の種類     | `PartKind`               | `and`、`dFlipFlop`、`module` など。保存データと同じ名前                                                                                                      |
| 特別な部品     | `SpecialKind`            | INPUT、OUTPUT、CLOCK、モジュール。`spec.ts` を持たない（[部品の種類](parts.md)）                                                                             |
| BUF            | `'buf'`                  | 展開したモジュールのピンに使う内部用の部品。利用者は置けない                                                                                                 |
| ピン           | `PinRef`                 | 部品の入出力の口。番号で指す。入力ピンは左、出力ピンは右（dip / qfp のモジュールは、ピン番号で辺が決まる）                                                   |
| ピンの割り当て | `Pinout`                 | 部品のピンの名前と、モジュールの外側のピン番号（どのピン番号にどの内側のポートをつなぐか）。シート上の配置を決めるときは、モジュールのパッケージも一緒に渡す |
| パッケージ     | `Package`                | モジュールの形。形の種類（`dip` / `qfp` / `split`。画面では DIP / QFP / ロジック）とピンの数で、本体の大きさと、ピンを置ける辺と位置が決まる                 |
| ポート         | なし                     | モジュールの中の INPUT / OUTPUT。外側のピンになる                                                                                                            |
| ポート番号     | `Part.portNumber`        | INPUT / OUTPUT を見分ける番号（1 から）。入力と出力で別々に振り、置いたときに決まる。メイン回路の INPUT / OUTPUT も持つ。ピン番号とは別のもの                |
| ピン番号       | `Part.pinNumber`         | ポートを割り当てる外側のピンの番号（1 から）。`dip` / `qfp` で使う                                                                                           |
| NC             | なし                     | どのポートにも割り当てていないピン番号。線と「NC」の文字だけを描き、何にもつながらない                                                                       |
| 配線           | `Wire`                   | 縦と横の線分をつないだ線。部品とは別に置け、端の位置でピンやほかの配線とつながる                                                                             |
| 折れる点       | `Wire.points`            | 配線が曲がる点。`points` は始点・折れる点・終点の並び                                                                                                        |
| ネット         | `Net`                    | 配線でつながったピンと配線のまとまり（`geometry/net.ts`）                                                                                                    |
| 分岐           | なし                     | 配線の端がほかの配線の途中にあり、そこでつながっていること。丸い印を描く                                                                                     |
| 交差           | なし                     | 配線の途中どうしが交わるだけで、つながっていないこと                                                                                                         |
| 結合           | `mergeWiresAt`           | 2 本の配線の端だけが合わさって 1 本に見える所で、2 本を 1 本の配線にすること                                                                                 |
| 分割           | `splitWire`              | 配線を、途中か折れる点で 2 本に分けること                                                                                                                    |
| 分かれ目       | `findWireJoints`         | 2 本の配線の端だけが合わさっている点。分割モードの間、印を出す                                                                                               |
| 端の印         | なし                     | 配線を 1 本選んだときに両端に出す四角。ドラッグで端の区間の長さを変える。画面の文言では「配線の端」と書く                                                   |
| 出力のぶつかり | `isConflict`             | 1 つのネットに出力ピンが 2 つ以上あるエラー。値が決まらない                                                                                                  |
| ラベル         | `Part.label`             | INPUT / OUTPUT に付ける名前。モジュールのピン名になる                                                                                                        |
| CLOCK の周期   | `Part.period`            | CLOCK が ON と OFF を一往復する tick 数                                                                                                                      |

- 「回路」はメイン回路とモジュールをまとめた言い方。増やせるのはモジュールだけなので、増やす話は「モジュールの追加」と書く。
- 部品の種類の名前（`PartKind`）は、保存データの `kind` と同じキャメルケース（`input`、`rsLatch` など）。画面に出す名前（INPUT、RS Latch など）は、種類の見せ方（`view.ts` の `label`）が持つ。ドキュメントでは画面に出す名前で書いてよい。

## 画面

| 言葉               | コードでの名前         | 意味                                                                                   |
| ------------------ | ---------------------- | -------------------------------------------------------------------------------------- |
| ヘッダー           | `Header`               | 画面の最上部。プロジェクト全体に効く操作を置く                                         |
| タブ / タブバー    | `TabBar`               | 回路を切り替える部分。タブ 1 つが回路 1 つ                                             |
| シートのツールバー | `SheetToolbar`         | タブの下の、開いている回路に効く操作を並べた場所                                       |
| シート             | `Sheet`                | 回路を描く領域。「キャンバス」とは呼ばない                                             |
| パレット           | `Palette`              | シートの左にある、置ける部品の一覧                                                     |
| プロパティ欄       | `PropertyPanel`        | シートの右にある、選んだ部品の項目を編集する場所                                       |
| 削除エリア         | `TrashZone`            | シートの右下にある、部品をドラッグして消す場所                                         |
| ズーム             | `ZoomControls`         | シートの右下にある、拡大縮小のボタン                                                   |
| ステータスバー     | `StatusBar`            | 画面の最下部の、ヒントと発振の警告を出す場所                                           |
| 表示               | `View`                 | シートの表示位置と倍率                                                                 |
| 環境設定           | `Preferences`          | 利用者ごとの設定（シミュレーションの速さ、アクセントカラーなど）                      |
| モジュール設定     | `ModuleSettingsDialog` | モジュールのパッケージとピンの割り当てを編集するダイアログ。シートのツールバーから開く |
| シート設定         | `SheetSettingsDialog`  | 回路のシートの大きさ（幅と高さ、マス）を変えるダイアログ。シートのツールバーから開く   |
| シートの大きさ     | `CircuitSheet`         | 回路ごとのシートの幅と高さ（マス）。保存データの `sheet`                               |
| 表示言語           | `Language`             | 画面に出す言語（日本語か英語）。環境設定の「自動」では、ブラウザの言語で決まる         |
| 文言の表           | `Messages`             | 言語ごとの画面の文言をまとめたもの（`i18n/ja.ts`、`i18n/en.ts`）                       |

## 操作の状態

| 言葉                    | コードでの名前 | 意味                                                           |
| ----------------------- | -------------- | -------------------------------------------------------------- |
| 選択                    | `Selection`    | 選んでいる部品と配線（どちらも複数可）                         |
| 選択モード / 配線モード / 分割モード | `Tool` | シートのクリックで選ぶか、配線を引くか、配線を分けるか。`V` / `W` / `S` で切り替える |
| 配線中                  | `pending`      | 配線モードで 1 点目を置いてから、描き終えるか取り消すまで      |
| 貼り付け中              | `placing`      | Ctrl+V のあと、貼り付ける位置をクリックするまで                |

## シミュレーション

| 言葉 | コードでの名前       | 意味                                                         |
| ---- | -------------------- | ------------------------------------------------------------ |
| tick | なし                 | シミュレーションの時間の単位。1 tick ごとに回路を 1 段進める |
| 遅延 | `delayOf`            | 部品の入力が変わってから、出力に現れるまでの tick 数         |
| シミュレーションの速さ | `ticksPerSecond` | 1 秒に進める tick 数（環境設定）。計算が間に合わないと、これより遅く進む |
| 発振 | `SimResult.unstable` | 入力を変えていないのに、値が変わり続けている状態             |
| 展開 | `flattenProject`     | モジュールを中身の部品に置き換えて、1 つの回路にすること     |

## データの受け渡し

| 言葉        | 意味                                                                  |
| ----------- | --------------------------------------------------------------------- |
| 保存データ  | localStorage に自動で保存するプロジェクト                             |
| 共有用 JSON | 「書き出し」で作り、「読み込み」で取り込む JSON。他人に渡すためのもの |
