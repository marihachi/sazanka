# 描画の重さ

画面の描き直しを減らす仕組み。重さを測る条件と目安は[ブラウザでの動作確認](browser-check.md)の「フレームレートを測る」にある。

## なぜ描き直しを減らすか

- Chakra UI の部品は、描き直すたびにスタイルを作り直すので重い。描き直しが多いと、すぐにフレームレートが落ちる。
- 部品のドラッグでは、一歩ごとに App（画面全体）が描き直される。そこで、ドラッグで中身の変わらない部品は描き直さないようにしている。
- フレームレートが下がっていたら、まず描き直しが増えていないかを疑う。

## 描き直さない仕組み

- ヘッダー、タブバー、シートのツールバー、パレット、プロパティ欄、ステータスバー、ズーム、削除エリアは `React.memo` で包み、props が変わらなければ描き直さない。
- App からこれらへ渡す関数は、`app/useStableCallbacks.ts` で固定する。App を描き直しても同じ関数のままで、呼ぶと最新の中身を実行する。その場で `() => ...` を書いて渡すと、毎回違う関数になり `React.memo` が効かなくなる。シートからズームへ渡す関数も、同じ考え方で固定している（`Sheet.tsx` の `zoom`）。
- 一部の部品は、props の比べ方を自分で持っている。props を足したり意味を変えたりしたら、比べ方も直す。直さないと、変わったのに描き直されない。
  - タブバー（`sameTabs`）: 回路は ID と名前だけ比べる。
  - プロパティ欄（`samePanel`）: 選んだ部品の位置（x, y）は比べない。
  - ステータスバー（`sameStatus`）: ヒントは文の中身で比べる。
- パレットのモジュールの一覧は、回路の名前と、どの回路にどのモジュールを置いているかが変わったときだけ作り直す（`modules/useModules.ts` の `modulesKey`）。パレットに出す情報を足したら、`modulesKey` にも足す。

## シミュレーションの結果

- シミュレーションの結果は、App を通さずシートにだけ渡す（`SimStore` と `useSyncExternalStore`。[シミュレーション](simulation.md)）。tick ごとに画面全体を描き直すと、CLOCK が動いているだけで画面全体が重くなるため（CPU を 4 倍遅くした計測で、58 fps から 7 fps まで落ちた）。
- tick ごとに変わる値を、App の状態や props に戻さない。
- CLOCK の ON/OFF をプロジェクトに書かないのも、反転のたびに画面全体の描き直しと保存が起きないようにするため。
