# シミュレーション

## 評価モデルの前提

- 時間を tick で刻んで進める。1 tick ごとに、遅延のある部品が「遅延の分だけ前に計算した値」を出し、遅延のない部品（INPUT / CLOCK / HIGH / OUTPUT と、モジュールのピンになる BUF）は同じ tick のうちに値を伝える。
  - 遅延は部品の種類ごと（`delayOf`）。NAND / NOR を 1 段とし、それを反転する AND / OR は 2 段、XOR は 3 段、ゲートを組み合わせて作る記憶素子は RS ラッチが 2 段、EN 付きの RS ラッチ・D ラッチ・エッジトリガ型が 3 段としている。
  - 出力が動くのは、入力の変化が遅延の間ずっと続いたときだけ。遅延より短いパルスは出力に現れない（実物のゲートと同じ）。
  - そのため、ゲートを通したクロックや、フリップフロップの出力を次段のクロックにつなぐ非同期カウンタも、段ごとに遅れて動く。
  - 入力を変えていないのに値が変わり続けたら発振とみなす（`OSCILLATION_TICKS`）。周期の短い振動では「値が変わる tick」と「変わらない tick」が交互に来るので、落ち着いていない状態が続いた長さで判定している。
  - CLOCK の周期（一往復の tick 数）は CLOCK ごとに持つ（部品の `period`、既定 100 tick、`component.ts` の `clockFlipsAt`）。すべての CLOCK は時刻 0 に OFF から始まり、それぞれの半周期ごとに反転する。
  - 半周期が発振の判定の長さ（`OSCILLATION_TICKS`、50 tick）より短い CLOCK では、遅延のある回路は落ち着く前に次の反転が来て、そのままでは発振と誤って判定される。そのため、そういう CLOCK が反転するたびに発振の数えをやり直している（`useSimulation.ts`）。その代わり、周期の短い CLOCK を置いた回路では、本当の発振も検出できない。既定の周期（半周期 50 tick）ならやり直さず、発振も検出できる。
  - CLOCK の半周期より遅延の長い経路を持つ同期回路は、値が落ち着く前に次のクロックの立ち上がりが来る（実物のタイミング違反と同じ）。CLOCK の既定の周期や、発振の判定の長さを変えるときは、この2点も考えること。
  - 「落ち着いた」とみなすのは、いちばん長い遅延より長く値が変わらなかったとき（`SETTLED_TICKS`）。遅延の待ち行列にまだ値が残っていることがあるため。遅延の長い部品を足したら、`SETTLED_TICKS` と、テストの `settle` ヘルパーの打ち切り条件も合わせて直す。
- 画面では一定間隔で tick を進める（`useSimulation`）。間隔は環境設定で ms 単位で変えられる（既定 10ms、1〜1000ms）。CLOCK の周期も tick 数で決まるので、間隔に比例して伸び縮みする。一時停止して 1 tick ずつ進めたり戻したりできる。
  - 計算と描画を分けている。計算は React の外（ref）で経過時間ぶんの tick を進め、画面へはフレームに1回だけ渡す。値が変わらなかったフレームでは描き直さない。tick を短くしても描画の回数は増えない。
  - CLOCK がなく値が落ち着いたら、フレームのループ自体を止める。回路を触ると（プロジェクトが変わるので）また動き出す。止める判定は、そのループで1回以上 tick を進めてからにしている。編集直後に、編集前の「落ち着いた」状態を見て止まってしまうのを防ぐため。
  - 一時停止中は時間が止まっているので、編集しても値は変わらない。新しく置いた部品や配線の値は、再開するか 1 tick 進めるまで反映されない。
  - 戻すために、少し前までの結果を覚えている（`HISTORY_TICKS`）。CLOCK を反転した tick を戻すときは、反転も元に戻す。
  - 回路を編集したら、覚えている結果は捨てる。編集前の値に戻しても今の回路と噛み合わないため。CLOCK の反転だけは、自分で起こした変化なので捨てない。この判定は描画中に行っている（効果の中だと、「1 tick 戻す」ボタンの押せる / 押せないが1回遅れて表示されるため）。
- 計算するのは、いま開いているタブの回路だけ。モジュールのタブを見ている間、メイン回路の計算は止まっている。これも仕様。
  - ただし CLOCK の ON/OFF はプロジェクト全体で反転させているので、見ていない回路の CLOCK も切り替わり続ける。タブを戻すと、その回路は止めたときの結果から、今の CLOCK の値で計算を再開する。

## 壊してはいけない不変条件

- フリップフロップの状態や、ラッチのようなフィードバック回路の値は、前回の計算結果（`SimResult`）を部品 ID で引き継いで保っている。
  - 展開後の部品 ID の付け方（`外側の部品ID/内側の部品ID`）を変えると、状態が引き継がれずに消える。
  - 部品 ID を作り直すような処理を入れる場合も同じ。
- モジュールのピンの順番は、定義の中の INPUT と OUTPUT を座標順（上から、同じ高さなら左から）に並べたもの。
  - そのため、モジュールの中で INPUT や OUTPUT を動かすとピンの順番が入れ替わり、外側の配線が別のピンにつながってしまう。
  - 利用者に順番が分かるよう、モジュールのタブでは INPUT / OUTPUT の上にピンの番号（#1, #2…、INPUT と OUTPUT で別々）を表示している（`Sheet.tsx` の `pinNumbers`）。ピン番号の決め方を変えるときは、この表示も合わせる。
  - ピン番号の決め方を変えるときは、既存の配線への影響を考えること。
