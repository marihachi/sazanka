# シミュレーション

回路の評価（`simulation/sim.ts`）と、時間を進めるループ（`simulation/useSimulation.ts`）の考え方。

## 進めている計画

- tick の速さを 1 秒あたりの tick 数で指定し、計算を速くする計画が [docs/plans/tick-rate/plan.md](../plans/tick-rate/plan.md) にある。評価や時間を進めるループを触るときは、先に読む。

## 評価のしかた

- 時間を tick で刻んで進める。モジュールを展開（`flatten.ts`）し、番号で引く形（`CompiledCircuit`。`compileCircuit`）にしてから、配列の上で評価する（`stepState`）。
  - 番号で引く形では、部品を並びの番号で、出力ピンの値を `Uint8Array` の添字で指す。入力ピンごとに、それを動かす出力ピンの値の添字を先に求めておく。部品の種類ごとの評価の関数も、先に引いておく。
  - 状態（`SimState`）は番号で引く形。部品 ID で引く形の結果（`SimResult`）は、画面（シート）に渡すとき（`toResult`）と、回路を編集して部品の番号が変わったときの引き継ぎ（`toResult` → `toState`）にだけ作る。
  - `step`（プロジェクトの 1 回路を 1 tick 進める）と `stepCircuit`（展開済みの回路を 1 tick 進める）は、部品 ID で引く形を受け取って返す。呼ぶたびに番号で引く形にし直すので、テストのためのもの。
- 画面のループ（`useSimulation.ts`）は、展開と番号で引く形への変換を tick ごとにはやり直さない。回路を編集したとき（プロジェクトが変わったとき）とタブを切り替えたときだけ行う。
- 1 tick の流れ（`stepState`）:
  1. 遅延のある部品が、遅延の分だけ前に計算した値を出す。ただし、その間ずっと同じ値だったときだけ。
  2. 遅延のない部品（INPUT、CLOCK、HIGH、OUTPUT、BUF）を伝える。
  3. 遅延のある部品が、落ち着いた値から次に出す値を計算し、待ち行列（`pending`）に入れる。
- 2 と 3 では、どの部品も同じ時点の値を見るので、部品を並べた順番で結果が変わらない。この性質を崩さない。
- 2 は、遅延のない部品を、入力を動かす側が先に来るように並べておき（`immediateOrder`）、その順に 1 周だけ計算する。値が変わらなくなるまで何周も計算するのと同じ結果になる。
  - 遅延のない部品だけで輪ができている（BUF の輪など）と並べられない。そのときは、どの部品も周の始めの値を見て計算する周を、値が変わらなくなるまで（部品の数 + 1 回まで）繰り返す。
  - 並べ方は 1 周の速さのためだけのもの。結果を並べ方に頼らせない。
- 前回の結果がないとき（開いた直後、読み込んだ直後、タブを初めて開いたとき）は、待ち行列を今の値で埋め、落ち着いた状態から始める。
- 何もつながっていない入力ピンは OFF。
- 計算は、配線そのものではなく、「入力ピン → それを動かす出力ピン」のつながり（`sim.ts` の `Netlist` の `links`）で行う。展開（`flatten.ts`）のときに、回路ごとに配線をネットに分け（`geometry/net.ts` の `computeNets`）、出力ピンがちょうど 1 つのネットからだけつながりを作る（`netLinks`）。
  - 出力ピンのないネットと、出力ピンが 2 つ以上ある（ぶつかっている）ネットの入力ピンは、つながりを作らないので OFF になる。

## 遅延

- 遅延は部品の種類ごと（`delayOf`。値は `parts/<種類>/spec.ts` の `delay`）。NAND / NOR を 1 段として、実物の段数に近づけている。

| 部品                                                               | 遅延（tick） |
| ------------------------------------------------------------------ | ------------ |
| INPUT、CLOCK、HIGH、OUTPUT、BUF                                    | 0            |
| NOT、NAND、NOR                                                     | 1            |
| AND、OR、RS ラッチ                                                 | 2            |
| XOR、XNOR、EN 付き RS ラッチ、D ラッチ、エッジトリガ型（D、T、JK） | 3            |

- BUF の遅延が 0 なのは、回路をモジュールにしただけで遅れないようにするため。
- 遅延より短いパルスは出力に現れない（実物のゲートと同じ）。そのため、ゲートを通したクロックや、フリップフロップの出力を次のクロックにつなぐ非同期カウンタは、段ごとに遅れて動く。

## 落ち着いたかと発振

- 「落ち着いた」は、いちばん長い遅延より長く値が変わらなかったとき（`SETTLED_TICKS` = 4）。遅延と同じ長さでは、待ち行列にまだ値が残っていることがあるため。
- 「発振」は、落ち着かない状態が `OSCILLATION_TICKS`（50 tick）より長く続いたとき。周期の短い振動では値が変わる tick と変わらない tick が交互に来るので、「変わり続けた回数」ではなく「落ち着いていない長さ」で見る。
- 半周期が `OSCILLATION_TICKS` より短い CLOCK があると、遅延のある回路は落ち着く前に次の反転が来て、発振と誤って判定される。そのため、そういう CLOCK が反転する tick では、発振の判定に使う長さを数え直す（`useSimulation.ts` の `advance`）。その代わり、周期の短い CLOCK を置いた回路では、本当の発振も検出できない。
- 遅延の同じゲートを左右対称に組んだラッチ（NOR の RS ラッチを S=R=0 で、NAND なら S=R=1 で）は、前回の結果がない状態から始めると、2 つのゲートがそろって振れ続けて発振と判定される。実物の準安定と同じ動きとして仕様にしている。S か R を一度入れれば落ち着く。対称を崩すために部品を 1 つずつ順に評価する方法は採らない。並べた順番で結果が変わり、どちらに倒れるかを利用者に説明できなくなるため。
- CLOCK の半周期より遅延の長い経路を持つ同期回路は、落ち着く前に次の立ち上がりが来る（実物のタイミング違反と同じ）。CLOCK の既定の周期や `OSCILLATION_TICKS` を変えるときは、この 2 点を考える。

## CLOCK

- 周期（一往復の tick 数）は CLOCK ごとに持つ（部品の `period`。既定 100、2〜10000）。すべての CLOCK は時刻 0 に OFF から始まり、半周期ごとに反転する（`part.ts` の `clockFlipsAt`）。周期が奇数なら、ON と OFF の長さが 1 tick 違う。
- CLOCK の ON/OFF はプロジェクトに書かず、`useSimulation` の中（`clockOn`）で持ち、展開した回路の CLOCK に当てて計算する（`withClockStates`）。プロジェクトに書くと、反転のたびにプロジェクトが変わり、画面全体の描き直しと保存が起きるため。
  - ON/OFF は展開前の部品（回路 ID と部品 ID）ごとに持つ。同じモジュールを何か所に置いても、中の CLOCK はそろって反転する。展開後の CLOCK がどの部品から来たかは、展開の結果の `clocks` にある。
  - 反転したときは、展開し直さずに、ON/OFF だけを当て直す。反転する CLOCK を探すための一覧も、プロジェクトが変わったときだけ作る（`listClocks`）。
- CLOCK はプロジェクト全体で反転させている。見ていない回路の CLOCK も切り替わり続ける。

## 時間を進めるループ

- 画面では、`requestAnimationFrame` のフレームごとに、経過時間ぶんの tick を進める（`frameTicks.ts`）。1 tick に満たない端数は次のフレームへ持ち越す。速さは環境設定の「1 秒に進める tick 数」（`ticksPerSecond`、既定 100、1〜100,000）で変えられる。CLOCK の周期も tick 数なので、速さに反比例して伸び縮みする。
  - CLOCK の周期を秒で示すとき（プロパティ欄とヒント）は、`clockPeriodSeconds`（`circuit/part.ts`）で有効数字 3 桁に丸める。
- 計算は React の外（ref）で進め、画面へはフレームに 1 回だけ渡す。値が変わらなかったフレームでは描き直さない。速くしても描画の回数は増えない。フレームより速い CLOCK の点滅は、間引いて見える（開発者と決めた）。
- 1 フレームの計算は 8ms まで（`FRAME_BUDGET_MS`）。超えたら、tick を進めるループを抜け、そのフレームの残りの tick は進めない。遅れは取り戻さない（残りの数を覚えておかない）。上限を tick 数ではなく時間で決めるので、画面のリフレッシュレートで速さが変わらず、重い回路でも fps が落ちすぎない。
  - 間に合わない回路では、シミュレーションが指定の速さより遅く進む。利用者には、環境設定の説明文で伝えるだけで、遅れていることは知らせない（開発者と決めた）。
  - 取り戻そうとすると、重い回路では遅れが積み上がり続け、重さが引いたあとに早送りになるため。
- 1 フレームで数える経過時間は 200ms まで（`MAX_FRAME_ELAPSED_MS`）。タブを離れていた間（フレームが来ない）の tick を、戻ったときに一度に進めないため。そのため、タブを離れていたあとや 5 fps を下回るときは、シミュレーションの時間が実時間より遅れる。
- 計算の速さの目安（Node、ほぼ毎 tick 値が動く重い条件）は、展開後 290 部品で 1 tick 約 5.5µs（1 秒に約 8.7 万 tick）、1154 部品で約 22µs（約 2.2 万 tick）。CLOCK の周期が長く値の動かない tick が多ければ、もっと速い。
- 結果は React の状態にせず、購読できる入れ物（`SimStore`）でシートにだけ渡す。App が描き直すのは、発振しているか（`unstable`）が変わったときだけ（[描画の重さ](performance.md)）。
- CLOCK がなく値が落ち着いたら、ループを止める。回路を触るとプロジェクトが変わるので、また動き出す。止める判定は、そのループで 1 tick 以上進めてから行う。編集直後に、編集前の「落ち着いた」状態を見て止まらないようにするため。

## 一時停止と 1 tick 送り・戻し

- 一時停止中は時間が止まる。編集しても、新しい部品や配線の値は、再開するか 1 tick 進めるまで変わらない。
- 1 tick 戻すために、直前 300 tick の結果を覚えている（`HISTORY_TICKS`）。CLOCK を反転した tick を戻すときは、反転も戻す。
  - 毎 tick 覚えるので、番号で引く形の状態のまま、輪のように使い回す入れ物（`createHistory`）に入れる。`stepState` は前の状態を書き換えずに新しい状態を返すので、覚えた状態はそのまま戻せる。
- この結果は、回路を編集したら捨てる。編集前の値に戻しても、今の回路と噛み合わないため。タブを切り替えたときも捨てる（前のタブの回路の結果のため）。
  - 回路ごとに分けて覚えないのは、tick の数と CLOCK の反転がプロジェクト全体で 1 本なので、回路ごとに戻すと CLOCK の値と噛み合わないため。
  - この判定は、`useEffect` ではなく描画中に行う。`useEffect` の中だと、「1 tick 戻す」ボタンの押せる / 押せないが 1 回遅れて表示されるため。

## 計算する回路

- 計算するのは、開いているタブの回路だけ。モジュールのタブを見ている間、メイン回路の計算は止まる。
- 回路ごとの最後の結果は覚えている。タブを戻すと、その回路は止めたときの結果から、今の CLOCK の値で再開する。
- モジュールを削除したときと、新規作成・読み込みのときは、覚えている結果を捨てる（`forget`）。

## 触ると壊れるもの

- フリップフロップの状態やラッチの値は、回路を編集したとき、前回の結果を部品 ID で引き継いで保っている（`toResult` → `toState`）。展開後の部品 ID の付け方（`外側の部品ID/内側の部品ID`）を変えたり、部品 ID を作り直す処理を入れたりすると、状態が消える。
- モジュールのピンの順番（`PinRef.pin`）は、`module.ts` の `getPortsInPinOrder` で決まる。
  - パッケージが `split` なら、中の INPUT と OUTPUT を座標順（上から、同じ高さなら左から）に並べたもの。モジュールの中で INPUT や OUTPUT を動かすとピンの順番が入れ替わり、外側の配線の先にあるピンが別の信号のピンになる。
  - `dip` / `qfp` なら、入力と出力のそれぞれを、外側のピン番号（`pinNumber`）の順に並べたもの。動かしても順番は変わらない。外側のピンに出せないポート（番号がない・範囲外・重なり。`findUnexposedPorts`）は除く。除いたポートの INPUT は、展開すると何にもつながらない（OFF）。
  - ピンの位置は番号で決まる。ピンが減ると、減ったピンの位置にあった配線の端は、どこにもつながらなくなる（配線は消さない）。
  - シート上では、INPUT / OUTPUT の上にポート番号（「入力 1」）を出す。ピンの並びやピン番号ではない（ピン番号はプロパティ欄とモジュール設定で見る）。決め方を変えるときは、既存の配線への影響を考える。
- いちばん長い遅延を延ばしたら、`SETTLED_TICKS` と、テストの `settle` の打ち切り条件（`stableTicks > 3`）も合わせる。
