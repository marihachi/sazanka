# Skill の追加・編集

Skill（`.agents/skills/` と `.claude/skills/`）を足すとき、直すときの手順。何を Skill にして何をドキュメントに残すか、なぜ2箇所に置くかは [AGENTS.md](../../AGENTS.md) の「Skill」にある。

## 中身の書き方

- frontmatter は `name` と `description` の2つ。
  - `name` はフォルダ名と同じにする。英語の kebab-case。
  - `description` は**どんなときに使うか**まで書く。エージェントはこの文とやることを見比べて呼び出すかを決めるので、「〜について」だけだと呼ばれない。「〜をしたあと、〜を確認するときに使う」のように、きっかけを入れる。
- 本文は手順として書く。順に踏むもの（番号付き）と、判断の材料（箇条書き）を分ける。
- 落とし穴は「ハマりやすい点」「注意」としてまとめ、避け方まで書く。
- 文章は日本語（[作業の進め方](workflow.md)）。
- 補助ファイル（スクリプトの雛形など）は同じフォルダに置き、SKILL.md から相対リンクで案内する。
  - `.agents/skills/<name>/` と `.claude/skills/<name>/` は深さが同じなので、リポジトリ内へのリンクはどちらも `../../../` から始める。両方で同じリンクが使える。
  - `.mjs` などは Biome の対象になる。`npm run check` を通す。

## 追加するとき

手順がまだドキュメントにない場合は、Skill が初めの置き場所になる。ドキュメントに書いてから移す必要はない。ただし、**手順ではなく決まりや理由**（なぜそうするか、開発者と決めた方針）が混ざっているときは、そこだけドキュメント側に分ける。

1. `.agents/skills/<name>/SKILL.md` を作る。
2. `.claude/skills/` に同じフォルダをコピーする。
3. `cmp` で全ファイルが同一であることを確かめる。
4. 元になったドキュメントがあれば、そこから1行で案内する。手順をドキュメントから移したときは、移した本文をドキュメント側から消す（重ねて書かない）。元がない手順なら、この手順は要らない。
5. `npm run check` を通す。

## 編集するとき

1. どちらか一方を直す。
2. もう一方へコピーし直し、`cmp` で同一を確かめる。**片方だけ直した状態で終わらせない。**
3. 手順が元のドキュメントと食い違ったら、そちらも直す。

## 消すとき

両方のフォルダを消し、ドキュメントからの案内も消す。

## 注意

- 判断の前提になること（なぜそうするか、どこに置くか）は Skill に書かない。Skill は呼ばれて初めて読まれるので、呼ぶかどうかを決める前に必要な知識は、必ず読むドキュメントの側に無いと効かない。この手順自体を Skill にせずドキュメントに置いているのも同じ理由で、Skill を足すこと自体が滅多にないため、名前との一致で呼び出されるのを当てにできない。
- 新しく作った Skill が認識されるかは、利用可能な Skill の一覧に出るかで確かめられる。出ないときは、フォルダ名と `name` の食い違い、frontmatter の書式、置き場所を疑う。
