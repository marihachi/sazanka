# Skill の追加・編集

Skill を足す・直す・消すときの置き場所と手順。何を Skill にするかは[ドキュメントの書き方](documentation.md)の「Skill にするもの」にある。

## 置き場所

- Skill はエージェントごとの仕組みで、共通の置き場所が決まっていない。そのため `.agents/skills/`（Codex など）と `.claude/skills/`（Claude Code）の両方に置く。
- どんな Skill があるかの一覧は、どこにも持たない。エージェントには Skill の名前と `description` が渡されるので、それが唯一の出どころになる。

### 開発者からの指示

- `.agents/skills/` と `.claude/skills/` には、同じ内容で置く。片方だけ直さない。
- Skill に対応していないエージェントは考えない。

## 中身の書き方

- frontmatter は `name` と `description` の 2 つ。
  - `name` はフォルダ名と同じ。英語の kebab-case。
  - `description` には、どんなときに使うかまで書く。エージェントは、この文とこれからする作業を見比べて呼ぶかどうかを決めるので、「〜について」だけだと呼ばれない。「〜したあと、〜を確認するときに使う」のように、きっかけを入れる。
- 本文は手順として書く。順に行うこと（番号付きの一覧）と、判断の材料（箇条書き）を分ける。
- 落とし穴は「ハマりやすい点」「注意」にまとめ、避け方まで書く。
- 文章は日本語。
- 補助ファイル（スクリプトの雛形など）は同じフォルダに置き、`SKILL.md` から相対リンクで案内する。`.mjs` などは Biome の対象なので、`npm run check` を通す。
- 判断の前提（なぜそうするか、どこに置くか）は Skill に書かない。Skill は呼ばれて初めて読まれるので、呼ぶかどうかを決める前に要る知識は、「作業前に必ず読むドキュメント」に書いておかないと役に立たない。

### 開発者からの指示

- Skill には、ほかのプロジェクトでも使える手順だけを書く。このアプリ固有の事柄（コマンド、URL、パス、フォルダ名、保存データのキー、画面の部品の名前など）は、ドキュメントに書いて Skill から参照する。Skill を別のプロジェクトへ持っていっても、そのまま使えるようにするため。
  - 参照は、リンクやパスではなく、ドキュメントのファイル名をインラインコードで書く（例: `browser-check.md`）。各 Skill のはじめの参照に「`AGENTS.md` の一覧から辿る」と添える。`AGENTS.md` はどのプロジェクトにも置く入口なので、Skill がドキュメントの置き場所を知らずに済む。
  - Skill を使っていて、このアプリに合わせて具体的に書いた方が良いこと（コマンド、値、例、落とし穴など）が出てきたら、Skill には足さず、ドキュメントに書いて Skill から参照する。当てはまるドキュメントがなければ、その Skill 用のドキュメントを作り、`AGENTS.md` の一覧に載せる（例: `browser-check.md`）。
- ドキュメントのファイル名は重ねない（置き場所が違っても同じ名前にしない）。ファイル名だけで一意に決まるようにするため。重なっているのに気付いたら、重ならない名前に変え、参照している箇所（`AGENTS.md`、ほかのドキュメント、Skill）も直す。Skill の `SKILL.md` は決まった名前なので対象外。

## 追加するとき

案（使う場面、手順の概要、名前の候補）を示して合意し、開始の指示を受けてから作る（[作業の進め方](workflow.md)）。

手順がまだドキュメントにないなら、Skill が初めの置き場所になる。ただし、手順ではなく決まりや理由（なぜそうするか、開発者と決めた方針）が混ざっていたら、そこだけドキュメントに分ける。

1. `.agents/skills/<name>/SKILL.md` を作る。
2. `.claude/skills/` に同じフォルダをコピーする。
3. `cmp` などで、全ファイルが同じであることを確かめる。
4. 元にしたドキュメントがあれば、そこから 1 行で案内する。手順をドキュメントから移したなら、ドキュメント側の本文は消す。
5. `npm run check` を通す。

新しい Skill が認識されたかは、利用できる Skill の一覧に出るかで確かめる。出ないときは、フォルダ名と `name` の食い違い、frontmatter の書式、置き場所を疑う。

## 直すとき

1. どちらか一方を直す。
2. もう一方へコピーし直し、同じであることを確かめる。片方だけ直した状態で終わらせない。
3. 手順が元のドキュメントと食い違ったら、ドキュメントも直す。

## 消すとき

両方のフォルダを消し、ドキュメントからの案内も消す。

## この手順を Skill にしていない理由

Skill を足すことは滅多になく、名前との一致で呼ばれるのを当てにできないため。
