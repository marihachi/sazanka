# 文言と表示言語

画面の文言の置き場所と足し方、表示言語（日本語と英語）の仕組み。画面の配置やダイアログの決まりは [UI](ui.md)、英語での言い方は[用語](glossary.md)の「英語の UI での言い方」にある。

## 仕組みと決まり

- 画面の文言は、言語ごとの文言の表（`i18n/ja.ts`、`i18n/en.ts`）に書き、画面の側は `useMessages()` で引く。コードの中に直接書かない。部品の種類ごとの文言（表示名、説明、ヒント）は種類の `view.ts` に、アクセントカラーの色の名前は `preferences/preferences.ts` に、言語ごとに書く。置き場所は[ソースの構成](structure.md)の `i18n/`。
- 文言を足すときは、日本語の表に足してから、英語の表にも足す。表の形は日本語の表から作っているので、英語を書き忘れると型エラーになる。言語ごとに書く値（`Localized`）も同じ。
- 英語は、日本語より文字数が多くなる。狭い欄（パレット、プロパティ欄、モジュール設定の選択肢、シート上の部品の上に出す `In 1`）に出る文言は短くし、幅を狭くして（600px、400px）収まるかを確かめる。
- 英語の文言に日本語の文字（「・」なども）を混ぜない。テスト（`i18n/messages.test.ts`）で確かめている。言い方は[用語](glossary.md)の「英語の UI での言い方」にそろえる。
- 計算の側（検証、読み込み）は文を返さず、エラーの種類（大文字のスネークケース）を返す。文は表の `errors` に種類ごとに書く。
- 表示言語は `App.tsx` が環境設定とブラウザの言語から決め（`i18n/language.ts` の `resolveLanguage`）、`LanguageContext` で画面全体に渡す。
  - `App` と、`App` で呼ぶフック（`useModules`、`useProjectFile`、`useClipboard`）は Context の外にあるので、`useMessages()` を使えない。`App` は `getMessages(lang)` で表を引き、フックには引数 `m` で渡す。`App` で呼ぶフックを足すときも同じ。
  - 言語を切り替えると、文言を引く部品は `React.memo` で包んでいても描き直される。`App` で作って props で渡す文言は、`App` が描き直されて作り直す。`useMemo` で文言を作るときは、依存に表（`m`）を入れる。
- 環境設定の言語の欄は、ダイアログのいちばん上に置き、欄の名前に両方の言語を並べている（「言語 / Language」）。今の言語が読めない人も見つけられるようにするため。
- メイン回路の名前は、保存した名前ではなく、表示言語の名前で出す（`i18n/messages.ts` の `getCircuitName`）。回路の名前を画面に出すときは、これを通す。モジュールは付けた名前のまま。
- ステータスバーのヒントを出し続ける時間は、1 文字を読む時間（表の `hints.msPerChar`）を言語ごとに持つ（日本語 250ms、英語 80ms）。
- `index.html` の `lang` は、アプリが表示言語に合わせて書き換える。`meta description` はアプリが動く前に読まれて切り替えられないので、英語にしている（開発者が決めた）。

## 触ったら確かめること

文言（`i18n/` の表、部品の種類の `view.ts` の文言）や、表示言語の仕組みを触ったら、ヘッドレスブラウザ（Skill の `browser-check`）で確かめる。

- 日本語と英語の両方で、触った文言が出る場所を見る。言語は環境設定で切り替えるか、ブラウザの言語（`navigator.languages`）を変えて開く（[ブラウザでの動作確認](browser-check.md)の「表示言語」）。
- 英語で、狭い画面（例: 幅 600px、400px）でも文字が切れたり、横にはみ出したりしない。
- 環境設定で言語を切り替えると、開いているダイアログ、ヘッダー、タブ（メイン回路の名前）、パレット、プロパティ欄、ステータスバー、`html` の `lang` がその場で変わり、再読み込みしても残る。
