# データ形式 version 2

sazanka が保存・共有する回路データの形式（version 2）の仕様。version 1 からの違いは [version 1 からの変更](#version-1-からの変更)にある。

対象は次の2つ。どちらも、中身のプロジェクトの形（[プロジェクト](#プロジェクト)以降）は共通で、外側の包み方だけが違う。

- **保存データ**: ブラウザの localStorage に自動で保存するデータ。
- **共有用 JSON**: 画面上部の「書き出し」で作り、「読み込み」で読む文字列。

版の番号は2つで別々に持っている（保存データは `file/storage.ts` の `STORAGE_VERSION`、共有用 JSON は `file/share.ts` の `SHARE_VERSION`）。今はどちらも 2。

## 外側の包み方

### 保存データ

localStorage のキー `sazanka.project` に、次の JSON を文字列にして置く。

```json
{
  "version": 2,
  "project": { ... }
}
```

| 項目      | 型           | 内容                          |
| --------- | ------------ | ----------------------------- |
| `version` | 数値         | 形式の版。`2`                 |
| `project` | オブジェクト | [プロジェクト](#プロジェクト) |

### 共有用 JSON

```json
{
  "app": "sazanka",
  "version": 2,
  "project": { ... }
}
```

| 項目      | 型           | 内容                                               |
| --------- | ------------ | -------------------------------------------------- |
| `app`     | 文字列       | sazanka のデータであることの目印。常に `"sazanka"` |
| `version` | 数値         | 形式の版。`2`                                      |
| `project` | オブジェクト | [プロジェクト](#プロジェクト)                      |

## プロジェクト

メイン回路と、部品として使う回路（モジュール）をまとめたもの。

| 項目       | 型     | 必須 | 内容                                         |
| ---------- | ------ | ---- | -------------------------------------------- |
| `circuits` | 配列   | ○    | [回路](#回路)の一覧。先頭はメイン回路        |
| `author`   | 文字列 |      | 作者名。書き出すときに入力された場合だけ付く |

- 先頭の回路の `id` は `"main"`（メイン回路）でなければならない。2つ目以降はモジュール。
- 回路の `id` は、プロジェクトの中で重ならない。

## 回路

| 項目         | 型     | 内容                                                                        |
| ------------ | ------ | --------------------------------------------------------------------------- |
| `id`         | 文字列 | 回路の ID。メイン回路は `"main"`。モジュールの参照（部品の `custom`）に使う |
| `name`       | 文字列 | 回路の名前。タブとパレットに表示する                                        |
| `components` | 配列   | [部品](#部品)の一覧                                                         |
| `wires`      | 配列   | [配線](#配線)の一覧                                                         |

## 部品

| 項目     | 型     | 必須              | 内容                                                                        |
| -------- | ------ | ----------------- | --------------------------------------------------------------------------- |
| `id`     | 文字列 | ○                 | 部品の ID。回路の中で重ならない                                             |
| `kind`   | 文字列 | ○                 | 部品の種類（[部品の種類とピン](#部品の種類とピン)）                         |
| `x`      | 数値   | ○                 | 本体の左上の横位置（px）                                                    |
| `y`      | 数値   | ○                 | 本体の左上の縦位置（px）                                                    |
| `label`  | 文字列 |                   | `INPUT` / `OUTPUT` のラベル。モジュールの中では、外から見たピンの名前になる |
| `custom` | 文字列 | `CUSTOM` のとき ○ | 部品として置いた回路の `id`                                                 |
| `period` | 整数   |                   | `CLOCK` の周期（ON/OFF を一往復する tick 数、2〜10000）。なければ 100       |

座標について:

- 1マスは 20px。アプリで置いた部品は、座標が 20 の倍数になる。
- シートは横 6000px・縦 4000px で、左上が原点。アプリで置いた部品は、本体とピンがこの範囲に収まる。
  - ただし、この大きさを決める前に作った回路には、範囲の外にある部品もありうる。読み込むときは範囲を確かめない。

## 配線

縦と横の線分をつないだ線。部品とは別に存在し、部品を指さない。何とつながっているかは、位置で決まる（[つながりの決め方](#つながりの決め方)）。

| 項目     | 型     | 内容                                                                                                  |
| -------- | ------ | ----------------------------------------------------------------------------------------------------- |
| `id`     | 文字列 | 配線の ID。回路の中で重ならない                                                                       |
| `points` | 配列   | 線が通る点の並び（2 つ以上）。`{ "x": 数値, "y": 数値 }` で、始点から順に並べる。始点と終点が配線の端 |

- 隣り合う 2 点は、`x` か `y` が同じ（どの区間も縦か横）。
- アプリで引いた配線は、点が 20px 単位（グリッド）に乗り、シートの範囲（端を含む）に収まる。同じ点が続くことや、まっすぐ進む途中の点はない。

### つながりの決め方

- 配線の端が、次の場所にあれば、そことつながる。
  - 部品のピンの先（[部品の種類とピン](#部品の種類とピン)の位置）。
  - ほかの配線の上（端、折れる点、途中のどこでも）。途中にあるときは、そこから分岐している。
- 配線の途中どうしが交わるだけ（どちらの端でもない点で交わる）なら、つながらない。
- 配線の途中がピンの先を通るだけなら、そのピンにはつながらない。
- つながった配線とピンのまとまりを「ネット」と呼ぶ。ネットの中の入力ピンは、ネットの中の出力ピンの値になる。
  - 出力ピンがないネットの入力ピンは OFF。
  - 出力ピンが 2 つ以上あるネットはエラー。入力ピンは OFF として扱う。

### ピンの先の位置

部品の左上を (`x`, `y`) として、ピンの先の位置は次のとおり。1 マスは 20px。

| 部品                                  | 本体の大きさ（幅×高さ）                 | 入力ピンの先                                                                       | 出力ピンの先                                      |
| ------------------------------------- | --------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------- |
| `INPUT`、`CLOCK`、`HIGH`、`OUTPUT`    | 40×40                                   | (`x` - 20, `y` + 20)                                                               | (`x` + 60, `y` + 20)                              |
| 論理ゲート（`AND` など）、`NOT`       | 60×80                                   | 2 入力: (`x` - 20, `y` + 20) と (`x` - 20, `y` + 60)。1 入力: (`x` - 20, `y` + 40) | (`x` + 80, `y` + 40)                              |
| ラッチ・フリップフロップ（`RS` など） | 60×80                                   | (`x` - 20, `y` + 20 × (番号 + 1))                                                  | Q: (`x` + 80, `y` + 20)、Q̄: (`x` + 80, `y` + 60) |
| `CUSTOM`                              | 幅 80、高さ 20 × (多い方のピンの数 + 1) | (`x` - 20, `y` + 20 × (番号 + 1))                                                  | (`x` + 100, `y` + 20 × (番号 + 1))                |

- モジュールのピンが減ったときは、減ったピンの位置につながっていた配線は、どこにもつながらない線として残る。

## 部品の種類とピン

ピン番号は、下の表の並び順（0 から）。

| `kind`   | 表示名      | 入力ピン           | 出力ピン           |
| -------- | ----------- | ------------------ | ------------------ |
| `INPUT`  | INPUT       | なし               | 1本                |
| `CLOCK`  | CLOCK       | なし               | 1本                |
| `HIGH`   | HIGH        | なし               | 1本（常に ON）     |
| `OUTPUT` | OUTPUT      | 1本                | なし               |
| `AND`    | AND         | 2本                | 1本                |
| `OR`     | OR          | 2本                | 1本                |
| `NOT`    | NOT         | 1本                | 1本                |
| `NAND`   | NAND        | 2本                | 1本                |
| `NOR`    | NOR         | 2本                | 1本                |
| `XOR`    | XOR         | 2本                | 1本                |
| `XNOR`   | XNOR        | 2本                | 1本                |
| `RS`     | RS Latch    | S, R               | Q, Q̄              |
| `RSEN`   | RS-EN Latch | S, EN, R           | Q, Q̄              |
| `DLATCH` | D Latch     | D, EN              | Q, Q̄              |
| `DFF`    | D-FF        | D, CLK             | Q, Q̄              |
| `TFF`    | T-FF        | T, CLK             | Q, Q̄              |
| `JKFF`   | JK-FF       | J, CLK, K          | Q, Q̄              |
| `CUSTOM` | モジュール  | 中身の回路で決まる | 中身の回路で決まる |

### モジュールのピン

`CUSTOM` の部品のピンは、`custom` が指す回路の中の `INPUT` と `OUTPUT` で決まる。

- 入力ピンは中の `INPUT`、出力ピンは中の `OUTPUT` を、座標の順（上から、同じ高さなら左から）に並べたもの。
- ピンの名前は、それぞれの `label`（なければ名前なし）。
- 中の `INPUT` / `OUTPUT` を動かすと並び順が変わり、外側の配線が別のピンにつながる。

## 読み込むときの検証

保存データも共有用 JSON も、読み込むときに次を確かめる。1つでも満たさなければ、読み込まずに断る。

- `version` が数値で、今の版以下であること（新しい版のデータは断る）。
- 共有用 JSON は、`app` が `"sazanka"` であること。
- プロジェクト:
  - `circuits` が配列で、先頭の回路の `id` が `"main"` であること。
  - `author` があるなら文字列であること。
  - 回路の `id` が重ならないこと。
- 回路:
  - `id` と `name` が文字列で、`components` と `wires` が配列であること。
- 部品:
  - `id` が文字列で、回路の中で重ならないこと。
  - `kind` が[部品の種類とピン](#部品の種類とピン)の表のどれかであること。
  - `x` と `y` が数値であること。
  - `CUSTOM` の `custom` が、プロジェクトの中にある回路の `id` であること。
  - `period` があるなら、2〜10000 の整数であること。
- 配線:
  - `id` が文字列であること。
  - `points` が、`x` と `y` が数値のオブジェクトの配列で、2 つ以上あり、隣り合う 2 点の `x` か `y` が同じであること。

確かめていないこと:

- `label` の型。
- 配線の点がグリッドやシートの範囲に乗っているか。
- 配線の ID が重なっていないか。
- モジュールが循環して参照していないか。アプリでは循環を作れないが、手で書き換えたデータで循環していた場合は、計算するときにその参照を無視する。
- 表に書いていない項目。あっても断らないが、意味は持たない。

## ID の付け方

- アプリの中では、部品・配線・回路の ID に、ランダムな短い文字列を使う。
- 共有用 JSON に書き出すときは、読みやすくするため、部品と配線の ID を回路ごとに `part-1`、`wire-1` からの連番に付け直す。回路の `id` はモジュールの参照に使うので変えない。
- 共有用 JSON を読み込むときは、部品と配線の ID を、アプリの中と同じランダムな ID に付け直す。

## version 1 からの変更

- 配線を、出力ピンと入力ピンの参照（`from`、`to`、折れる点の `points`）から、通る点の並び（`points`）に変えた。配線は部品とは別に存在し、つながりは位置で決まる。
- version 1 のデータは、読み込むときに version 2 に変える（`file/upgradeV1.ts`）。
  - 配線は、version 1 のアプリが描いていた形（出力ピンから横に出て、折れる点を横→縦の順に通り、入力ピンへ横から入る。折れる点がなければ中間で 1 回折れる）を点の並びにする。
  - 存在しない部品やピンを指す配線は、位置が決まらないので捨てる。
  - version 1 では交わっていても無関係だった配線が、変えたあとに端が重なってつながることがある。
- version 1 の仕様は [archive/v1.md](archive/v1.md) にある。

## version 2 の中で変えたもの

まだない。

## 保存データに含めないもの

次の値も localStorage に置くが、利用者ごとの表示の設定なので、この形式には含めない。版も持たず、読めなければ既定値で動く。

- `sazanka.views`: 回路ごとの、シートの表示位置と倍率。
- `sazanka.paletteCollapsed`: パレットで折り畳んでいるグループ。
- `sazanka.preferences`: 環境設定のウィンドウの値（1 tick を進める間隔、方眼の表示、配線の角を丸めるか、アクセントカラー）。
