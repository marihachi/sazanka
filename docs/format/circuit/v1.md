# 回路の形式 version 1

sazanka の回路 1 つ分のデータの形式（version 1）の仕様。メイン回路もこの形式で持つ。メイン回路以外の回路は、部品としてほかの回路に置ける（置いたものをモジュールと呼ぶ）。

まだ公開していない（作業中）。公開するまでは、中身を変えてよい（[保存データ](../../../agent/docs/persistence.md)の「版の状態」）。

回路のデータは、単独では置かない。次のものの中に入る。

- [プロジェクトの形式](../project/v1.md)のデータ（保存データとプロジェクトファイル）の、要素の `circuit`。
- 回路ファイル（[計画 22](../../../agent/plans/module-files/plan.md)で作る）。

どこに入っても、形は同じ。

## 回路

```json
{
  "format": "sazanka-circuit",
  "version": 1,
  "id": "7b3e…",
  "name": "全加算器",
  "author": "",
  "package": { "kind": "split" },
  "sheet": { "width": 300, "height": 200 },
  "elements": [ ... ]
}
```

| 項目       | 型           | 必須                   | 内容                                                                      |
| ---------- | ------------ | ---------------------- | ------------------------------------------------------------------------- |
| `format`   | 文字列       | ○                      | 回路のデータであることの目印。常に `"sazanka-circuit"`                   |
| `version`  | 数値         | ○                      | 形式の版。`1`                                                             |
| `id`       | 文字列       | ○                      | 回路の ID。メイン回路は `"main"`（[ID の付け方](#id-の付け方)）         |
| `name`     | 文字列       | メイン回路以外は ○     | 回路の名前。空（空白だけを含む）にはできない。メイン回路は持たない      |
| `author`   | 文字列       | ○                      | 作者名。入れていなければ空文字 `""`                                       |
| `package`  | オブジェクト | ○                      | [パッケージ](#パッケージ)。メイン回路も持つ                               |
| `sheet`    | オブジェクト | ○                      | [シートの大きさ](#シートの大きさ)                                         |
| `elements` | 配列         | ○                      | [要素](#要素)（部品と配線）の一覧                                         |

- `id` が `"main"` の回路がメイン回路。メイン回路は、プロジェクトに必ず 1 つある（[プロジェクトの形式](../project/v1.md)）。
- メイン回路の名前は、アプリが表示言語に合わせて出す（「メイン」/「Main」）。改名はできない。
- メイン回路は、「外側のピンがどこにもつながっていない回路」とみなす。パッケージを `dip` / `qfp` にしてピン番号を割り当ててもよいが、ピンはどこにもつながらない。メイン回路は、ほかの回路に部品として置けない。
- 省略したときの意味が既定値になる項目は作らない。既定値を変えたときに、古いデータの意味が変わるため。省略できるのは、省略したときの意味が「ない」ことの項目（`portName`、`pinNumber`、メイン回路の `name`）と、部品の `rotation`（省略は `0`。「0 は回していない」は変えようがない）だけ。

## 座標

部品の位置と配線の点は、マス単位の整数で書く。シートの左上が原点で、`x` は右へ、`y` は下へ増える。

- アプリは 1 マスを 20px で描くが、データには px を書かない。
- シートの大きさ（`sheet`）も同じマス単位。

## パッケージ

回路をモジュールとして置いたときの形。本体の大きさと、外側のピンを置ける辺と位置が決まる。どのピンにどのポートをつなぐか（割り当て）は、パッケージではなく、中の `input` / `output` の `pinNumber` で決まる。

| 項目   | 型     | 内容                                           |
| ------ | ------ | ---------------------------------------------- |
| `kind` | 文字列 | 形の種類。`"dip"`、`"qfp"`、`"split"` のどれか |
| `pins` | 整数   | ピンの数。`dip` と `qfp` のとき必須            |

| `kind`  | 形                        | `pins`                     |
| ------- | ------------------------- | -------------------------- |
| `dip`   | 左右の 2 辺にピンを置く   | 4 以上 256 以下の偶数      |
| `qfp`   | 4 辺にピンを置く          | 8 以上 256 以下の 4 の倍数 |
| `split` | 入力は左、出力は右に置く  | なし                       |

## シートの大きさ

回路を描くシートの大きさ。単位はマス。左上が原点で、右と下へ広がる。

| 項目     | 型   | 内容                            |
| -------- | ---- | ------------------------------- |
| `width`  | 整数 | 横のマスの数。20 以上 1000 以下 |
| `height` | 整数 | 縦のマスの数。20 以上 1000 以下 |

## 要素

回路に置いたもの。部品と配線を、1 つの一覧（`elements`）に並べる。

- どの要素も `kind`（種類）を持ち、種類で何の要素かが決まる。`kind` が `"wire"` なら[配線](#配線)、[部品の種類とピン](#部品の種類とピン)の表にある種類なら[部品](#部品)。
- 種類の名前は、部品と配線で 1 つの名前の空間を分け合う（`wire` という名前の部品の種類は作らない）。
- 要素がほかに持つ項目は、種類で決まる。
- 一覧の並び順に意味はない。アプリは、種類ごとに次の順に書く（同じ種類の中は、アプリの中の順）: `input`、`output`、`clock`、`high`、`and`、`or`、`not`、`nand`、`nor`、`xor`、`xnor`、`rsLatch`、`rsEnLatch`、`dLatch`、`dFlipFlop`、`tFlipFlop`、`jkFlipFlop`、`sevenSegment`、`module`、`wire`。
- 部品か配線かという分け方は、一覧の分け方ではなく、種類の性質として持つ。種類を足すとき（バスやネットラベルなど）に、どちらの一覧に入れるかで迷わないため。
- 要素は `id` を持たない（[ID の付け方](#id-の付け方)）。

### 部品

| 項目         | 型     | 必須                         | 内容                                                                                                                     |
| ------------ | ------ | ---------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `kind`       | 文字列 | ○                            | 部品の種類（[部品の種類とピン](#部品の種類とピン)）                                                                      |
| `x`          | 整数   | ○                            | 本体の左上の横位置（マス）                                                                                               |
| `y`          | 整数   | ○                            | 本体の左上の縦位置（マス）                                                                                               |
| `portName`   | 文字列 |                              | `input` / `output` のポート名。モジュールとして置いたとき、外から見たピンの名前になる                                           |
| `portNumber` | 整数   | `input` / `output` のとき ○  | `input` / `output` を見分ける番号（ポート番号。1 から）。入力と出力で別々に振る。メイン回路でも持つ                      |
| `pinNumber`  | 整数   |                              | `input` / `output` の、外側のピン番号（1 から）。パッケージが `dip` / `qfp` のときだけ使う                               |
| `circuitId`  | 文字列 | `module` のとき ○            | モジュールとして置いた回路の `id`                                                                                        |
| `circuitName` | 文字列 | `module` のとき ○           | モジュールとして置いた回路の名前の写し（下の説明）                                                                       |
| `circuitSize` | オブジェクト | `module` のとき ○     | モジュールとして置いた回路の、本体の大きさの写し。`{ "width": 幅, "height": 高さ }`（マス、1 以上の整数。下の説明）       |
| `period`     | 整数   | `clock` のとき ○             | `clock` の周期（ON/OFF を一往復する tick 数、2〜10000）                                                                  |
| `rotation`   | 整数   |                              | 部品の向き。[ピンの先の位置](#ピンの先の位置)の表の向きから時計回りに回した角度（`0`、`90`、`180`、`270`）。なければ `0` |

- ポート番号は、同じ回路の中で、入力どうし・出力どうしで重ならない。
- `circuitName` は、保存するたびに、指している回路のその時の名前を写したもの。指す回路があるときは、表示には回路の `name` を使い、写しは使わない。指す回路が見つからないときに、何が足りないかを見せるために持つ。メイン回路を指すことはない。
- `circuitSize` は、保存するたびに、指している回路をモジュールとして置いたときの本体の大きさ（ピンと、本体の上に書く名前は含まない。回していない向き）を写したもの。指す回路があるときは使わない。指す回路が見つからないときに、元と同じ大きさの箱で描くために持つ（ピンは描かない）。`x` と `y` は本体の左上で、パッケージの形によらないので、同じ位置に同じ大きさで重なる。
- `rotation` があると、本体の幅と高さ、ピンの出る辺と位置が、本体ごと時計回りに回る。`x` と `y` は、回した後の本体の左上。
  - 例: `and`（幅 3・高さ 4 マス。入力は左、出力は右）を `90` にすると、幅 4・高さ 3 マスになり、入力は上、出力は下に出る。
  - ピンの先の位置の求め方は、[ピンの先の位置](#ピンの先の位置)にある。
  - アプリは `0` のときは書かない。
- アプリで置いた部品は、本体とピンがシート（`sheet`）の範囲に収まる。
  - ただし、シートの大きさを決める前に作った回路には、範囲の外にある部品もありうる。読み込むときは範囲を確かめない。

### 配線

縦と横の線分をつないだ線。部品とは別に存在し、部品を指さない。部品も配線を指さない。何とつながっているかは、位置で決まる（[つながりの決め方](#つながりの決め方)）。

| 項目     | 型     | 内容                                                                                                  |
| -------- | ------ | ----------------------------------------------------------------------------------------------------- |
| `kind`   | 文字列 | 配線の種類。今は `"wire"`（普通の配線）だけ                                                           |
| `points` | 配列   | 線が通る点の並び（2 つ以上）。`{ "x": 整数, "y": 整数 }` で、始点から順に並べる。始点と終点が配線の端 |

- 隣り合う 2 点は、`x` か `y` が同じ（どの区間も縦か横）。
- 種類（`kind`）は、あとで足すことがある。知らない種類の配線を含むデータは、読み込むときに断る（[読み込むときの検証](#読み込むときの検証)）。
- アプリで引いた配線は、点がシートの範囲（端を含む）に収まる。同じ点が続くことや、まっすぐ進む途中の点はない。

#### つながりの決め方

`kind` が `"wire"` の配線の決まり。

- 配線の端が、次の場所にあれば、そことつながる。
  - 部品のピンの先（[ピンの先の位置](#ピンの先の位置)）。
  - ほかの配線の上（端、折れる点、途中のどこでも）。途中にあるときは、そこから分岐している。
- 配線の途中どうしが交わるだけ（どちらの端でもない点で交わる）なら、つながらない。
- 配線の途中がピンの先を通るだけなら、そのピンにはつながらない。
- つながった配線とピンのまとまりを「ネット」と呼ぶ。ネットの中の入力ピンは、ネットの中の出力ピンの値になる。
  - 出力ピンがないネットの入力ピンは OFF。
  - 出力ピンが 2 つ以上あるネットはエラー。入力ピンは OFF として扱う。

#### ピンの先の位置

部品の左上を (`x`, `y`) として、ピンの先の位置は次のとおり。単位はマス。

| 部品                                       | 本体の大きさ（幅×高さ）               | 入力ピンの先                                                                                      | 出力ピンの先                                 |
| ------------------------------------------ | ------------------------------------- | ------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `input`、`clock`、`high`、`output`         | 2×2                                   | (`x` - 1, `y` + 1)                                                                                | (`x` + 3, `y` + 1)                           |
| 論理ゲート（`and` など）、`not`            | 3×4                                   | 2 入力: (`x` - 1, `y` + 1) と (`x` - 1, `y` + 3)。1 入力: (`x` - 1, `y` + 2)                      | (`x` + 4, `y` + 2)                           |
| ラッチ・フリップフロップ（`rsLatch` など） | 3×4                                   | (`x` - 1, `y` + 番号 + 1)                                                                         | Q: (`x` + 4, `y` + 1)、Q̄: (`x` + 4, `y` + 3) |
| `module`（パッケージが `split`）           | 幅 4、高さ 多い方のピンの数 + 1       | (`x` - 1, `y` + 番号 + 1)                                                                         | (`x` + 5, `y` + 番号 + 1)                    |
| `module`（パッケージが `dip`）             | 幅 3、高さ 2 × (`pins` / 2 - 1) + 2   | 下の「dip のピンの先」                                                                            | 下の「dip のピンの先」                       |
| `module`（パッケージが `qfp`）             | 正方形。1 辺 2 × (`pins` / 4 - 1) + 4 | 下の「qfp のピンの先」                                                                            | 下の「qfp のピンの先」                       |
| `sevenSegment`                             | 5×8                                   | 番号 0〜3（a〜d）: (`x` + 番号 + 1, `y` - 1)。番号 4〜7（e、f、g、DP）: (`x` + 番号 - 3, `y` + 9) | なし                                         |

- モジュールのピンが減ったとき（中の回路のポートを減らしたときなど）は、減ったピンの位置につながっていた配線は、どこにもつながらない線として残る。
- 上の表は `rotation` が `0` のとき。回した部品のピンの先は、次のように求める。表で求めた位置を、部品の左上から見た位置 (`px`, `py`) とし、回す前の本体の幅を W、高さを H とする。
  - `90`: (`x` + H - `py`, `y` + `px`)
  - `180`: (`x` + W - `px`, `y` + H - `py`)
  - `270`: (`x` + `py`, `y` + W - `px`)
  - 例: `and`（W = 3、H = 4）の入力 0 の先は、回す前は (`x` - 1, `y` + 1)、つまり (`px`, `py`) = (-1, 1)。`90` なら (`x` + 3, `y` - 1)。

##### dip のピンの先

外側のピン番号を n、ピン数を N（`pins`）とする。番号は実際の IC と同じく、左上の 1 番から反時計回りに振る。

- n ≤ N / 2（左の辺を上から下へ）: (`x` - 1, `y` + 1 + 2 × (n - 1))
- n > N / 2（右の辺を下から上へ）: (`x` + 4, `y` + 1 + 2 × (N - n))
- 例: 8 ピンなら、1 番は (`x` - 1, `y` + 1)、4 番は (`x` - 1, `y` + 7)、5 番は (`x` + 4, `y` + 7)、8 番は (`x` + 4, `y` + 1)。
- どのポートにも割り当てていない番号（NC）のピンは、配線とつながらない。

##### qfp のピンの先

外側のピン番号を n、ピン数を N、1 辺の本数を Q = N / 4、1 辺の長さを S = 2 × (Q - 1) + 4 とする。k は、その辺の中で番号の順に数えて何本めか（0 から。k = (n - 1) を Q で割った余り）。番号は左上の 1 番から反時計回りに振り、どの辺も角から 2 マスあけて 2 マスおきに並べる。

- n ≤ Q（左の辺を上から下へ）: (`x` - 1, `y` + 2 + 2 × k)
- Q < n ≤ 2Q（下の辺を左から右へ）: (`x` + 2 + 2 × k, `y` + S + 1)
- 2Q < n ≤ 3Q（右の辺を下から上へ）: (`x` + S + 1, `y` + S - 2 - 2 × k)
- 3Q < n（上の辺を右から左へ）: (`x` + S - 2 - 2 × k, `y` - 1)
- 例: 8 ピン（S = 6）なら、1 番は (`x` - 1, `y` + 2)、3 番は (`x` + 2, `y` + 7)、6 番は (`x` + 7, `y` + 2)、8 番は (`x` + 2, `y` - 1)。
- NC のピンは、dip と同じく配線とつながらない。

## 部品の種類とピン

ピン番号は、下の表の並び順（0 から）。

| `kind`         | 表示名      | 入力ピン                | 出力ピン                             |
| -------------- | ----------- | ----------------------- | ------------------------------------ |
| `input`        | INPUT       | なし                    | 1本                                  |
| `clock`        | CLOCK       | なし                    | 1本                                  |
| `high`         | HIGH        | なし                    | 1本（常に ON）                       |
| `output`       | OUTPUT      | 1本                     | なし                                 |
| `and`          | AND         | 2本                     | 1本                                  |
| `or`           | OR          | 2本                     | 1本                                  |
| `not`          | NOT         | 1本                     | 1本                                  |
| `nand`         | NAND        | 2本                     | 1本                                  |
| `nor`          | NOR         | 2本                     | 1本                                  |
| `xor`          | XOR         | 2本                     | 1本                                  |
| `xnor`         | XNOR        | 2本                     | 1本                                  |
| `rsLatch`      | RS Latch    | S, R                    | Q, Q̄                                 |
| `rsEnLatch`    | RS-EN Latch | S, EN, R                | Q, Q̄                                 |
| `dLatch`       | D Latch     | D, EN                   | Q, Q̄                                 |
| `dFlipFlop`    | D-FF        | D, CLK                  | Q, Q̄                                 |
| `tFlipFlop`    | T-FF        | T, CLK                  | Q, Q̄                                 |
| `jkFlipFlop`   | JK-FF       | J, CLK, K               | Q, Q̄                                 |
| `sevenSegment` | 7セグ       | a, b, c, d, e, f, g, DP | なし（入力が ON のセグメントが光る） |
| `module`       | モジュール  | 中身の回路で決まる      | 中身の回路で決まる                   |

### モジュールのピン

`module` の部品のピンは、`circuitId` が指す回路の中の `input` と `output` で決まる。

- パッケージが `split` のとき:
  - 入力ピンは中の `input` を入力のポート番号の順に、出力ピンは中の `output` を出力のポート番号の順に並べたもの。
  - 中の `input` / `output` を動かしても、ピンは変わらない。
- パッケージが `dip` / `qfp` のとき:
  - 外側のピンは、中の `input` / `output` の `pinNumber` で決まる。入力か出力かは問わず、1 から `pins` までの通し番号。
  - 外側のピンに出すのは、`pinNumber` が 1〜`pins` の整数で、ほかのポートと重ならないものだけ。番号がない・範囲の外・重なるポートは、どれも出さない（重なりは、どちらも出さない）。
  - どのポートにも割り当てていない番号は NC（何にもつながらない）。
  - 中の `input` / `output` を動かしても、ピンは変わらない。
- ピンの名前は、それぞれの `portName`（なければ名前なし）。

## 読み込むときの検証

回路のデータを読み込むときに、次を確かめる。1 つでも満たさなければ、読み込まずに断る。プロジェクトの中の回路では、1 つでも断れば、プロジェクトごと断る（[プロジェクトの形式](../project/v1.md)の「読み込むときの検証」）。

- `format` が `"sazanka-circuit"` であること。
- `version` が数値で、今の版以下であること（新しい版のデータは断る）。
- `id` が文字列であること。
- メイン回路以外は、`name` が文字列で、空（空白だけを含む）でないこと。
- `author` が文字列であること。
- `package` が[パッケージ](#パッケージ)の表のどれかの形であること（メイン回路も）。
- `sheet` の `width` と `height` が 20 以上 1000 以下の整数であること。
- `elements` が配列であること。
- 要素:
  - `kind` が `"wire"` なら配線、それ以外は部品として、下を確かめる。知らない種類の要素は、部品の種類にないので断る。
- 部品:
  - `kind` が[部品の種類とピン](#部品の種類とピン)の表のどれかであること。
  - `x` と `y` が整数であること。
  - `input` / `output` の `portNumber` が 1 以上の整数で、入力どうし・出力どうしで重ならないこと。
  - `pinNumber` があるなら、整数であること。
  - `module` の部品の `circuitId` と `circuitName` が文字列であること。
  - `clock` の `period` が 2〜10000 の整数であること。
  - `rotation` があるなら、`0`、`90`、`180`、`270` のどれかであること。
- 配線:
  - `points` が、`x` と `y` が整数のオブジェクトの配列で、2 つ以上あり、隣り合う 2 点の `x` か `y` が同じであること。

確かめていないこと:

- メイン回路の `name`。あっても読み込むときに捨てる。
- 部品と配線の `id`。あっても読み込むときに捨てる。
- `portName` の型。
- `pinNumber` が `pins` の範囲にあるか、ほかと重なっていないか。範囲外や重なりがあっても断らない（そのポートは外側のピンに出ない）。
- `portName` が、ほかのポートと重なっていないか。アプリでは重なる名前を付けられないが、読み込みでは断らず、名前も変えない。
- `circuitName` が、指す回路の今の名前と同じか。違っていても断らない（表示には回路の `name` を使う）。
- 配線の点がシートの範囲に乗っているか。
- 回路が循環して参照していないか（回路 A に、A を含む回路のモジュールを置くなど）。アプリでは循環を作れないが、手で書き換えたデータで循環していた場合は、計算するときにその参照を無視する。
- 表に書いていない項目。あっても断らないが、意味は持たない。

## ID の付け方

- ID を持つのは回路だけ。モジュールの部品が回路を指すのに使う（部品の `circuitId`）。
- 回路の `id` は、プロジェクトをまたいでも重ならない文字列にする。形は決めない（アプリは UUID version 4 の形で作る）。
  - 回路を別のプロジェクトへ持ち込んでも、ID を付け直さずに済ませるため。同じ `id` なら、同じ回路（の別の版）とみなす。
- メイン回路の `id` は、どのプロジェクトでも `"main"`。メイン回路は別のプロジェクトへ持ち込まないので、ぶつからない。メイン回路以外は `"main"` を使えない。
- 回路の ID は、回路を足したときに一度だけ付ける。保存、書き出し、読み込みでは付け直さない。
- 部品と配線は ID を持たない。どこからも参照されないため。アプリは、読み込むたびに部品と配線に ID を付けて、選択や編集に使う。

## 一体の形式 version 4 からの変更

回路の形式は、プロジェクトと回路が一体の形式（version 1〜4。最後の [version 4](../integrated/v4.md)）の「回路」を、単独で扱える形にしたもの。一体の形式 version 4 の回路からの違いは次のとおり。

- `format`（`"sazanka-circuit"`）と `version` を持つ。
- `author`（作者名）を持つ。一体の形式では、プロジェクトが持っていた。
- メイン回路もパッケージを持つ（省略できない）。
- `sheet` を省略できなくした。
- モジュールの部品が回路を指す項目を、`module` から `circuitId` に変えた。名前の写し `circuitName` を足した。
- `input` / `output` の `portNumber` と、`clock` の `period` を省略できなくした。ポート番号の重なりは断る（一体の形式では、読み込むときに付け直していた）。
- split のモジュールの外側のピンの順を、中の位置の順から、ポート番号の順にした。
- メイン回路以外の名前を、空にできなくした。

一体の形式 version 4 の回路は、読み込むときに回路の形式 version 1 に変える（`file/upgrade/circuit/v1.ts` の `upgradeToCircuitV1`。プロジェクト全体の変え方は[プロジェクトの形式](../project/v1.md)の「一体の形式 version 4 からの変更」）。

- `format` と `version` を書き込む。
- `author` に、一体の形式のプロジェクトの `author` を写す。なければ空文字にする。
- メイン回路に `{ "kind": "split" }` のパッケージを書き込む。
- `sheet` がなければ、横 300 マス・縦 200 マスを書き込む。
- `clock` の `period` がなければ、`100` を書き込む。
- `input` / `output` のポート番号を整える。
  - まず、番号がないものと重なるものに、一体の形式の読み込みと同じ決め方で番号を付ける（入力と出力で別々に、中の位置の順で後ろの重なるもの・ないものに、空いているいちばん小さい番号を付ける）。
  - パッケージが `split` の回路とメイン回路は、そのあと、入力と出力で別々に、1 から位置の順（上から、同じ高さなら左から）に振り直す。今までと同じピンの順になるので、外側の配線は同じピンにつながったまま。
    - 飛びのある番号は詰まる。例: 番号が 1、3、4 で、位置が上から入力 4、入力 1、入力 3 なら、上から 1、2、3 になる。
    - 位置の順と番号の順がもともとそろっていて飛びもない回路は、番号が変わらない。
    - メイン回路のピンはどこにもつながらないので、配線には響かない。シート上の「入力 1」などの表示が変わることはある。
  - パッケージが `dip` / `qfp` の回路は、振り直さない。
- モジュールの部品の `module` を `circuitId` に移し、指す回路の名前を `circuitName` に写す（名前はプロジェクト全体の変え方で整えた後のもの）。
- メイン回路以外の名前が空なら、名前を付ける（プロジェクト全体の変え方で行う）。
