# データ形式 version 3

sazanka が保存・共有する回路データの形式（version 3）の仕様。version 2 からの違いは [version 2 からの変更](#version-2-からの変更)にある。

version 3 は公開した（2026-10-08）。今ある項目や値は変えない。部品の種類や、省略できる項目を足すのはよい（版は上げない。[保存データ](../../agent/docs/persistence.md)の「形式を変えるとき」）。(開発者からの指示)

対象は次の2つ。どちらも、中身のプロジェクトの形（[プロジェクト](#プロジェクト)以降）は共通で、外側の包み方だけが違う。

- **保存データ**: ブラウザの localStorage に自動で保存するデータ。
- **共有用 JSON**: 画面上部の「書き出し」で作り、「読み込み」で読む文字列。

版の番号は2つで別々に持っている（保存データは `file/storage.ts` の `STORAGE_VERSION`、共有用 JSON は `file/share.ts` の `SHARE_VERSION`）。今はどちらも 3。

## 外側の包み方

### 保存データ

localStorage のキー `sazanka.project` に、次の JSON を文字列にして置く。

```json
{
  "version": 3,
  "project": { ... }
}
```

| 項目      | 型           | 内容                          |
| --------- | ------------ | ----------------------------- |
| `version` | 数値         | 形式の版。`3`                 |
| `project` | オブジェクト | [プロジェクト](#プロジェクト) |

### 共有用 JSON

```json
{
  "app": "sazanka",
  "version": 3,
  "project": { ... }
}
```

| 項目      | 型           | 内容                                               |
| --------- | ------------ | -------------------------------------------------- |
| `app`     | 文字列       | sazanka のデータであることの目印。常に `"sazanka"` |
| `version` | 数値         | 形式の版。`3`                                      |
| `project` | オブジェクト | [プロジェクト](#プロジェクト)                      |

## プロジェクト

メイン回路と、部品として使う回路（モジュール）をまとめたもの。

| 項目       | 型     | 必須 | 内容                                         |
| ---------- | ------ | ---- | -------------------------------------------- |
| `circuits` | 配列   | ○    | [回路](#回路)の一覧。先頭はメイン回路        |
| `author`   | 文字列 |      | 作者名。書き出すときに入力された場合だけ付く |

- 先頭の回路の `id` は `"main"`（メイン回路）でなければならない。2つ目以降はモジュール。
- 回路の `id` は、プロジェクトの中で重ならない。

## 回路

| 項目      | 型           | 必須               | 内容                                                                        |
| --------- | ------------ | ------------------ | --------------------------------------------------------------------------- |
| `id`      | 文字列       | ○                  | 回路の ID。メイン回路は `"main"`。モジュールの参照（部品の `module`）に使う |
| `name`    | 文字列       | ○                  | 回路の名前。タブとパレットに表示する                                        |
| `package` | オブジェクト | モジュールのとき ○ | [パッケージ](#パッケージ)。メイン回路は持たない                             |
| `sheet`   | オブジェクト |                    | [シートの大きさ](#シートの大きさ)。メイン回路もモジュールも持つ             |
| `parts`   | 配列         | ○                  | [部品](#部品)の一覧                                                         |
| `wires`   | 配列         | ○                  | [配線](#配線)の一覧                                                         |

### パッケージ

モジュールの形。本体の大きさと、外側のピンを置ける辺と位置が決まる。どのピンにどのポートをつなぐか（割り当て）は、パッケージではなく、中の `input` / `output` の `pinNumber` で決まる。

| 項目   | 型     | 内容                                           |
| ------ | ------ | ---------------------------------------------- |
| `kind` | 文字列 | 形の種類。`"dip"`、`"qfp"`、`"split"` のどれか |
| `pins` | 整数   | ピンの数。`dip` と `qfp` のとき必須            |

| `kind`  | 形                                                         | `pins`                     |
| ------- | ---------------------------------------------------------- | -------------------------- |
| `dip`   | 左右の 2 辺にピンを置く                                    | 4 以上 256 以下の偶数      |
| `qfp`   | 4 辺にピンを置く                                           | 8 以上 256 以下の 4 の倍数 |
| `split` | 入力は左、出力は右に置く（version 2 までのモジュールの形） | なし                       |

- 省略はできない。既定値で補うと、既定値を変えたときに、古いデータのモジュールのピンの位置が変わって配線が外れるため。

### シートの大きさ

回路を描くシートの大きさ。単位はマス（1 マスは 20px）。左上が原点で、右と下へ広がる。

| 項目     | 型   | 内容                           |
| -------- | ---- | ------------------------------ |
| `width`  | 整数 | 横のマスの数。20 以上 1000 以下 |
| `height` | 整数 | 縦のマスの数。20 以上 1000 以下 |

- アプリは、300×200 のときも必ず書く。
- 省略したときは、横 300 マス・縦 200 マスとして扱う。この値は変えない（変えると、古いデータの回路の大きさが変わる）。
- 項目を足す前のデータにはないので、省略を許す。

## 部品

| 項目         | 型     | 必須              | 内容                                                                                                        |
| ------------ | ------ | ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `id`         | 文字列 | ○                 | 部品の ID。回路の中で重ならない                                                                             |
| `kind`       | 文字列 | ○                 | 部品の種類（[部品の種類とピン](#部品の種類とピン)）                                                         |
| `x`          | 数値   | ○                 | 本体の左上の横位置（px）                                                                                    |
| `y`          | 数値   | ○                 | 本体の左上の縦位置（px）                                                                                    |
| `label`      | 文字列 |                   | `input` / `output` のラベル。モジュールの中では、外から見たピンの名前になる                                 |
| `module`     | 文字列 | `module` のとき ○ | 部品として置いた回路の `id`                                                                                 |
| `period`     | 整数   |                   | `clock` の周期（ON/OFF を一往復する tick 数、2〜10000）。なければ 100                                       |
| `pinNumber`  | 整数   |                   | モジュールの中の `input` / `output` の、外側のピン番号（1 から）。パッケージが `dip` / `qfp` のときだけ使う |
| `portNumber` | 整数   |                   | `input` / `output` を見分ける番号（ポート番号。1 から）。入力と出力で別々に振る。メイン回路でも持つ         |

座標について:

- 1マスは 20px。アプリで置いた部品は、座標が 20 の倍数になる。
- シートの大きさは回路の `sheet` で決まり（省略したときは横 6000px・縦 4000px）、左上が原点。アプリで置いた部品は、本体とピンがこの範囲に収まる。
  - ただし、シートの大きさを決める前に作った回路には、範囲の外にある部品もありうる。読み込むときは範囲を確かめない。

## 配線

縦と横の線分をつないだ線。部品とは別に存在し、部品を指さない。何とつながっているかは、位置で決まる（[つながりの決め方](#つながりの決め方)）。

| 項目     | 型     | 内容                                                                                                  |
| -------- | ------ | ----------------------------------------------------------------------------------------------------- |
| `id`     | 文字列 | 配線の ID。回路の中で重ならない                                                                       |
| `points` | 配列   | 線が通る点の並び（2 つ以上）。`{ "x": 数値, "y": 数値 }` で、始点から順に並べる。始点と終点が配線の端 |

- 隣り合う 2 点は、`x` か `y` が同じ（どの区間も縦か横）。
- アプリで引いた配線は、点が 20px 単位（グリッド）に乗り、シートの範囲（端を含む）に収まる。同じ点が続くことや、まっすぐ進む途中の点はない。

### つながりの決め方

- 配線の端が、次の場所にあれば、そことつながる。
  - 部品のピンの先（[部品の種類とピン](#部品の種類とピン)の位置）。
  - ほかの配線の上（端、折れる点、途中のどこでも）。途中にあるときは、そこから分岐している。
- 配線の途中どうしが交わるだけ（どちらの端でもない点で交わる）なら、つながらない。
- 配線の途中がピンの先を通るだけなら、そのピンにはつながらない。
- つながった配線とピンのまとまりを「ネット」と呼ぶ。ネットの中の入力ピンは、ネットの中の出力ピンの値になる。
  - 出力ピンがないネットの入力ピンは OFF。
  - 出力ピンが 2 つ以上あるネットはエラー。入力ピンは OFF として扱う。

### ピンの先の位置

部品の左上を (`x`, `y`) として、ピンの先の位置は次のとおり。1 マスは 20px。

| 部品                                       | 本体の大きさ（幅×高さ）                 | 入力ピンの先                                                                                                       | 出力ピンの先                                     |
| ------------------------------------------ | --------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------ |
| `input`、`clock`、`high`、`output`         | 40×40                                   | (`x` - 20, `y` + 20)                                                                                               | (`x` + 60, `y` + 20)                             |
| 論理ゲート（`and` など）、`not`            | 60×80                                   | 2 入力: (`x` - 20, `y` + 20) と (`x` - 20, `y` + 60)。1 入力: (`x` - 20, `y` + 40)                                 | (`x` + 80, `y` + 40)                             |
| ラッチ・フリップフロップ（`rsLatch` など） | 60×80                                   | (`x` - 20, `y` + 20 × (番号 + 1))                                                                                  | Q: (`x` + 80, `y` + 20)、Q̄: (`x` + 80, `y` + 60) |
| `module`（パッケージが `split`）           | 幅 80、高さ 20 × (多い方のピンの数 + 1) | (`x` - 20, `y` + 20 × (番号 + 1))                                                                                  | (`x` + 100, `y` + 20 × (番号 + 1))               |
| `module`（パッケージが `dip`）             | 幅 60、高さ 40 × (`pins` / 2 - 1) + 40  | 下の「dip のピンの先」                                                                                             | 下の「dip のピンの先」                           |
| `module`（パッケージが `qfp`）             | 正方形。1 辺 40 × (`pins` / 4 - 1) + 80 | 下の「qfp のピンの先」                                                                                             | 下の「qfp のピンの先」                           |
| `sevenSegment`                             | 100×160                                 | 番号 0〜3（a〜d）: (`x` + 20 × (番号 + 1), `y` - 20)。番号 4〜7（e、f、g、DP）: (`x` + 20 × (番号 - 3), `y` + 180) | なし                                             |

- モジュールのピンが減ったときは、減ったピンの位置につながっていた配線は、どこにもつながらない線として残る。

#### dip のピンの先

外側のピン番号を n、ピン数を N（`pins`）とする。番号は実際の IC と同じく、左上の 1 番から反時計回りに振る。

- n ≤ N / 2（左の辺を上から下へ）: (`x` - 20, `y` + 20 + 40 × (n - 1))
- n > N / 2（右の辺を下から上へ）: (`x` + 80, `y` + 20 + 40 × (N - n))
- 例: 8 ピンなら、1 番は (`x` - 20, `y` + 20)、4 番は (`x` - 20, `y` + 140)、5 番は (`x` + 80, `y` + 140)、8 番は (`x` + 80, `y` + 20)。
- どのポートにも割り当てていない番号（NC）のピンは、配線とつながらない。

#### qfp のピンの先

外側のピン番号を n、ピン数を N、1 辺の本数を Q = N / 4、1 辺の長さを S = 40 × (Q - 1) + 80 とする。k は、その辺の中で番号の順に数えて何本めか（0 から。k = (n - 1) を Q で割った余り）。番号は左上の 1 番から反時計回りに振り、どの辺も角から 40 あけて 40 おきに並べる。

- n ≤ Q（左の辺を上から下へ）: (`x` - 20, `y` + 40 + 40 × k)
- Q < n ≤ 2Q（下の辺を左から右へ）: (`x` + 40 + 40 × k, `y` + S + 20)
- 2Q < n ≤ 3Q（右の辺を下から上へ）: (`x` + S + 20, `y` + S - 40 - 40 × k)
- 3Q < n（上の辺を右から左へ）: (`x` + S - 40 - 40 × k, `y` - 20)
- 例: 8 ピン（S = 120）なら、1 番は (`x` - 20, `y` + 40)、3 番は (`x` + 40, `y` + 140)、6 番は (`x` + 140, `y` + 40)、8 番は (`x` + 40, `y` - 20)。
- NC のピンは、dip と同じく配線とつながらない。

## 部品の種類とピン

ピン番号は、下の表の並び順（0 から）。

| `kind`         | 表示名      | 入力ピン                | 出力ピン                             |
| -------------- | ----------- | ----------------------- | ------------------------------------ |
| `input`        | INPUT       | なし                    | 1本                                  |
| `clock`        | CLOCK       | なし                    | 1本                                  |
| `high`         | HIGH        | なし                    | 1本（常に ON）                       |
| `output`       | OUTPUT      | 1本                     | なし                                 |
| `and`          | AND         | 2本                     | 1本                                  |
| `or`           | OR          | 2本                     | 1本                                  |
| `not`          | NOT         | 1本                     | 1本                                  |
| `nand`         | NAND        | 2本                     | 1本                                  |
| `nor`          | NOR         | 2本                     | 1本                                  |
| `xor`          | XOR         | 2本                     | 1本                                  |
| `xnor`         | XNOR        | 2本                     | 1本                                  |
| `rsLatch`      | RS Latch    | S, R                    | Q, Q̄                                 |
| `rsEnLatch`    | RS-EN Latch | S, EN, R                | Q, Q̄                                 |
| `dLatch`       | D Latch     | D, EN                   | Q, Q̄                                 |
| `dFlipFlop`    | D-FF        | D, CLK                  | Q, Q̄                                 |
| `tFlipFlop`    | T-FF        | T, CLK                  | Q, Q̄                                 |
| `jkFlipFlop`   | JK-FF       | J, CLK, K               | Q, Q̄                                 |
| `sevenSegment` | 7セグ       | a, b, c, d, e, f, g, DP | なし（入力が ON のセグメントが光る） |
| `module`       | モジュール  | 中身の回路で決まる      | 中身の回路で決まる                   |

### モジュールのピン

`module` の部品のピンは、`module` が指す回路の中の `input` と `output` で決まる。

- パッケージが `split` のとき:
  - 入力ピンは中の `input`、出力ピンは中の `output` を、座標の順（上から、同じ高さなら左から）に並べたもの。
  - 中の `input` / `output` を動かすと並び順が変わり、外側の配線が別のピンにつながる。
- パッケージが `dip` / `qfp` のとき:
  - 外側のピンは、中の `input` / `output` の `pinNumber` で決まる。入力か出力かは問わず、1 から `pins` までの通し番号。
  - 外側のピンに出すのは、`pinNumber` が 1〜`pins` の整数で、ほかのポートと重ならないものだけ。番号がない・範囲の外・重なるポートは、どれも出さない（重なりは、どちらも出さない）。
  - どのポートにも割り当てていない番号は NC（何にもつながらない）。
  - 中の `input` / `output` を動かしても、ピンは変わらない。
- ピンの名前は、それぞれの `label`（なければ名前なし）。

## 読み込むときの検証

保存データも共有用 JSON も、読み込むときに次を確かめる。1つでも満たさなければ、読み込まずに断る。

- `version` が数値で、今の版以下であること（新しい版のデータは断る）。
- 共有用 JSON は、`app` が `"sazanka"` であること。
- プロジェクト:
  - `circuits` が配列で、先頭の回路の `id` が `"main"` であること。
  - `author` があるなら文字列であること。
  - 回路の `id` が重ならないこと。
- 回路:
  - `id` と `name` が文字列で、`parts` と `wires` が配列であること。
  - モジュールの回路は、`package` が[パッケージ](#パッケージ)の表のどれかの形であること。
  - `sheet` があるなら、`width` と `height` が 20 以上 1000 以下の整数であること。
- 部品:
  - `id` が文字列で、回路の中で重ならないこと。
  - `kind` が[部品の種類とピン](#部品の種類とピン)の表のどれかであること。
  - `x` と `y` が数値であること。
  - `module` の部品の `module` が、プロジェクトの中にある回路の `id` であること。
  - `period` があるなら、2〜10000 の整数であること。
  - `pinNumber` があるなら、整数であること。
  - `portNumber` があるなら、1 以上の整数であること。
- 配線:
  - `id` が文字列であること。
  - `points` が、`x` と `y` が数値のオブジェクトの配列で、2 つ以上あり、隣り合う 2 点の `x` か `y` が同じであること。

確かめていないこと:

- `label` の型。
- `pinNumber` が `pins` の範囲にあるか、ほかと重なっていないか。範囲外や重なりがあっても断らない。
- `portNumber` があるか、ほかと重なっていないか。断らずに、読み込むときに付け直す（ないものと、中の位置の順で後ろの重なるものに、空いているいちばん小さい番号を付ける）。
- `label` が、ほかのポートと重なっていないか。アプリでは重なる名前を付けられないが、読み込みでは断らず、名前も変えない。
- メイン回路の `package`。あっても意味は持たない。
- 配線の点がグリッドやシートの範囲に乗っているか。
- 配線の ID が重なっていないか。
- モジュールが循環して参照していないか。アプリでは循環を作れないが、手で書き換えたデータで循環していた場合は、計算するときにその参照を無視する。
- 表に書いていない項目。あっても断らないが、意味は持たない。

## ID の付け方

- アプリの中では、部品・配線・回路の ID に、ランダムな短い文字列を使う。
- 共有用 JSON に書き出すときは、読みやすくするため、部品と配線の ID を回路ごとに `part-1`、`wire-1` からの連番に付け直す。回路の `id` はモジュールの参照に使うので変えない。
- 共有用 JSON を読み込むときは、部品と配線の ID を、アプリの中と同じランダムな ID に付け直す。

## version 2 からの変更

- 回路の部品の一覧の項目名を `components` から `parts` に変えた。
- モジュールを指す部品の項目名を `custom` から `module` に変えた。
- 部品の種類の名前を、キャメルケースに変えた（`INPUT` → `input`、`DFF` → `dFlipFlop`、`CUSTOM` → `module` など。[部品の種類とピン](#部品の種類とピン)の表）。
- モジュールの回路に、モジュールの形（パッケージ、`package`）を足した。
- モジュールの中の `input` / `output` に、外側のピン番号（`pinNumber`）を足した。
- `input` / `output` に、見分けるための番号（`portNumber`）を足した。
- version 2 のデータは、読み込むときに version 3 に変える（`file/upgradeV2.ts`）。
  - 上の項目名と種類の名前を変える。
  - モジュールの回路に `{ "kind": "split" }` を書き込む。ピンの位置は version 2 と同じになるので、配線は書き換えない。
  - `input` / `output` に、入力と出力で別々に、中の位置の順（上から、同じ高さなら左から）で 1 から `portNumber` を書き込む。
- version 1 のデータは、version 2 に変えてから、続けて version 3 に変える。
- version 2 の仕様は [archive/v2.md](archive/v2.md) にある。

## version 3 の中で変えたもの

公開したあとに足したもの。版は上げていない（足すだけで、今あるデータの読み方は変わらないため）。

- 部品の種類 `sevenSegment`（7 セグメントディスプレイ）を足した。
- 回路に、シートの大きさ（`sheet`）を足した。省略したときは 300×200 マス。

## 保存データに含めないもの

次の値も localStorage に置くが、利用者ごとの表示の設定なので、この形式には含めない。版も持たず、読めなければ既定値で動く。

- `sazanka.views`: 回路ごとの、シートの表示位置と倍率。
- `sazanka.paletteCollapsed`: パレットで折り畳んでいるグループ。
- `sazanka.preferences`: 環境設定のウィンドウの値（1 tick を進める間隔、方眼の表示、配線の角を丸めるか、アクセントカラー）。
