# プロジェクトの形式 version 1

sazanka のプロジェクトのデータの形式（version 1）の仕様。プロジェクトに入っている回路の中身は、[回路の形式](../circuit/v1.md)で書く。

まだ公開していない（作業中）。公開するまでは、中身を変えてよい（[保存データ](../../../agent/docs/persistence.md)の「版の状態」）。

対象は次の 2 つ。どちらも、この形式のデータそのもので、外側の包みはない。

- **保存データ**: ブラウザの localStorage のキー `sazanka.project` に、JSON を文字列にして置くデータ。変わるたびに自動で保存する。
- **プロジェクトファイル**: プロジェクト全体を書き出したファイル（UTF-8 の JSON）。ファイル名は `project-YYYY-MM-DD.sazanka.json`（端末の日付）。

## プロジェクト

```json
{
  "format": "sazanka-project",
  "version": 1,
  "folders": ["adders"],
  "circuits": [
    { "path": "", "circuit": { "format": "sazanka-circuit", "version": 1, "id": "main", ... } },
    { "path": "adders", "circuit": { "format": "sazanka-circuit", "version": 1, "id": "7b3e…", "name": "全加算器", ... } }
  ]
}
```

| 項目      | 型     | 必須 | 内容                                                              |
| --------- | ------ | ---- | ----------------------------------------------------------------- |
| `format`  | 文字列 | ○    | プロジェクトのデータであることの目印。常に `"sazanka-project"`    |
| `version` | 数値   | ○    | 形式の版。`1`                                                     |
| `folders` | 配列   | ○    | [フォルダ](#フォルダ)のパスの一覧（文字列）。空でもよい           |
| `circuits` | 配列   | ○    | [プロジェクトの要素](#プロジェクトの要素)の並び                   |

- `circuits` の並びは、プロジェクトパネルでの回路の並び。
- `id` が `"main"` の回路（メイン回路）が、必ず 1 つだけある。並びのどこにあってもよく、フォルダにも入れられる。
- 回路の `id` は、プロジェクトの中で重ならない。
- プロジェクトは作者名を持たない。作者名は回路が持つ（回路の `author`）。

## プロジェクトの要素

プロジェクトに入っている回路 1 つと、それを置くフォルダの組。

| 項目     | 型           | 必須 | 内容                                                                    |
| -------- | ------------ | ---- | ----------------------------------------------------------------------- |
| `path`   | 文字列       | ○    | 回路を置くフォルダの[パス](#パス)。フォルダに入れないものは `""`  |
| `circuit` | オブジェクト | ○    | [回路の形式](../circuit/v1.md)のデータ（版を含む）をそのまま入れる |

- 回路のデータは、プロジェクトの中に持つ（インライン）。回路ファイルの中の回路のデータと、まったく同じ形。
- 回路の `id` は回路のデータの中にあるので、要素には書かない。
- フォルダはプロジェクトが決める。回路のデータは、どこに置かれるかを知らない。
- 同じフォルダの中の回路の名前は重ならない（大文字と小文字は区別する）。メイン回路は名前を持たないので、比べない。

## フォルダ

回路を整理するための入れ物。`folders` に、プロジェクトのフォルダをすべて並べる。

- 入れ子のフォルダ（`lib/gates`）は、親（`lib`）も並べる。一覧にないフォルダが暗に生まれないようにするため。
- 空のフォルダも、一覧にあれば残る。
- `folders` の並びが、プロジェクトパネルでのフォルダの並び。
- 同じパスを 2 回並べない。
- 要素の `path` は、`""` か、`folders` にあるパスのどれか。

### パス

フォルダの場所を表す文字列。

- 区切りは `/`。フォルダに入れないものは `""`。
- 先頭と末尾の `/`、空の部分（`a//b`）、`.`、`..` は使えない。
- 部分の中は、`/` 以外ならどの文字でもよい（日本語や空白も使える）。
- 大文字と小文字は区別する。
- 長さの上限は決めない。

## ファイルの見分け方

データの種類は `format` で見分ける。

| `format`              | 種類                                                 |
| --------------------- | ---------------------------------------------------- |
| `"sazanka-project"`   | プロジェクト（この文書）                             |
| `"sazanka-circuit"`    | 回路（[回路の形式](../circuit/v1.md)）    |
| `"sazanka-circuits"`   | 回路ファイル（[計画 22](../../../agent/plans/module-files/plan.md)で作る） |
| なし                  | 一体の形式（version 1〜4）か、sazanka のデータでない |

- 一体の形式は `format` を持たず、いちばん外に `version` と `project` を持ち、`project` の中に `circuits` を持つ。プロジェクトファイル（一体の形式では「共有用 JSON」）は、さらに `"app": "sazanka"` を持つ。
- 版の番号（`version`）だけでは見分けない。一体の形式の version 1 と、プロジェクトの形式の version 1 があるため。
- プロジェクトを読み込むときに、回路のデータや回路ファイルを選んでいたら、種類が違うこととして断る（壊れたデータとは分けて知らせる）。

## 読み込むときの検証

保存データもプロジェクトファイルも、読み込むときに次を確かめる。1 つでも満たさなければ、読み込まずに断る。

- `format` が `"sazanka-project"` であること。一体の形式なら、先に[一体の形式 version 4 からの変更](#一体の形式-version-4-からの変更)のとおりに変えてから確かめる。
- `version` が数値で、今の版以下であること（新しい版のデータは断る）。
- `folders` が文字列の配列で、どれも[パス](#パス)の決まりに合い、`""` でなく、重ならないこと。入れ子のフォルダの親が `folders` にあること。
- `circuits` が配列で、どの要素も:
  - `path` が文字列で、`""` か `folders` にあるパスであること。
  - `circuit` が[回路の形式](../circuit/v1.md)の「読み込むときの検証」を通ること。
- `id` が `"main"` の回路が、ちょうど 1 つあること。
- 回路の `id` が重ならないこと。
- 同じフォルダの中で、メイン回路以外の回路の `name` が重ならないこと。
- `module` の部品の `circuitId` が、プロジェクトの中にある回路の `id` であること。

確かめていないこと:

- 表に書いていない項目。あっても断らないが、意味は持たない。

## 一体の形式 version 4 からの変更

一体の形式（version 1〜4）は、プロジェクトと回路を 1 つの形で持っていた（最後の版は [version 4](../integrated/v4.md)）。プロジェクトの形式は、プロジェクトの構造（どの回路が入っているか、並び、フォルダ）だけを持ち、回路の中身は回路の形式で持つ。

- 外側の包み（保存データの `{ version, project }`、共有用 JSON の `{ app, version, project }`）をやめ、プロジェクトのデータそのものにした。
- `format` を足した。
- 回路の平らな並び（`circuits`。回路のデータそのものの並び）を、要素の並び（`circuits`。フォルダのパスと回路のデータの組の並び）にした。
- フォルダ（`folders` と要素の `path`）を足した。
- メイン回路を先頭に置く決まりをやめた。
- プロジェクトの `author` をやめた（回路が持つ）。
- 同じフォルダの中で、回路の名前が重なるデータを断るようにした。

一体の形式のデータは、読み込むときに、今までの変換（version 1 → 2 → 3 → 4）で version 4 にしてから、プロジェクトの形式 version 1 に変える（`file/upgrade/project/v1.ts` の `upgradeToProjectV1`）。

- 回路の並びを、同じ並びのまま要素の並びにする。どの要素も `path` は `""`（フォルダなし）。`folders` は空。メイン回路は先頭になる。
- メイン回路以外で名前が空（空白だけを含む）の回路に、「回路<n>」の名前を付ける。n は、ほかの回路の名前と重ならないいちばん小さい数（1 から）。
- そのあと、同じ名前の回路が並びの中にあれば、2 つめ以降の名前の後ろに ` (2)`、` (3)` などを付ける（付けた名前がほかと重なるなら、次の数にする）。
- 回路 1 つずつを、回路の形式 version 1 に変える（[回路の形式](../circuit/v1.md)の「一体の形式 version 4 からの変更」）。プロジェクトの `author` は、すべての回路（メイン回路を含む）の `author` に写す。部品の `moduleName` には、上で整えた後の名前を写す。
- プロジェクトの `author` は消す。

## 保存データに含めないもの

次の値も localStorage に置くが、利用者ごとの表示の設定なので、この形式には含めない。版も持たず、読めなければ既定値で動く。

- `sazanka.views`: 回路ごとの、シートの表示位置と倍率。回路の `id` で引く。
- `sazanka.paletteCollapsed`: パレットで折り畳んでいるグループ。
- `sazanka.preferences`: 環境設定の値（1 秒に進める tick 数、方眼の表示、配線の角を丸めるか、アクセントカラー、表示言語）。
