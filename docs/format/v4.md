# データ形式 version 4

sazanka が保存・共有する回路データの形式（version 4）の仕様。version 3 からの違いは [version 3 からの変更](#version-3-からの変更)にある。

version 4 は公開した（2026-10-13）。今ある項目や値は変えない。部品の種類や、省略できる項目を足すのはよい（版は上げない。[保存データ](../../agent/docs/persistence.md)の「形式を変えるとき」）。(開発者からの指示)

対象は次の2つ。どちらも、中身のプロジェクトの形（[プロジェクト](#プロジェクト)以降）は共通で、外側の包み方だけが違う。

- **保存データ**: ブラウザの localStorage に自動で保存するデータ。
- **共有用 JSON**: 画面上部の「書き出し」で作り、「読み込み」で読む文字列。ファイル（UTF-8）に保存して受け渡すこともできる。中身は同じ。

版の番号は2つで別々に持っている（保存データは `file/storage.ts` の `STORAGE_VERSION`、共有用 JSON は `file/share.ts` の `SHARE_VERSION`）。今はどちらも 4。

## 外側の包み方

### 保存データ

localStorage のキー `sazanka.project` に、次の JSON を文字列にして置く。

```json
{
  "version": 4,
  "project": { ... }
}
```

| 項目      | 型           | 内容                          |
| --------- | ------------ | ----------------------------- |
| `version` | 数値         | 形式の版。`4`                 |
| `project` | オブジェクト | [プロジェクト](#プロジェクト) |

### 共有用 JSON

```json
{
  "app": "sazanka",
  "version": 4,
  "project": { ... }
}
```

| 項目      | 型           | 内容                                               |
| --------- | ------------ | -------------------------------------------------- |
| `app`     | 文字列       | sazanka のデータであることの目印。常に `"sazanka"` |
| `version` | 数値         | 形式の版。`4`                                      |
| `project` | オブジェクト | [プロジェクト](#プロジェクト)                      |

## プロジェクト

メイン回路と、部品として使う回路（モジュール）をまとめたもの。

| 項目       | 型     | 必須 | 内容                                         |
| ---------- | ------ | ---- | -------------------------------------------- |
| `circuits` | 配列   | ○    | [回路](#回路)の一覧。先頭はメイン回路        |
| `author`   | 文字列 |      | 作者名。書き出すときに入力された場合だけ付く |

- 先頭の回路の `id` は `"main"`（メイン回路）でなければならない。2つ目以降はモジュール。
- 回路の `id` は、プロジェクトの中で重ならない（[ID の付け方](#id-の付け方)）。要素（部品と配線）は `id` を持たない。

## 座標

部品の位置と配線の点は、マス単位の整数で書く。シートの左上が原点で、`x` は右へ、`y` は下へ増える。

- アプリは 1 マスを 20px で描くが、データには px を書かない。
- シートの大きさ（回路の `sheet`）も同じマス単位。

## 回路

| 項目       | 型           | 必須               | 内容                                                                        |
| ---------- | ------------ | ------------------ | --------------------------------------------------------------------------- |
| `id`       | 文字列       | ○                  | 回路の ID。メイン回路は `"main"`。モジュールの参照（部品の `module`）に使う |
| `name`     | 文字列       | モジュールのとき ○ | 回路の名前。タブとパレットに表示する。メイン回路は持たない                  |
| `package`  | オブジェクト | モジュールのとき ○ | [パッケージ](#パッケージ)。メイン回路は持たない                             |
| `sheet`    | オブジェクト |                    | [シートの大きさ](#シートの大きさ)。メイン回路もモジュールも持つ             |
| `elements` | 配列         | ○                  | [要素](#要素)（部品と配線）の一覧                                           |

- メイン回路の名前は、アプリが表示言語に合わせて出す（「メイン」/「Main」）。改名はできない。

### パッケージ

モジュールの形。本体の大きさと、外側のピンを置ける辺と位置が決まる。どのピンにどのポートをつなぐか（割り当て）は、パッケージではなく、中の `input` / `output` の `pinNumber` で決まる。

| 項目   | 型     | 内容                                           |
| ------ | ------ | ---------------------------------------------- |
| `kind` | 文字列 | 形の種類。`"dip"`、`"qfp"`、`"split"` のどれか |
| `pins` | 整数   | ピンの数。`dip` と `qfp` のとき必須            |

| `kind`  | 形                                                         | `pins`                     |
| ------- | ---------------------------------------------------------- | -------------------------- |
| `dip`   | 左右の 2 辺にピンを置く                                    | 4 以上 256 以下の偶数      |
| `qfp`   | 4 辺にピンを置く                                           | 8 以上 256 以下の 4 の倍数 |
| `split` | 入力は左、出力は右に置く（version 2 までのモジュールの形） | なし                       |

- 省略はできない。既定値で補うと、既定値を変えたときに、古いデータのモジュールのピンの位置が変わって配線が外れるため。

### シートの大きさ

回路を描くシートの大きさ。単位はマス。左上が原点で、右と下へ広がる。

| 項目     | 型   | 内容                            |
| -------- | ---- | ------------------------------- |
| `width`  | 整数 | 横のマスの数。20 以上 1000 以下 |
| `height` | 整数 | 縦のマスの数。20 以上 1000 以下 |

- アプリは、300×200 のときも必ず書く。
- 省略したときは、横 300 マス・縦 200 マスとして扱う。この値は変えない（変えると、古いデータの回路の大きさが変わる）。

## 要素

回路に置いたもの。部品と配線を、1 つの一覧（回路の `elements`）に並べる。

- どの要素も `kind`（種類）を持ち、種類で何の要素かが決まる。`kind` が `"wire"` なら[配線](#配線)、[部品の種類とピン](#部品の種類とピン)の表にある種類なら[部品](#部品)。
- 種類の名前は、部品と配線で 1 つの名前の空間を分け合う（`wire` という名前の部品の種類は作らない）。
- 要素がほかに持つ項目は、種類で決まる。
- 一覧の並び順に意味はない。アプリは、種類ごとに次の順に書く（同じ種類の中は、アプリの中の順）: `input`、`output`、`clock`、`high`、`and`、`or`、`not`、`nand`、`nor`、`xor`、`xnor`、`rsLatch`、`rsEnLatch`、`dLatch`、`dFlipFlop`、`tFlipFlop`、`jkFlipFlop`、`sevenSegment`、`module`、`wire`。
- 部品か配線かという分け方は、一覧の分け方ではなく、種類の性質として持つ。種類を足すとき（バスやネットラベルなど）に、どちらの一覧に入れるかで迷わないため。
- 要素は `id` を持たない（[ID の付け方](#id-の付け方)）。

### 部品

| 項目         | 型     | 必須              | 内容                                                                                                        |
| ------------ | ------ | ----------------- | ----------------------------------------------------------------------------------------------------------- |
| `kind`       | 文字列 | ○                 | 部品の種類（[部品の種類とピン](#部品の種類とピン)）                                                         |
| `x`          | 整数   | ○                 | 本体の左上の横位置（マス）                                                                                  |
| `y`          | 整数   | ○                 | 本体の左上の縦位置（マス）                                                                                  |
| `portName`   | 文字列 |                   | `input` / `output` のポート名。モジュールの中では、外から見たピンの名前になる                               |
| `module`     | 文字列 | `module` のとき ○ | 部品として置いた回路の `id`                                                                                 |
| `period`     | 整数   |                   | `clock` の周期（ON/OFF を一往復する tick 数、2〜10000）。なければ 100                                       |
| `pinNumber`  | 整数   |                   | モジュールの中の `input` / `output` の、外側のピン番号（1 から）。パッケージが `dip` / `qfp` のときだけ使う |
| `portNumber` | 整数   |                   | `input` / `output` を見分ける番号（ポート番号。1 から）。入力と出力で別々に振る。メイン回路でも持つ         |

- アプリで置いた部品は、本体とピンがシート（回路の `sheet`）の範囲に収まる。
  - ただし、シートの大きさを決める前に作った回路には、範囲の外にある部品もありうる。読み込むときは範囲を確かめない。

### 配線

縦と横の線分をつないだ線。部品とは別に存在し、部品を指さない。部品も配線を指さない。何とつながっているかは、位置で決まる（[つながりの決め方](#つながりの決め方)）。

| 項目     | 型     | 内容                                                                                                  |
| -------- | ------ | ----------------------------------------------------------------------------------------------------- |
| `kind`   | 文字列 | 配線の種類。今は `"wire"`（普通の配線）だけ                                                           |
| `points` | 配列   | 線が通る点の並び（2 つ以上）。`{ "x": 整数, "y": 整数 }` で、始点から順に並べる。始点と終点が配線の端 |

- 隣り合う 2 点は、`x` か `y` が同じ（どの区間も縦か横）。
- 種類（`kind`）は、あとで足すことがある。足すときは、部品の種類と同じく版を上げない。知らない種類の配線を含むデータは、読み込むときに断る（[読み込むときの検証](#読み込むときの検証)）。
- アプリで引いた配線は、点がシートの範囲（端を含む）に収まる。同じ点が続くことや、まっすぐ進む途中の点はない。

#### つながりの決め方

`kind` が `"wire"` の配線の決まり。

- 配線の端が、次の場所にあれば、そことつながる。
  - 部品のピンの先（[ピンの先の位置](#ピンの先の位置)）。
  - ほかの配線の上（端、折れる点、途中のどこでも）。途中にあるときは、そこから分岐している。
- 配線の途中どうしが交わるだけ（どちらの端でもない点で交わる）なら、つながらない。
- 配線の途中がピンの先を通るだけなら、そのピンにはつながらない。
- つながった配線とピンのまとまりを「ネット」と呼ぶ。ネットの中の入力ピンは、ネットの中の出力ピンの値になる。
  - 出力ピンがないネットの入力ピンは OFF。
  - 出力ピンが 2 つ以上あるネットはエラー。入力ピンは OFF として扱う。

#### ピンの先の位置

部品の左上を (`x`, `y`) として、ピンの先の位置は次のとおり。単位はマス。

| 部品                                       | 本体の大きさ（幅×高さ）               | 入力ピンの先                                                                                                     | 出力ピンの先                                 |
| ------------------------------------------ | ------------------------------------- | ---------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `input`、`clock`、`high`、`output`         | 2×2                                   | (`x` - 1, `y` + 1)                                                                                               | (`x` + 3, `y` + 1)                           |
| 論理ゲート（`and` など）、`not`            | 3×4                                   | 2 入力: (`x` - 1, `y` + 1) と (`x` - 1, `y` + 3)。1 入力: (`x` - 1, `y` + 2)                                     | (`x` + 4, `y` + 2)                           |
| ラッチ・フリップフロップ（`rsLatch` など） | 3×4                                   | (`x` - 1, `y` + 番号 + 1)                                                                                        | Q: (`x` + 4, `y` + 1)、Q̄: (`x` + 4, `y` + 3) |
| `module`（パッケージが `split`）           | 幅 4、高さ 多い方のピンの数 + 1       | (`x` - 1, `y` + 番号 + 1)                                                                                        | (`x` + 5, `y` + 番号 + 1)                    |
| `module`（パッケージが `dip`）             | 幅 3、高さ 2 × (`pins` / 2 - 1) + 2   | 下の「dip のピンの先」                                                                                           | 下の「dip のピンの先」                       |
| `module`（パッケージが `qfp`）             | 正方形。1 辺 2 × (`pins` / 4 - 1) + 4 | 下の「qfp のピンの先」                                                                                           | 下の「qfp のピンの先」                       |
| `sevenSegment`                             | 5×8                                   | 番号 0〜3（a〜d）: (`x` + 番号 + 1, `y` - 1)。番号 4〜7（e、f、g、DP）: (`x` + 番号 - 3, `y` + 9)                | なし                                         |

- モジュールのピンが減ったときは、減ったピンの位置につながっていた配線は、どこにもつながらない線として残る。

##### dip のピンの先

外側のピン番号を n、ピン数を N（`pins`）とする。番号は実際の IC と同じく、左上の 1 番から反時計回りに振る。

- n ≤ N / 2（左の辺を上から下へ）: (`x` - 1, `y` + 1 + 2 × (n - 1))
- n > N / 2（右の辺を下から上へ）: (`x` + 4, `y` + 1 + 2 × (N - n))
- 例: 8 ピンなら、1 番は (`x` - 1, `y` + 1)、4 番は (`x` - 1, `y` + 7)、5 番は (`x` + 4, `y` + 7)、8 番は (`x` + 4, `y` + 1)。
- どのポートにも割り当てていない番号（NC）のピンは、配線とつながらない。

##### qfp のピンの先

外側のピン番号を n、ピン数を N、1 辺の本数を Q = N / 4、1 辺の長さを S = 2 × (Q - 1) + 4 とする。k は、その辺の中で番号の順に数えて何本めか（0 から。k = (n - 1) を Q で割った余り）。番号は左上の 1 番から反時計回りに振り、どの辺も角から 2 マスあけて 2 マスおきに並べる。

- n ≤ Q（左の辺を上から下へ）: (`x` - 1, `y` + 2 + 2 × k)
- Q < n ≤ 2Q（下の辺を左から右へ）: (`x` + 2 + 2 × k, `y` + S + 1)
- 2Q < n ≤ 3Q（右の辺を下から上へ）: (`x` + S + 1, `y` + S - 2 - 2 × k)
- 3Q < n（上の辺を右から左へ）: (`x` + S - 2 - 2 × k, `y` - 1)
- 例: 8 ピン（S = 6）なら、1 番は (`x` - 1, `y` + 2)、3 番は (`x` + 2, `y` + 7)、6 番は (`x` + 7, `y` + 2)、8 番は (`x` + 2, `y` - 1)。
- NC のピンは、dip と同じく配線とつながらない。

## 部品の種類とピン

ピン番号は、下の表の並び順（0 から）。

| `kind`         | 表示名      | 入力ピン                | 出力ピン                             |
| -------------- | ----------- | ----------------------- | ------------------------------------ |
| `input`        | INPUT       | なし                    | 1本                                  |
| `clock`        | CLOCK       | なし                    | 1本                                  |
| `high`         | HIGH        | なし                    | 1本（常に ON）                       |
| `output`       | OUTPUT      | 1本                     | なし                                 |
| `and`          | AND         | 2本                     | 1本                                  |
| `or`           | OR          | 2本                     | 1本                                  |
| `not`          | NOT         | 1本                     | 1本                                  |
| `nand`         | NAND        | 2本                     | 1本                                  |
| `nor`          | NOR         | 2本                     | 1本                                  |
| `xor`          | XOR         | 2本                     | 1本                                  |
| `xnor`         | XNOR        | 2本                     | 1本                                  |
| `rsLatch`      | RS Latch    | S, R                    | Q, Q̄                                 |
| `rsEnLatch`    | RS-EN Latch | S, EN, R                | Q, Q̄                                 |
| `dLatch`       | D Latch     | D, EN                   | Q, Q̄                                 |
| `dFlipFlop`    | D-FF        | D, CLK                  | Q, Q̄                                 |
| `tFlipFlop`    | T-FF        | T, CLK                  | Q, Q̄                                 |
| `jkFlipFlop`   | JK-FF       | J, CLK, K               | Q, Q̄                                 |
| `sevenSegment` | 7セグ       | a, b, c, d, e, f, g, DP | なし（入力が ON のセグメントが光る） |
| `module`       | モジュール  | 中身の回路で決まる      | 中身の回路で決まる                   |

### モジュールのピン

`module` の部品のピンは、`module` が指す回路の中の `input` と `output` で決まる。

- パッケージが `split` のとき:
  - 入力ピンは中の `input`、出力ピンは中の `output` を、座標の順（上から、同じ高さなら左から）に並べたもの。
  - 中の `input` / `output` を動かすと並び順が変わり、外側の配線が別のピンにつながる。
- パッケージが `dip` / `qfp` のとき:
  - 外側のピンは、中の `input` / `output` の `pinNumber` で決まる。入力か出力かは問わず、1 から `pins` までの通し番号。
  - 外側のピンに出すのは、`pinNumber` が 1〜`pins` の整数で、ほかのポートと重ならないものだけ。番号がない・範囲の外・重なるポートは、どれも出さない（重なりは、どちらも出さない）。
  - どのポートにも割り当てていない番号は NC（何にもつながらない）。
  - 中の `input` / `output` を動かしても、ピンは変わらない。
- ピンの名前は、それぞれの `portName`（なければ名前なし）。

## 読み込むときの検証

保存データも共有用 JSON も、読み込むときに次を確かめる。1つでも満たさなければ、読み込まずに断る。

- `version` が数値で、今の版以下であること（新しい版のデータは断る）。
- 共有用 JSON は、`app` が `"sazanka"` であること。
- プロジェクト:
  - `circuits` が配列で、先頭の回路の `id` が `"main"` であること。
  - `author` があるなら文字列であること。
  - 回路の `id` が重ならないこと。
- 回路:
  - `id` が文字列で、`elements` が配列であること。
  - モジュールの回路は、`name` が文字列であること。
  - モジュールの回路は、`package` が[パッケージ](#パッケージ)の表のどれかの形であること。
  - `sheet` があるなら、`width` と `height` が 20 以上 1000 以下の整数であること。
- 要素:
  - `kind` が `"wire"` なら配線、それ以外は部品として、下を確かめる。知らない種類の要素は、部品の種類にないので断る。
- 部品:
  - `kind` が[部品の種類とピン](#部品の種類とピン)の表のどれかであること。
  - `x` と `y` が整数であること。
  - `module` の部品の `module` が、プロジェクトの中にある回路の `id` であること。
  - `period` があるなら、2〜10000 の整数であること。
  - `pinNumber` があるなら、整数であること。
  - `portNumber` があるなら、1 以上の整数であること。
- 配線:
  - `points` が、`x` と `y` が整数のオブジェクトの配列で、2 つ以上あり、隣り合う 2 点の `x` か `y` が同じであること。

確かめていないこと:

- メイン回路の `name`。あっても読み込むときに捨てる。
- 部品と配線の `id`。あっても読み込むときに捨てる。
- メイン回路の `package`。あっても意味は持たない。
- `portName` の型。
- `pinNumber` が `pins` の範囲にあるか、ほかと重なっていないか。範囲外や重なりがあっても断らない。
- `portNumber` があるか、ほかと重なっていないか。断らずに、読み込むときに付け直す（ないものと、中の位置の順で後ろの重なるものに、空いているいちばん小さい番号を付ける）。
- `portName` が、ほかのポートと重なっていないか。アプリでは重なる名前を付けられないが、読み込みでは断らず、名前も変えない。
- 配線の点がシートの範囲に乗っているか。
- モジュールが循環して参照していないか。アプリでは循環を作れないが、手で書き換えたデータで循環していた場合は、計算するときにその参照を無視する。
- 表に書いていない項目。あっても断らないが、意味は持たない。

## ID の付け方

- ID を持つのは回路だけ。モジュールの参照（部品の `module`）に使う。
- 回路の `id` は、プロジェクトをまたいでも重ならない文字列にする。形は決めない（アプリは UUID version 4 の形で作る）。
  - モジュールを別のプロジェクトへ持ち込んでも、ID を付け直さずに済ませるため。
- メイン回路の `id` は、どのプロジェクトでも `"main"`。メイン回路は別のプロジェクトへ持ち込まないので、ぶつからない。モジュールの回路は `"main"` を使えない。
- 回路の ID は、モジュールを足したときに一度だけ付ける。保存、書き出し、読み込みでは付け直さない。
- 部品と配線は ID を持たない。どこからも参照されないため。アプリは、読み込むたびに部品と配線に ID を付けて、選択や編集に使う。

## version 3 からの変更

- 部品の位置と配線の点を、px からマス単位の整数に変えた。
- 回路の `id` を、プロジェクトをまたいでも重ならないものにした。
- 回路の部品の一覧 `parts` と配線の一覧 `wires` を、1 つの一覧 `elements` にまとめた（[要素](#要素)）。
- 部品と配線の `id` をやめた。共有用 JSON の書き出しで部品と配線の ID を `part-1`、`wire-1` に付け直すこともなくなった。
- 配線に種類（`kind`）を足した。
- `input` / `output` のポート名の項目名を `label` から `portName` に変えた。
- メイン回路は `name` を持たなくなった。
- version 3 のデータは、読み込むときに version 4 に変える（`file/upgradeV3.ts`）。
  - 部品の位置と配線の点を 20 で割り、いちばん近い整数に丸める（ちょうど中間なら大きい方）。部品と配線を同じ規則で丸めるので、縦横の向きと、ピンの先とのつながりは保てる。
  - メイン回路以外の回路に、新しい `id` を付ける。部品の `module` も、新しい回路の `id` に書き換える。
  - 部品と配線の `id` を消す。配線には `"kind": "wire"` を書き込む。
  - `parts` と `wires` を `elements` にまとめる（並び順はそのまま。部品、配線の順）。
  - 部品の `label` を `portName` に移す。
  - メイン回路の `name` を消す。
- version 2 と 1 のデータは、version 3 に変えてから、続けて version 4 に変える。
- version 3 の仕様は [archive/v3.md](archive/v3.md) にある。

## 保存データに含めないもの

次の値も localStorage に置くが、利用者ごとの表示の設定なので、この形式には含めない。版も持たず、読めなければ既定値で動く。

- `sazanka.views`: 回路ごとの、シートの表示位置と倍率。回路の `id` で引く。
- `sazanka.paletteCollapsed`: パレットで折り畳んでいるグループ。
- `sazanka.preferences`: 環境設定の値（1 秒に進める tick 数、方眼の表示、配線の角を丸めるか、アクセントカラー、表示言語）。
