# シートの大きさの変更（計画）

状態: **進行中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../agent/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../agent/documentation.md)の「計画の文書」）。

## 目的

メイン回路とモジュールのシートの大きさを、回路ごとに変えられるようにする。

## 前提

- シートの大きさは定数で、すべての回路で横 300 マス・縦 200 マス（`geometry/layout.ts` の `SHEET_WIDTH` / `SHEET_HEIGHT`）。
- 定数を使っている所:
  - 位置の補正: `clampPosition`、`clampMove`、`dragWireEnd`（`geometry/layout.ts`）、`wireGridPoint`（`sheet/Sheet.tsx`）。
  - 開いたときの表示: `centerView`、`hideOutside`、`fitView`（`geometry/view.ts`）。
  - シートの外の描画: `Sheet.tsx` の `sheetStart` / `sheetEnd`。
- 回路のデータ（`CircuitDef`）には、大きさを持つ項目がない。
- version 3 には、省略できる項目を足してよい（版は上げない。[version 3](../../format/v3.md)）。
- シートより外にある部品（大きさを決める前に作った回路など）が残っていることがある（[シートの表示](../../agent/view.md)）。

## 決めたこと

開発者が決めたこと:

- 保存形式: 回路のオブジェクト（`circuits` の各要素）に `sheet: { width, height }` を足す。メイン回路もモジュールも持つ。版は上げない。
  - 300×200 のときも書く。新しく作る回路にも書く。
  - 読み込んだデータに `sheet` がないときは、300×200 として扱う。この値は形式の文書に書いて固定する（アプリの既定値を変えても、古いデータの大きさは変わらない）。
  - 採らなかった案: `name` などと並べて `width` / `height` を足す（モジュールの回路では、置いたときの部品の幅と取り違えやすい。シートの項目を足したときに平たく混ざる）。`sheetWidth` / `sheetHeight`（平たく書けるが、シートの項目が増えると長い名前が並ぶ）。`project` の直下に回路 ID ごとの表を持つ（回路の削除や読み込みで 2 か所をそろえる必要が出る）。
- 大きさの範囲: 1 辺 20〜1000 マスの整数（とりあえずの値）。
- 縮めて部品や配線が収まらなくなる大きさは、適用できなくする。ダイアログにエラーを出し、収まる範囲が「a × b マス以上」であることが伝わるようにする。
- 収まるかを調べる範囲: 部品（本体、ピンの先、上の名前。`partBounds`）と、配線（の点）。
- すでにシートの外にある部品や配線があるときも、一律に「すべて収まること」を求める。
  - 採らなかった案: 広げるときだけ通す（決まりが複雑になる）。
- 画面: シートのツールバーに「シート設定」のボタンを置き、共通のダイアログ「シート設定」で幅と高さ（マス）を編集する。メイン回路でもモジュールでも出す。
  - 英語: Sheet settings。
  - 採らなかった案: モジュール設定に足す（メイン回路では別の入口が要る。モジュール設定は本文の高さを決めてプレビューを並べた作りで、これ以上複雑にしたくない）。「回路の設定」に統合する（モジュール設定を作り直すことになる）。
- ファイル: `sheet/SheetSettingsDialog.tsx`。
- 向き: 左上（回路の座標の原点）を固定し、右と下で増やしたり減らしたりする。中身をずらす機能は作らない。

- 単位: マス。グリッドに必ず乗るため。
  - 採らなかった案: px（20 の倍数かどうかの検証が要る）。
- エラーの文言: 「部品と配線が収まるのは {w} × {h} マス以上です。」/ "Parts and wires need at least {w} × {h} cells."

エージェントが決めたこと:

- 型は `project.ts` の `CircuitSheet`（`{ width, height }`、マス）。`CircuitDef.sheet` は型では省略できる（テストで回路を手短に作れるように。`package` と同じ）。回路の大きさは `getCircuitSheet(def)` で引き、ないときは `DEFAULT_SHEET`（300×200）。
  - 採らなかった名前: `SheetSize`（`Sheet.tsx` に、画面の上のシートの要素の大きさ（px）を表す同じ名前の型がある）。
- 必ず書くために、読み込み（`readStored`、`parseProject`）と保存・書き出し（`saveProject`、`serializeProject`）で `withCircuitSheet` を通し、ない回路に 300×200 を入れる。新しく作る回路（空のプロジェクト、モジュールの追加）にも書く。JSON で `parts` より前に来るよう、`name` / `package` のあとに置く。
- 定数を使っていた関数（`clampPosition`、`clampMove`、`placeOffset`、`dragWireEnd`、`centerView`、`fitView`、`overview`）は、回路の大きさ（`CircuitSheet`）を引数で受け取る。px に直すのは各関数の中（`getSheetEnd`、× `GRID`）。`Sheet` は受け取っている `circuit` から引く（props は足さない）。
  - 採らなかった案: px の大きさを別の型にして渡す（型が 1 つ増える）。
- 部品と配線が収まる最小の大きさ（マス）は、`geometry/view.ts` の `circuitBounds` を使って求める（`minCircuitSheet`）。`circuitBounds` が同じ範囲（部品と配線の点）を求めているため。
- 適用は 1 回の `commit`（元に戻す 1 回で戻る）。
- 検証（`checkProject`）は、`sheet` があるときに範囲（1 辺 20〜1000 の整数）を確かめる。エラーの種類は `BAD_SHEET`。

## 段階

### 段階 1: 計算とデータ

- 型、検証、大きさを返す関数、定数を引数に置き換える変更、最小の大きさの計算とテスト。
- すべての回路が 300×200 のままなので、見た目は変わらない。
- 確かめること: 型チェック、テスト、ビルド。

### 段階 2: ダイアログ

- ボタン、ダイアログ、文言（日本語と英語）、適用、エラーの表示。
- 確かめること（ブラウザ）: 広げる・縮めることができ、シートの外の色が変わる。収まらない大きさではエラーが出て適用できない。元に戻すで戻る。再読み込みと書き出し・読み込みのあとも大きさが残る。狭い画面でも崩れない。
