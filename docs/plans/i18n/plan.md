# 表示言語の設定（計画）

状態: **進行中**（段階 2 を終えた。段階 3 の開始の合図を待っている）。

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../agent/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../agent/documentation.md)の「計画の文書」）。

## 目的

画面の文言を、日本語と英語で切り替えられるようにする。

## 前提

- 画面の文言は、日本語でコードに直接書いている（テスト以外の約 45 ファイル、約 300 行）。多いのは `hints/hints.ts`、`modules/ModuleSettingsDialog.tsx`、`simulation/SheetToolbar.tsx`、`app/Header.tsx`、`circuit/project.ts`（検証エラー）、`modules/useModules.ts`、`file/useProjectFile.ts`。
- 計算の側の `.ts` も文を返している（`checkProject`、`share.ts` と `storage.ts` のエラー、`hints.ts`、部品の種類の `view.ts` の `description` / `hints`）。これらは React を import できない（[コードの書き方](../../agent/coding-style.md)の「React を import できるファイル」）。
- メイン回路の名前は、保存データに `'メイン'` として入っている（`project.ts` の空のプロジェクト）。メイン回路は改名できない。
- 環境設定は `sazanka.preferences` に保存し、版はない。読めない項目は既定値にする（[保存データ](../../agent/persistence.md)の「利用者ごとの設定」）。
- `index.html` は `lang="ja"` で、`meta description` も日本語。

## 決めたこと

開発者が決めたこと:

- 言語は日本語と英語の 2 つ。
- ライブラリは使わず、自前で作る。
  - 採らなかった案: i18next + react-i18next（依存とバンドルが増えるわりに、2 言語では得るものが少ない）。Lingui（ビルドの手順が増える）。
- 初めは「自動」: ブラウザの言語（`navigator.languages`）が `ja` で始まれば日本語、それ以外は英語。
  - 採らなかった案: 日本語に固定（英語の利用者が、日本語の画面で設定を探すことになる）。
- 設定は環境設定のダイアログに置く。選択肢は「自動」「日本語」「English」。
  - 採らなかった案: ヘッダーにも置く（ヘッダーはプロジェクト全体の操作の場所）。
- 保存: `sazanka.preferences` に `language: 'auto' | 'ja' | 'en'` を足す。読めないときは `'auto'`。
- メイン回路の名前だけ、ID（`MAIN_ID`）を見て表示言語の名前で出す。保存してある名前は使わない。モジュールは、付けられた名前をそのまま出す。
- 新しいフォルダは `src/i18n/`。
  - 採らなかった名前: `locale/`、`lang/`。
- 部品の種類ごとの説明とヒントは、種類のフォルダの `view.ts` に両方の言語で書く（例: `description: { ja, en }`）。種類を足すときに、そのフォルダだけを触れば済むようにするため。
  - 採らなかった案: `i18n/` の表にまとめる（種類を足すたびに、フォルダの外も直すことになる）。
- 新しいモジュールの既定の名前（「モジュールを追加」の入力欄に初めから入る名前）は、追加するときの表示言語にする（`モジュール1` / `Module1`）。
- `index.html` の `meta description`（検索結果やリンクの共有で出る説明文）は英語にする。アプリが動く前に読まれ、表示言語では切り替えられないため、1 つに決める。英語にするのは、英語の README を主にしているのに合わせるため。
- 英語の文言はエージェントが書き、開発者が確かめる。用語は `glossary.md` に英語の列を足してそろえる。

エージェントが決めたこと:

- 計算の側は、文ではなくエラーの種類と値（例: `{ code: 'DUPLICATE_PART_ID', circuit, id }`）を返す。種類の名前は大文字のスネークケース（[コードの書き方](../../agent/coding-style.md)の「名前」）。保存データのエラーも、ほかと同じ `{ code }` の形にした。画面の側で、表示言語の文にする。計算の側を言語から切り離し、テストが言語の状態に左右されないようにするため。
  - 採らなかった案: 言語をモジュールの変数に置き、計算の側から直接引く（テストが言語の状態に左右される。切り替えたときの描き直しも漏れやすい）。
- `hints.ts` の `statusHints` は、言語（`Language`）を引数で受け取り、表を自分で引く。部品の種類のヒントも言語で選ぶため、表だけでは足りない（計画の初めは表を受け取る案だった）。
- 画面の側は、React の Context で言語を渡し、`useMessages()` で表を、`useLanguage()` で言語を引く（`i18n/useMessages.ts`）。Context の既定値は `'ja'`。
- 言語は `App.tsx` が環境設定とブラウザの言語から決め（`resolveLanguage`）、画面全体を `LanguageContext.Provider` で包んで渡す。
  - `App` 自身と、`App` で呼ぶフック（`useModules`、`useProjectFile`、`useClipboard`）は Provider の外なので、Context では受け取れない。`App` は表を直接引き（`getMessages`）、フックには引数 `m` で渡す。
  - 採らなかった案: 言語の Provider を `main.tsx` に置く（言語は環境設定の状態から決まり、環境設定は `App` が持っているため）。
- 言語の型（`Language`）は、段階 1 では `'ja'` だけ。段階 2 で `'en'` を足すと、言語ごとに書き分けた値（`Localized`）の英語の抜けが、すべて型エラーとして出る。
- 表の形（`Messages`）は、日本語の表（`ja.ts`）の型から作る。
- 表示名（`label`、`bodyLabel`）は `LocalText`（文字列 1 つか、言語ごとの値）。AND などは言語で変わらないので文字列のまま。7 セグだけ言語ごとにした。説明とヒントは `Localized` で、必ず言語ごとに書く。
- アクセントカラーの色の名前（`ACCENT_PRESETS` の `label`）も `Localized` にした。色の定義と一緒に直すため。
- パレットの `GROUPS` は ID の並びだけにし、見出しは表の `palette.groups` から引く。モジュール設定の `PACKAGE_KINDS` も同じ。
- エラーの文は、表の `errors` に種類（`code`）ごとに置く（文字列か、そのエラーを受け取って文を返す関数。型は `messages.ts` の `ErrorTexts`）。種類から文を引く処理は、言語によらないので `messages.ts` の `describeShareError` などに置く。表の中に `switch` を書かずに済み、ほかの言語の表も文言を書くだけで済むため（開発者の提案）。
  - 採らなかった案: 言語ごとの表の外に、`switch` で文を選ぶ関数を言語ごとに書く（段階 1 の初めはこの形だった）。
- 開発者向けの内部エラー（`throw new Error(...)` の文。`mustGet` など）は訳さない。利用者には出ないため。
- 言語を切り替えたときは、Context の値が変わるので、文言を引く部品は `React.memo` で包んでいても描き直される。`App` で作って props で渡す文言（ステータスバーのヒント、パレットの置けない理由）は、`App` が描き直されて作り直す（パレットの一覧の `useMemo` は依存に `m` を入れた）。
  - 計画の初めは「画面全体を描き直す（作り直す）」としていたが、作り直すと入力中の値やシートの状態が消えるのでやめた。切り替えで表示が古いまま残るところがないことは、ブラウザで確かめた。
- 「自動」は、ブラウザでいちばん優先している言語（`navigator.languages` の先頭）が `ja` か `ja-` で始まれば日本語、それ以外は英語。2 番目以降に日本語があっても見ない。
- 言語の欄は、環境設定のダイアログのいちばん上に置き、欄の名前を「言語 / Language」（英語では「Language / 言語」）にした。今の言語が読めない人も見つけられるように。
- メイン回路の名前は `i18n/messages.ts` の `getCircuitName` で出す（タブ、モジュールを削除できないときの「使っている回路」の一覧）。保存データの名前（「メイン」）は書き換えない。
  - 表示言語のメイン回路の名前（英語なら `Main`）は、新しいモジュールの名前に使えないようにした。同じ名前のタブが並んで見分けられなくなるため。
- ステータスバーのヒントを出し続ける時間は、1 文字を読む時間（表の `hints.msPerChar`）を言語ごとに持つ。日本語は今までどおり 250ms、英語は 80ms。英語は文字数が日本語の 2〜3 倍になり、同じ値では 1 文が 30 秒近く出続けるため。
- 英語のヒントの区切りは「・」（全角の中黒）ではなく「·」にした。英語の表に日本語の文字が混ざっていないかは、テスト（`messages.test.ts`）で確かめる（欄の名前の「言語」と選択肢の「日本語」は除く）。
- 英語の「入力 1」「出力 2」は `In 1`、`Out 2`。シート上の INPUT / OUTPUT の上に出すので短くした。
- モジュール設定のパッケージの選択肢は、英語では欄に収まるよう短くした（`DIP (pins on 2 sides)`、`QFP (pins on 4 sides)`、`Logic (in → out)`）。
- `index.html` の `lang` の初めの値は、英語の説明文に合わせて `en` にした。アプリが動いたら表示言語に書き換える。

## 仕組みの案

- `i18n/` に置くもの: 文言の型、言語ごとの表（`ja.ts`、`en.ts`）、言語の決め方（`'auto'` から `ja` / `en` を決める）、画面に渡すフック。
- 依存の向きは `ui` → `i18n` → `util`。`ui/` の共通のダイアログの文言（「OK」など）も表から引くため。
- 表は、型で両方の言語の抜けを防ぐ（英語の表も日本語と同じ型を満たす）。値を差し込む文は関数にする（例: `` (name) => `「${name}」を削除しますか？` ``）。
- `index.html` の `lang` は、表示言語に合わせて書き換える。`meta description` は英語に書き換える（段階 2）。

## 段階

1. **済み**。文言を表に集める（振る舞いを変えない組み替え。Skill の `refactor`）。日本語の表だけを作り、画面に出る文言をすべて表から引く。区切り: `ui/` と `app/` → ヒント → 部品の `view.ts` → 検証エラー（エラーの種類を返す形）。
   - 確かめること: テストが通る。画面の文言が前と同じ。
   - 結果: 変更前の日本語の文字列 220 件が、すべて変更後のコードに残っていることを照合した。変更前と変更後を並べて起動し、31 の状態（部品の選択、各ダイアログ、エラー、ツールチップ）で画面の文言が一致した。フレームレートは変わらない（ビルドしたもの、CPU 4 倍遅く、CLOCK 15 個: どちらも 60 fps）。
   - 段階 2 で直すところ: 保存データの「メイン」はまだ保存した名前のまま出している。
2. **済み**。英語と言語の設定を足す（機能の追加。Skill の `modify`）。英語の表、環境設定の項目と保存、「自動」の決め方、`lang` の書き換え、メイン回路の名前の出し方。
   - 確かめること: ブラウザで両方の言語を通して見る。狭い画面で英語の長い文言があふれない。フレームレート。
   - 結果: ブラウザの言語が英語・日本語・フランス語のときに、それぞれ英語・日本語・英語で開く。環境設定で切り替えると、開いているダイアログ、ヘッダー、タブ、パレット、プロパティ欄、ステータスバー、`lang` がその場で変わり、再読み込みしても残る。幅 600px・400px・320px で横にはみ出さない（モジュール設定のパッケージの選択肢が切れていたので、英語を短くした）。フレームレートは段階 1 と同じ（どちらも 60 fps）。言語の連続切り替え、入力途中の切り替え、元に戻す（言語は戻らない）、知らない言語の値（自動として扱う）でも例外は出ない。
3. ドキュメントを直す: `workflow.md`（言語）、`glossary.md`（英語の列）、`structure.md`（`i18n/` と依存の向き）、`persistence.md`（環境設定の表）、`ui.md`（文言の足し方と確かめること）、`parts.md`（種類を足すときの英語の文言）。
