# 表示言語の設定（計画）

状態: **計画中**（決めることはすべて決まった。段階 1 の開始の合図を待っている）。

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../agent/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../agent/documentation.md)の「計画の文書」）。

## 目的

画面の文言を、日本語と英語で切り替えられるようにする。

## 前提

- 画面の文言は、日本語でコードに直接書いている（テスト以外の約 45 ファイル、約 300 行）。多いのは `hints/hints.ts`、`modules/ModuleSettingsDialog.tsx`、`simulation/SheetToolbar.tsx`、`app/Header.tsx`、`circuit/project.ts`（検証エラー）、`modules/useModules.ts`、`file/useProjectFile.ts`。
- 計算の側の `.ts` も文を返している（`checkProject`、`share.ts` と `storage.ts` のエラー、`hints.ts`、部品の種類の `view.ts` の `description` / `hints`）。これらは React を import できない（[コードの書き方](../../agent/coding-style.md)の「React を import できるファイル」）。
- メイン回路の名前は、保存データに `'メイン'` として入っている（`project.ts` の空のプロジェクト）。メイン回路は改名できない。
- 環境設定は `sazanka.preferences` に保存し、版はない。読めない項目は既定値にする（[保存データ](../../agent/persistence.md)の「利用者ごとの設定」）。
- `index.html` は `lang="ja"` で、`meta description` も日本語。

## 決めたこと

開発者が決めたこと:

- 言語は日本語と英語の 2 つ。
- ライブラリは使わず、自前で作る。
  - 採らなかった案: i18next + react-i18next（依存とバンドルが増えるわりに、2 言語では得るものが少ない）。Lingui（ビルドの手順が増える）。
- 初めは「自動」: ブラウザの言語（`navigator.languages`）が `ja` で始まれば日本語、それ以外は英語。
  - 採らなかった案: 日本語に固定（英語の利用者が、日本語の画面で設定を探すことになる）。
- 設定は環境設定のダイアログに置く。選択肢は「自動」「日本語」「English」。
  - 採らなかった案: ヘッダーにも置く（ヘッダーはプロジェクト全体の操作の場所）。
- 保存: `sazanka.preferences` に `language: 'auto' | 'ja' | 'en'` を足す。読めないときは `'auto'`。
- メイン回路の名前だけ、ID（`MAIN_ID`）を見て表示言語の名前で出す。保存してある名前は使わない。モジュールは、付けられた名前をそのまま出す。
- 新しいフォルダは `src/i18n/`。
  - 採らなかった名前: `locale/`、`lang/`。
- 部品の種類ごとの説明とヒントは、種類のフォルダの `view.ts` に両方の言語で書く（例: `description: { ja, en }`）。種類を足すときに、そのフォルダだけを触れば済むようにするため。
  - 採らなかった案: `i18n/` の表にまとめる（種類を足すたびに、フォルダの外も直すことになる）。
- 新しいモジュールの既定の名前（「モジュールを追加」の入力欄に初めから入る名前）は、追加するときの表示言語にする（`モジュール1` / `Module1`）。
- `index.html` の `meta description`（検索結果やリンクの共有で出る説明文）は英語にする。アプリが動く前に読まれ、表示言語では切り替えられないため、1 つに決める。英語にするのは、英語の README を主にしているのに合わせるため。
- 英語の文言はエージェントが書き、開発者が確かめる。用語は `glossary.md` に英語の列を足してそろえる。

エージェントが決めたこと:

- 計算の側は、文ではなくエラーの種類と値（例: `{ code: 'duplicatePartId', circuit, id }`）を返す。画面の側で、表示言語の文にする。計算の側を言語から切り離し、テストが言語の状態に左右されないようにするため。
  - 採らなかった案: 言語をモジュールの変数に置き、計算の側から直接引く（テストが言語の状態に左右される。切り替えたときの描き直しも漏れやすい）。
- `hints.ts` は、文言の表を引数で受け取る。
- 画面の側は、React の Context で文言の表を渡す（`i18n/useMessages.ts`）。
- 言語を切り替えたら、画面全体を描き直す。`React.memo` で止めている部品の描き直し漏れを防ぐため。切り替えはまれなので、重さは問題にならない。

## 仕組みの案

- `i18n/` に置くもの: 文言の型、言語ごとの表（`ja.ts`、`en.ts`）、言語の決め方（`'auto'` から `ja` / `en` を決める）、画面に渡すフック。
- 依存の向きは `ui` → `i18n` → `util`。`ui/` の共通のダイアログの文言（「OK」など）も表から引くため。
- 表は、型で両方の言語の抜けを防ぐ（英語の表も日本語と同じ型を満たす）。値を差し込む文は関数にする（例: `` (name) => `「${name}」を削除しますか？` ``）。
- `index.html` の `lang` は、表示言語に合わせて書き換える。`meta description` は英語に書き換える（段階 2）。

## 段階

1. 文言を表に集める（振る舞いを変えない組み替え。Skill の `refactor`）。日本語の表だけを作り、画面に出る文言をすべて表から引く。区切り: `ui/` と `app/` → ヒント → 部品の `view.ts` → 検証エラー（エラーの種類を返す形）。
   - 確かめること: テストが通る。画面の文言が前と同じ。
2. 英語と言語の設定を足す（機能の追加。Skill の `modify`）。英語の表、環境設定の項目と保存、「自動」の決め方、`lang` の書き換え、メイン回路の名前の出し方。
   - 確かめること: ブラウザで両方の言語を通して見る。狭い画面で英語の長い文言があふれない。フレームレート。
3. ドキュメントを直す: `workflow.md`（言語）、`glossary.md`（英語の列）、`structure.md`（`i18n/` と依存の向き）、`persistence.md`（環境設定の表）、`ui.md`（文言の足し方と確かめること）、`parts.md`（種類を足すときの英語の文言）。
