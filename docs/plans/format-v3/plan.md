# 保存データの version 3（計画）

状態: **進行中**（段階 3 を終えた）。

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../agent/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../agent/documentation.md)の「計画の文書」）。

version 3 の形式は、公開するまで変えてよい。公開する時期は開発者が決める。

## 目的

- モジュールの外側のピン番号を、入力か出力かを問わず 1 から通しで振る。ピンを出す辺も番号から決める。実際の IC と同じ考え方にする。
- 128 ピン程度のモジュール（マイコンなど）も作れるようにする。左右だけでは足りないので、上下の辺にもピンを出す。
- モジュールごとにパッケージ（モジュールの形。形の種類とピン数）を持たせる。どのポート（モジュールの中の `input` / `output`）にも割り当てていない番号は NC にする。
- 保存データと共有用 JSON の版を 3 に上げる。古い版のデータの配線は書き換えず、つながりをそのまま保つ。
- あわせて、部品の種類の名前をキャメルケースにそろえる。回路の部品の一覧の項目名を `components` から `parts` に、モジュールを指す項目名を `custom` から `module` に変える。

## 背景

- 配線は部品を指さず、端の位置がピンの先と重なるかでつながる（[保存データ](../../agent/persistence.md)、`docs/format/v2.md`）。そのため、モジュールのピンの位置が変わると、古い版のデータの配線が黙って外れる。
- 配線の端を延ばして直す変換は採らない。入力ピンは同じ縦の線に並ぶので、延ばした線の端が隣のピンの配線に重なり、別々だった配線がつながってしまう。
- そこで、配置をモジュールごとにデータに持たせる。古い版のデータのモジュールには、version 2 までの形（`split`）を書き込み、形を変えない。

## 保存データ（version 3）

```json
{
  "version": 3,
  "project": {
    "circuits": [
      {
        "id": "main",
        "name": "メイン",
        "parts": [{ "id": "p1", "kind": "module", "module": "k3x9", "x": 2900, "y": 1900 }],
        "wires": []
      },
      {
        "id": "k3x9",
        "name": "半加算器",
        "package": { "kind": "dip", "pins": 8 },
        "parts": [
          { "id": "a", "kind": "input", "x": 2800, "y": 1900, "label": "A", "pinNumber": 1 },
          { "id": "s", "kind": "output", "x": 3000, "y": 1900, "label": "S", "pinNumber": 8 }
        ],
        "wires": []
      }
    ]
  }
}
```

### 部品の種類

- 項目名は `kind` のまま。`parts` の要素の `kind` なので、部品の種類だと置かれている場所から分かる。`package` の `kind`（形）も同じ考え方。
- 種類の名前は、次の表のとおりに変える。

| version 2                   | version 3    |
| --------------------------- | ------------ |
| `INPUT`                     | `input`      |
| `OUTPUT`                    | `output`     |
| `CLOCK`                     | `clock`      |
| `HIGH`                      | `high`       |
| `AND`                       | `and`        |
| `OR`                        | `or`         |
| `NOT`                       | `not`        |
| `NAND`                      | `nand`       |
| `NOR`                       | `nor`        |
| `XOR`                       | `xor`        |
| `XNOR`                      | `xnor`       |
| `RS`                        | `rsLatch`    |
| `RSEN`                      | `rsEnLatch`  |
| `DLATCH`                    | `dLatch`     |
| `DFF`                       | `dFlipFlop`  |
| `TFF`                       | `tFlipFlop`  |
| `JKFF`                      | `jkFlipFlop` |
| `CUSTOM`                    | `module`     |
| `BUF`（内部用。保存しない） | `buf`        |

- アプリの中の種類の名前も同じにする。保存データとアプリの中で名前を分けると、読み替える場所が増えるため。
- モジュールを指す項目名を `custom` から `module` に変える（アプリの中の `Component.custom` も）。`custom` は、モジュールの内部名が `CUSTOM` だったころの名残のため。`moduleId` にしないのは、モジュールを ID ではなくパスで指す案（[モジュールのファイル保存](../../design/module-files.md)）になっても名前がずれないようにするため。
- 回路の部品の一覧の項目名を `components` から `parts` に変える（アプリの中の `Circuit.components` も）。部品の型の名前（`Part`）とそろえるため。React のコンポーネント（画面の部品）と紛らわしくなくなる利点もある。
- 型と定数の名前も合わせて変える。

| 今                                       | version 3           | 理由                                                                |
| ---------------------------------------- | ------------------- | ------------------------------------------------------------------- |
| `Component`                              | `Part`              | `parts` とそろえる                                                  |
| `ComponentKind`                          | `PartKind`          | `Part.kind` とそろえる                                              |
| `PartKind`（仕様の一覧にある種類だけ）   | `SpecKind`          | 上の `PartKind` とぶつかるため。`SpecialKind`（特別な部品）と対になる |
| `PlaceableComponentKind`                 | `PlaceablePartKind` |                                                                     |
| `isComponent`                            | `isPart`            |                                                                     |
| `PARTS`（`parts/specs.ts`）              | `PART_SPECS`        | `circuit.parts` と紛らわしくならないよう。`PART_VIEWS` と並べる     |
| `specs.ts` の中の `Part` 型              | `ListedSpec`        | 新しい `Part` とぶつかるため                                        |
| `ComponentView`（シート上の部品を描く）  | `SheetPart`         | 種類の見せ方の型 `PartView` とぶつかるため                          |

- `parts/` フォルダは、部品の種類ごとの定義の置き場所として、名前を変えない。
- 種類のフォルダの名前も合わせる（例: `parts/dff/` → `parts/dFlipFlop/`）。
- 画面に出る名前（「AND」「D-FF」など）は見せ方（`view.ts` の `label`）が持つので、変わらない。

### `package`

モジュールの回路だけが持つ。メイン回路は持たない。

形の項目名も `kind`。`package` の中なので、形の種類だと分かる。

| `kind`  | 項目         | 意味                                                                 |
| ------- | ------------ | -------------------------------------------------------------------- |
| `dip`   | `pins`（数） | 2 辺に出す。`pins` は 4 以上の偶数                                   |
| `qfp`   | `pins`（数） | 4 辺に出す。`pins` は 8 以上の 4 の倍数                              |
| `split` | なし         | 入力は左、出力は右（version 2 までの形）。新しいモジュールでも選べる |

- `pins` の上限は 256。
- `dip` / `qfp` の名前は、実際の IC のパッケージの名前をそのまま使う（開発者と見直して決めた）。入れ物の名前 `package` と続けて読んで自然で、データシートの「DIP-8」「QFP-128」がそのまま当てはまるため。採らなかった案: `dual` / `quad`（辺の数だけを表す）、`twoSided` / `fourSided`（長い）、`inLine` / `quadFlat`（2 辺だと伝わりにくい）。
- NC のピンに名前（電源の表記など）を書けるようにするときは、`package` に省略できる項目として足す。版は上げない。

### `pinNumber`

- モジュールの中の `input` / `output` が持つ、外側のピン番号。1 から `pins` までの整数。
- `package` が `dip` / `qfp` のときだけ使う。`split` では使わない。
- 割り当てなし、範囲外、重なりがあっても、読み込みは断らない。画面で知らせる（下の「ピン番号の割り当て」）。

### 読み込むときの検証（`checkProject` に足すもの）

- モジュールの回路が `package` を持ち、`kind` が `dip` / `qfp` / `split` のどれかであること。
- `pins` が、`kind` に合った数で、上限以下であること。
- `pinNumber` があるなら、整数であること。

`package` は省略できない。既定値で補う形にすると、あとで既定値を変えたときに、今回と同じく古い版のデータの配線が外れるため。

## パッケージごとの形

長さはマス単位。

| `kind`  | 並べ方                                                                      | ピンの間隔 | 大きさ                           | モジュール名 |
| ------- | --------------------------------------------------------------------------- | ---------- | -------------------------------- | ------------ |
| `dip`   | 左を上から下へ 1〜N/2、右を下から上へ N/2+1〜N                              | 2          | 幅 3、高さ (N/2 - 1) × 2 + 2     | 本体の上     |
| `qfp`   | 左（上から下）→ 下（左から右）→ 右（下から上）→ 上（右から左）。各辺 N/4 本 | 2          | 正方形。1 辺 (N/4 - 1) × 2 + 2   | 本体の中     |
| `split` | 入力は左、出力は右。それぞれ中の位置の順（上から、同じ高さなら左から）      | 1          | 幅 4、高さはピンの多い方の数 + 1 | 本体の上     |

- N は `pins`。番号は左上の 1 番から反時計回りに振る（実際の IC と同じ）。
- `split` は今のモジュールの形そのもの。古い版のデータは、これでピンの位置が変わらない。
- 128 ピンの QFP は 1 辺 64 マスで、シート（300 × 200 マス）に収まる。
- 外側のピンの横に、ピン番号を出す。
- 配置は、部品の種類ごとの配置（`parts/module/layout.ts`）が `package` から作る。
- `package` とピン番号は、`portsOf` で配置まで届ける。
  - 今は、ピンの位置を求めるときに 2 段で動く。まず `portsOf(部品, プロジェクト)`（`circuit/module.ts`）がピンの一覧（名前の並び）を作る。次に `inputPinPos(部品, ピンの一覧, 番号)` などがそれを受け取り、中の `layoutOf` が配置を決める。
  - DIP / QFP の配置には、`package` とポートごとの `pinNumber` も要る。どちらもモジュールの中身の回路に書いてあり、読めるのはプロジェクトを受け取る `portsOf` だけ。
  - そこで、`portsOf` が作る一覧に `package` と外側のピン番号も入れる。`inputPinPos` などの呼び出し方は変わらない。
  - 一覧の中身がピンの名前だけではなくなるので、名前を変える: `Ports` → `Pinout`、`portsOf` → `pinoutOf`（IC のピンの割り当てを指す言葉）。
  - 採らなかった案: `inputPinPos` などにもプロジェクトを渡し、その中でモジュールの中身を読む。呼び出している 12 ファイルをすべて直すことになるため。

### 入力か出力かの見分け

`dip` / `qfp` では、辺から入力か出力かが分からないので、見た目で見分ける印を付ける。

- ピンの線に、向きを示す小さな三角を付ける。入力は本体へ向き、出力は外へ向く。
- 色は使わない。色の見分けにくい人にも分かるようにするため。ON / OFF の表示（線の色）や、出力のぶつかり（`conflict`）の赤ともぶつからない。
- 採らなかった案: ピンの先の丸の形を変える（入力は白抜き、出力は塗りつぶし）、ピンの先の色（入力は青、出力は赤）。
- `split` には付けない。入力は左、出力は右と辺で分かり、`split` は今のモジュールの形のままにするため。

### 上下の辺のピン名

`qfp` の上下の辺のピン名は、90 度回して、本体の内側に縦に書く（実際の IC の回路図の記号と同じ）。

- ピンの間隔は 2 マス（40px）なので、横書きでは長い名前が隣とぶつかるため。
- ピン番号は短いので、横書きのまま、ピンの先の近くに出す。
- 採らなかった案: 横書きのまま短くする（先頭 2〜3 文字）。上下のピン名は書かず、ポインターを載せたときだけ出す。

## ピン番号の割り当て

`dip` / `qfp` のモジュールの中での決まり。

- 自動の割り当て: 次のときに、空いているいちばん小さい番号を入れる。空きがなければ割り当てない。
  - モジュールの中に `input` / `output` を置いたとき。
  - 貼り付けたとき。番号がほかと重なっていたら付け直す。
- 割り当ては置く操作の一部にする。元に戻すも 1 回で済む。
- メイン回路に貼り付けた `input` / `output` からは、`pinNumber` を外す。
- 中で動かしても、番号は変わらない。
- 割り当てなし・範囲外・重なりのポートは、外側にピンとして出さない。重なりは、どちらも出さない（どちらを出すか決められないため）。中の部品に印を付け、ステータスバーで知らせる。
- ポートを消すと、その番号は NC になる。外の配線は消さずに、何にもつながらない線として残す。今の「モジュールのピンが減っても、配線は消さずに残す」決まり（[保存データ](../../agent/persistence.md)の「消さないもの」）と同じ扱い。
- ピン数を超えるポートを足しても、ピン数は自動で広げない。形が変わるのは、利用者がピン数を変えたときだけにする。
- NC: どのポートにも割り当てていない番号。線を引き、`NC` と書く。つながりは作らない（ネットにピンの先として加えない）。
- 電源ピン（VCC / GND）は今回は作らない。電源にしたい番号は NC のままにしておけば、実際の IC の配置を写せる。

## シミュレーションとの関係

- シミュレーションと展開は、今の「入力の何番目、出力の何番目」でつなぐ仕組み（`PinRef.pin`、`simulation/flatten.ts`）のまま使う。
- この「何番目」は、外側のピン番号とは別のもの。`dip` / `qfp` では、入力と出力の並びを、それぞれピン番号の順にする（NC と、外に出さないポートは除く）。
- 配線は位置でつながるので、この並びは保存しない。

## 読み込みの変換

古い版の変換を順に適用する形（1 → 2 → 3）にすることと、変換が今のアプリのコードに頼らないようにすることは、別の計画（[古い版の変換を順に適用する形にする](../upgrade-chain/plan.md)）で行う。その計画は、この計画の段階 2 より前に終える。

### `upgradeV2`（2 → 3、`file/upgradeV2.ts`）

- 回路の `components` を `parts` に、部品の `custom` を `module` に移し、種類の名前を上の表のとおりに読み替える。
- モジュールの回路（2 つ目以降）に `{ "kind": "split" }` を書き込む。
- 配線は書き換えない。
- `upgradeV2` は、変換を順に適用する入口の並びに加える。
- 保存データの `STORAGE_VERSION`（`file/storage.ts`）と、共有用 JSON の `SHARE_VERSION`（`file/share.ts`）を、どちらも 3 に上げる。

### 確かめ方

- 変換ごとにテストする（その版の入力と、次の版の出力）。
- 順に適用した結果もテストする。version 1 のデータ（モジュールの出力につないだ配線を含む）を読み込むと、version 3 の形になり、つながりが変わらないこと。

## 段階

各段階の区切りで止め、次の段階の合図を待つ。

### 準備（済み）

- 未コミットだった、モジュールの配置の変更（幅 3、2 マスおき）を戻した。段階 1 では、今の形を基準に見た目が変わらないことを確かめるため。この形は段階 3 の DIP に引き継ぐ。

### 段階 1: ピンの描き方を辺に合わせる

振る舞いを変えない組み替え（Skill の `refactor`）。

- `parts/layout.ts` の `PinSide` に `top` / `bottom` を足す。
- `geometry/layout.ts`: ピンの先の位置を求める処理（`pinTip`）を上下に対応させる。部品の占める範囲とはみ出し補正を、ピンの辺から決める形にする。
- `sheet/ComponentView.tsx`: ピンの線とピン名を、入力か出力かではなく辺で描き分ける。
- 確かめること:
  - テストが通ること。
  - シートの SVG が変更前と同じこと（全種類の部品とモジュールを置いた回路で比べる）。
  - はみ出し補正の結果が同じこと。
  - 描画の重さ（フレームレート）が変わらないこと。
- 実装で決めたこと（開発者に聞かずに決めたこと）:
  - ピンの座標は、根元（本体の辺の上）と先端をまとめた `SheetPin`（`side`、`base`、`tip`）で表す。1 本分を求めるのが `sheetPin`、部品のすべてのピンを求めるのが `sheetPinsOf`。描画では線を根元から先端まで引くので、先端だけを返す `pinTip` を広げた。`inputPinPos` / `outputPinPos` は先端だけを返す形のまま残した（配線とのつながりなど、呼び出している所が多いため）。
  - 部品の占める範囲は `outerMargin`（本体の外の幅）で求め、`componentBounds` と `clampPosition` の両方から使う。左右は、ピンがなくても 1 マス取る（INPUT の左など。今の範囲とはみ出し補正の結果を変えないため）。上下は、その辺にピンがあるときだけ取る。採らなかった案: 左右もピンのある辺だけ取る（INPUT や OUTPUT の範囲が変わり、組み替えではなくなる）。
  - ピンの線は、左か上の端から、右か下の端へ引く（左・上の辺は先端から根元へ、右・下の辺は根元から先端へ）。今の SVG（入力は先端から、出力は根元から）と同じ出力にするため。描き分けは `ComponentView.tsx` の `PinLead`、ピン名は `PinName`。
  - 上下の辺のピン名は、段階 4 まで描かない（`PinName` は何も返さない）。
- 結果:

### 段階 3: DIP とピン番号

振る舞いを変える変更（Skill の `modify`）。

- DIP の配置、ピン番号の自動の割り当て、NC、入力か出力かの印（向きを示す三角）、外側のピン番号の表示、割り当ての問題の知らせ（中の部品の印とステータスバー）。
- 新しいモジュールは DIP の 8 ピンで作る。
- 確かめること:
  - テスト: 配置（番号と位置）、割り当て（置く・貼り付けで付け直す・空きがない・重なり）、NC のピンの先に配線の端があってもつながらないこと、展開でピン番号の順に中の `input` / `output` とつながること。
  - ブラウザ: 見た目、配線のつながり、描画の重さ（フレームレート）。
- 実装で決めたこと（開発者に聞かずに決めたこと）:
  - 外側のピン番号は、`Pinout` に `pinNumbers`（`inputs` / `outputs` と同じ並びの番号の配列）として足した。dip / qfp のモジュールだけが持つ。採らなかった案: `inputs` / `outputs` をピンごとのオブジェクト（名前と番号）にする（ピン名を使うすべての場所を直すことになる）。
  - ピン番号の決まりは `circuit/module.ts` に置いた: `usesPinNumbers`（dip / qfp か）、`portProblems`（外側のピンに出せないポートと理由 `unassigned` / `outOfRange` / `duplicate`）、`assignPinNumbers`（置く・貼り付けでの割り当て）。`portParts` は、dip / qfp ではピン番号の順に並べ、外に出せないポートを除く。展開（`flatten.ts`）と配置は `portParts` / `pinoutOf` を通すので、そのまま dip に従う。
  - 配置の型に足したもの（どれも省略できる。既定の配置は書かなくてよい）: `PinPlacement.number`（ピンの横に書く番号）、`PartLayout.nc`（NC のピンの置き方）、`PartLayout.directionMarks`（向きの印を付けるか）。`geometry/layout.ts` の `sheetPinsOf` は、`nc` と `directionMarks` も返す。NC のピンも部品の占める範囲に含める。
  - 描き方（`SheetPart.tsx`）: 向きの三角はピンの線の中ほど（入力は本体へ、出力は外へ向く）。外側のピン番号は、線の上の中ほどに小さく書く。NC は線だけで先端の丸を描かず、本体の内側にピン名と同じ形で「NC」と書く。
  - `assignPinNumbers` は、前からあるポートの番号を直さない（重なっていても）。前からある範囲の中の番号は使用中とみなし、新しいポートには空いている番号を入れる。
  - `split` のモジュールに貼り付けた INPUT / OUTPUT からも、ピン番号を外す（計画ではメイン回路だけ）。`split` では番号を使わず、残すと、あとで dip に変えたときに古い番号が紛れ込むため。
  - モジュールの中の INPUT / OUTPUT の上の番号（`#n`）は、split では今までどおり入力・出力ごとの順、dip / qfp ではピン番号そのもの。
  - 外側のピンに出せないポートの印は、仮に「番号の代わりに赤い `#n?`（番号がなければ `#?`）」にした。
  - ステータスバー: 外側のピンに出せないポートがあるときは、右端にオレンジの `Badge` を出し、何も選んでいなければヒントでも知らせる。そのポートを選ぶと、ヒントの先頭に理由を出す。モジュールのヒントのうち「上下の並びを変えるとピンの順番も変わる」は split だけに出し、dip / qfp では「空いているいちばん小さいピン番号が付く」を出す。
  - テストの回路を作る `wired`（`simulation/testCircuits.ts`）に、モジュールのピンを中身の回路から決める引数を足した（dip のモジュールの展開のテストのため）。
- 開発者と決めたこと:
  - 外側のピンに出せないポートの印は、見本 B にする: 番号の代わりに赤い `#n?`（番号がなければ `#?`）を書き、本体の輪郭を赤い破線にする。選んでいる間は、選択の色の破線にする（選んだことが分かるように）。採らなかった見本: A（赤い `#n?` だけ。文字が小さく見落としやすい）、C（本体の右上に赤い丸の「!」。ほかの警告の印と取り違えやすい）。
  - 画面に出る文言は、ひとまず下の内容にする（開発者の指示）:
  - ステータスバーの `Badge`: 「ピンに出ていない INPUT / OUTPUT があります」
  - 何も選んでいないときのヒント: 「赤い #? の INPUT / OUTPUT は、ピン番号がないか、範囲の外か、ほかと同じ番号のため、外側のピンに出ていない」
  - 選んだときのヒント: 「この INPUT / OUTPUT はピン番号がないため、外側のピンに出ていない」（範囲外は「ピン番号がピン数の範囲の外にあるため」、重なりは「ほかと同じピン番号のため」）
  - dip / qfp のモジュールのヒント: 「INPUT / OUTPUT を置くと、空いているいちばん小さいピン番号が付く。動かしても番号は変わらない」
- 結果:
  - テスト: 252 件が通った。足したもの: dip の配置（番号と位置、NC、向きの印）、`portProblems` と `portParts` の並び、`assignPinNumbers`（置く・貼り付け・前からある重なり・空きがない・メイン回路と split）、NC のピンの先に配線の端があってもつながらないこと、展開でピン番号の順に中の INPUT / OUTPUT とつながること、ヒント。
  - ブラウザ:
    - DIP 8 ピンのモジュールを置くと、1〜8 番の番号、6 本の NC、入力と出力の向きの印が描かれ、1 番と 8 番を通して信号が伝わる。
    - モジュールの中に INPUT / OUTPUT を置くと 2 番、3 番と付き、元に戻す 1 回で番号ごと消える。同じ番号の INPUT を貼り付けると空いている番号に付け直す。メイン回路に貼り付けると番号を外す。新しいモジュールは dip の 8 ピン。
    - 番号の重なり・範囲外・番号なしのポートに赤い `#n?` が付き、ステータスバーとヒントで知らせる。
    - 荒い操作: 4 ピンのモジュールで INPUT を 6 回連打すると 1〜4 番と番号なし 2 つになる。全選択して貼り付けを連打しても番号は重ならない。元に戻すの連打、再読み込みも問題なし。
    - version 2 のデータ（split のモジュールを含む）のシートの SVG は、メイン回路とモジュールのタブの両方で変更前と同じ。これまでの確認（シートの操作、配線とシミュレーション、パレット・タブ・ダイアログ）も通った。
    - フレームレート（ビルドしたもの、CPU 4 倍遅く、dip のモジュールを置いた回路）: 変更前と後で差はない（CLOCK だけで約 60 fps、ドラッグ中で約 59.5 fps）。

### 段階 5: モジュール設定

振る舞いを変える変更（Skill の `modify`）。

パッケージとピンの割り当ては、「モジュール設定」のダイアログで編集する。プロパティ欄では編集しない。ピン数が多いと、ポートを 1 つずつ選んでプロパティ欄で番号を入れるのは大変で、全体の割り当ても見渡せないため。

- 中身:
  - パッケージ: 形の種類（`dip` / `qfp` / `split`）とピン数。
  - ピンの割り当て: ピン番号ごとに、割り当てるポート（中の `input` / `output`。ラベルで示す）を選ぶ一覧。割り当てない番号は NC。入力か出力かと、割り当てのないポートも見えるようにする。まとめて割り当てるボタン（例: 上から順に割り当て直す）を置く。
- 変更は「適用」でまとめて 1 回の編集にする。元に戻すも 1 回で済む。
- 形が変わる変更（形の種類やピン数を変える）と、ピンの割り当ての変更では、外の配線が外れることがあると、ダイアログの中に書く。
  - 割り当ての変更だけでもピンの位置が動き、外の配線が別のポートにつながったり、何にもつながらなくなったりする。モジュールの見た目は変わらないので、気付きにくい。
  - 採らなかった案:
    - 影響のあるピンと場所を一覧で出す: 作る量が増える。使う場所の多いモジュールで困ると分かってから足せる。
    - 適用のときに確認のダイアログを出す: このアプリの確認は取り返しのつかない操作に使う決まりで、割り当ての変更は元に戻すで戻せる。ダイアログは同時に 1 つだけで、モジュール設定の上に重ねられない。
    - 知らせない: 見た目で気付けないため。
- `split` から `dip` / `qfp` に変えるときは、今の並び順（入力、出力の順）でピン番号を自動で割り当てる。
- プロパティ欄では、ピン番号は表示だけにする。編集する場所を 1 つにして、迷わないようにするため。
- ダイアログの書き方は [UI](../../agent/ui.md) の「ダイアログ」に従う（`DialogFrame`、同時に 1 つだけ出すなど）。
- 開き方: モジュールのタブを開いているとき、シートのツールバーの「モジュール設定」ボタンから開く。「モジュールを削除」と同じく、そのモジュールに効く操作の並びに置く。
- モジュールの見本を入れる。今の設定（適用する前の変更を含む）で、シート上でどう見えるかを出す。モジュールのタブ（中身）からは外側の形が見えず、見本がないと、適用してから別のタブで確かめることになるため。
  - 見本は、シート上の部品の描画（`SheetPart`）を、ダイアログの中の小さな SVG で使い回して作る。段階 1〜4 で、シート上の部品は配置のデータから描く形になっているので、描き方を新しく作らずに済む。
  - ダイアログは、一覧と見本を左右に並べる広さにする。狭い画面では、上下に並べる。
