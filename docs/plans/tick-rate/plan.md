# シミュレーションの速さの見直し（計画）

状態: **計画中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../agent/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../agent/documentation.md)の「計画の文書」）。

## 目的

シミュレーションを今より速く動かせるようにする。tick の速さを 1 秒あたりの tick 数で指定し、最大 100,000 tick/秒（100 kHz）まで設定できるようにする。

## 前提

- tick の速さは、環境設定の間隔 `tickMs`（ms、1〜1000 の整数、既定 10）で決まる（`preferences/preferences.ts`）。1ms より短くできない。
- 1 フレームで進める tick は 20 まで（`simulation/frameTicks.ts` の `MAX_TICKS_PER_FRAME`）。60 fps では毎秒 1200 tick が上限になる。画面のリフレッシュレートで上限が変わる。
  - 20 にした目的は、描画が重いときやタブを離れていたあとに、遅れを一気に取り戻して早送りにならないようにすること。計算の重さから決めた値ではない。
- 1 tick ごとに、モジュールの展開（`flattenProject`。配線のネットの計算を含む）をやり直している（`sim.ts` の `step`）。CLOCK が反転するたびに、CLOCK の状態を当てたプロジェクトも作り直している（`useSimulation.ts` の `withClockStates`）。
- 評価（`stepCircuit`）は、文字列のキー（`pinKey`）の `Map` で値を持ち、周回ごとに `Map` を写している。
- シートが結果から読むのは `SimResult.values`（`pinKey` で引く）だけ（`sheet/Sheet.tsx`）。

### 計測（Node、開発機）

全加算器のモジュール（中に半加算器のモジュールが 2 つ）を K 個並べ、周期 4 の CLOCK を配った回路で、1 tick の計算時間を測った。周期が短いので、ほぼ毎 tick 値が動く重い条件。

| 回路（展開後の部品数） | 今の 1 tick | うち展開 | うち評価 | 配列版の試作の 1 tick |
| ---------------------- | ----------- | -------- | -------- | --------------------- |
| 全加算器 × 4（74）     | 230µs       | 140µs    | 57µs     | 0.48µs                |
| 全加算器 × 16（290）   | 860µs       | 560µs    | 230µs    | 2.8µs                 |
| 全加算器 × 64（1154）  | 3500µs      | 2300µs   | 1000µs   | 10.7µs                |

- 配列版の試作は、ピンを番号で引く配列で毎 tick 全部品を評価したもの。フリップフロップ、1 tick 戻すための履歴、シートに渡す結果への変換は入っていない。1 部品あたり約 10ns。
- 1 フレームの計算を 8ms、60 fps とすると、配列版で 100 kHz に届くのは、すべてが動き続ける条件で 500 部品くらいまで。遅い PC やスマートフォンでは数倍遅いと見込む。

## 決めたこと

開発者が決めたこと:

- tick の速さは、1 秒あたりの tick 数で指定する。
- 保存する項目: 環境設定（`sazanka.preferences`）の `ticksPerSecond`。
  - 古い `tickMs` しかないときは、`1000 / tickMs` に変換して読む。
  - 採らなかった案: `tickHz`、`tickRate`（`ticksPerSecond` の方が意味をそのまま読める）。
- 範囲と既定値: 1〜100,000 の整数、既定 100（今の既定の 10ms と同じ速さ）。
- 環境設定の見出し: 「シミュレーションの速さ（tick/秒）」。
  - 採らなかった案: 「tick の周波数（Hz）」。
- 計算が間に合わない分は、今と同じく捨てる（シミュレーションが指定より遅く進む）。利用者には何も知らせない。
  - 採らなかった案: ステータスバーに実際の速さを出す。
- 描画は今と同じくフレームに 1 回。フレームより速い CLOCK の点滅は、間引いて見えてよい。
- まずは 100 kHz を目標にし、配列化で届かせる。1 MHz が要るようになったら、イベント駆動（入力の変わった部品だけを計算し、何も起きない tick を飛ばす）か Web Worker を足す。

エージェントが決めたこと:

- 1 フレームで進める量の上限を、tick 数ではなく計算時間（8ms）で決める。速さがリフレッシュレートで変わらず、重い回路でも fps が落ちすぎないようにするため。
  - 採らなかった案: tick 数の上限を上げる（回路の重さで 1 フレームの時間が変わり、大きな回路で fps が落ちる）。
- 変えない値: 発振の判定（`OSCILLATION_TICKS` = 50）、CLOCK の周期（2〜10000 tick、既定 100）、1 tick 戻すための履歴（300 tick）。どれも遅延の段数や tick ずつ見る操作を基準にした値で、速さとは関係しないため。
- 展開した回路を配列の形にしても、シートに渡す `SimResult.values` は今の形（`pinKey` で引く `Map`）のままにし、作るのはフレームに 1 回だけにする。シートとテストへの影響を小さくするため。

## 段階

### 1. 展開を使い回す（組み替え。Skill の `refactor`）

- 展開は、回路を編集したときとタブを切り替えたときだけ行い、tick ごとにはしない。
- CLOCK の ON/OFF は、プロジェクトを作り直さずに、展開した回路の評価に外から渡す。
- 反転する CLOCK を、tick ごとにプロジェクト全体から探さない。CLOCK の一覧を覚えておく。
- 確かめること: 既存のテストが通る。計測で、展開の分の時間が消えている。ブラウザで、CLOCK、一時停止、1 tick 送り・戻し、タブの切り替え、編集後の再開が今と同じに動く。

### 2. 評価を配列で行う（組み替え。Skill の `refactor`）

- 展開した回路を、ピンを番号で引く配列の形に 1 回だけ変換し、評価はその配列で行う。
- 今の決まりを守る: 全部品が同じ時点の値を見る（並べた順番で結果が変わらない）、遅延より短いパルスは出力に出ない、落ち着いたかと発振の判定。
- 1 tick 戻すための履歴は、毎 tick の記録が軽く済む形にする。
- 確かめること: `sim.test.ts`、`simDetail.test.ts` がそのまま通る。計測で、配列版の試作に近い速さが出る。ブラウザで、1 と同じ確認をする。

### 3. tick の速さを 1 秒あたりの tick 数にする（振る舞いの変更。Skill の `modify`）

- 1 フレームで進める量の上限を、計算時間で決める。間に合わない分は捨てる。
- 環境設定の項目、範囲、見出しと説明、保存と古い `tickMs` の読み替え、CLOCK の周期の秒数の表示（プロパティ欄とヒント）を、1 秒あたりの tick 数に合わせる。日本語と英語の両方。
- 確かめること: 保存と読み替えのテスト（`readStored` などの環境に依存しない部分）。ブラウザで、1 と 100,000 で動くこと、古い `tickMs` の保存データからの読み替え、重い回路で fps が落ちすぎないこと、タブに戻ったときに早送りにならないこと。荒い操作のテストもする。
