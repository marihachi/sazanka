# Skill の追加・編集

Skill を足すとき、直すときの手順。何を Skill にして何をドキュメントに残すかは [AGENTS.md](../../AGENTS.md) の「手順の Skill 化」にある。

## 置き場所

- Skill はエージェントごとの仕組みで、共通の置き場所が定まっていない。そのため `.agents/skills/` と `.claude/skills/` の両方に、**同じ内容で**置く（`.agents/` を Codex などが、`.claude/` を Claude Code が読む）。片方だけ直さないこと。
- Skill に対応していないエージェントは考慮しない（開発者の方針）。
- どんな Skill があるかの一覧は、どこにも持たない。エージェントには利用可能な Skill の名前と `description` が渡されるので、それが唯一の出どころになる。

## 中身の書き方

- Skill には、ほかのプロジェクトでも使える手順だけを書く。このアプリ固有の事柄（コマンド、URL、パス、フォルダの名前、保存データのキー、画面の部品の名前など）は Skill に直接書かず、ドキュメントに書いて、Skill からはドキュメントを参照する（開発者の方針）。Skill を別のプロジェクトへ持っていっても、そのまま使えるようにするため。
  - 参照は、ファイルへのリンクやパスではなく、ドキュメントのファイル名をインラインコードで書き（例: `browser-check.md`）、各 Skill のはじめの参照に「`AGENTS.md` の一覧から辿る」と添える。`AGENTS.md` はどのプロジェクトにも置く入口なので、Skill がドキュメントの置き場所を知らずに済む。パスやリンクは置き場所が違うプロジェクトで使えなくなる。
  - ファイル名だけで一意に決まるよう、ドキュメントのファイル名は重ねない（置き場所が違っても同じ名前にしない）（開発者の方針）。重なっているのに気付いたら、重ならない名前に変え、参照している箇所（`AGENTS.md` の一覧、ほかのドキュメント、Skill）も合わせて直す。Skill の `SKILL.md` は決まった名前なので対象外。
  - Skill を使っていて、このアプリに合わせて具体的に書いた方が良いこと（コマンド、値、例、落とし穴など）が出てきたら、Skill には足さず、ドキュメントに書いて Skill から参照する（開発者の方針）。当てはまるドキュメントがなければ、その Skill 用のドキュメントを別に作り、`AGENTS.md` の一覧に載せる。
  - 例: `browser-check` の、起動のコマンドや開く URL、状態の用意の仕方は[ブラウザでの動作確認](browser-check.md)に分けてある。
- frontmatter は `name` と `description` の2つ。
  - `name` はフォルダ名と同じにする。英語の kebab-case。
  - `description` は**どんなときに使うか**まで書く。エージェントはこの文とやることを見比べて呼び出すかを決めるので、「〜について」だけだと呼ばれない。「〜をしたあと、〜を確認するときに使う」のように、きっかけを入れる。
- 本文は手順として書く。順に踏むもの（番号付き）と、判断の材料（箇条書き）を分ける。
- 落とし穴は「ハマりやすい点」「注意」としてまとめ、避け方まで書く。
- 文章は日本語（[作業の進め方](workflow.md)）。
- 補助ファイル（スクリプトの雛形など）は同じフォルダに置き、SKILL.md から相対リンクで案内する。
  - `.mjs` などは Biome の対象になる。`npm run check` を通す。

## 追加するとき

Skill を新しく作るのは、案（使うとき、手順の概要、名前の候補）を示して合意し、開始の指示を受けてから始める。[作業の進め方](workflow.md) の「合意してから進める」も参照。

手順がまだドキュメントにない場合は、Skill が初めの置き場所になる。ドキュメントに書いてから移す必要はない。ただし、**手順ではなく決まりや理由**（なぜそうするか、開発者と決めた方針）が混ざっているときは、そこだけドキュメント側に分ける。

1. `.agents/skills/<name>/SKILL.md` を作る。
2. `.claude/skills/` に同じフォルダをコピーする。
3. `cmp` で全ファイルが同一であることを確かめる。
4. 元になったドキュメントがあれば、そこから1行で案内する。手順をドキュメントから移したときは、移した本文をドキュメント側から消す（重ねて書かない）。元がない手順なら、この手順は要らない。
5. `npm run check` を通す。

## 編集するとき

1. どちらか一方を直す。
2. もう一方へコピーし直し、`cmp` で同一を確かめる。**片方だけ直した状態で終わらせない。**
3. 手順が元のドキュメントと食い違ったら、そちらも直す。

## 消すとき

両方のフォルダを消し、ドキュメントからの案内も消す。

## 注意

- 判断の前提になること（なぜそうするか、どこに置くか）は Skill に書かない。Skill は呼ばれて初めて読まれるので、呼ぶかどうかを決める前に必要な知識は、必ず読むドキュメントの側に無いと効かない。この手順自体を Skill にせずドキュメントに置いているのも同じ理由で、Skill を足すこと自体が滅多にないため、名前との一致で呼び出されるのを当てにできない。
- 新しく作った Skill が認識されるかは、利用可能な Skill の一覧に出るかで確かめられる。出ないときは、フォルダ名と `name` の食い違い、frontmatter の書式、置き場所を疑う。
