# ライセンス

公開しているアプリ（GitHub Pages）は、同梱しているライブラリの複製を配布していることになる。ライブラリや素材のライセンスが求める表示を、配布物に必ず含めること（プロジェクトの方針）。

## 同梱しているライブラリ

- MIT などのライセンスは、配布物にライセンス文（著作権表示と許諾表示）を含めることを条件にしている。ビルドで JS を圧縮すると、ライブラリの中のライセンスのコメントは消えるので、それだけでは条件を満たさない。
- そのため、ビルドで同梱しているライブラリのライセンス文を `dist/licenses.txt` に書き出し、「このアプリについて」からリンクしている（開発者の方針）。
  - 一覧は手で書かず、`rollup-plugin-license` で集めている（`vite.config.ts` の `licensesText`）。ビルドに実際に入ったモジュールが対象なので、依存に挙がっているだけで配布していないパッケージは載らない。
  - 実際に入ったものはビルドが終わるまで分からないので、JS に埋め込まず別のファイルにしている。開発用のサーバー（`npm run dev`）ではファイルができないので、リンク先は開けない。
  - ライセンス文のファイルが同梱されていないパッケージは、`package.json` の `license`（MIT などの種類）だけを載せ、本文の代わりに同梱されていない旨を出す。種類も分からないパッケージは一覧に載せない（開発者の方針）。どちらもビルドのログに `[licenses]` で始まる警告を出すので、依存を足したら警告を確かめる。
  - `devDependencies`（Vite、TypeScript など）は配布物に入らないので対象外。ビルドや実行時に読み込むものを `devDependencies` に入れないこと。
- 依存ライブラリを足すときは、ライセンスが MIT と両立するか（GPL などで、このアプリのライセンスに影響しないか）と、ライセンス文の表示以外の条件がないかを確かめる。迷ったら開発者に相談する。

### 触ったら確かめること

依存ライブラリを足したり、ライセンスの集め方（`vite.config.ts`）を触ったりしたら、次を確かめる。

- `npx vite build` のログに `[licenses]` の警告が出ていないか。出ていたら、そのパッケージのライセンスを確かめる。
- `dist/licenses.txt` に、足したライブラリが載っている。
- ビルドしたものを `npx vite preview` で開き、「このアプリについて」のリンクから `licenses.txt` が文字化けせずに開ける。開発用のサーバーではファイルができないので、この確認はできない。

## 素材

- ロゴの文字は Inter SemiBold（SIL OFL）の字形をパスにして使っている（[アイコンとロゴ](icons.md)）。フォントのファイル自体は配布していないので、ライセンスの表示は必須ではないと考えている（開発者の判断）。今は念のため、README と「このアプリについて」にフォント名とライセンスを書いている。
- アイコン（`src/assets/icons/` と `src/parts/<種類>/icon.svg`）は、このプロジェクトで描いたもの。外から素材を持ってくるときは、ライセンスを確かめ、必要な表示を「このアプリについて」に足す。
