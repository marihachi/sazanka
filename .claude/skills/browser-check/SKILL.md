# ヘッドレスブラウザでの動作確認

画面や操作に関わる変更をしたら、テストとビルドが通るだけで済ませず、実際にブラウザで動かして確かめる（開発者の方針）。どうしても確かめられなかった場合は、報告にそう明記する。

確認のたびに使い捨てのスクリプトを書いて走らせる。スクリプトはリポジトリに置かない（作業用のフォルダに置く）。ブラウザを操作する仕組みも、プロジェクトの依存には加えず、作業用のフォルダに入れる。

## 手順

1. 開発サーバーを起動する（`npx vite --port 5199 --strictPort` をバックグラウンドで）。ポートが埋まっていたら、別のポートに変えて自分で立て直す。すでに動いているサーバーにつなぐと、自分の変更を見ている保証がない（開発者が別の作業で立てていることがある）。
2. スクリプトでヘッドレスブラウザを起動し、`http://localhost:5199/sazanka/` を開く（`vite.config.ts` の `base` の下に置かれる）。使えるブラウザは開発環境によって異なるので、その環境にあるものを確かめてから使う。
   - 例: Node が使える環境なら、作業用のフォルダに `puppeteer-core` を入れ、その環境にインストール済みのブラウザ（実行ファイルのパスを指定する）を動かす。スクリーンショットだけなら、ブラウザのヘッドレスモードをコマンドで呼ぶだけでも足りる。
3. 確かめたいことに応じて、操作・読み取り・スクリーンショットを行う。操作は下の「人の操作をまねる」に従う。雛形は [script-template.mjs](script-template.mjs)（人の操作をまねる関数も入っている）。
4. 終わったらサーバーとブラウザを止める。

## 人の操作をまねる

確認の操作は、人がする速さと間隔でする（開発者の方針。理由は[作業の進め方](../../../docs/agent/workflow.md)）。雛形の関数（`click`、`doubleClick`、`drag`、`type`、`hover`）を使えば、次の値になる。

- **クリック**: 対象の上へポインターを動かしてから、押して 60ms ほど置いて離す。要素の `click()` を `evaluate` の中で呼んだり、合成したイベントを送ったりしない。
- **ダブルクリック**: 1 回目と 2 回目のクリックの間を 100ms あける。
- **ドラッグ**: 押したあと 100ms ほど置き、1 歩 5〜10px ほど、1 歩ごとに 16ms（1 フレーム）ほど待ちながら動かす。離す前にも 100ms ほど置く。
- **文字の入力**: 1 文字ごとに 50ms ほどあける（`page.keyboard.type` の `delay`）。
- **操作と操作の間**: 200〜300ms あける。続けて押すボタンも同じ。
- **ポインターを載せる**: 対象へ動かしたあと、ツールチップなら 700ms ほど待つ（出るまで 400ms かかる）。
- 例外: ブラウザのドラッグ＆ドロップ（パレットからシートへ置くときの `dataTransfer`）は、ヘッドレスブラウザでは実際のポインター操作で起こせない。`DataTransfer` を持たせた `DragEvent` を送るしかないので、そのときだけ合成イベントを使い、報告にそう書く。

## 荒い操作を試す

作業の区切りに、触った範囲へ行う（いつ行うかは[作業の進め方](../../../docs/agent/workflow.md)）。ここでは人の速さをまねなくてよい。連打などは、むしろ速く行う。

### 試す操作

触った範囲に当てはまるものを選ぶ。

- **連打**: 「+」、元に戻す・やり直し、1 tick 進める、ダイアログの確定ボタン、Enter。
- **割り込み**: ダイアログが開く途中の Esc。ドラッグ中の Esc・右クリック・ホイール・ショートカット（Ctrl+Z など）。ドラッグ中のタブの切り替え。
- **はみ出し**: 部品やタブを画面の外までドラッグして離す。
- **入力**: 空欄、とても大きな数、全角の数字、改行の入った貼り付け、とても長い名前（タブやパレットでの表示も見る）。
- **画面**: ドラッグ中やダイアログを開いている間の、画面の幅の変更。とても狭い幅（320px）。
- **速さ**: 3 回続けてのクリック、クリックとダブルクリックの混ざった操作。

### 合否の決め方

次のどれかが起きたら不合格。

- ページの例外やコンソールのエラーが出る。
- 画面が操作できない状態のまま戻らない（ダイアログが閉じない、ドラッグが終わらないなど）。
- 保存データが壊れる。再読み込みして、同じ状態で開けるかで確かめる。
- 元に戻すで、操作の前に戻せない。
- 同じものが二重にできる（確定ボタンの連打でモジュールが 2 つできるなど）。

期待と違っても壊れていないものは、不合格にせず「気になる動き」として報告する。

## 確かめ方の例

- **見た目**: スクリーンショットを撮って、画像として確認する。
- **操作**: ボタンや部品をクリックする、文字を入力する、キーを押す。
- **状態**: 表示されている文言、ボタンが押せるかどうか、配線やランプの色、タブの一覧を読む。
- **回数や間隔の測定**: 値が変わる間隔（ms）、一定時間の DOM の書き換え回数、フレームの要求回数。描画を間引く仕組みが効いているかは、これで測る。
- **エラー**: ページの例外、コンソールのエラー、失敗した通信（404 など）を集めて最後に出す。想定していない読み込み失敗に気付ける。

## ハマりやすい点

- **回路を用意するときは localStorage に直接書く**。画面で組み立てるより速い。ただし、最初のページ読み込みが終わるのを待ってから書き込むこと。待たずに書くと、アプリ側の自動保存に上書きされて空のまま始まる。書き込んだら再読み込みする。
- **部品の座標は、シートの表示範囲に合わせる**。シートは横 300 マス・縦 200 マスあり、開いた直後はその真ん中（`x` が 2500 前後、`y` が 1900 前後）が見えている（`components/view.ts` の `centerView`）。原点に近い座標（`x: 200` など）に置くと画面の外になり、クリックしても何にも当たらない。座標は部品同士が重ならないよう、`GRID`（20）の何倍かずつ離す。
- **CSS Modules のクラス名はハッシュが付く**ので、完全一致では探せない。`wire` を含み `wire-hit` を含まない、のように部分一致で見る。
- **新しいプロファイルで開くと localStorage は空**（メイン回路だけ）になる。スクリプトを分けて走らせると、前の確認の状態は残らない。
- 保存データの形は [保存データ](../../../docs/agent/persistence.md)、部品や配線の呼び方は [用語](../../../docs/agent/glossary.md) にある。
