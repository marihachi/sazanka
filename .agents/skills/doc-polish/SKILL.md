# ドキュメントの文章を整える

ドキュメントの書き方を整える手順。中身（何を書くか）は変えない。中身がコードや取り決めと合っているかの見直しは Skill の `doc-review` にある。書き方と表記の決まりは `documentation.md`、用語は `glossary.md`（どちらも `AGENTS.md` の一覧から辿る）にある。

## 手順

1. **範囲を決める**。ファイルか、節か、直近で変えた部分だけか。決まっていなければ、直近で変えた部分にする（`git diff` で見る）。
2. **書き方の決まりを読む**。`documentation.md` の書き方と表記、`glossary.md` の用語を読む。
3. **文を直す**。
   - 1 文に 1 つのことを書く。長い文は分ける。
   - 結論を先に書き、理由は後に添える。
   - 重複、遠回しな言い方、意味の薄い修飾を削る。
   - 指示語（「それ」「上の」など）が何を指すかを、はっきりさせる。
4. **言葉をそろえる**。用語、表記のゆれ、同じものを別の言葉で呼んでいる箇所を直す（決まりは `documentation.md` の表記と `glossary.md`）。
5. **構成を整える**。
   - 見出しの粒度をそろえる。
   - 順に行うことは番号付きの一覧、判断の材料は箇条書きにする。
   - 表の桁をそろえる。
6. **意味が変わっていないかを確かめる**。差分を読み、規則の強さ（「〜する」と「〜してよい」など）、範囲、条件が変わっていないかを見る。見出しの名前を変えたなら、その見出しを名指ししている箇所も直す。
7. **報告する**。直した内容を種類（文、言葉、構成）ごとにまとめる。意味に関わりそうな直しは別に挙げて、確認してもらう。

## 注意

- 開発者が決めた規則として区別されている記述（区別の仕方は `AGENTS.md` にある）は、言い回しも勝手に変えない。直したい点があれば挙げて、開発者に確認してもらう。
- 表記の決まりにない迷いが出たら、決め打ちせずに開発者に聞く。決まったら `documentation.md` の表記に足す。
- インラインコードやコードブロックの中は、表記の決まりで直さない。
- 開発者が手で直した箇所を、整えるついでに元に戻してしまわないよう気を付ける。直す前に `git diff` と `git log` で、直近に手が入った箇所を見ておく。
