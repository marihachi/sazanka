# 実装

合意した計画を、段階に分けて実装する手順。始めるのは、開発者から開始の指示があってから（決まりは `workflow.md` の「実装を始める合図」。`AGENTS.md` の一覧から辿る）。計画を立てるところは Skill の `plan` にある。

## 手順

1. **合図を確かめる**。開発者の指示が、実装を始めることをはっきり言っているかを確かめる（`workflow.md` の「実装を始める合図」）。曖昧なら始めずに聞く。
2. **範囲を確かめる**。合意した計画と、今回始めてよいと言われた範囲（全部か、ある段階までか）を確かめる。範囲がはっきりしなければ、始める前に聞く。
3. **ドキュメントを読む**。触るものに当てはまる実装のドキュメントを読む（`AGENTS.md` の一覧）。
4. **段階ごとに実装する**。計画の段階の順に進める。途中で計画を変えたくなったら、勝手に変えずに止めて示す。範囲の外の直したいところに気付いたら、直さずに報告に挙げる。
5. **段階ごとに確かめる**。整形、Lint、型、テスト、ビルドを通す（コマンドは `workflow.md`）。
6. **ドキュメントを合わせる**。触った部分のドキュメントを今のコードに合わせ、決めたこと、選んだ理由、落とし穴、触ると壊れるものを書く（書き方は `AGENTS.md` の「ドキュメントの書き方」）。
7. **区切りで止める**。段階が終わったら、やったこと、確かめたこと、次の段階、決めてほしいことを報告し、次の段階の指示を待つ。まとめて進めてよいと言われているなら、止まらずに次の段階へ進む。
8. **動作を確かめる**。画面や操作に関わる変更は、実装が一通り終わったところでブラウザで確かめる（Skill の `browser-check`）。作業の区切りなら、荒い操作のテストも行う。途中の段階ごとに確かめるかは、開発者の指示に従う。
9. **報告する**。やったこと、確かめたこと、確かめられなかったこと、気になる動き、決めてほしいことを分けて書く。コミットは頼まれたときだけ行う。

## 注意

- 確かめて NG が出たら、直す前に、確認の手順の誤りではないかを見る。直したら、関係する確認をやり直す。
- 変更前のコードでも同じことが起きるかを確かめると、自分の変更で壊したのか、元からなのかを切り分けられる。
- 実装の途中で開発者から止めるよう言われたら、すぐ止め、どこまで進んでいるかを報告する。
