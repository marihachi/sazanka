# ドキュメントの見直し

[AGENTS.md](../../../AGENTS.md) と `docs/agent/` を、今のコードと取り決めに合わせる。書き方の方針そのものは AGENTS.md の「ドキュメントの書き方」にあるので、まずそれを読む。

作業で触った部分の見直しは毎回行う。この Skill は、大きく作り変えたあとや、開発者に頼まれたときの**全体の見直し**に使う。

## 手順

1. **範囲を決める**。全体か、ある責務の周りだけか。全体なら `docs/agent/` の全ファイルを対象にする。
2. **コードとの食い違いを探す**。ドキュメントが挙げている名前（ファイル、関数、定数、クラス名、キー名）が今も存在するかを確かめる。改名や削除に取り残された記述がいちばん出やすい。
3. **消すものを探す**。
   - コードを読めば分かるようになった記述。
   - 今後の判断に役立たない過去の経緯（以前の名前、採らなかった案、直した不具合）。
   - 役目を終えた記述（未リリース前提の判断など）。
4. **足りないものを探す**。直近の実装で決めたこと、選んだ理由、落とし穴、触ると壊れるものが書かれているか。書かれていなければ、その責務のファイルに足す。
5. **一覧との対応を確かめる**。`docs/agent/` の全ファイルが AGENTS.md の「必ず読む」か「触るとき」のどちらかの一覧に載っているか。逆に、一覧にあってファイルがないものがないか。
6. **用語のぶれを確かめる**。[用語](../../../docs/agent/glossary.md) の言い方と、各ドキュメント・UI の文言・コードコメントがそろっているか。同じものを別の言葉で呼んでいる箇所を直す。
7. **責務の混ざりを確かめる**。1つのファイルに別の責務が混ざっていたら分け、元のファイルから1行で案内する。分けたら 5 もやり直す。
8. **整形**。Markdown は Biome の対象外なので手で整える。表の桁をそろえ、リンクが切れていないか確かめる。最後に `npm run check` が通ることだけ確かめる（コードを触っていなければ影響はないが、リンク切れの見落としに気付けることがある）。
9. **報告**。見つけた問題と直した内容を、問題ごとに分けて開発者に伝える。確認して問題がなかった観点も、何を見たかが分かるように添える。

## 注意

- Skill（`.agents/skills/` と `.claude/skills/`）を直したときは、両方の内容をそろえる（[Skill の追加・編集](../../../docs/agent/skills.md)）。
- ドキュメントを消すか残すかで迷ったら、決め打ちせずに開発者に聞く。
- 開発者が手で直した箇所を、整理のついでに元に戻してしまわないよう気を付ける。直す前に `git diff` と `git log` で、直近に手が入った箇所を見ておく。
