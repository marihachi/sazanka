# 描画の重さ

画面の描き直しを減らす仕組み。重さを測る条件と目安は[ブラウザでの動作確認](browser-check.md)の「フレームレートを測る」にある。

## なぜ描き直しを減らすか

- Chakra UI の部品は、描き直すたびにスタイルを作り直すので重い。描き直しが多いと、すぐにフレームレートが落ちる。
- 部品のドラッグでは、一歩ごとに App（画面全体）が描き直される。そこで、ドラッグで中身の変わらない部品は描き直さないようにしている。
- フレームレートが下がっていたら、まず描き直しが増えていないかを疑う。

## 描き直さない仕組み

- ヘッダー、タブバー、シートのツールバー、パレット、プロパティ欄、ステータスバー、ズーム、削除エリアは `React.memo` で包み、props が変わらなければ描き直さない。
- App からこれらへ渡す関数は、`app/useStableCallbacks.ts` で固定する。App を描き直しても同じ関数のままで、呼ぶと最新の中身を実行する。その場で `() => ...` を書いて渡すと、毎回違う関数になり `React.memo` が効かなくなる。シートからズームへ渡す関数も、同じ考え方で固定している（`Sheet.tsx` の `zoom`）。
- 一部の部品は、props の比べ方を自分で持っている。props を足したり意味を変えたりしたら、比べ方も直す。直さないと、変わったのに描き直されない。
  - タブバー（`sameTabs`）: 回路は ID と名前だけ比べる。
  - プロパティ欄（`samePanel`）: 選んだ部品の位置（x, y）は比べない。
  - ステータスバー（`sameStatus`）: ヒントは文の中身で比べる。
- パレットのモジュールの一覧は、回路の名前と、どの回路にどのモジュールを置いているかが変わったときだけ作り直す（`modules/useModules.ts` の `modulesKey`）。パレットに出す情報を足したら、`modulesKey` にも足す。

## 部品のピン

- シート上の部品のピン（線、向きの印、外側のピン番号、ピン名）は、部品の左上を原点とする座標で描き、外側の `<g transform="translate(...)">` で部品の位置へ動かす（`SheetPart.tsx` の `PinLeads` と `PinNames`）。部品を動かしても中身の props が変わらないので、`React.memo` で描き直しを省ける。ピンの多いモジュール（128 ピンの QFP など）のドラッグで効く（CPU を 4 倍遅くした計測で、23 fps から 59 fps になった）。
  - 比べ方（`samePinLeads`、`samePinNames`）は、ピンの割り当て（名前、パッケージ、ピン番号）とピンの値を中身で比べ、ピン番号を書くか（`showPinNumbers`）も比べる。ピンの描き方に使う値を足したら、比べ方にも足す。
- ピンの座標は、部品ごとに配置を 1 回だけ求めてから使う（`calcSheetPins`）。ピンごとに `inputPinPos` / `outputPinPos` を呼ぶと、そのたびに部品の配置全体を作り直すので、ピンの多いモジュールではピンの数の 2 乗の手間になる。

## モジュール設定

- ピンの割り当ての一覧は、ピン数が多い（128 ピンなど）と、行が 128、選択肢が合わせて 1 万 6 千ほどになる。1 つ変えるたびに全部を描き直すと重い（CPU を 4 倍遅くして 1.4 秒）ので、行を `React.memo` で包み（`PinRow`）、選択肢の要素は 1 回だけ作って行どうしで使い回す。行に渡す関数は `useCallback` で固定する（0.38 秒になった）。

## 配線のつながり

- 開いている回路のネット（`geometry/net.ts` の `computeNets`）は、`App.tsx` で回路が変わったときだけ計算し（`useMemo`）、シートに渡す。シートの描き直しのたびに計算しない。
- シミュレーションの展開（`flatten.ts`）も、回路ごとにネットを計算する。部品や配線のドラッグでは、一歩ごとに両方が走る。
- 配線をネットに分けるとき、配線の端を通る配線を探すのに、横線は y、縦線は x ごとに分けておき、調べる組を減らしている。

## シミュレーションの結果

- シミュレーションの結果は、App を通さずシートにだけ渡す（`SimStore` と `useSyncExternalStore`。[シミュレーション](simulation.md)）。tick ごとに画面全体を描き直すと、CLOCK が動いているだけで画面全体が重くなるため（CPU を 4 倍遅くした計測で、58 fps から 7 fps まで落ちた）。
- tick ごとに変わる値を、App の状態や props に戻さない。
- シートに渡す結果（部品 ID で引く形の `SimResult`）は、フレームに 1 回、値が変わったときだけ作る（`toResult`）。tick ごとに作らないのは、1 tick の計算よりずっと重いため（展開後 290 部品で、1 tick 約 5.5µs に対して約 0.12ms）。
- CLOCK の ON/OFF をプロジェクトに書かないのも、反転のたびに画面全体の描き直しと保存が起きないようにするため。
