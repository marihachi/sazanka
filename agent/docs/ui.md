# UI

画面の配置と、ボタン・ダイアログ・ヒントの決まり。操作の割り当ては[画面操作](interaction.md)、見た目は[見た目](styling.md)、アイコンは[アイコンとロゴ](icons.md)、画面の文言と表示言語は[文言と表示言語](i18n.md)にある。

## 画面の配置

操作のボタンは、その操作が効く範囲ごとに置き場所を分けている。操作を足すときも、どこに効くかで置き場所を決める。

| 場所                                                | 置くもの                                                                                                                          |
| --------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| ヘッダー（`app/Header.tsx`）                        | プロジェクト全体に効く操作: 新規作成、読み込み、書き出し、元に戻す、やり直し。右端に環境設定と「このアプリについて」              |
| タブバー（`circuits/TabBar.tsx`）                    | 回路の切り替えと、回路の追加（タブの末尾の「+」）                                                                           |
| シートのツールバー（`simulation/SheetToolbar.tsx`） | 開いている回路に効く操作: 選択モード・配線モード・分割モードの切り替え、回転、一時停止・再開、1 tick 戻す・進める、回路設定、回路の削除 |
| パレット（`palette/Palette.tsx`）                   | シートの左。置ける部品の一覧                                                                                                      |
| ズーム（`sheet/ZoomControls.tsx`）                  | シートの右下に重ねる。縮小、倍率（押すと等倍）、拡大、回路全体を表示                                                              |
| 削除エリア（`sheet/TrashZone.tsx`）                 | ズームの上に重ねる                                                                                                                |
| プロパティ欄（`app/PropertyPanel.tsx`）             | シートの右。選んだ部品の項目                                                                                                      |
| 問題パネル（`problems/ProblemsPanel.tsx`）          | シートの下、ステータスバーの上に開く。開いている回路の問題の一覧                                                                  |
| ステータスバー（`hints/StatusBar.tsx`）             | 画面の最下部。ヒントと、回せなかったときのお知らせ。右端に「問題」（問題の数と、問題パネルの開閉）                                |

- 元に戻す・やり直しをヘッダーに置くのは、履歴がすべての回路で 1 本の、プロジェクト全体の操作だから。
- シートのツールバーは、選択中のタブと同じ色（`bg.panel`）にして、そのタブの中の操作であることを示している。タブは Chakra の `Tabs`（`outline`）で、ドラッグでの並べ替えと名前の変更は `TabBar.tsx` が自前で足している。
- 環境設定は利用者ごとの値で、プロジェクトには含めない（型と選択肢は `preferences/preferences.ts`）。

## 削除エリア

- ふだんは丸いごみ箱のアイコンだけ。部品をドラッグし始めると、丸の下に「削除」と出し、上に載せると丸を赤くする。
- ドラッグしていないときも出しておくのは、ここへ運べば消せることに気付いてもらうため。
- 「削除」の文字の場所はふだんから空けておき、ドラッグ中だけ文字を見せる。出し入れで丸の位置がずれないようにするため。
- 配線の端のドラッグ（[画面操作](interaction.md)の「配線の調整」）では削除しないので、削除エリアは反応させない（`Sheet.tsx` が `'none'` として渡す）。
- 部品を落としたかは、丸の画面上の位置で判定する（`Sheet.tsx` の `trashRef`。文字の上は含めない）。エリアの置き場所を変えても、判定はそのまま働く。
- ステータスバーのヒントに場所（「右下の」）を書いているので、置き場所を変えたら文言の表（`i18n/ja.ts` の `hints`）も直す。

### 開発者からの指示

- 削除エリアは、シートの右下、ズームの上に重ねる。
- 丸の位置と大きさは、ドラッグの前後で変えない。運ぶ先が動くと狙いにくいため。

## プロパティ欄

- 選んだ部品が 1 つのとき、その種類と項目を出す。項目があるのは CLOCK（周期）と INPUT / OUTPUT（ポート名）。
- 狭い画面（Chakra の `md` 未満）では、部品を選んでいる間だけ出す。シートを狭くしすぎないため。
- CLOCK の周期は、範囲外の値ではエラーの文を出し、使える値になったらすぐに反映する。使えない値のまま欄を離れたら、今の値に戻す。
- 別の部品を選ぶと、入力中の文字は捨て、その部品の今の値を出す。
- INPUT / OUTPUT では、「ポート番号: 入力 1」（表示だけ）と「ポート名」の欄を出す。メイン回路でもほかの回路でも同じ。
- 名前の欄は、同じ回路のほかのポートと同じ名前（入力と出力をまたいで比べる）ならエラーを出して反映しない（欄の文字は残す）。
- ピン番号は、プロパティ欄にも、モジュールを置いた先のシートにも出さない。回路設定のプレビューでだけ、ピンの横に出す（どのピンに割り当てるかを見ながら選べるように）。パッケージとピンの割り当ては、回路設定で確かめ・設定する（開発者が決めた）。
- 部品ごとの項目は、プロパティ欄で編集する。部品に項目を足すときは、ここに入力欄を足す。(開発者からの指示)

## ボタン

- ボタンは `ui/ToolButton.tsx`（Chakra の `Button` / `IconButton` の `ghost`）を使う。文字はアクセントカラーにせず灰色（`colorPalette="gray"`）にする。ページ全体の既定のパレットはアクセントカラーなので、指定しないと Chakra のボタンは青緑になる。パレットの部品と見出しのボタンも同じ。
- 狭い画面（`md` 未満）では文字を隠してアイコンだけにする。文字はツールチップと読み上げ用のラベル（`aria-label`）に残す。
- 取り消しにくい危険な操作のボタン（回路の削除）は、`ToolButton` の `danger` で赤にする。
- 切り替えのボタン（選択モード・配線モード・分割モード）は、今選ばれている方を `ToolButton` の `active` で示す。地の色を付け（`subtle`）、`aria-pressed` も付ける。

## ツールチップ

- ボタンなどの説明は、`title` ではなく `ui/HintTooltip.tsx`（Chakra の `Tooltip`）で出す。見た目を Chakra にそろえるため。ポインターを載せてから 400ms で出る。
- 押せないボタン（`disabled`）はポインターのイベントを出さないので、そのままではツールチップが出ない。`span` などで包み、包んだ要素にツールチップを付ける（`ToolButton` の押せないとき、パレットの置けないモジュール）。
- タッチ操作ではツールチップが出ない。欠かせない説明は、ツールチップだけに頼らない。
- 既知の不具合: CLOCK が動いている間、ヘッダーのボタンのツールチップが、出てもすぐ消えたり、出たり消えたりする。ズームのボタンでは起きない。原因は分かっていない。
  - 再現した手順: 環境設定でシミュレーションの速さ（当時は tick の間隔）を変えて閉じ、パレットから CLOCK を置き、シートの何もない所をクリックしてから、ヘッダーのボタンにポインターを載せる。近い条件の別の手順では再現しないことがある。
  - 原因ではなかったもの: Chakra（zag）のツールチップの、祖先のスクロールで閉じる動き（`closeOnScroll`）。止めても直らず、スクロールも起きていなかった。
  - 原因ではなかったもの: tick ごとの App の描き直し。やめても直らなかった。

## ダイアログ

- ブラウザの `prompt` / `confirm` / `alert` は使わず、画面内のダイアログを使う。VS Code の中のブラウザのように、これらが何も表示せずに終わる環境がある（`prompt` は null、`confirm` は false を返す）ため。
- ダイアログは 1 つずつ別のファイルにする。共通のものは `ui/`、特定の機能のものはその機能のフォルダに置く。

| ダイアログ         | ファイル                            | 開いたときのフォーカス                               |
| ------------------ | ----------------------------------- | ---------------------------------------------------- |
| 確認とお知らせ     | `ui/ConfirmDialog.tsx`              | 確定（OK）ボタン                                     |
| 名前の入力         | `ui/PromptDialog.tsx`               | 入力欄（全選択）                                     |
| このアプリについて | `app/AboutDialog.tsx`               | 「閉じる」                                           |
| 環境設定           | `preferences/PreferencesDialog.tsx` | 「閉じる」                                           |
| 回路設定           | `circuits/CircuitSettingsDialog.tsx` | 幅の欄                                               |

- 外枠は `ui/DialogFrame.tsx`（Chakra の `Dialog`）にまとめている。Esc と外側のクリックで閉じること、フォーカスを中に閉じ込めることは Chakra に任せる。開いたときにフォーカスする要素は、各ダイアログが `initialFocus` で渡す。
- ダイアログの開閉は、`app/useDialogs.tsx` がそのコンポーネントを描くかどうかで表す（Chakra の `open` は常に true にしている）。
- ヘッダーの「書き出し」と「読み込み」は、アプリのダイアログを出さない（`file/useProjectFile.ts`）。書き出しは押すとすぐ保存の画面（使えるブラウザでは `showSaveFilePicker`、使えなければダウンロード）、読み込みは押すとすぐファイルを選ぶ画面を開く（`file/localFile.ts`）。保存の画面とファイルを選ぶ画面で取り消したときは、何もしない。保存できない・読めない・プロジェクトファイルでないときは、お知らせ（`ConfirmDialog`）で理由を出す。
  - ファイルを選ぶ画面は、ブラウザの操作の中でしか開けないので、押した操作の中で開く（`pickFile`）。
  - 保存の画面とファイルを選ぶ画面を開く前に、押したボタンからフォーカスを外す（`localFile.ts` の `releaseFocus`）。画面を閉じると、ブラウザはウィンドウと押したボタンにフォーカスを戻す。そのとき結果のお知らせが開いていると、ダイアログの外へフォーカスが移ったとみなされて、お知らせが閉じてしまう（タイミングで決まり、毎回ではない）。
  - 書き出しの途中にもう一度押されても、保存しない（`exporting`）。保存の画面は、開いている間にもう一度開こうとすると例外になるため。読み込みには付けない（取り消しを知らせる `cancel` イベントのないブラウザでは、終わりが分からず読み込めなくなるため。ファイルを選ぶ画面は開いている間ほかの操作を受け付けない）。
- 確定ボタンのある確認は `role="alertdialog"` にする。取り返しのつかない操作の確認は、確定ボタンを赤（`danger`）にする。
- ダイアログは同時に 1 つだけ出す。閉じるダイアログと入れ替わりに別のダイアログを開くと、Chakra（中の zag）は後から開いた方を入れ子とみなし、前のものを外したときに一緒に閉じてしまう。そのため、お知らせ（`ConfirmDialog`）は、入力のダイアログ（`PromptDialog`）が閉じてから出す（`useDialogs.tsx`）。
  - 閉じてすぐでも足りない。閉じたダイアログは、開く前の要素へフォーカスを返すのを `setTimeout(0)` で遅らせ、ほかのダイアログの中にフォーカスがあっても返す。お知らせがそれより先に開くと、フォーカスを外へ取られて閉じる。そのため、閉じてから 1 回待ってから出す（`inputClosed`）。
  - 出すときは `flushSync` で描き切る。描き切らないと、開発中の `StrictMode` が effect をやり直す（zag がダイアログを一度止めて動かし直す）のが、フォーカスを閉じ込め始めたあとになり、そのときのフォーカスの返しで同じように閉じる。
  - タイミングで決まるので、テストとビルドでは気付けない。ダイアログの開き方を変えたときや、ダイアログから続けて別のダイアログを出す流れを足すときは、あとから出したダイアログが残るかを、開発サーバーとビルドしたものの両方で、何度か確かめる（もとは、書き出し・読み込みのダイアログのあとのお知らせで起きた）。

### 回路設定

- シートのツールバーの右側に置き、「回路を削除」はその右に置く。メイン回路でもほかの回路でも出す。アイコンは `package.svg`。
  - メイン回路では「回路を削除」を出さないが、その場所は空けておく（`visibility: hidden`）。タブを切り替えても「回路設定」の位置が動かないようにするため（開発者が決めた）。
- 題名は「回路設定: 回路の表示名」（メイン回路は表示言語の名前。`getCircuitName`）。
- 中を「全般」と「モジュール」（英語は General / Module）の 2 つのタブに分ける（開発者が決めた、2026-10-21）。開いたときは「全般」。
  - 全般: 上から、名前（「名前」。メイン回路では出さない。名前を変えられないため）、作者名（「作者名 (省略可)」。空白だけなら空文字にする。保存データの `author` は省略できないので、空でも空文字を持たせる）と、シートの大きさ（「幅 (マス)」「高さ (マス)」。`sheet/SheetSizeFields.tsx`）。
  - モジュール（モジュールとして置いたときの設定）: 上から、パッケージ（形の種類とピン数）、ポートの名前（「ポート」の一覧。ポートごとに「入力 1」の見出しと名前の入力欄）、ピンの割り当て（ピン番号ごとに、割り当てるポートか NC を選ぶ）。左に設定、右にプレビュー（適用する前の設定で、モジュールとして置いたときにシート上でどう見えるか。`SheetPart` をそのまま使う）を並べ、狭い画面では上下に並べる。プレビューはモジュールのタブにだけ出す（開発者が決めた）。
  - 名前は、回路の追加と同じく、空の名前と、ほかの回路やメイン回路の表示名と同じ名前を断る（エラーは欄の下に出す）。
  - 使えない値があるタブの見出しには、赤い丸を付ける（`SettingsTabTrigger`）。ほかのタブを開いていても、「適用」を押せない理由のあるタブが分かるようにするため。
  - 下書きはダイアログが持つので、タブを切り替えても入力は消えない。「適用」は、どちらのタブからでも両方の変更をまとめて当てはめる。
  - `Tabs.Content` に `display` を書かない。選んでいないタブが隠れなくなるため。高さいっぱいに広げるのは、中の `Flex` で行う。
- 開いたときのフォーカスは幅の欄。
- 本文の高さは決めておき、中でスクロールする。種類やピン数、注意の有無、タブで高さが変わらないようにするため。広い画面ではポートの一覧と割り当ての一覧がそれぞれスクロールする。
- 変更は「適用」でまとめて 1 回の編集にする（元に戻す 1 回で戻る。`App.tsx` の `onApplyCircuitSettings`）。次のときは押せない。
  - 変えていないとき。
  - シートの大きさが範囲外の値（20 未満、1000 より大きい、整数でない）のときと、部品と配線が収まらないとき。エラーはシートの欄の下に 1 つだけ出す。範囲外を先に知らせ、両方使える値になってから「部品と配線が収まるのは a × b マス以上です」を出す。a と b は 20 を下回らない。大きさの決まりは[シートの表示](view.md)の「シートの大きさを変える」にある。
  - ピン数が使えない値のとき。
  - ほかのポートと同じ名前があるとき（名前未設定はいくつあってもよい）。
- 名前は、打つたびに割り当ての選択肢とプレビューに出す。ポートが多いと選択肢の作り直しが重いので、`useDeferredValue` で入力より遅らせてよいことにしている。
- パッケージかピンの割り当てを変えたとき（split でポート番号を変えたときも。ピンの順が変わるため）は、外の配線が外れたり別のピンにつながったりすることがあると、ダイアログの中に書く。メイン回路では書かない（置く先がないため）。確認のダイアログは出さない（元に戻すで戻せるため。ダイアログは同時に 1 つだけのため）。
- split から dip / qfp に変えると、ポートが収まるいちばん小さいピン数にし、入力をポート番号の順に、続けて出力をポート番号の順に、ピン番号を割り当てる（split のときのピンの順をそのまま引き継ぐため。開発者が決めた）。「上から順に割り当て直す」は、名前のとおり位置の順（入力を上から、続けて出力を上から）。
- ポートの一覧、ピンの割り当ての選択肢、「割り当てのないポート」は、入力をポート番号の順に、続けて出力をポート番号の順に並べる（`circuit/module.ts` の `listPortsInNumberOrder`）。見出しがポート番号なので、番号の順にしている。「上から順に割り当て直す」と「上から順に番号を振り直す」は、位置の順（`listPortsInPositionOrder`、`renumberPortsByPosition`）。2 つの並びを取り違えないこと。
- 一覧の見出しの右の「上から順に番号を振り直す」は、種類ごとに位置の順で 1 から番号を振り直す（`renumberPortsByPosition`。抜けも詰める）。一覧は下書きの番号の順に並ぶので、行も並び直す。
  - ポートを 1 つずつ入れ替える「上へ」「下へ」は置かない（開発者が決めた、2026-10-22）。番号の見出しが残って名前の行が動くので、名前が入れ替わったように見えて分かりにくいため。ピンが受け持つ信号を変えたいときは、中の配線をつなぎ直す。
- ポート番号の変更も、ほかの設定と一緒に「適用」で 1 回の編集にする（`applyCircuitSettings` の `portNumbers`）。
- 開いたときに同じピン番号のポートが 2 つ以上あれば（手で書き換えたデータなど、外から来たデータでだけ起きる）、一覧で先のもの（ポート番号の小さい方。入力と出力なら入力）にだけ番号を残す（`initialNumbers`）。
- ポートを別の番号に移すと、前の番号は NC になる。ピン数を減らすと、超えた番号のポートは割り当てなしになり、一覧の下に出る。
- メイン回路も dip / qfp にしてピンを割り当てられる。ピンはどこにもつながらない。外側のピンに出せないポートの警告（ステータスバーの警告と、ポートの印）は、メイン回路では出さない（`findUnexposedPortsToWarn`。開発者が決めた）。

## ステータスバーのヒント

- ヒントは `hints/hints.ts` の `statusHints` が状況から選ぶ。文は文言の表（`i18n/ja.ts` の `hints`）にあり、部品ごとの文は部品の種類の `view.ts` の `hints` にある。
- ヒントは短い文に分け、時間で順に切り替える（文が長いほど長く出す）。ステータスバーにポインターを載せている間は止める。
- 1 文だけになるのは、ドラッグ中（配線の端のドラッグ中を含む）、貼り付け中、配線中、配線モード、分割モード、名前の編集中、配線だけを 1 本選んでいるとき、発振中、出力のぶつかり、ピンに出ていないポートがあるとき（あとの 3 つは何も選んでいないとき）。シートの外の警告では、ヒントは変えない。
- 回そうとしてシートからはみ出したときは、オレンジの `Badge` で「はみ出すため回転できません」を 3 秒出す（[画面操作](interaction.md)の「回転」）。時間で消える。回路の問題は、ステータスバーではなく問題パネルに出す（下の「問題パネル」）。
- 回路の中に、外側のピンに出せないポート（ピン番号がない・範囲外・重なり）があるときは、そのポートの上のポート番号を赤くして「?」を添え（例: `入力 2 ?`）、本体の輪郭を赤い破線にする（選んでいる間は、選択の色の破線）。そのポートを選ぶと、ヒントの先頭に理由を出す。
- 何も選んでいないときのヒントは、開いている回路で変える（`hints/hints.ts` の `inMain` と `numberedPackage`）。
  - メイン回路以外のタブでは、タブの改名と並べ替え、ポートを置くとピンが増えること、メイン回路のシミュレーションが止まることを先に出す。
  - どの回路でも、回路設定のヒントを出す。
  - パッケージで変える。`dip` / `qfp` は置いたポートが空いているピンに割り当てられること（メイン回路でも出す）。`split` は並び順の注意（外側の配線のことなので、メイン回路では出さない）。
- 分かりにくい操作や仕様に気付いたら、ステータスバーのヒントに足す。機能を足したり変えたりしたときも、ヒントが要るか考える。(開発者からの指示)

## 問題パネル

[計画 23](../plans/problems-panel/plan.md)で作った。

- ステータスバーの右端に「問題」（`ProblemsToggle`）を置き、押すたびに、シートとステータスバーの間にパネルを開閉する（開発者が決めた、2026-10-23。はじめはシートとステータスバーの間にタブの列を置いていたが、ステータスバーに移した）。開くとシートの下に収まり、その分シートが縮む（シートの上には重ねない。開発者が決めた）。開いている間は、「問題」の背景を `bg.muted` にする。
- パネルの上にタブバー（Chakra の `Tabs`、`line`）を置き、今は「問題」のタブだけを出す。タブにも問題の数を出す。同じ位置に出すパネルが増えたら、タブを足す（開発者が決めた、2026-10-23）。一覧だけがスクロールし、タブバーは動かない。
- タブバーの右端に閉じるボタン（Chakra の `CloseButton`）を置く。「問題」を押しても閉じられるが、パネルの中からも閉じられるように（開発者が決めた、2026-10-23）。
- 「問題」には、エラーと警告のアイコン（`assets/icons/error.svg`、`warning.svg`）と、それぞれの行の数を出す。色は、エラーがあれば赤、警告だけならオレンジ、0 なら灰色。ステータスバー（`sameStatus`）は、数と開いているかで比べる。
- 出すのは、今のタブの回路の問題だけ（`problems/problems.ts` の `collectProblems`）。ほかのタブや、開いていない回路の問題は出さない（開発者が決めた）。エラーを先に並べる。
  - エラー: 発振しています、出力がぶつかっています。警告: ピンに出ていない INPUT / OUTPUT があります（メイン回路では出さない）、シートの外に部品か配線があります。
  - 行には、種類のアイコン、文、か所の数を出す。発振は、どの部品が発振しているか分からないので、か所の数を出さず、押せない（開発者が決めた）。
- 行を押すと、元になっている部品と配線を選ぶ（出力のぶつかりは、ぶつかっている出力の部品とそのネットの配線）。選んだものが画面の外にあれば、映るように表示を動かす（`geometry/view.ts` の `revealView`。倍率は収まらないときだけ下げる。シートの外のものも映せるよう、シートの外が映るのは構わない）。
- 高さは、パネルの上の端の取っ手（`role="separator"`）をドラッグするか、取っ手にフォーカスして上下の矢印キーで変える。72px（タブバーと 1 行）から画面の高さの 6 割まで。取っ手をダブルクリックすると、既定の高さ（140px）に戻す（開発者が決めた、2026-10-23）。ドラッグ中は保存せず、離したときに保存する。開いているかと高さは localStorage に覚える（[保存データ](persistence.md)の表）。
- 問題の一覧は、回路が変わるたびに（部品のドラッグの一歩ごとにも）作り直すので、パネルは中身で比べて、変わらなければ描き直さない（`samePanel`）。

## 触ったら確かめること

ヘッドレスブラウザ（Skill の `browser-check`）で確かめる。

ヘッダー、タブバー、シートのツールバーのボタン（`ToolButton.tsx`）を触ったら:

- 広い画面では、ボタンにアイコンと文字が出る。
- 狭い画面（`md` 未満。例: 幅 600px）では、アイコンだけになり、並びが崩れない。
- 押せないボタン（元に戻す・やり直しなど）が薄く出る。
- 選択モード・配線モード・分割モードのボタンは、今のモードのものに地の色が付く。`V` / `W` / `S` で切り替えても、ボタンの表示が合う。
- メイン回路以外を開いているとき、「回路を削除」が赤で出る。

ダイアログ（`*Dialog.tsx`）を触ったら:

- 開いたときのフォーカスが、上の表のとおり。
- Esc と外側のクリックで閉じる。開いている間は Ctrl+Z などのショートカットが効かない。
- 回路の追加: すでにある名前ではエラーが出て確定できない。Enter で確定すると、回路ができて開く。
- 回路の削除の確認: `alertdialog` で、確定ボタンが赤い。キャンセルでは消えず、確定で消える。
- 書き出し: 押すとすぐ保存の画面が出て（Chromium）、`project-YYYY-MM-DD.sazanka.json` が保存される。取り消しても何も起きない。Firefox と Safari ではダウンロードになる。
- 読み込み: 押すとすぐファイルを選ぶ画面が出る。プロジェクトファイルを選ぶと置き換わり、元に戻す・やり直しの履歴が消える。読めないファイル、プロジェクトファイルでないもの、回路ファイルでは、理由のお知らせが出て、今のプロジェクトは変わらない。取り消しても何も起きない。
- 環境設定: シミュレーションの速さが範囲外ならエラーの文が出て、使える値は反映される。方眼の表示の切り替えがシートに効く。色見本でアクセントカラーが変わる。言語の切り替えは[文言と表示言語](i18n.md)の「触ったら確かめること」。
- 回路設定: メイン回路でもほかの回路でもボタンが出て、タブを切り替えても位置が動かない（メイン回路では「回路を削除」が出ず、場所は空く）。開くと「全般」のタブで、幅の欄にフォーカスがあり、変えていなければ「適用」が押せない。split の回路で INPUT を上下に動かしてから「上から順に番号を振り直す」を押すと、行とプレビューのピンの順が位置の順になり、配線の注意が出る（メイン回路では出ない）。使えない値のあるタブに赤い丸が付き、ほかのタブに切り替えても残る。
  - シートの大きさ: 20 未満や空欄では範囲のエラー、部品より小さくすると「a × b マス以上」のエラーが出て適用できない。a × b にすると適用でき、シートの外の色が変わる。再読み込みと書き出しのあとも大きさが残る。
  - パッケージ: split から DIP にすると上から順に番号が付き、プレビューが変わる。ピン数が使えない値ならエラーが出て適用できない。メイン回路を DIP にすると、置いたポートにピン番号が付く。
  - ポートの名前: 変えるとプレビューと選択肢に出て、配線の注意は出ない。同じ名前ではエラーが出て適用できない。
  - 作者名: 入れて適用すると、書き出したファイルの `author` に入る。空にすると空文字になる。
  - 作者名、シート、パッケージ、名前をまとめて変えて適用すると、元に戻す 1 回ですべて戻る。
  - 128 ピンでも、打つ・選ぶたびに重くならない。
- 狭い画面（例: 幅 400px）でも、ダイアログが画面に収まる。

パレット（`Palette.tsx`）を触ったら:

- グループの見出しで、そのグループだけが折り畳まれる。「すべて折りたたむ」「すべて展開」が効き、ボタンの名前が入れ替わる。折り畳みは再読み込みしても残る。
- 部品のボタンのクリックで、部品が置かれる。シートへのドラッグ（HTML のドラッグ＆ドロップ）でも置ける（再現の仕方は[ブラウザでの動作確認](browser-check.md)）。

削除エリア（`TrashZone.tsx`）を触ったら:

- ふだんは丸いアイコンだけで、ズームの上にあり、重ならない。
- 部品をドラッグし始めると、丸の下に「削除」と出る。丸の位置と大きさは変わらない。上に載せると赤くなり、離すと部品が消えて元の丸に戻る。元に戻すで部品が戻る。
- エリアの外で離すと、部品は消えずに動く。エリアの上から押してドラッグしても、範囲選択が始まらない。
- 狭い画面（例: 幅 400px）でも画面に収まる。

プロパティ欄（`PropertyPanel.tsx`）を触ったら:

- 部品を選ぶと種類と項目が出る。何も選んでいないときは案内の文が出る。
- CLOCK の周期: 範囲外の値ではエラーの文が出る。使える値は反映され、秒の説明も変わる。
- INPUT / OUTPUT のポート名: 入れると、シートの部品に出る。
- 狭い画面（例: 幅 600px）では部品を選んでいる間だけ出る。`md` 以上（例: 幅 800px）では、選んでいなくても出る。

ツールチップ（`HintTooltip.tsx` と、それを使うボタン）を触ったら:

- ヘッダー、シートのツールバー、ズームのボタンに説明が出る。押せないボタン（例: 履歴がないときのやり直し）にも出る。
- パレットの部品には説明が出る。置けないモジュール（例: そのモジュール自身を開いているとき）は押せず、置けない理由が出る。パレットの下の方の部品は、スクロールして見える位置に出してから試す。
- メイン回路以外のタブには操作の説明が出て、メイン回路のタブには出ない。

ステータスバー（`StatusBar.tsx`）、問題パネル（`ProblemsPanel.tsx`）、ズーム（`ZoomControls.tsx`）を触ったら:

- ヒントは時間で切り替わり、ポインターを載せている間は止まる。1 文だけの状態では切り替わらないので、何もない回路で試す。
- 発振する回路（NOT の出力を自分の入力へつなぐ）では、問題パネルに「発振しています」が出て、ステータスバーの「問題」の数が赤くなる。行は押せない。
- 2 つの INPUT の出力ピンを配線でつなぐと、問題パネルに「出力がぶつかっています」が出て、その配線が赤くなる。行を押すと、2 つの INPUT と配線が選ばれる。
- dip の回路の中で、2 つの INPUT に同じピン番号を付ける（保存データに直接書く）と、問題パネルに「ピンに出ていない INPUT / OUTPUT があります」が出て、その 2 つのポート番号が赤くなって「?」が付き、本体の輪郭が赤い破線になる。
- 座標が負の配線の点がある回路（保存データに直接書く）を開くと、問題パネルに「シートの外に部品か配線があります」が出る。ほかの回路のタブでは出ない。行を押すと、その配線が選ばれ、画面の外にあれば映るように表示が動く。
- 問題パネルは、ステータスバーの「問題」と右上の × で開閉でき、開くとシートが縮む。取っ手のドラッグと矢印キーで高さが変わり、再読み込みのあとも開閉と高さが残る。問題がなければ「問題はありません」と出て、「問題」の数は灰色の 0。
- 拡大・縮小で倍率が変わり、倍率のボタンで 100% に戻る。ボタンを押しても範囲選択が始まらない。狭い画面でもボタンが画面に収まる。
