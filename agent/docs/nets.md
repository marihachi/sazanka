# つながり

配線と部品のピンが、どうつながるか（ネット）の決まり。保存データの形式では決めず、アプリが決める。値がネットをどう伝わるかは[シミュレーション](simulation.md)、配線の編集（分割、結合）は[編集と元に戻す](editing.md)と[画面操作](interaction.md)にある。

## 決まり

- 配線の端が、ほかの配線の上（端、折れる点、途中のどこでも）にあれば、つながる。途中にあるときは、そこから分岐している。
- 配線の途中どうしが交わるだけ（どちらの端でもない点で交わる）なら、つながらない。
- 部品のピンの先（位置は、部品の配置で決まる。[部品の種類](parts.md)の「配置」と、形式の文書の「ピンの先の位置」）が、配線の上（端、折れる点、途中のどこでも）にあれば、つながる。配線の途中に接するときは、配線の両側とピンの 3 本が集まる点なので、分岐の印を描く（開発者からの指示）。
- 部品のピンの先どうしが同じ点にあれば、配線がなくてもつながる。3 つ以上重なっても同じ。部品をぴったり重ねて置くと、ピンの先がすべて重なり、出力どうしもつながってぶつかる（それでよいとした。開発者からの指示。[計画 30](../plans/pin-to-pin/plan.md)）。
- どのポートにもつながらないピン（NC）は、何ともつながらない。
- つながった配線とピンのまとまりを「ネット」と呼ぶ。ネットの中の入力ピンは、ネットの中の出力ピンの値になる。出力ピンがないネットと、出力ピンが 2 つ以上ある（ぶつかっている）ネットの入力ピンは OFF（[シミュレーション](simulation.md)）。

## コード

- ネットを作るのは `geometry/net.ts` の `computeNets`。配線を、端の位置でまとめてネットにし、配線の上（端か途中）にあるピンの先のピンを入れる。そのあと、配線の通らない点で、ピンの先が 2 つ以上重なっていれば、配線のないネット（`wires` が空）を作る。何ともつながっていないピンは、どのネットにも入らない。
- 分岐の印は、配線の端のある点と、配線の上にあるピンの先の点で、集まる線の数（配線の端は 1 本、配線の途中は 2 本、ピンは 1 本）が 3 以上なら描く。
- 出力どうしがぶつかっているネットのピンは `Nets.conflictPins`（`conflictPinKey`）に入れる。シートは、そのピンの線を赤く描く（`SheetPart.tsx` の `PinLead` の `conflict`。配線の赤と同じ色）。ピンどうしがつながっている所に、分岐の印のような印は付けない（ピンの線が端どうしで接して見えるため。開発者からの指示）。
- 点が配線の上にあるかは `isOnWire`（線分ごとに `onSegment`）。
- シミュレーションは、ネットから「入力ピン → それを動かす出力ピン」のつながり（`netLinks`）を作って使う（`simulation/flatten.ts`）。問題パネル（`problems/problems.ts`）とシートの描画（`sheet/Sheet.tsx`。分岐の印とぶつかりの色）も、ネットを見る。
- 保存データの形式の文書（`docs/format/`）は、配線の点とピンの先の位置（どの座標を指すか）までを決める。つながり方を変えても、データの形は変わらない（開発者からの指示）。

## 触ると壊れるもの

- つながり方を変えると、保存した回路の動きが変わる（同じデータで、つながる所が変わる）。変えるときは、今までの回路でつながりが変わる所がないか、変わってよいかを開発者に確かめる。
