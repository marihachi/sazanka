## 目的

メイン回路を「外側のピンがどこにもつながっていないモジュール」として扱い、メイン回路とモジュールを分けて扱う所を減らす。

解きたい課題: メイン回路のポート（INPUT / OUTPUT）も、名前とポート番号を持つ。ところが、モジュール設定（ポートの名前、パッケージ、ピンの割り当て）はモジュールでしか開けず、メイン回路のポートはプロパティ欄で 1 つずつしか触れない。ポート番号を変える操作（[split のピンの順をポート番号の順にする](../split-pin-order/plan.md)の計画で足す）も、メイン回路で使えない。

あわせて、シート設定（シートの大きさ）とモジュール設定を、1 つの「回路設定」のダイアログにまとめる（開発者が決めた、2026-10-17）。メイン回路とモジュールで、同じ 1 つの設定を開くようにする。

形式の変更（メイン回路にパッケージを持たせる）は [保存データをプロジェクトと回路に分ける](../project-format/plan.md)（計画 19。もとは計画 17 の version 5 だったが、2026-10-17 に 19 にまとめた）にある。この計画は、その上で画面と操作を揃える。進める順は 19 → 18（この計画）→ 16。

## 前提

- メイン回路は、ほかの回路に部品として置かれない。シミュレーションは、もともと開いている回路をいちばん外側として動かす（メイン回路もモジュールも同じ）。
- 今メイン回路を分けて扱っている所:
  - シートのツールバー（`app/App.tsx`）: メイン回路では「モジュール設定」と「モジュールを削除」を出さない。
  - ヒント（`hints/hints.ts` の `inModule`）: メイン回路では、モジュールのヒント（タブの改名と並べ替え、ポートを置くとピンが増えること、モジュール設定のこと、パッケージごとのヒント）を出さない。
  - タブ（`modules/TabBar.tsx`）: メイン回路は先頭に固定で、改名と並べ替えができない。
  - パレット（`modules/useModules.ts`）: メイン回路は出さない。
  - 削除（`useModules.ts`）、並べ替え（`project.ts` の `moveCircuit`）: メイン回路は対象外。
  - 表示名（`i18n/messages.ts` の `getCircuitName`）: メイン回路は表示言語の名前（「メイン」/「Main」）。
  - 置いたポートへのピン番号（`circuit/module.ts` の `assignPinNumbers`）: パッケージのない回路（メイン回路）は split と同じに扱う。新しい形式（計画 19）でメイン回路がパッケージを持てば、そのまま揃う。

## 決めたこと

開発者が決めたこと（2026-10-17）。

- メイン回路を「外側のピンがどこにもつながっていないモジュール」とみなす。
- メイン回路は、今までどおりほかの回路に置けない。
- メイン回路にもパッケージを持たせる（形式は計画 19）。
- 残す違い: メイン回路は先頭のタブに固定で、削除・改名・並べ替えができず、パレットに出ない。いちばん外側の回路という性質のため。
  - タブの扱いは、あとで[計画 21](../project-panel/plan.md)のプロジェクトパネルで変わる（タブは開いている回路だけを並べ、メイン回路のタブも閉じられる）。この計画では、今のタブのままにする。
- シート設定とモジュール設定を、1 つの「回路設定」のダイアログにまとめる。ツールバーのボタンも 1 つにする。メイン回路でもモジュールでも同じものを開く。
  - 採らなかった案: メイン回路でも「モジュール設定」のまま開く。どちらも「回路設定」に改名する（2 つのダイアログのまま）。メイン回路のタブでだけ「回路設定」と出す。
- 回路設定のダイアログの作り（2026-10-17）:
  - 並べ方: 1 枚の画面に、今のモジュール設定の並び（左に設定、右にプレビュー）のまま、左の設定のいちばん上に「シート」の欄（幅と高さ）を足す。その下に今までどおり、パッケージ、ポート、ピンの割り当てを並べる。採らなかった案: ダイアログの中にタブを 2 つ置く。
    - レビューで変えた（2026-10-21、開発者が決めた）: ダイアログの中を「基本」と「ポート」の 2 つのタブに分ける。基本は作者名とシートの大きさ、ポートはパッケージ（形の種類とピン数）、ポートの名前、ピンの割り当て。プレビューはポートのタブにだけ出す。採らなかった案: パッケージを基本に置く。プレビューを両方のタブに出す。
    - エージェントが決めたこと: 開いたときは基本のタブ（フォーカスは幅の欄のまま）。使えない値があるタブの見出しに赤い丸を付ける（ほかのタブからでも「適用」を押せない理由が分かるように）。英語のタブ名は General / Ports。ポートの一覧の見出しは、タブ名と重ならないよう「ポートの名前」（Port names）にした。
    - 確かめたこと: ブラウザで、幅 1280 と 500 で、タブの切り替え、ほかのタブの使えない値の印、タブをまたいだ変更をまとめて適用できること、タブでダイアログの大きさが変わらないこと。128 ピンの QFP で開くのが 6.3 秒から 3.0 秒に（CPU を 4 倍遅くして。ポートのタブの中身を開いたときに描かないため）、名前の入力と割り当ての変更は同じくらい。
  - 適用: 「適用」を 1 つにし、シートの大きさとポートとピンの変更を、まとめて 1 回の編集にする（元に戻す 1 回で戻る）。どこかに使えない値があれば（シートが範囲外・部品が収まらない、ピン数が使えない、ポートの名前が重なる）、押せない。エラーはそれぞれの欄の下に出す。採らなかった案: シートとポートとピンで、適用を分ける。
  - ツールバーのボタン: 文言は「回路設定」（英語は「Circuit settings」）、ツールチップは「回路設定: シートの大きさ、パッケージ、ポートの名前、ピンの割り当てを変える」、アイコンは今のモジュール設定のもの（`package.svg`）。ツールバーの右側に置き、「モジュールを削除」はその右に置く。メイン回路とモジュールを切り替えても「回路設定」の位置が変わらないようにする（メイン回路では「モジュールを削除」を出さないが、その分の場所は空けておく）。採らなかった案: アイコンを歯車（`preferences.svg`）にする。
  - 開いたときのフォーカス: 幅の欄（今のシート設定と同じ）。採らなかった案: 「キャンセル」。
- ファイルの名前と置き場所（2026-10-17）: 回路設定のダイアログは `modules/CircuitSettingsDialog.tsx` に置き、今の `modules/ModuleSettingsDialog.tsx` と `sheet/SheetSettingsDialog.tsx` は消す。シートの幅と高さの欄と、その検証の表示は `sheet/SheetSizeFields.tsx` に分けて、回路設定から使う（シートの大きさの決まりは `sheet/` の責務のため。`modules` → `sheet` の向きは今の依存の向きのとおり）。
  - 採らなかった案: `sheet/` に置く（モジュールのパッケージとピンの割り当てが `sheet/` に入る）。名前の候補 `CircuitDialog.tsx`、`CircuitSettings.tsx`。
- 用語（2026-10-17 に決めたが、2026-10-20 の用語の変更で置き換わった）: 定義は「回路」、置いたものは「モジュール」と呼ぶ（[用語](../../docs/glossary.md)）。メイン回路は特別な回路。画面の言葉は段階 3 でそろえる。
  - もとの決めごと: 「モジュール」の意味は変えず、メイン回路を「モジュールと同じ設定を持つが、ほかの回路に置けない回路」と書く。採らなかった案: メイン回路もモジュールの 1 つと呼ぶ。

- 回路設定に「作者名」の欄を足す（2026-10-17。作者名をモジュールごとに持つと、[計画 19](../project-format/plan.md)で決めた）。メイン回路でも入れられる。欄は、ダイアログの左のいちばん上（シートの欄の上）に置き、文言は「作者名（省略可）」（英語: Author (optional)）（2026-10-18）。空のままなら、保存データの `author` は空文字になる（計画 19 で必須にした）。回路設定で当てはめるときは、作者名、パッケージ、シートの大きさ、フォルダのパスなど、保存データで省略できない項目をなくさない（欄を空にしても空文字を持たせ、変えない項目は残す。[保存データ](../../docs/persistence.md)の「形式を変えるとき」）。名前のように回路そのものについての項目なので、先頭に置く。

- ピンに出ていないポートの警告（「ピンに出ていない INPUT / OUTPUT があります」、ポート番号の赤い「?」、本体の赤い破線）は、メイン回路では出さない（2026-10-18）。メイン回路のピンはどこにもつながらず、割り当てていなくても困らないため。必要になったら足す。この警告は、いずれ[問題パネル](../problems-panel/plan.md)（計画 23）に出す。
  - 採らなかった案: モジュールと同じく出す。

## エージェントが決めること（案）

- ヒント: メイン回路でも出すのは、パッケージごとのヒント（split の並び、dip / qfp の割り当て）と、モジュール設定のヒント。出さないのは、タブの改名と並べ替え、「モジュールのタブを開いている間は、メイン回路のシミュレーションは止まる」。ポートを置くとピンが増える、のヒントは、メイン回路ではピンがどこにもつながらないので出さない。`inModule` を、出すヒントごとの条件に分ける。
- 型: `CircuitDef.package` を省略できない型にするか（今は「メイン回路が持たないため」省略できる）。計画 19 で、メイン回路も必ず持つようになれば、省略できない型にする。テストでモジュールを手短に作るために省略できるようにしている点は、テスト用の作り方の関数で補う。
