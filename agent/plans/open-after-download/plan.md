# 保存してから開くと、保存とファイルを選ぶ画面が同時に出る（計画 27）

- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

「開く…」の前の確認で「保存してから続ける」を選んだとき、ダウンロードで保存するブラウザ（Firefox、Safari、Electron の中のブラウザ）でも、保存とファイルを選ぶ画面が 1 つずつ出るようにする。不具合修正。

開発者が見つけた（2026-10-24）。

## 再現の手順

1. ダウンロードで保存するブラウザで開き、回路を編集する（ファイルに保存していない変更がある状態にする）。
2. 「ファイル」のメニューの「開く…」を選ぶ。
3. 確認で「保存してから続ける」を選ぶ。
4. ダウンロード（保存先を聞く設定なら、その画面）と、ファイルを選ぶ画面が同時に始まる。

ヘッドレスの Chrome で、`showSaveFilePicker` を消してから試し、ダウンロードが始まると同時にファイルを選ぶ画面が開くことを確かめた（2026-10-24）。

## 原因

`file/useProjectFile.ts` の `pickAfterLeaving`:

- クリックの効力（`navigator.userActivation.isActive`）が残っていれば、すぐにファイルを選ぶ画面を開く。残っていなければ、「保存しました。開くファイルを選んでください。」の確認を出し、押してもらってから開く。
- Chrome と Edge では、保存の画面（`showSaveFilePicker`）が効力を使い切るので、確認が挟まる。
- ダウンロード（`<a download>`）は効力を使い切らないので、確認が挟まらずに、ファイルを選ぶ画面がすぐに開く。

## 直し方

「保存してから続ける」で保存したあとは、ブラウザによらず、必ず確認を出してからファイルを選ぶ画面を開く（案 A。開発者が決めた、2026-10-24）。

- 確認を出すかを、クリックの効力ではなく、保存したかで決める。どのブラウザでも同じ順番になる。
- Chrome と Edge の動きは変わらない（今も確認が出ている）。
- 「保存しない」のあとは、今までどおり、すぐにファイルを選ぶ画面を開く。
- 新規作成の前の確認は変えない（保存のあとに開く画面がないため）。

採らなかった案:

- ダウンロードが終わるのを待ってから開く: ダウンロードが終わったかはページから分からない。待つ間にクリックの効力も切れる。
- ダウンロードで保存するブラウザでは「保存してから続ける」を出さない: 保存してから開くことができなくなる。

## 決めたこと

- 確認の文言は、ダウンロードで保存したときも、今の「保存しました。開くファイルを選んでください。」のままにする（開発者が決めた、2026-10-24）。ダウンロードで保存するブラウザでは、利用者がダウンロードを取り消したかをアプリは知れないが、Chrome と Edge と同じ文言にそろい、ほとんどのブラウザの既定では保存先を聞かずに保存されるため。
  - 採らなかった案: ダウンロードで保存したときだけ「ダウンロードしました。開くファイルを選んでください。」にする（文言を 1 つ足す）。

## 段階

1. 直す。`useProjectFile.ts` で、「保存してから続ける」で保存できたあとは、必ず確認を出す。[UI](../../docs/ui.md) の「開く前と新規作成の前の確認」と「触ったら確かめること」を直す（操作マニュアルには、この流れを書いていないので直さない）。
   - 確かめること: 整形、Lint、型、テスト、ブラウザで次の 3 つ。
     - ダウンロードで保存するとき（`showSaveFilePicker` を消す）: 確認が出るまで、ファイルを選ぶ画面が開かない。確認の「ファイルを選ぶ」で開き、選んだファイルを開ける。
     - 保存の画面を使うとき（偽物の `showSaveFilePicker`）: 今までどおり、確認が出てから開く。取り消したら続けない。
     - 「保存しない」: すぐにファイルを選ぶ画面が開く。

実装は Skill の `modify` で進める。
