# 部品と配線の回転（計画）

状態: **完了**（2026-10-14 に開発者のレビューを終えた）

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

選んだ部品と配線を、`R` キーで 90 度ずつ回せるようにする。

解きたい課題: 今は部品の向きが種類ごとに決まっている（入力は左、出力は右など）。そのため、上下につなぐ回路や、右から左へ流れる回路を描くと、配線が遠回りになる。

## 前提

- ピンの座標は、どこも種類の配置（`parts/layouts.ts` の `getLayout` が返す `PartLayout`）から作る。シート上の座標に直すのは `geometry/layout.ts`。ネット（`geometry/net.ts`）、展開（`simulation/flatten.ts`）、当たり判定、はみ出しの判定、範囲選択は、どれもこの配置を使う。
  - 配置そのものを回した形にすれば、つながりとシミュレーションは手を入れずに回転に追従する。
- 配置の長さはマス単位の整数で、ピンの先はグリッドに乗る。グリッドの点を中心に 90 度回すと、グリッドの点はグリッドの点に移る。
- 部品の位置（`Part.x` / `Part.y`）は本体の左上。
- 保存データの version 4 は公開済み（2026-10-13）。公開後も、省略できる項目を足すだけなら版を上げない（[保存データ](../../docs/persistence.md)の「形式を変えるとき」）。
- 保存の形との変換（`file/storage.ts` の `toStoredProject` / `fromStoredProject`）は、部品の項目をそのまま通す。項目を足しても変換は直さなくてよい。検証（`circuit/part.ts` の `isPart`）は足す必要がある。
- 本体の中の描き込みとピン名は、`sheet/SheetPart.tsx` が描く。ピン名（`PinName`）は 4 辺のどれにも書ける。
- 部品のドラッグ中は、元に戻す・やり直しを受け付けない（[編集と元に戻す](../../docs/editing.md)）。
- パレットからのドラッグは、ブラウザのドラッグ＆ドロップを使う。ドラッグ中はキーのイベントが届かない。

## 回し方（案）

- 配置を時計回りに 90 度回すと、幅と高さが入れ替わる（`w' = h`、`h' = w`）。ピンの辺と位置は次のように移る（本体の中の点 (x, y) は (h − y, x) に移るため）。

| 回す前の辺 | 回した後の辺 | 回した後の位置 `at` |
| ---------- | ------------ | ------------------- |
| `left`     | `top`        | `h − at`            |
| `top`      | `right`      | `at`                |
| `right`    | `bottom`     | `h − at`            |
| `bottom`   | `left`       | `at`                |

- `h` は回す前の高さ。180 度と 270 度は、これを 2 回、3 回くり返す。
- 回した配置を返す関数（仮の名前は `rotateLayout`）は `parts/layout.ts` に置く。`geometry/layout.ts` は、部品の配置を引くところ（今の `getLayout(c.kind, pinout)`）を、部品の向きを通した配置にする。

## 気になるところ

- 本体の上に書くもの（モジュール名の `nameAbove`、INPUT / OUTPUT のポート番号）も一緒に回り、回した後は横か下に来る。部品の占める範囲（`calcMarginAroundBody`）も、名前の 1 マスを回した辺で取る。
- 回す中心をグリッドに合わせるとき、いつも同じ向きに寄せると、4 回回しても元の位置に戻らず、回すたびにずれていく（AND 1 つで、4 回ごとに 2 マス）。段階 2 で、寄せる向きを決めてずれないようにした（「エージェントが決めたこと」）。
- 回すと、つながっていた配線と部品のピンの位置がずれることがある（部品だけを選んで回したとき）。部品を動かしたときと同じく、つながりは切れる。配線はついてこない（[編集と元に戻す](../../docs/editing.md)の「開発者からの指示」）。
- 古いアプリ（回転を知らない版）は、もう公開されていないので考えない。

## 段階

各段階で、`npm run format`、`npm run lint`、`npx tsc -b`、`npm test`、`npx vite build` を通す。

1. データと座標
   - `Part` に向きの項目を足す。検証（`isPart`）に足す。
   - 配置を回す関数を作り、`geometry/layout.ts` の配置を引くところをすべて通す。
   - 形式の文書（`docs/format/v4.md`）の「部品」の表と、「version 4 の中で変えたもの」に書き足す。
   - テスト: 配置を回したときの大きさとピンの辺・位置、4 回で元に戻ること、回した部品のピンの先とネットのつながり、検証が向きの値を受け付けて、おかしな値を断ること。
   - 確かめること: 保存データの読み書きで向きが残る。向きを書かない古いデータがそのまま読める。
2. 編集
   - `editing/edit.ts` に、選んだ部品と配線をまとめて回す関数を作る（中心の求め方とはみ出しの扱いは「決めたこと」）。
   - テスト: 部品だけ、配線だけ、両方を回したときの位置と点、4 回回したときの戻り方、はみ出すときに回さないこと。
3. 画面
   - `R`（と `Shift+R`）を `editing/useShortcuts.ts` に足す。`App.tsx` で 1 回の `commit` にする。貼り付け中の回転は `editing/useClipboard.ts`。
   - ツールバーの「回転」ボタンとアイコン（「決めたこと」）。
   - `sheet/SheetPart.tsx` の描画（「決めたこと」の文字と図の描き方）。
   - 回せなかったときのバッジ（`hints/StatusBar.tsx`）。
   - ヒント（`hints/hints.ts`、文言の表）、日本語と英語の文言、操作マニュアル（`docs/manual/`）。
   - エージェント向けドキュメント: [画面操作](../../docs/interaction.md)のキーボードと選択、[部品の種類](../../docs/parts.md)の配置、[編集と元に戻す](../../docs/editing.md)の表。
   - 確かめること: ブラウザで、部品・配線・モジュール（dip / qfp / split）・7 セグメントを回し、つながりとシミュレーションが合うこと。元に戻す 1 回で戻ること。荒い操作（連打、ドラッグ中の `R`、貼り付け中の `R`）。`SheetPart.tsx` を変えるので、フレームレートも測る。

実装は Skill の `modify` で進める。

## 決めたこと

開発者が決めたこと。

- 回す向きとキー: `R` で時計回りに 90 度、`Shift+R` で反時計回りに 90 度。
  - 採らなかった案: `R` の時計回りだけ（3 回押せば反時計回りと同じ）。
- 複数を選んでいるとき: 選んだ部品と配線を 1 つのまとまりとし、その中心の回りに回す。中心はグリッドの点に合わせる。配線 1 本だけのときも、その中心の回りに回す。
  - 理由: 配線も回すので、部品ごとにその場で回すと、配線との形が崩れるため。
  - 採らなかった案: 部品はそれぞれその場で回し、配線は回さない（配線を回すという要望に合わない）。
- 回すとシートからはみ出すとき: 回さない（何も変えず、履歴にも積まない）。ステータスバーにバッジを出して知らせる。
  - 採らなかった案: まとまりごとシートの内側へずらす（`clampMove`）。何も知らせない。
  - バッジは、ほかのバッジ（シートの外の部品など）と違い、状態ではなく出来事を知らせるので、しばらくして消す。
  - 貼り付け中は、もともとポインターの位置からシートに収まるようにずらして置く（`geometry/layout.ts` の `placeOffset`）。回したあともその置き方のままにし、シートより大きくて収まらないときだけ回さない。
- 回せる場面: 選択中と、貼り付け中（ポインターについて動いている間）。
  - 部品のドラッグ中は受け付けない（元に戻すを受け付けないのと同じ理由）。
  - パレットからのドラッグ中は、キーが届かないので対象外。
  - 採らなかった案: 選択中だけ。
- スマホ向けのボタン: シートのツールバーに「回転」ボタン（時計回り）を足す。スマホにはキーボードがないため。
  - 採らなかった案: 足さない（キーだけ）。
- `R` が効くモード: 選択モードで何か選んでいるときと、貼り付け中だけ。配線モードと分割モードでは何もしない（どちらも選択を使わないため）。
- 回したあとの配線の結合: しない。移動と同じ扱い（[編集と元に戻す](../../docs/editing.md)の「結合」）。
- ツールバーのボタン: 文言は「回転」/「Rotate」、ツールチップは「回転 (R)」。アイコンは時計回りの矢印を自作する（[アイコンとロゴ](../../docs/icons.md)）。
- ヒント: 部品か配線を選んでいるときのヒントに「R で回転」（英語は「R to rotate」）を足す。
- 文字と図の描き方: 部品の描画（本体、ピン、ピン名、部品名、ポート名、ポート番号、描き込み）をまるごと回す。文字も一緒に回り、180 度では逆さに、90 度と 270 度では横倒しになる。見た目のとおりに回すことを優先する（開発者が決めた）。
  - 採らなかった案: 文字は横書きのまま、ピンとぶつからない位置へ動かし、図だけを回す（文字は読みやすいが、文字ごとに置き場所を決め直すことになる）。
- 保存データの項目名と値: `rotation`。時計回りの角度で `0` / `90` / `180` / `270`。`0` のときは書かない。
  - 採らなかった案: `rotate`（同じ値）、`facing`（`"east"` / `"south"` / `"west"` / `"north"`。部品が向く方位）。
- 回せなかったときのバッジ: オレンジのバッジ「はみ出すため回転できません」/「Can't rotate: off the sheet」を 3 秒出して消す。続けて押したら、そこから 3 秒に延ばす。
  - 採らなかった案: 次に何か操作するまで出し続ける。
- 決めなくてよいこと: プロパティ欄には向きを出さない。モジュール設定のプレビューは、回さない向きのまま描く。

## エージェントが決めたこと

段階 1:

- 向きの型 `Rotation`（`0 | 90 | 180 | 270`）と一覧 `ROTATIONS` は `parts/layout.ts` に置き、`circuit/part.ts` から import する。
  - 理由: 依存の向きが `circuit` → `parts` なので、配置を回す側（`parts`）に置くと逆向きの import が要らない。
  - 採らなかった案: `circuit/part.ts` に置く（`parts/layout.ts` から `circuit/` を import することになる）。
- 配置を回す関数は `rotateLayout(layout, rotation)`、辺を回す関数は `rotateSide(side, rotation)`（`parts/layout.ts`）。90 度ずつの回転（`turnLayout`）をくり返して求める。
  - 採らなかった案: 角度ごとに式を書き分ける（式が 3 つになり、テストで確かめる組み合わせが増える）。
- シート上の配置を引く入口を `geometry/layout.ts` の `getPartLayout(c, pinout)` にし、`bodySize`、`calcSheetPins`、`inputPinPos` / `outputPinPos`、`clampPosition`、`partBounds` をこれに替えた。`getLayout` は種類の配置（回していない向き）を引くだけにする。
- `nameAbove` は配置の中では回さず、回していない向きでの上を指したまま残す。`calcMarginAroundBody(layout, rotation)` が `rotateSide('top', rotation)` で名前の辺を求める。
  - 理由: 画面の描画は、回していない向きで描いてから全体を回す（「決めたこと」の文字と図の描き方）ので、そのときは回していない配置の `nameAbove` をそのまま使える。
  - 採らなかった案: 配置に「名前を書く辺」の項目を足す（種類の `layout.ts` すべてに関わる）。
- 部品の `rotation` は、0 のときは持たせない（保存データに書かないため）。検証は 0 も受け付ける。

段階 2:

- 回す関数は `editing/edit.ts` の `rotateParts(circuit, comps, wires, direction, pinoutOf, sheet?)`。向きは `TurnDirection`（`'cw'` / `'ccw'`）。はみ出して回せないときは `undefined` を返す。
  - ピンの割り当ては、`clampMove` などと同じく呼ぶ側から関数で受け取る（`edit.ts` はプロジェクトを知らないため）。
  - `sheet` を省くと、はみ出しを見ない。貼り付け中（段階 3）は、置く位置をあとで `placeOffset` で決めるので、省いて呼ぶ。
- 回す中心は、部品の本体と配線の点を囲む長方形の中心にする（`turnCenter`）。ピンの先や名前の分（`partBounds`）は入れない。
  - 理由: 本体と配線の点は回すと一緒に回るので、長方形の形が変わらない。`partBounds` は左右に必ず 1 マス取るなど、回しても形が保たれず、4 回回しても元に戻らない。
- 中心は、マス単位で x と y が両方整数か、両方 0.5 余るなら、そのまま使う（どちらでもグリッドの点はグリッドの点に移る）。片方だけ 0.5 余るときは、その座標を、中心の x + y が偶数になる側の整数に寄せる。
  - 理由: こうすると、4 回回したときと、時計回りの後に反時計回りにしたときに、寄せた分が打ち消し合って元の位置に戻る。どの寄せ方なら戻るかは、幅・高さ・位置を総当たりで試して確かめた（戻る決め方は、偶数にするものと奇数にするものの 2 つだけだった）。
  - 採らなかった案: いつも切り上げる（`snap`）。回すたびにずれていく。前回の中心を覚えておく。選択が変わるたびに覚え直す必要があり、状態が増える。

段階 3:

- 描画は、`SheetPart.tsx` で部品の向きを外して（`const { rotation = 0, ...c } = comp`）回していない向きで描き、全体を `<g transform>` で回す（`rotateTransform`）。描き込みとピン（`PinLeads` / `PinNames`）は回転を知らないので、`React.memo` の比べ方も変えずに済む。
- 回す操作は `App.tsx` の `rotate(direction)`。回せるかは `canRotate`（選択モードで選んでいるか、貼り付け中）で、ツールバーのボタンの押せる・押せないにも使う。
- 貼り付け中は `useClipboard.ts` の `rotatePlacing`。`rotateParts` をシートなしで呼び、回したものの範囲（`geometry/view.ts` の `circuitBounds`）がシートより大きいときだけ断る。`circuitBounds` は、貼り付けるもの（ID と名前のない回路）にも使えるよう、受け取る型を `CircuitDef` から `Circuit` に広げた。
- 回せなかったときのバッジは、`App.tsx` が 3 秒のタイマーで出し入れし（`showCannotRotate`）、`StatusBar` には出すかどうかだけを渡す。
  - 採らなかった案: `StatusBar` の中でタイマーを持つ（出来事を知らせる回数を props で渡すことになり、`sameStatus` の比べ方が分かりにくくなる）。
- ツールバーの「回転」は、モードのボタンの右に区切りを入れて置く（シミュレーションの操作の前）。編集の操作で、シミュレーションとは別のまとまりのため。
- ヒントの「R で回転」は、部品を選んだとき（`partSelected`）、複数を選んだとき（`multipleSelected`）、配線を 1 本選んだとき（`wireSelected`）、貼り付け中（`placing`）に足した。

- 段階 1（データと座標）: 終えた。
  - `Part.rotation`、検証、`rotateLayout`、`getPartLayout`、形式の文書（部品の表、ピンの先の位置、検証、version 4 の中で変えたもの）、エージェント向けドキュメント（部品の種類の「配置」、ソースの構成、用語）。
  - テスト: 配置の回転（4 回で戻る、2 回・3 回が 180 度・270 度と同じ、ピンが整数のマス）、回した部品のピンの先・大きさ・占める範囲・はみ出さない位置、回した部品のネットのつながり、検証、保存と読み込みで向きが残ること。
  - 画面の描画（`SheetPart.tsx`）はまだ回していない。向きを持つデータを読み込むと、本体の大きさとピンの位置だけが回り、描き込みは崩れて見える（段階 3 で直す）。
- 段階 2（編集）: 終えた。
  - `rotateParts`、`turnCenter`、[編集と元に戻す](../../docs/editing.md)の「回転」。
  - テスト: 部品 1 つ・配線 1 本の回り方、選んでいないものを変えないこと、つながる配線と一緒に回すとつながったままなこと、4 回で元に戻ること・時計回りと反時計回りが打ち消し合うこと（AND、INPUT、7 セグメント、部品と配線のまとまり）、はみ出すときに回さないこと。
- 段階 3（画面）: 終えた。
  - `R` / `Shift+R`、ツールバーの「回転」、貼り付け中の回転、部品の描画の回転、回せなかったときのバッジ、ヒント、日本語と英語の文言、アイコン（`assets/icons/rotate.svg`）、操作マニュアル、エージェント向けドキュメント（画面操作の「回転」、編集と元に戻すの表、UI、部品の種類）。
  - ブラウザで確かめたこと（開発用のサーバー）: 全部選んで `R` で回り、回した INPUT → OR → OUTPUT で信号が伝わる。元に戻す 1 回で戻る。`Shift+R` は反時計回り。ボタンは何も選んでいないときと配線モードで押せない。配線モードで `R` は効かない。すべての種類（モジュールは split / dip / qfp）を 4 つの向きで描き、ピンの先 108 個がすべてグリッドに乗る。はみ出すときは回らずバッジが出て、続けて押すと延び、3 秒で消える。ドラッグ中の `R` は効かず、元に戻す 1 回でドラッグ前に戻る。貼り付け中に回せ、シートより大きいものは回らずバッジが出る。30 回連打のあと 2 回足すと元の位置に戻り、再読み込みしても同じ。英語と、幅 600px・400px でボタンとバッジが収まり、ツールチップが出る。ページの例外とコンソールのエラーはなかった。
  - フレームレート（ビルドしたもの、CPU 4 倍遅く、CLOCK 15 個と AND 15 個）: 変える前と後で、待機中 60 fps、ドラッグ中 59 fps 前後で差はなかった（longtask の合計も 170〜340ms で、前後の幅が重なる）。回した部品が半分ある回路でも同じ。
  - 確かめていないこと: スマホの実機（タッチでのツールバーのボタン）。ビルドしたものでの操作の確認（フレームレートの計測だけビルドしたもので行った）。
