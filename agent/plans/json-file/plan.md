# 書き出しと読み込みの JSON ファイル（計画）

状態: **進行中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

ヘッダーの「書き出し」で共有用 JSON をファイルに保存し、「読み込み」でファイルから取り込めるようにする。

## 前提

- 書き出しは、共有用 JSON をダイアログ（`ui/TextDialog.tsx`）の欄に出し、「コピー」でクリップボードに入れるだけ（`file/useProjectFile.ts` の `exportProject`）。
- 読み込みは、貼り付けた文字列を `file/share.ts` の `parseProject` で検証して取り込む（`importProject`）。
- ファイルの中身は今の共有用 JSON と同じにする。形式は変わらないので、版は上げない（[保存データ](../../docs/persistence.md)の「形式を変えるとき」）。

## 決めたこと

開発者が決めたこと:

- 画面: 今の書き出し・読み込みのダイアログにファイルの操作を足す。文字列の欄とコピーは残す。
  - 採らなかった案: ファイルだけにする（貼り付けでの共有ができなくなる）。ヘッダーに別のボタンを足す（ボタンが増え、狭い画面で窮屈になる）。
- 書き出し: 「コピー」の横に「ファイルに保存」のボタンを並べる。
  - 採らなかった案: 読み込みと同じくラジオボタンで選ぶ（書き出しは選ぶものがなく、押すボタンを分ければ済む）。
- 読み込み: 「読み込み元」をラジオボタン（「ファイル」「テキスト」）で選び、ファイルなら「ファイルを選択」で選んでから「読み込む」を押す。確定のボタンは「読み込む」の 1 つだけにする。
  - 最初に選ばれているのは「ファイル」。
  - 開いたときは、選ばれているラジオボタンにフォーカスする。
  - ファイルのときは、選んだファイル名を横に出す。選んでいなければ「選択されていません」と出し、「読み込む」は押せない。テキストのときは、今の貼り付け欄を出す。
  - 読めなければ、今と同じくダイアログにエラーを出して閉じない。
  - 採らなかった案: 選んだらすぐに読み込む（ボタンが「読み込む」で終わるものが 2 つになり、違いが分かりにくい）。中身を貼り付け欄に入れる。
- 保存するファイル名: `sazanka-YYYY-MM-DD.json`（例: `sazanka-2026-10-11.json`。日付は端末の時刻）。
  - 採らなかった案: `sazanka-project.json`（何度も保存すると見分けにくい）。時刻まで付ける（長い）。
- ファイルのドラッグ＆ドロップでの読み込みは入れない。
- ファイルの保存と選択の処理は `src/file/localFile.ts` に置く。

エージェントが決めたこと:

- 保存は Blob を作り、`<a download>` で保存させる（`localFile.ts` の `saveJsonFile`。ファイル名は `getExportFileName`）。Blob の URL は、すぐに消すと保存が始まる前に消えるブラウザがあるので、10 秒待ってから消す。`showSaveFilePicker` は Chromium でしか動かないので使わない（特定の環境を前提にしないため）。
- 選択は `accept=".json,application/json"` のファイルの入力で、`File.text()` で読み、今の読み込みと同じ処理（`parseProject`）に渡す。先頭の BOM は外す。
- ブラウザ標準のファイルの入力は見せず、Chakra のボタンで作る（Chakra の `FileUpload` が使えれば使う。ライブラリは足さない）。標準の入力はボタンの文字がブラウザの言語で出て、表示言語と合わないため。
- `TextDialog` は回路を知らないままにする。書き出しの「ファイルに保存」は、`TextRequest` の `extraAction`（確定ボタンの左に並べるボタン。押すと今の文字列を渡し、閉じない）で足した。保存の失敗は知る手段がないので、エラーは出さない。読み込みのダイアログは作りが変わるので、`TextDialog` に足すか別のダイアログにするかは、実装のときに決めて書き足す。
- 書き出すファイルの中身は、作者名を反映した、欄と同じ文字列にする。

- JSON でないファイルや壊れたファイルのエラーは、貼り付けのときと同じ文（`errors.share`）を出す。

## 段階

1. 書き出しのファイル保存。ブラウザで、保存したファイルの中身が「コピー」の文字列と同じかを確かめる。
2. 読み込み元の切り替えとファイル選択。正しいファイル、壊れたファイル、JSON でないファイル、作者名入り（お知らせが出るか）で確かめ、元に戻すで戻ることも見る。日本語と英語、狭い画面（400px）も確かめる。
3. ドキュメント: [保存データ](../../docs/persistence.md)、[UI](../../docs/ui.md)（触ったら確かめること）、[ブラウザでの動作確認](../../docs/browser-check.md)（ヘッドレスでの保存と選択の確かめ方）、[ソースの構成](../../docs/structure.md)（`localFile.ts`）、[操作マニュアル](../../../docs/manual/README.md)。

## 進み具合

- ブランチ: `json-file`。
- 段階 1（書き出しのファイル保存）: 済み。日本語（幅 1280px）と英語（幅 400px）で、「ファイルに保存」で `sazanka-2026-10-11.json` が保存され、中身が欄の文字列（作者名入り）と同じこと、ダイアログが閉じないこと、ボタンの並び（閉じる / ファイルに保存 / コピー）が崩れないことを確かめた。
