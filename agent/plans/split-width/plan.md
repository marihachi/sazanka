# split のモジュールの幅を変えられるようにする（計画 29）

状態: **進行中**

- 前提: [計画 28](../gate-symbols/plan.md)（回路の形式 version 2 を作る計画）。計画 28 の PR が `format-next` にマージされてから始める。計画 28 のベースブランチが `format-next` なので、この計画のベースブランチも `format-next`（[作業の進め方](../../docs/workflow.md)の「ブランチ」）。
- 開始の合図を受けたら、段階の区切りで止めずに最後の段階まで進める。迷うことがあれば止めて聞く（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

パッケージが split（画面ではロジック）の回路を、モジュールとして置いたときの本体の幅を、回路ごとに変えられるようにする（今は 4 マスに決め打ち）。例: 3 にする、5 にする。

開発者が求めた（2026-10-25）。

## 決めたこと

以下は開発者と決めた（2026-10-25）。

- 計画 28 とは別の計画にし、計画 28 を前提にする。計画 28 で作る回路の形式 version 2 は公開前（作業中）なので、その version 2 に幅を足す（公開前の版は直してよい。[保存データ](../../docs/persistence.md)の「開発者からの指示」）。版をもう 1 つ上げずに済む。
  - 採らなかった案: 計画 28 に入れる（1 つの PR が大きくなる。見た目の変更とモジュールの設定は別の機能）。
- 幅を変えると、そのモジュールを置いてあるところでは出力のピンが左右に動く。出力のピンにつながっていた配線は、外れて残す（モジュールのピンを減らしたときと同じ扱い）。
  - 採らなかった案: 配線の端をピンに合わせて動かす（ほかの回路の中の配線まで書き換えることになる）。
- 幅は 2〜20 マスの整数。幅が狭いと、左右のピン名が四角の中で重なることがあるが、警告は出さない（利用者に任せる）。
- メイン回路も、split ならほかの回路と同じく幅を持ち、回路設定で変えられる（どこにも置かれないので見た目には効かないが、扱いをそろえる）。

### 名前と既定値

以下は開発者と決めた（2026-10-25）。

- 保存データの項目名は `width` で、パッケージ（`package`）の中に置く（例: `{ "kind": "split", "width": 4 }`。dip と qfp の `pins` と同じ置き方）。シートの大きさ（`sheet.width`）と同じ言い方で、単位もマス。
  - パッケージの中に置くのは、幅に意味があるのが split だけだから（dip は幅 3、qfp は正方形に決まっている）。形の種類ごとの項目は、`isPackage` で 1 か所で確かめられる。
  - 採らなかった案: `bodyWidth`（ほかに `body` の付く項目名がない）。
- 画面の文言: 入力欄の名前は、シートの大きさと同じ「幅 (マス)」（英語: Width (cells)）。範囲外のときのエラーは「幅は 2〜20 の整数で入力してください」（英語: Enter a whole number from 2 to 20 for the width.）。
- 新しく作る split の回路と、v1 から変換した split の回路の幅は、どちらも 4（今と同じ見た目のまま）。

## 今のコードと、変えるところ

- 型: `circuit/project.ts` の `Package` の split は `{ kind: 'split' }` で、幅を持たない。検証は同じファイルの `isPackage`。
- 配置: `parts/module/layout.ts` の `makeSplitLayout` が幅 4 に決め打ちしている。出力のピンの先は (`x` + 5, …)。幅を受け取り、出力のピンの先を (`x` + 幅 + 1, …) にする。
- split を作る所: 空のプロジェクト（`project.ts`）、回路の追加（`circuits/useCircuits.ts`）、パッケージを持たない回路の既定（`circuit/module.ts`、`file/storage.ts`、`circuits/CircuitSettingsDialog.tsx`）、一体の形式からの変換（`file/upgrade/circuit/v1.ts`、`file/upgrade/integrated/upgradeV2.ts`）。幅を必ず持たせる（省略できない項目は、作る所と変える所でなくさない。[保存データ](../../docs/persistence.md)）。
  - 一体の形式の変換（`integrated/`）と v1 への変換は、v1 の形（幅なし）を作るので直さない。v1 → v2 の変換で幅を書き込む。
- 画面: 回路設定（`circuits/CircuitSettingsDialog.tsx`）の「モジュール」タブで、パッケージがロジックのときに幅の入力欄を出す。DIP（幅 3 に決め打ち）と QFP（正方形）には出さない。プレビューも幅に合わせて描く。
- 見つからないモジュールの大きさの写し（`Part.circuitSize`）は、置いたときの本体の大きさを写すので、幅を変えたあとに置き直せば新しい幅になる。今の仕組みのままでよい見込み（実装のときに確かめる）。

## 段階

1. 保存データと配置。
   - `Package` の split に幅を足し、検証（`isPackage`）で 2〜20 の整数を確かめる。split を作る所で幅を持たせる。
   - 回路の形式 v2 の文書（`docs/format/circuit/v2.md`。計画 28 で作る）に、split の幅と、v1 からの変更（幅 4 を書き込む）と、ピンの先の位置を書き足す。v1 → v2 の変換（`file/upgrade/circuit/v2.ts`）で、split のパッケージに幅 4 を書き込む。テストも書く。
   - 配置（`makeSplitLayout`）で幅を使う。テストを足す（幅 2、4、20 で、出力のピンの先が `x` + 幅 + 1）。
   - [保存データ](../../docs/persistence.md)、[部品の種類](../../docs/parts.md)の「配置」を直す。
   - 確かめること: 整形、Lint、型、テスト、ビルド。ブラウザで、v1 で保存した split のモジュールを含む回路を開くと、配線がつながったままで、見た目も変わらない。
2. 回路設定。
   - 回路設定の「モジュール」タブに幅の入力欄を足す（日本語と英語の文言。[文言と表示言語](../../docs/i18n.md)）。適用すると、1 回の編集として元に戻せる（今の回路設定と同じ）。
   - [UI](../../docs/ui.md)の回路設定の節を直す。操作マニュアル（`docs/manual/README.md`）の回路設定にも書き足す。
   - 確かめること: 整形、Lint、型、テスト、ビルド。ブラウザで、幅を 3 と 5 にすると、プレビューと、置いてあるモジュールの幅が変わる。出力につながっていた配線は外れて残る。元に戻すで戻る。範囲外（1、21、全角の数字、空）ではエラーが出て適用できない。荒い操作（入力欄に大きな数、連打）。フレームレート（描画に関わるため）。

実装は Skill の `modify` で進める。

## 進み具合

- 段階 1: 終えた。PR #41。整形、Lint、型、テスト（535 件）、ビルドが通る。
  - `Package` の split を `{ kind: 'split'; width: number }` にし、`isPackage` で 2〜20 の整数を確かめる。既定のパッケージ `DEFAULT_SPLIT_PACKAGE`（幅 4。`DEFAULT_SPLIT_WIDTH`）を `project.ts` に置き、split を作る所とパッケージを持たない回路の既定に使う（エージェントが決めた。幅 4 を何か所にも書かないため）。
  - 配置（`makeSplitLayout`）は幅を受け取る。パッケージを持たないモジュール（テストで作るもの）は幅 4（`module/layout.ts` の `SPLIT_DEFAULT_WIDTH`。`parts/` は `circuit/project.ts` を import しない決まりのため、値を別に持つ）。
  - v1 → v2 の変換（`upgradeToCircuitV2`）で、split のパッケージに幅 4 を書き込む。回路の形式 v2 は公開前なので、計画 28 で作った変換を直した。
  - 古い形式の変換のテスト（一体の形式、プロジェクトの形式 v1）は、変換の結果を今の検証で確かめていたので、中の回路を今の版にしてから確かめる形にした（`upgradeProjectCircuits` を export した）。
  - README のスクリーンショットの回路の JSON（回路の形式 v2 で書いていた）に、幅 4 を足した（足さないと検証で断られる）。
  - 回路設定の幅の入力欄は段階 2。今は、開いたときの幅のまま適用する。
  - ブラウザで確かめた: version 1 のプロジェクトファイル（split のモジュール）を開くと、外側の配線がつながったまま、出力が点く。README の回路の JSON が読み込める。
- 段階 2: 終えた。整形、Lint、型、テスト（535 件）、ビルドが通る。
  - 回路設定の「モジュール」タブで、パッケージがロジックのときに「幅 (マス)」の入力欄を出す（ピン数の欄と同じ位置）。下書きは `splitWidthText`（エージェントが決めた。シートの幅の `widthText` と分けるため）。範囲外なら「幅は 2〜20 の整数で入力してください」を出し、適用できない。幅を変えたときも、パッケージが変わったとして配線の注意を出す（`samePins` がパッケージ全体を比べるため）。
  - 文言は `circuitSettings.splitWidth` と `splitWidthError`（日本語と英語）。[UI](../../docs/ui.md)と操作マニュアルを直した。
  - ブラウザで確かめた: 範囲外（1、21、空欄、4.5、-3、99999999）はエラーが出て適用できない。6 にして適用すると、モジュールと、置いてあるモジュールの大きさの写し（`circuitSize`）が 6 になり、出力につながっていた配線は外れる（入力を ON にしても出力は点かない）。元に戻すで戻る。適用の連打でも 1 回分で、元に戻す 1 回で戻る。再読み込みしても壊れない。`1e1` は 10 として受け付ける（ピン数の欄と同じ）。
  - フレームレートは変える前と同じ（待機 60 fps、ドラッグ 60 fps）。
  - 気になる動き: 幅を広げると、外れた出力の配線の端が本体の中に残り、見た目ではつながっているように見える（ピンを減らしたときと同じ）。
- レビューで直したこと:
  - 回路設定で幅を変えると、プレビューのピンが前の幅の位置に残っていた（開発者が見つけた）。ピンの描き直しを省く比べ方（`SheetPart.tsx` の `samePinNames`）が、パッケージのピン数だけを比べ、split の幅を比べていなかったため。dip / qfp のピン数と split の幅を `packageSizeOf` で比べるようにした。シートに置いたモジュールも同じ比べ方なので、一緒に直る。[描画の重さ](../../docs/performance.md)に、配置を変える値を足したら比べ方にも足すことを書いた。ブラウザで、幅 2 と 20 でプレビューのピンが本体の右の辺に付くことを確かめた。
