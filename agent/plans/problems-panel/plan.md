# 問題パネル（計画）

状態: **計画中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

回路の問題（エラーと警告）をまとめて一覧にする「問題パネル」を作る。どこで起きているかが分かり、行を押せばその場所へ行けるようにする。

解きたい課題: 今の警告は、ステータスバーの右端のバッジに出しているだけで、どの回路のどこで起きているかが分からない。開いていない回路の問題も見えない。あとで足す未解決のモジュール（[計画 20](../unresolved-module/plan.md)）の「見つからないモジュール」も、ここに出す。

## 前提

- 今ステータスバーに出している警告（`hints/StatusBar.tsx`。決まりは [UI](../../docs/ui.md)の「ステータスバーのヒント」）:
  - 発振しています（赤）: シミュレーションの値が決まらない。開いている回路のシミュレーションで分かる。
  - 出力がぶつかっています（赤）: 1 つのネットに出力ピンが 2 つ以上ある。開いている回路のネット（`geometry/net.ts` の `isConflict`）で分かる。
  - ピンに出ていない INPUT / OUTPUT があります（オレンジ）: 開いているモジュールの中のポート（`circuit/module.ts` の `findUnexposedPorts`）。メイン回路では出さない（[計画 18](../main-as-module/plan.md)で、メイン回路も DIP / QFP にできるようになるが、ひとまず対象外と決めた）。
  - シートの外に部品か配線があります（オレンジ）: 開いている回路（`geometry/view.ts` の `fitsInSheet`）。
  - はみ出すため回転できません（オレンジ）: 回そうとしたときに 3 秒だけ出すお知らせ。問題ではなく出来事。
- どれも開いている回路のことだけを見ている。

## 決めたこと

開発者が決めたこと（2026-10-17）。

- 回路の問題を一覧にする問題パネルを作る。
- 見つからないモジュール（計画 20）は、問題パネルに出す。プロジェクトパネル（[計画 21](../project-panel/plan.md)）には出さない。
- この計画は、プロジェクト管理機能（計画 1）の下位の計画ではなく、独立した計画にする（今ある警告すべてに関わるため）。

## 決めてほしいこと

推す案を先に書く。

1. 置き場所
   - 推す案: シートの下、ステータスバーの上に開くパネル。ステータスバーの右端の問題の数のバッジ（例: ⛔ 2、⚠ 1）を押すと開閉する（VS Code の「問題」と同じ形）。開いているかどうかは画面の状態として localStorage に覚える。
   - 案 B: アイコンの列（計画 21）に 3 つ目（「問題」）を足し、サイドパネルで見る（場所は増えないが、見ている間はプロジェクトや部品が隠れる）。
2. 出す範囲
   - 推す案: プロジェクト全体の問題を出す（開いていない回路の問題も分かるように）。ただし、発振はシミュレーションしている回路（開いている回路）のことだけ。
   - 案 B: 開いている回路の問題だけを出す（今と同じ範囲）。
3. 行に出すものと、押したとき
   - 推す案: 種類（エラー ⛔ / 警告 ⚠）、文、起きている回路の名前（と、か所の数）。行を押すと、その回路を開き、元になっている部品や配線を選ぶ（見つからないモジュールなら、それを置いている部品）。
4. エラーと警告の分け方
   - 推す案: エラーは、発振、出力のぶつかり、見つからないモジュール（どれも回路が正しく動かない）。警告は、ピンに出ていないポート、シートの外の部品（動くが直した方がよい）。
5. ステータスバー
   - 推す案: 今の警告のバッジは、問題の数のバッジ（エラーと警告の数）にまとめる。回転できなかったときのお知らせ（出来事）は、今までどおりバッジで 3 秒出す。
   - 発振のように、今まさに起きていることを知らせる短い文をステータスバーに残すか。推す案: 残さない（数のバッジが赤くなり、パネルで中身が分かるため）。

## 段階（案）

決めてほしいことが決まってから、細かく書く。実装は Skill の `modify` で進める。

1. 問題を集める計算（プロジェクト全体の問題の一覧。種類、文の種類、回路、元になっている部品や配線）とテスト。
2. 問題パネルとステータスバーのバッジ、行を押したときの移動。
3. 文言（日本語と英語）、[UI](../../docs/ui.md)、操作マニュアル、ブラウザでの確認（フレームレートも。問題の計算を回路が変わるたびに行うため）。

## 気になるところ

- プロジェクト全体の問題を集めると、回路が変わるたびに、開いていない回路のネットなども計算することになる。回路の数が多いと重くなるかもしれない。開いていない回路は、その回路が変わったときだけ計算し直す（覚えておく）などの工夫が要るかもしれない。
