# 問題パネル（計画 23）

状態: **進行中**

用語（2026-10-20）: 定義は「回路」、置いたものは「モジュール」と呼び分けることにした（[用語](../../docs/glossary.md)）。この文書の操作やファイル、形式の名前は新しい言い方に直した。それ以外で「モジュール」が定義を指している所は、「回路」と読み替える。

- 開始の合図を受けたら、段階の区切りで止めずに最後の段階まで進める。迷うことがあれば止めて聞く（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

回路の問題（エラーと警告）をまとめて一覧にする「問題パネル」を作る。どこで起きているかが分かり、行を押せばその場所へ行けるようにする。

解きたい課題: 今の警告は、ステータスバーの右端のバッジに出しているだけで、どの回路のどこで起きているかが分からない。開いていない回路の問題も見えない。あとで足す未解決のモジュール（[計画 20](../unresolved-module/plan.md)）の「見つからない回路」も、ここに出す。

## 前提

- 今ステータスバーに出している警告（`hints/StatusBar.tsx`。決まりは [UI](../../docs/ui.md)の「ステータスバーのヒント」）:
  - 発振しています（赤）: シミュレーションの値が決まらない。開いている回路のシミュレーションで分かる。
  - 出力がぶつかっています（赤）: 1 つのネットに出力ピンが 2 つ以上ある。開いている回路のネット（`geometry/net.ts` の `isConflict`）で分かる。
  - ピンに出ていない INPUT / OUTPUT があります（オレンジ）: 開いているモジュールの中のポート（`circuit/module.ts` の `findUnexposedPorts`）。メイン回路では出さない（[計画 18](../main-as-module/plan.md)で、メイン回路も DIP / QFP にできるようになるが、ひとまず対象外と決めた）。
  - シートの外に部品か配線があります（オレンジ）: 開いている回路（`geometry/view.ts` の `fitsInSheet`）。
  - はみ出すため回転できません（オレンジ）: 回そうとしたときに 3 秒だけ出すお知らせ。問題ではなく出来事。
- どれも開いている回路のことだけを見ている。

## 決めたこと

開発者が決めたこと（2026-10-17）。

- 回路の問題を一覧にする問題パネルを作る。
- 見つからない回路（計画 20）は、問題パネルに出す。プロジェクトパネル（[計画 21](../project-panel/plan.md)）には出さない。
- この計画は、プロジェクト管理機能（計画 1）の下位の計画ではなく、独立した計画にする（今ある警告すべてに関わるため）。

開発者が決めたこと（2026-10-18）。

- 置き場所は、シートの下、ステータスバーの上。
  - シートとステータスバーの間に、タブの列を置き、「問題」のタブを 1 つだけ出す。タブを押すたびに、タブの上にパネルを開閉する。開くとシートの下に収まり、その分シートが縮む（シートの上には重ねない）。開いているかどうかは、画面の状態として localStorage に覚える。
  - 見た目: タブはパネルの下の端に付き、下に垂れ下がる形にする（上の端ではない）。タブの列は画面の横幅いっぱいに伸ばし、タブは左に寄せる。開いているときは、タブとパネルを同じ背景の色にし、境の線を引かずに 1 つながりに見せる（タブがパネルの取っ手に見えるように）。閉じているときは、タブだけが列に残る。

    ```
    閉じているとき                      開いているとき
    │       シート       │              │   シート（縮む）   │
    ├────────────────────┤              ├────────────────────┤
    │ [問題 ⛔ 2 ⚠ 1]     │              │ ⛔ 出力がぶつかって… │ ← パネル
    ├────────────────────┤              │ ⚠ シートの外に部品… │
    │ ヒント…            │              ├┐                ┌──┤
                                        ││ 問題 ⛔ 2 ⚠ 1  │  │ ← タブ（パネルとつながる）
                                        ├┴────────────────┴──┤
                                        │ ヒント…            │ ← ステータスバー
    ```

  - タブには問題の数（⛔ 2 ⚠ 1）を出す。色は、エラーがあれば赤、警告だけならオレンジ、0 なら灰色。
  - あとで別の中身が要るようになったら、タブを横に足せる。
  - 閉じていても、タブの列の分（24px ほど）シートが縮む。
  - 採らなかった案: アイコンの列（計画 21）に「問題」を足し、サイドパネルで見る（見ている間はプロジェクトや部品が隠れる）。ステータスバーの数のバッジを押して開閉する（押せる場所だと気付きにくい）。シートの上に重ねて開き、固定もできるようにする。パネルの中に、エラーと警告で絞り込む切り替えを置く（問題の種類が少ないので、要るようになったら足す）。
- 出す範囲は、プロジェクト全体の問題と、今選んでいるタブの回路の問題だけ。
  - プロジェクト全体の問題: どれか 1 つの回路ではなく、プロジェクトに関わる問題。今のところは見つからない回路（計画 20）だけ。モジュールごとに 1 行で、置いている回路をまたいだか所の数を出す。
  - 今のタブの回路の問題: 発振、出力のぶつかり、ピンに出ていないポート、シートの外の部品。ほかのタブで開いている回路や、開いていない回路の問題は出さない。
  - 採らなかった案: 開いていない回路も含めて、プロジェクトのすべての回路の問題を出す（回路が変わるたびに、ほかの回路のネットも計算することになる）。タブで開いている回路すべての問題を出す。
- 行には、種類（エラー ⛔ / 警告 ⚠）、文、か所の数を出す。起きている回路の名前は出さない（今のタブの回路のことなので、見れば分かる）。
- 行を押すと、今の回路の中で、元になっている部品や配線を選ぶ。見つからない回路の行を押しても、ほかの回路は開かない。今の回路にそれを置いている部品があれば選び、なければ何もしない。
- エラーは、発振、出力のぶつかり、見つからない回路（どれも回路が正しく動かない）。警告は、ピンに出ていないポート、シートの外の部品（動くが直した方がよい）。
- ステータスバーの今の警告のバッジはなくし、問題の数は「問題」のタブに出す。ステータスバーに残るのは、ヒントと、回転できなかったときのお知らせ（出来事。今までどおりバッジで 3 秒出す）だけ。発振のように今起きていることを知らせる短い文も、ステータスバーに残さない（タブの数が赤くなり、パネルで中身が分かるため）。

開発者が決めたこと（2026-10-23、始めるときに決めた）。

- 「発振しています」の行を押しても、何も選ばない（か所の数も出さない）。今のシミュレーションは、回路全体が落ち着かないことしか分からず、どの部品が発振しているかを持っていないため。要るようになったら、発振している部品を追う仕組みを足す。採らなかった案: 落ち着かない間に値が変わり続けた部品を記録して選ぶ（tick ごとの計算が重くなる）。
- 行を押して選んだ部品や配線が画面の外にあれば、選んだものの範囲が画面に収まるように表示を動かす（倍率は、収まらないときだけ下げる）。すべて画面に入っていれば動かさない。採らなかった案: 選ぶだけにする。
- パネルの高さは、パネルの上の端をドラッグして変えられ、localStorage に覚える。採らなかった案: 決めた高さ（5 行ほど）で中をスクロールする。
- ファイル: `src/problems/` を新しく作り、問題を集める計算を `problems.ts`（テストは `problems.test.ts`）、タブの列とパネルを `ProblemsPanel.tsx` に置く。依存の向きは `app` → `problems` → `geometry` / `circuit`。採らなかった案: `hints/` に置く（`hints/` の責務がヒントから広がる）。

## 段階（案）

決めてほしいことが決まってから、細かく書く。実装は Skill の `modify` で進める。

1. 問題を集める計算（プロジェクト全体の問題と、今の回路の問題の一覧。種類、文の種類、元になっている部品や配線）とテスト。
   - 済み（2026-10-23）。エージェントが決めたこと:
     - `problems/problems.ts` の `collectProblems(circuit, project, nets, unstable)`。ネットは画面の描画と同じものを受け取り、計算し直さない。発振はシミュレーションでしか分からないので、呼ぶ側が渡す。
     - 問題は種類（`UNSTABLE`、`CONFLICT`、`UNEXPOSED_PORTS`、`OUTSIDE_SHEET`）、エラーか警告か、か所の数、元になっている部品と配線の ID を持つ。エラーを先に並べる。
     - か所の数: 出力のぶつかりはネットの数、ピンに出ていないポートはポートの数、シートの外は部品と配線の数。発振は数えない。
     - 選ぶもの: 出力のぶつかりは、ぶつかっている出力の部品と、そのネットの配線。シートの外の部品と配線は、`geometry/view.ts` に足した `findOutsideSheet` で求める（見方は `fitsInSheet` と同じ）。
     - プロジェクト全体の問題（見つからない回路）は、計画 20 で足す。
   - 確かめたこと: テスト（問題の種類ごと、メイン回路でピンに出ていないポートを出さないこと、並び、数え方）。
   - ドラフトの PR: #28。
2. 問題パネルと「問題」のタブ、ステータスバーのバッジをなくすこと、行を押したときの選択。
   - 済み（2026-10-23）。エージェントが決めたこと:
     - `problems/ProblemsPanel.tsx`。タブの列（高さ 24px）とパネルを、シートとステータスバーの間に、画面の横幅いっぱいに置いた。開いているときは、タブをパネルと同じ背景（`bg.panel`）にし、下の角を丸めて垂れ下がる形にした。
     - タブには「問題」と、エラーと警告のアイコン（`assets/icons/error.svg`、`warning.svg` を足した）と数を出す。数は行の数（か所の数ではない）。
     - 高さは 48px から画面の高さの 6 割まで。パネルの上の端の取っ手（`role="separator"`）をドラッグするか、取っ手にフォーカスして上下の矢印キー（16px ずつ）で変える。ドラッグ中は保存せず、離したときに保存する。開いているかと高さは `sazanka.problemsPanel` に保存する（既定は閉じていて 140px）。
     - 行を押すと、元になっている部品と配線を選び、`geometry/view.ts` に足した `revealView` で、画面の外にあれば映るように表示を動かす。
     - ステータスバーは、ヒントと「はみ出すため回転できません」だけにした。問題の文は、文言の表の `status` から `problems.messages` に移した。
   - 確かめたこと: ブラウザで、タブの数と色、開閉でシートが縮むこと、行を押したときの選択と表示の動き、高さのドラッグと矢印キー、再読み込みのあとも開閉と高さが残ること。コンソールのエラーなし。
3. 文言（日本語と英語）、[UI](../../docs/ui.md)、操作マニュアル、ブラウザでの確認（フレームレートも。問題の計算を回路が変わるたびに行うため）。
   - 済み（2026-10-23）。エージェントが決めたこと:
     - 問題の一覧は部品のドラッグの一歩ごとにも作り直すので、パネルは中身（種類、か所の数、部品と配線の ID）で比べて、変わらなければ描き直さない（`samePanel`）。
     - [UI](../../docs/ui.md)に「問題パネル」の節を足し、ステータスバーの節から警告のバッジの記述を外した。[保存データ](../../docs/persistence.md)の localStorage の表に `sazanka.problemsPanel` を足した。操作マニュアルの「警告」を「問題」にした。
   - 確かめたこと: ブラウザで、問題がないとき（「問題はありません」、灰色の 0）、発振（赤、行は押せない）、英語（Problems、1 place）、幅 400 の画面（横にはみ出さない）。フレームレート（CPU を 4 倍遅くして、ビルドしたもの。CLOCK 15 個）: 待機は変更前も後も 60 fps、ドラッグは変更前 58.7 fps、後 58.9 fps（パネルを開いて 58.5 fps）。コンソールのエラーなし。

## 気になるところ

- 見つからない回路は、プロジェクトのすべての回路の部品を見て求める。回路が変わるたびに求めるが、部品の `circuitId` を見るだけなので軽い見込み（ネットの計算は今の回路だけ）。
