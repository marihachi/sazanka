## 目的

- NOT の本体を 3×4 マスから 3×2 マスに小さくする。
- ゲート 7 種類（NOT、AND、OR、XOR、NAND、NOR、XNOR）の本体に、名前の代わりにゲートの記号（MIL 記号）を描き、何のゲートか見て分かるようにする。

開発者が求めた（2026-10-24）。見た目は、作業用のフォルダで作ったモックを見ながら、開発者と決めた。

## 決めたこと

以下は開発者と決めた（2026-10-24）。

### 大きさ

- NOT（1 入力）は 3×2 マス。入力と出力のピンは、上から 1 マスめ。
- 2 入力のゲート（AND、OR、XOR、NAND、NOR、XNOR）は、今の 3×4 マスのまま。
- 採らなかった案: NOT を 2×2（出力のピンの先が 1 マス縮み、古いデータの配線をずらすだけではつなげない）。2 入力のゲートを 2×4、3×2、2×2（2×4 は記号が細くつぶれる。高さ 2 では入力のピンが四角の上下の角に付く）。

### 記号

- 四角の輪郭は今のまま残し、その中の真ん中に、余白を取って記号を描く。選んだときの強調、問題があるときの赤い輪郭、当たり判定も今のまま。
  - 採らなかった案: 輪郭をやめて記号だけにする（強調、赤い輪郭、当たり判定の描き方を作り直すことになる）。
- 記号には短いリード（線）を付ける。リードは記号の一部で、ピンにはつながない（開発者が決めた）。
  - 採らなかった案: 記号を四角いっぱいに描き、ピンから記号まで足でつなぐ（高さ 2 で足が折れ曲がり、すっきりしない）。
- 記号の形（線の太さ 1.5px、文字と同じ色、塗らない）:
  - NOT: 三角と否定の丸。三角は幅 16px・高さ 18px（正三角形に近い形）、否定の丸は半径 2.5px、リードは入力・出力とも 6px。
  - AND: 左が平らで右が半円の形。OR: 左がへこみ、右がとがった形。XOR: OR の左に、もう 1 本の弧。
  - NAND、NOR、XNOR: AND、OR、XOR の出力に否定の丸（半径 2.5px）を付ける。
  - 2 入力の記号は、高さ 22px、全体の幅（リードを含む）44px。入力のリードは 9px（XOR と XNOR は 7px にし、その分だけ本体を長くする）、出力のリードは 6px。入力のリードは、記号の高さの 1/4 と 3/4 の位置。
  - 形は、下の「記号の描き方」の式どおりに描けば、モックと同じになる（開発者がモックで見て決めた形。回転したときやほかの拡大率で崩れるなら、合わせて直して、ここも直す）。
- 回した部品は、記号も一緒に回す（今の名前の文字と同じく、本体の描き込みを最後にまとめて回す。`rotateTransform`）。

### 記号の描き方

モックで描いた式。長さは px で、本体の左上を原点にする（回していない向き）。本体の幅を `w`、高さを `h` とする（3×4 なら 60×80、3×2 なら 60×40）。

- 線: 塗らない（`fill="none"`）、色は `gray.300`（`--chakra-colors-gray-300`。名前の文字の `fg` より少し暗い。実装のあとで開発者が選んだ。採らなかった案: `fg`、`fg.muted`）、太さ 1.5、角は丸める（`stroke-linejoin="round"`）。
- 値:
  - 2 入力か: `two` = NOT 以外。
  - 否定の丸を付けるか: `bubble` = NOT、NAND、NOR、XNOR。
  - 形: `base` = NOT は `not`、AND と NAND は `and`、OR と NOR は `or`、XOR と XNOR は `xor`。
  - 入力のリード `Lin` = 2 入力なら 9（`base` が `xor` なら 7）、NOT なら 6。出力のリード `Lout` = 6。否定の丸の半径 `r` = 2.5。
  - 記号の高さ `H` = 2 入力なら min(`h` − 18, 22)（3×4 では 22）。ただし `and`（AND と NAND）は min(`h` − 18, 24)（22 では横長に見えるため。レビューのときに開発者がモックで見て決めた。採らなかった案: 26、28。OR と XOR より大きく見える）。NOT なら 18。
  - 記号の本体の幅（否定の丸を含む）`Wb` = 2 入力なら min(`w` − 16, 44) − `Lin` − `Lout`（3×4 では AND と OR が 29、XOR が 31）、NOT なら round(`H` × 0.9) + 2`r`（= 21）。
  - リードを含む幅 `total` = `Wb` + `Lin` + `Lout`。
  - 本体の左端 `x0` = (`w` − `total`) / 2 + `Lin`。上端 `y0` = (`h` − `H`) / 2。
  - 本体の右端（否定の丸の手前）`end` = `x0` + `Wb` − (`bubble` なら 2`r`、でなければ 0)。`Wm` = `end` − `x0`。
  - `X(f)` = `x0` + `f` × `Wm`、`Y(f)` = `y0` + `f` × `H`。
  - 入力のリードの高さの割合 `fs` = 2 入力なら [0.25, 0.75]、NOT なら [0.5]。
- 本体の形（SVG のパス）:
  - `not`: `M X(0),Y(0) L X(1),Y(0.5) L X(0),Y(1) Z`
  - `and`: `M X(0),Y(0) H X(0.5) A Wm/2,H/2 0 0 1 X(0.5),Y(1) H X(0) Z`
  - `or` と `xor`: `g` = `xor` なら 0.2、`or` なら 0。`bw` = (1 − `g`) × `Wm` × 0.25。
    - `M X(g),Y(0) Q X(g)+bw,Y(0.5) X(g),Y(1) Q X(g+(1−g)×0.6),Y(1) X(1),Y(0.5) Q X(g+(1−g)×0.6),Y(0) X(g),Y(0) Z`
    - `xor` は、左にもう 1 本の弧を足す: `M X(0),Y(0) Q X(0)+bw,Y(0.5) X(0),Y(1)`
- 否定の丸: 中心 (`end` + `r`, `Y(0.5)`)、半径 `r`。
- 入力のリード: `fs` のそれぞれについて、(`x0` − `Lin`, `Y(f)`) から、本体の左の線まで水平に引く。線の x は、`not` と `and` なら `X(0)`、`or` と `xor` なら `X(0)` + 2 × `bw` × `f` × (1 − `f`)（`xor` は左の弧まで。`or` は本体の左の弧まで）。
- 出力のリード: (`x0` + `Wb`, `Y(0.5)`) から (`x0` + `Wb` + `Lout`, `Y(0.5)`) まで。
- 名前（7 種類すべて）: 今のモジュールの `nameAbove` と同じく、本体の上の外（`y` = −6、文字は `styles.label`）に、横の真ん中にそろえて書く。

### 記号を SVG のファイルにする

以下は開発者と決めた（レビューのとき）。

- 記号は、種類のフォルダの `symbol.svg`（`parts/and/symbol.svg` など）に置く。見た目をファイルで直接直せるようにするため。1 種類 = 1 フォルダにもそろう。
- `symbol.svg` は文字列として読み込み、本体の中にそのまま描く。線の色は `currentColor` にし、アプリ側で決める（今は `gray.300`）。
  - 採らなかった案: 今のまま `GateSymbol.tsx` が式で描く（形を変えるには式を読む必要がある）。`<image>` で描く（線の色をファイルに書き込むことになり、アプリ側で変えられない）。
- 形と寸法は、下の「記号の描き方」の式で描いたものを、そのまま SVG に書き出す（見た目は変えない）。リードと余白も SVG に含める。

### 名前

- ゲート 7 種類とも、四角の外の上に名前を書く（モジュールと同じ、配置の `nameAbove`）。名前の 1 マスは、部品の占める範囲に入る（範囲選択、はみ出しの判定）。保存データには関わらない。
  - 採らなかった案: 四角の中の記号の上に書く。名前を書かない。
- NOT も、ほかのゲートと同じく「NOT」と書く（開発者が決めた、2026-10-25。はじめは記号だけにしていた）。

### 保存データ

- NOT のピンの先の位置が変わるので、[回路の形式](../../../docs/format/circuit/v1.md)を version 2 に上げる（v1 は公開済みで、v1 の中では意味を変えない。[保存データ](../../docs/persistence.md)の「形式を変えるとき」）。
- v1 → v2 の変換で、NOT の位置をずらして、ピンの先を元の場所に残す。配線は書き換えない。
  - 向きが `0` と `180`: `y` を 1 増やす。
  - 向きが `90` と `270`: `x` を 1 増やす。
  - どの向きでも、入力と出力の両方のピンの先が元の場所に残る（形式の文書の回したピンの先の式で確かめた）。
- プロジェクトの形式と回路ファイルの形式の版は上げない（中の回路の版で見分けるため。[保存データ](../../docs/persistence.md)の「版の状態」）。
- 2 入力のゲートは大きさもピンも変わらないので、変換しない。
- [計画 29](../split-width/plan.md)（split のモジュールの幅）が、この計画で作る version 2 に、split の幅を足す（計画 29 は、この計画のあとに始める）。

### 置き場所と範囲

以下は開発者と決めた（2026-10-24）。

- 記号の描き方は `parts/GateSymbol.tsx` に 7 種類まとめ、どの記号を描くかは種類の見せ方（`view.ts`）に書く（例: `symbol: { gate: 'and', negated: true }`）。記号は AND、OR、XOR の 3 つの形と否定の丸の組み合わせなので、1 か所にまとめると形をそろえやすい。種類の見せ方に書くのは、ほかの見せ方（表示名、アイコン）と同じ場所に置くため。
  - 採らなかった案: 種類ごとの描き込み（`<種類>/Body.tsx` と `PART_BODIES`。7 セグメントと同じ形）。今の `PART_BODIES` は名前を書かない決まりなので、ゲートの名前（`nameAbove`）を書くには決まりを変える必要があり、7 つのファイルに同じ形が分かれる。
- README のスクリーンショットを撮り直す（[README のスクリーンショット](../../docs/screenshot.md)）。
- パレットのアイコン（`icon.svg`）は、今のまま変えない。
