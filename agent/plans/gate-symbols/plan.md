# ゲートを記号で描き、NOT を小さくする（計画 28）

状態: **計画中**

- 開始の合図を受けたら、段階の区切りで止めずに最後の段階まで進める。迷うことがあれば止めて聞く（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

- NOT の本体を 3×4 マスから 3×2 マスに小さくする。
- ゲート 7 種類（NOT、AND、OR、XOR、NAND、NOR、XNOR）の本体に、名前の代わりにゲートの記号（MIL 記号）を描き、何のゲートか見て分かるようにする。

開発者が求めた（2026-10-24）。見た目は、作業用のフォルダで作ったモックを見ながら、開発者と決めた。

## 決めたこと

以下は開発者と決めた（2026-10-24）。

### 大きさ

- NOT（1 入力）は 3×2 マス。入力と出力のピンは、上から 1 マスめ。
- 2 入力のゲート（AND、OR、XOR、NAND、NOR、XNOR）は、今の 3×4 マスのまま。
- 採らなかった案: NOT を 2×2（出力のピンの先が 1 マス縮み、古いデータの配線をずらすだけではつなげない）。2 入力のゲートを 2×4、3×2、2×2（2×4 は記号が細くつぶれる。高さ 2 では入力のピンが四角の上下の角に付く）。

### 記号

- 四角の輪郭は今のまま残し、その中の真ん中に、余白を取って記号を描く。選んだときの強調、問題があるときの赤い輪郭、当たり判定も今のまま。
  - 採らなかった案: 輪郭をやめて記号だけにする（強調、赤い輪郭、当たり判定の描き方を作り直すことになる）。
- 記号には短いリード（線）を付ける。リードは記号の一部で、ピンにはつながない（開発者が決めた）。
  - 採らなかった案: 記号を四角いっぱいに描き、ピンから記号まで足でつなぐ（高さ 2 で足が折れ曲がり、すっきりしない）。
- 記号の形（線の太さ 1.5px、文字と同じ色、塗らない）:
  - NOT: 三角と否定の丸。三角は幅 16px・高さ 18px（正三角形に近い形）、否定の丸は半径 2.5px、リードは入力・出力とも 6px。
  - AND: 左が平らで右が半円の形。OR: 左がへこみ、右がとがった形。XOR: OR の左に、もう 1 本の弧。
  - NAND、NOR、XNOR: AND、OR、XOR の出力に否定の丸（半径 2.5px）を付ける。
  - 2 入力の記号は、高さ 22px、全体の幅（リードを含む）44px。入力のリードは 9px（XOR と XNOR は 7px にし、その分だけ本体を長くする）、出力のリードは 6px。入力のリードは、記号の高さの 1/4 と 3/4 の位置。
  - 細かい寸法は、実装のときにモックの形を写す（回転したときやほかの拡大率で崩れるなら、合わせて直す）。
- 回した部品は、記号も一緒に回す（今の名前の文字と同じく、本体の描き込みを最後にまとめて回す。`rotateTransform`）。

### 名前

- 2 入力のゲートは、四角の外の上に名前を書く（モジュールと同じ、配置の `nameAbove`）。名前の 1 マスは、部品の占める範囲に入る（範囲選択、はみ出しの判定）。保存データには関わらない。
  - 採らなかった案: 四角の中の記号の上に書く。名前を書かない。
- NOT は名前を書かない（記号だけ）。

### 保存データ

- NOT のピンの先の位置が変わるので、[回路の形式](../../../docs/format/circuit/v1.md)を version 2 に上げる（v1 は公開済みで、v1 の中では意味を変えない。[保存データ](../../docs/persistence.md)の「形式を変えるとき」）。
- v1 → v2 の変換で、NOT の位置をずらして、ピンの先を元の場所に残す。配線は書き換えない。
  - 向きが `0` と `180`: `y` を 1 増やす。
  - 向きが `90` と `270`: `x` を 1 増やす。
  - どの向きでも、入力と出力の両方のピンの先が元の場所に残る（形式の文書の回したピンの先の式で確かめた）。
- プロジェクトの形式と回路ファイルの形式の版は上げない（中の回路の版で見分けるため。[保存データ](../../docs/persistence.md)の「版の状態」）。
- 2 入力のゲートは大きさもピンも変わらないので、変換しない。

## 今のコードと、変えるところ

- 配置: NOT は自分の配置がなく、ゲートの既定の配置（`parts/layout.ts` の `gateLayout`）を使っている。`parts/not/layout.ts` を作って `parts/layouts.ts` の `PART_LAYOUTS` に足す。2 入力のゲートは `gateLayout` に `nameAbove: true` を付ける（内部用の BUF も `gateLayout` を使うが、シートには描かないので影響しない。実装のときに確かめる）。
- 描き方: ゲートの名前は、`sheet/SheetPart.tsx` が本体の真ん中（`nameAbove` なら上）に書いている。記号を描く部品を足し、ゲートの種類では名前の代わりに記号を描く。
- 読み込み: `file/upgrade/index.ts` の `CIRCUIT_FORMAT_VERSION` を 2 にし、回路 1 つずつを v1 → v2 にする変換（`file/upgrade/circuit/v2.ts`）を作る。保存データ、プロジェクトファイル（一体の形式から変えたものも）、回路ファイルの読み込みのすべてで通す。
- テスト: NOT の位置やピンを使うテスト（`geometry/layout.test.ts`、`parts/layouts.test.ts` など）を、新しい大きさに合わせる。どの種類の部品も置いた形のまま保存して検証を通るテスト（`storage.test.ts`）は、そのまま通るはず。

## 決めてほしいこと

1. 記号を描く部品の置き場所と名前。
   - 推す案: `parts/GateSymbol.tsx` に 7 種類の記号の描き方をまとめ、どの記号を描くかは種類の見せ方（`view.ts`）に書く（例: `symbol: { gate: 'and', negated: true }`）。記号は AND、OR、XOR の 3 つの形と否定の丸の組み合わせなので、1 か所にまとめると形をそろえやすい。種類の見せ方に書くのは、ほかの見せ方（表示名、アイコン）と同じ場所に置くため。
   - ほかの案: 種類ごとの描き込み（`<種類>/Body.tsx` と `PART_BODIES`。7 セグメントと同じ形）。ただし、今の `PART_BODIES` は名前を書かない決まりなので、2 入力のゲートの名前（`nameAbove`）を書くには、決まりを変える必要がある。7 つのファイルに同じ形が分かれる。
2. README のスクリーンショットを撮り直すか。ゲートが写っていれば、見た目が変わるので、撮り直すことを推す（[README のスクリーンショット](../../docs/screenshot.md)）。
3. パレットのアイコン（`icon.svg`）も記号にそろえるか。今回の範囲の外にし、必要なら別の計画にすることを推す。
