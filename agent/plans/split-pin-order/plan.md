# split のピンの順をポート番号の順にする（計画）

状態: **計画中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

パッケージが split のモジュールの外側のピンの順を、中の INPUT / OUTPUT の位置の順から、ポート番号の順に変える。

解きたい課題: 今は、モジュールの中でポートを上下に動かすと外側のピンの順が変わり、置いた先の配線が別のピンにつながる。動かしただけで配線の意味が変わるのは気付きにくい。

## 取り決め（開発者からの指示、2026-10-14）

- プログラムの上でも、ポートの並びは基本的にポート番号の順を前提にする。位置の順（上から、同じ高さなら左から）を使うのは、番号を振り直すときだけ。
- この取り決めは、[用語](../../docs/glossary.md)の「回路のデータ」に「開発者からの指示」として書く（段階 1）。

## 前提

- 保存データの形式は version 4（2026-10-13 に公開）。split のピンの順は、形式の文書（`docs/format/v4.md` の「モジュールのピン」）で「座標の順」と決めている。
- ピンの順を変えると、今の保存データと共有用 JSON の配線が別のピンにつながる。古いデータがそのままでは同じ意味で読めなくなるので、版を上げて変換を足す（[保存データ](../../docs/persistence.md)の「開発者からの指示」）。
- 位置の順を使っている所（`circuit/module.ts`）:
  1. `getPortsInPinOrder` の split の分岐: split の外側のピンの順。展開（`simulation/flatten.ts`）とシート上の配置（`getPinout`）がこれを使う。**この計画で番号の順に変える**。
  2. `assignPortNumbers`: 置いた・貼り付けたポートが複数あるとき、番号を付ける順。番号を振る処理なので位置の順のまま。
  3. `fillPortNumbers`: 読み込みで、番号がない・重なるポートに番号を付け直す順。同じく位置の順のまま。
  4. `listPortsInPositionOrder`: モジュール設定の「上から順に割り当て直す」と、split から DIP / QFP に変えたときに、ピン番号を割り当てる順。下の「決めてほしいこと」の 3。
- ポート番号は、今は置いたときに決まり、利用者は変えられない（`app/PropertyPanel.tsx` で表示だけ）。split で番号の順がピンの順になると、ピンの順を並べ替える手段がなくなるので、番号を変える操作を足す。
- モジュール設定のポートの一覧は、[モジュール設定のポートの並び](../module-port-order/plan.md)の計画でポート番号の順にした（ブランチ `module-port-order`）。この計画はその上に積む。

## 決めたこと

開発者が決めたこと（2026-10-14）。

- split の外側のピンの順を、ポート番号の順にする。入力は入力のポート番号の順、出力は出力のポート番号の順。
- 採らなかった案: split は位置の順のまま、取り決めの例外にする（版を上げずに済み、番号を変える操作も要らないが、ポートを動かすとピンが入れ替わる課題が残る）。

## 決めてほしいこと

推す案を先に書く。

1. 古いデータ（version 4 まで）の split のモジュールで、ポート番号をどう付け直すか

   変換では、今の配線を保つために、位置の順とポート番号の順をそろえる。そのため、split のモジュールの中の INPUT / OUTPUT のポート番号は変わることがある。

   - 推す案: 今ある番号の組はそのままに、位置の順に配り直す。例: 入力 1 が下、入力 2 が上、入力 3 が真ん中なら、上から順に 1、2、3 と付け直す（番号の組 {1, 2, 3} は変わらない）。番号に飛びがあっても（{1, 3, 4} など）組は保つ。番号がない・重なるポートがあるときだけ、1 から位置の順に振り直す。
   - 案 B: いつも 1 から位置の順に振り直す。決め方は単純だが、飛びのある番号（ポートを消したあとなど）が詰まり、「入力 4」が「入力 3」になるなど、変えなくてよい番号まで変わる。
   - どちらでも、位置の順と番号の順がもともとそろっているモジュール（ふつうに上から置いたもの）は、番号が変わらない。メイン回路と、DIP / QFP のモジュールは変えない。

2. ポート番号を変える操作

   - 推す案: モジュール設定のポートの一覧に、行ごとの「上へ」「下へ」のボタンを置き、同じ種類（入力どうし、出力どうし）の中で隣と番号を入れ替える。ほかの設定と同じく「適用」でまとめて 1 回の編集にする。プレビューにすぐ出るので、ピンの順を見ながら変えられる。あわせて「上から順に番号を振り直す」ボタンを置く（位置の順に番号を振り直す。今までの split の並びに戻したいときのため。取り決めの「番号を振り直すときは位置の順」に当たる）。
   - 案 B: プロパティ欄のポート番号を入力欄にし、入れた番号がほかのポートと重なれば入れ替える。モジュール設定を開かずに変えられるが、ピンの順は見えない。
   - 案 C: A と B の両方。
   - メイン回路のポート番号はピンに関わらないので、どの案でも、メイン回路では番号を変える操作を出さない（案 B と C ではプロパティ欄に出すかも決める）。

3. split から DIP / QFP に変えたときの、ピン番号の割り当ての順

   - 推す案: ポート番号の順にする。split のときのピンの順を、DIP / QFP でもそのまま引き継ぐため。位置から番号を振り直すのではなく、今の並びを写すだけなので、取り決めの例外ではないと考える。
   - 案 B: 今のまま位置の順にする（取り決めの「振り直し」と同じ扱い）。split で番号を入れ替えていたら、DIP / QFP に変えたときにピンの順が変わる。
   - 「上から順に割り当て直す」は、名前のとおり位置の順のまま。

4. 実装するブランチ

   - 推す案: [モジュール設定のポートの並び](../module-port-order/plan.md)（ブランチ `module-port-order`）をマージしてから、`main` から新しいブランチ（名前の候補: `split-pin-order`、`port-number-order`）を作る。保存データの版を上げる大きな変更なので、分けておく。
   - 案 B: `module-port-order` に続けて入れる。

## ほかに変わるもの

- 置いたポートには、今までどおり空いているいちばん小さい番号を付ける。split では、その番号の位置にピンが増える（例: 入力 2 を消してから INPUT を置くと、それが入力 2 になり、2 番めのピンになる）。どこに置いても同じ。
- ヒント: split のモジュールの「INPUT / OUTPUT の上下の並びを変えるとピンの順番も変わり…」（`i18n/ja.ts` の `hints.splitModule`）は当てはまらなくなる。番号の順でピンが並ぶこと、番号はモジュール設定で変えられることを知らせる文に替える。
- モジュール設定の split の説明（`moduleSettings.splitHelp`「中の位置の順 (上から、同じ高さなら左から) に並びます」）を、ポート番号の順に直す。
- 操作マニュアル（`docs/manual/README.md` の「モジュール設定」）の「ロジックでは、ピンの順は中の INPUT / OUTPUT の上下の並びで決まる」を直す。
- エージェント向けドキュメント: [シミュレーション](../../docs/simulation.md)のポート番号の説明、[UI](../../docs/ui.md)の「モジュール設定」、[部品の種類](../../docs/parts.md)のモジュールの配置、[保存データ](../../docs/persistence.md)の版と変換。

## 段階

各段階で、`npm run format`、`npm run lint`、`npx tsc -b`、`npm test`、`npx vite build` を通す。

1. 取り決めと、データの形式（version 5）
   - [用語](../../docs/glossary.md)に取り決めを書く。
   - `STORAGE_VERSION` と `SHARE_VERSION` を 5 にし、`file/upgradeV4.ts` の `upgradeV4`（version 4 → 5）を作って `UPGRADES` に足す。変換は、決めてほしいことの 1 の決め方を中に持つ（今のアプリのコードに頼らない）。
   - `getPortsInPinOrder` の split の分岐を、ポート番号の順にする。
   - 形式の文書: `docs/format/v5.md` を作り、`v4.md` を `docs/format/archive/` に移す。「モジュールのピン」と「version 4 からの変更」を書く。
   - テスト: `upgradeV4` の変換（位置と番号がそろっているもの、ずれているもの、飛びのあるもの、番号がない・重なるもの、DIP / QFP とメイン回路は変えないこと）。いちばん古い版から version 5 まで順に通すテスト。split のピンの順が番号の順になること（`module.test.ts`、展開の `flatten`）。**変換の前後で、置いた先の配線が同じピンにつながったままなこと**（version 4 の回路を変換して展開し、シミュレーションの結果が変わらないこと）。
2. ポート番号を変える操作（決めてほしいことの 2 による）
   - 画面と、番号を入れ替える計算（`circuit/module.ts`。テストを書く）。
   - split から DIP / QFP に変えたときの割り当ての順（決めてほしいことの 3 による）。
3. 文言とドキュメント、ブラウザでの確認
   - ヒント、モジュール設定の説明、日本語と英語の文言、操作マニュアル、エージェント向けドキュメント。
   - ブラウザで: split のモジュールの中でポートを動かしても、置いた先の配線が外れないこと。番号を入れ替えるとピンの順が変わり、プレビューにも出ること。version 4 の保存データと共有用 JSON を読み込むと、配線が今までどおりつながり、シミュレーションの結果が変わらないこと。モジュール設定を触るので、[UI](../../docs/ui.md)の「触ったら確かめること」のモジュール設定も通す。128 ピンのモジュールで重くなっていないかも見る。

実装は Skill の `modify` で進める。

## 気になるところ

- 版を上げると、古い版のアプリ（もう公開していない）は新しいデータを読めない。今は最新版だけを公開しているので問題にならない（[保存データ](../../docs/persistence.md)の「形式を変えるとき」）。
- 変換でポート番号が変わったモジュールでは、シート上の「入力 1」などの表示が、前と違うポートに付く。配線とピンの順は保たれる。
- `fillPortNumbers`（読み込みで番号がない・重なるポートに付け直す）は位置の順のまま。version 5 のデータで番号が重なっていたら、split のピンの順は、付け直したあとの番号の順になる。
