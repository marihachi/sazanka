# split のピンの順をポート番号の順にする（計画 16）

## 目的

パッケージが split のモジュールの外側のピンの順を、中の INPUT / OUTPUT の位置の順から、ポート番号の順に変える。

解きたい課題: 今は、モジュールの中でポートを上下に動かすと外側のピンの順が変わり、置いた先の配線が別のピンにつながる。動かしただけで配線の意味が変わるのは気付きにくい。

形式の変更（ピンの順を番号の順にすること、古いデータの番号の振り直し、新しい形式）は [保存データをプロジェクトと回路に分ける](../project-format/plan.md)（計画 19）にある（2026-10-17。もとは計画 17 の version 5 に移していたが、19 にまとめた）。この計画は、形式以外の操作と文言を受け持つ。進める順は 19 → [メイン回路をほかの回路と同じに扱う](../main-as-module/plan.md)（18）→ この計画。

## 取り決め（開発者からの指示、2026-10-14）

- プログラムの上でも、ポートの並びは基本的にポート番号の順を前提にする。位置の順（上から、同じ高さなら左から）を使うのは、番号を振り直すときだけ。ドキュメントに書くのは計画 19 の段階 1。

## 前提

- 計画 19 を終えた時点で、split の外側のピンはポート番号の順に並ぶ。計画 18 を終えた時点で、シート設定とモジュール設定は「回路設定」（`modules/CircuitSettingsDialog.tsx`）にまとまり、メイン回路でも開ける。
- ポート番号は、今は置いたときに決まり、利用者は変えられない（`app/PropertyPanel.tsx` で表示だけ）。split で番号の順がピンの順になると、ピンの順を並べ替える手段がなくなるので、番号を変える操作を足す。
- 回路設定（もとのモジュール設定）のポートの一覧は、ポート番号の順（[モジュール設定のポートの並び](../module-port-order/plan.md)の計画、完了）。
- 「上から順に割り当て直す」と、split から DIP / QFP に変えたときのピン番号の割り当ては、今は位置の順（`circuit/module.ts` の `listPortsInPositionOrder`）。

## 決めたこと

開発者が決めたこと。

- split の外側のピンの順を、ポート番号の順にする（2026-10-14）。形式の変更と、古いデータの番号の振り直し方は計画 19 の「決めたこと」にある。
- 採らなかった案: split は位置の順のまま、取り決めの例外にする（版を上げずに済み、番号を変える操作も要らないが、ポートを動かすとピンが入れ替わる課題が残る）。
- ポート番号を変える操作（2026-10-17）: 設定のダイアログ（計画 18 で「回路設定」にまとめる）のポートの一覧に、行ごとの「上へ」「下へ」のボタンを置き、同じ種類（入力どうし、出力どうし）の中で隣と番号を入れ替える。ほかの設定と同じく「適用」でまとめて 1 回の編集にする。プレビューにすぐ出るので、ピンの順を見ながら変えられる。あわせて「上から順に番号を振り直す」ボタンを置く（位置の順に番号を振り直す。取り決めの「番号を振り直すときは位置の順」に当たる）。メイン回路でも使える（計画 18）。
  - 採らなかった案: プロパティ欄のポート番号を入力欄にする（ピンの順が見えない）。その両方。
  - レビューで変えた（2026-10-22、開発者が決めた）: 「上へ」「下へ」はやめ、「上から順に番号を振り直す」だけを残す。押すと、番号の見出しは同じ場所に残って名前の行が動くので、名前が入れ替わったように見えて分かりにくかったため。ピンが受け持つ信号を変えたいときは、中の配線をつなぎ直せばよい。ピンの順を位置の順にそろえたいときは、INPUT / OUTPUT を動かしてから振り直す。
    - 採らなかった案: 変えた行に元の番号を添える。動いた行を一瞬光らせる。行を動かさず見出しの番号だけを変える（一覧の順とピンの順がずれる）。
    - split から DIP / QFP に変えたときの割り当ては、ポート番号の順のまま（開発者が決めた）。
- split から DIP / QFP に変えたときのピン番号の割り当ては、ポート番号の順にする（2026-10-17）。split のときのピンの順を、DIP / QFP でもそのまま引き継ぐため。「上から順に割り当て直す」は、名前のとおり位置の順のまま。
  - 採らなかった案: 今のまま位置の順にする（split で番号を入れ替えていたら、DIP / QFP に変えたときにピンの順が変わる）。

## ほかに変わるもの

- 置いたポートには、今までどおり空いているいちばん小さい番号を付ける。split では、その番号の位置にピンが増える（例: 入力 2 を消してから INPUT を置くと、それが入力 2 になり、2 番めのピンになる）。どこに置いても同じ。
- ヒント: split のモジュールの「INPUT / OUTPUT の上下の並びを変えるとピンの順番も変わり…」（`i18n/ja.ts` の `hints.splitModule`）は当てはまらなくなる。番号の順でピンが並ぶこと、番号は回路設定で変えられることを知らせる文に替える。
- 回路設定の split の説明（今の `moduleSettings.splitHelp`「中の位置の順 (上から、同じ高さなら左から) に並びます」）を、ポート番号の順に直す。
- 操作マニュアル（`docs/manual/README.md`。計画 18 で「回路設定」の節になる）の「ロジックでは、ピンの順は中の INPUT / OUTPUT の上下の並びで決まる」を直す。
- エージェント向けドキュメント: [シミュレーション](../../docs/simulation.md)のポート番号の説明、[UI](../../docs/ui.md)の「モジュール設定」、[部品の種類](../../docs/parts.md)のモジュールの配置。

## 段階

各段階で、`npm run format`、`npm run lint`、`npx tsc -b`、`npm test`、`npx vite build` を通す。計画 19 と 18 を終えてから始める。

1. ポート番号を変える操作
   - 画面と、番号を入れ替える計算（`circuit/module.ts`。テストを書く）。
   - split から DIP / QFP に変えたときの割り当ての順を、ポート番号の順にする。
   - 済み（2026-10-21）。エージェントが決めたこと:
     - 計算は `circuit/module.ts` の `swapPortNumbers`（レビューで「上へ」「下へ」をやめたので消した）と `renumberPortsByPosition`（種類ごとに位置の順で 1 から振り直す。抜けも詰める）。`applyCircuitSettings` に、ポート番号（部品 ID → 番号）を足した。
     - 回路設定の「モジュール」のタブで、ポートの一覧の行ごとに「上へ」「下へ」のボタン（`chevron.svg` を回したもの）を置き、一覧の見出しの右に「上から順に番号を振り直す」を置いた。一覧は下書きの番号の順に並び、番号を入れ替えると行も入れ替わる。同じ種類の先頭の「上へ」と末尾の「下へ」は押せない。
     - split で番号を変えると、ピンの順が変わるので、置いた先の配線の注意を出す（`samePins` で、split ならポート番号も比べる）。
   - 確かめたこと: テスト（入れ替え、種類をまたがないこと、番号の抜け、振り直し、split のピンの順）。ブラウザで、モジュールの回路の「上へ」「下へ」と振り直しで見出しとプレビューのピンの順が変わること、配線の注意が出ること、適用と元に戻す 1 回、split から DIP に変えたときにポート番号の順に割り当てること、メイン回路でもボタンが出ること。コンソールのエラーなし。
   - ドラフトの PR: #27。
2. 文言とドキュメント、ブラウザでの確認
   - ヒント、回路設定の説明、日本語と英語の文言、操作マニュアル、エージェント向けドキュメント。
   - ブラウザで: split のモジュールの中でポートを動かしても、置いた先の配線が外れないこと。番号を入れ替えるとピンの順が変わり、プレビューにも出ること。メイン回路でも番号を変えられること。回路設定を触るので、[UI](../../docs/ui.md)の「触ったら確かめること」の回路設定も通す。128 ピンのモジュールで重くなっていないかも見る。

   - 済み（2026-10-21）。エージェントが決めたこと:
     - ヒント（`hints.splitPackage`）は 2 文にした:「ピンは INPUT / OUTPUT のポート番号の順に並ぶ。INPUT / OUTPUT を動かしても、ピンの順は変わらない」「「回路設定」でポート番号を入れ替えるとピンの順も変わり、外側の配線が別のピンにつながるので注意」。
     - 回路設定の split の説明は「入力は左、出力は右に、ポート番号の順 (入力 1、出力 1 がいちばん上) に並びます。ピン番号は使いません。」にした。
     - 番号を入れ替えると、ピンの割り当ての選択肢（「入力 1 A」）を全部の行で作り直すので、名前と同じく `useDeferredValue` で遅らせた（128 ピンの QFP で「下へ」が 2.3 秒から 0.5 秒。CPU を 4 倍遅くして）。
   - 確かめたこと: ブラウザで、split の回路の中で INPUT を動かしても、置いた先のモジュールのピンの順が変わらないこと。メイン回路でも「上へ」「下へ」が出ること。128 ピンの QFP で、開くのは 3.0 秒から 3.5 秒ほど（行ごとのボタンの分）、名前の入力と割り当ての変更は変わらないこと（CPU を 4 倍遅くして、変更前の `next` と並べて測った）。コンソールのエラーなし。

実装は Skill の `modify` で進める。
