# 発振が止まっても「発振しています」が消えない（計画 25）

状態: **進行中**

- 開始の合図を受けたら、段階の区切りで止めずに最後の段階まで進める。迷うことがあれば止めて聞く（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

発振している回路を直したら（ループの配線を消すなど）、「発振しています」の表示が消えるようにする。不具合修正。

[問題パネル](../problems-panel/plan.md)（計画 23）のレビューの途中で、開発者が見つけた（2026-10-23）。計画 23 とは別の不具合として扱う（開発者が決めた）。

## 再現の手順

1. NOT を置き、出力を自分の入力へ配線する（「発振しています」が出る）。
2. その配線を消す。
3. 待っても「発振しています」が消えない。CLOCK のない回路では、次に回路を触るまで残る。

公開している版（`main`。ステータスバーのバッジ）でも、計画 23 の問題パネル（ステータスバーの「問題」の数と、パネルの行）でも起きる（2026-10-23 にブラウザで確かめた）。

## 原因

`simulation/useSimulation.ts` のループ（`onFrame`）:

- シミュレーションの結果は、部品の値が変わったフレームでだけ画面に渡す（`if (changed) publish(...)`）。発振しているか（`unstable`）も、`publish` の中でしか App に伝えない。
- 発振が止まると、まず値が落ち着く。発振でないと判定されるのは、落ち着いた状態が何 tick か続いたあと（`stableTicks` が `SETTLED_TICKS` に届いて `activeTicks` が 0 に戻ったとき）で、そのときは値がもう変わらないので、判定が変わったことが伝わらない。
- CLOCK のない回路では、落ち着くとループ自体が止まるので、次に回路を触るまで表示が残る。

## 直し方（案）

- 値が変わっていなくても、発振の判定が前に知らせたものと変わったフレームでは、App に知らせる（`setUnstable`）。tick の計算は変えないので、重さは変わらない見込み。
- ループを止める前（落ち着いたと判断したとき）にも、同じく判定を知らせる。
- 一時停止中の 1 tick 送り・戻しでも、判定が変わったら知らせる（今は `publish` を通るので伝わる見込み。確かめる）。

## 段階（案）

1. 直す前に、再現の手順で起きることを確かめる。できれば、判定が変わったことを知らせる部分を、テストできる形にして失敗するテストを先に書く。
2. 直し方のとおり直す。テスト、ブラウザで再現の手順を通して表示が消えること、発振が続いている間は消えないこと、CLOCK のある回路でも変わらないことを確かめる。フレームレートも測る（描画に関わるコードのため）。

実装は Skill の `modify` で進める。
