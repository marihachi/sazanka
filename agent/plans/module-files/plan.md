## 目的

モジュールをファイルに書き出し、別のプロジェクトに持ち込んで再利用できるようにする。

[プロジェクト管理機能](../project-management/plan.md)（計画 1）の下位の計画。前提は、[保存データをプロジェクトと回路に分ける](../project-format/plan.md)（計画 19）、[未解決のモジュール](../unresolved-module/plan.md)（計画 20）、[プロジェクトパネル](../project-panel/plan.md)（計画 21。書き出しと持ち込みの操作はパネルに置く）。

## 前提

- モジュールは `id` だけで識別する。`id` は UUID の形で、プロジェクトをまたいでも重ならない。同じ `id` なら同じモジュール（の別の版）と見分けられる。
- 計画 19 の新しい形式では、プロジェクトは要素（フォルダのパスと、中に持つモジュール）の並びと、フォルダの一覧を持つ。部品は `circuitId` と名前の写し `circuitName` でモジュールを指す。回路の形式は `format: "sazanka-circuit"` と版を持つ。
- プロジェクト全体の書き出しと読み込みは、プロジェクトファイル。読み込むとプロジェクトを丸ごと置き換える。ヘッダーの「ファイル」のメニュー（名前を付けて保存…、開く…。名前は[計画 24](../project-file/plan.md)で決めた。計画 21 でいったんプロジェクトパネルの「⋯」に移したが、ヘッダーに戻した）。手元のファイルの保存と選択は `file/localFile.ts` が使える。

## 決めたこと

開発者が決めたこと（2026-10-17。もとは計画 1 で決めたもの）。

- 書き出せる単位は、プロジェクト全体（今のプロジェクトファイル）、モジュール 1 つ、複数のモジュール。それぞれ 1 ファイルで書き出す。
- 回路を書き出すファイルは、1 つでも複数でも、いつも回路ファイルの形式にする（例: `"format": "sazanka-circuits"`）。数でファイルの形が変わるとややこしいため。メイン回路は持たない。
- 回路ファイルはフォルダを持たない。中身は、モジュールのデータ（回路の形式そのまま）の平らな並び（2026-10-17）。フォルダは置き先のプロジェクトが決めるもので、持ち込むときに、持ち込み先のフォルダを指定できれば足りるため。
  - 持ち込み先は、読み込みのダイアログで選ぶ。ダイアログでファイルと持ち込み先のフォルダを選んで「読み込む」を押すと、回路ファイルのモジュールがすべてそのフォルダに入ってプロジェクトの並びに加わる（2026-10-17）。
  - 持ち込み先のフォルダは、木の形の一覧で選ぶ（新しいモジュールの追加と同じ部品。[計画 21](../project-panel/plan.md)）。
  - ダイアログの中で、新しいフォルダを作ってから、それを選べる（2026-10-17）。作ったフォルダは、その時点でプロジェクトにできるので、読み込まずに閉じても残る（空のフォルダとして残せる。計画 19）。新しいモジュールの追加のダイアログ（[計画 21](../project-panel/plan.md)）と同じ扱い。
  - 採らなかった案: プロジェクトパネルでフォルダを選んでからボタンを押し、選んでいるフォルダに入れる（ダイアログは出さない）。
  - 採らなかった案: 回路ファイルの中身を、プロジェクトの要素と同じ形（パスとインラインのモジュール）にして、フォルダも持ち運ぶ。
  - 採らなかった案: 1 つのときは回路の形式（`"sazanka-circuit"`）そのままで書く。プロジェクトの形式で、メイン回路なしを許す。
- 回路ファイルの形式は、プロジェクトと回路の形式とは別に v1 から数える。新しい種類を足すだけなので、ほかの形式の版には響かない。
- 追加: 空の回路を作る「新しい回路…」に加えて、回路ファイルを選んでプロジェクトに足せるようにする（持ち込み）。操作の置き場所は、下の「計画 21 のあとで決めたこと」。

- 書き出すモジュールが中で使っているモジュール（入れ子を含む）を、画面では「依存モジュール」と呼ぶ。書き出しのダイアログの選択は「依存モジュールを含める」（英語: Include dependencies）（2026-10-17）。[用語](../../docs/glossary.md)にも足す。
  - 採らなかった案: 「使っているモジュールも入れる」。

叩き台:

```json
{
  "format": "sazanka-circuits",
  "version": 1,
  "modules": [
    { "format": "sazanka-circuit", "version": 1, "id": "7b3e…", "name": "全加算器", ... },
    { "format": "sazanka-circuit", "version": 1, "id": "c91a…", "name": "半加算器", ... }
  ]
}
```

- 依存モジュール: 書き出すときに、依存モジュールを含めるかを選べるようにする（既定は含める）。含めないと、持ち込み先で足りなければ未解決のモジュールになる（2026-10-17）。採らなかった案: いつも含める。
- 持ち込んだときのぶつかり（2026-10-17）:
  - `id` が同じモジュールがすでにある（同じモジュールの別の版）: モジュールごとに「置き換える（更新）」か「スキップ（読み込まない）」を選ぶ（2026-10-18）。回路ファイルには複数のモジュールが入りうるので、一部だけ置き換えたいことがあるため。読み込みのダイアログの「読み込むモジュール」の一覧で選び、ピンが変わるとき（ポート番号やパッケージが違うとき）はその行で知らせる。既定の選択は「置き換える」。
    - 同じ `id` のモジュールは 1 つのプロジェクトに 2 つ置けない（部品が `id` で指すため）ので、置き換えるか、読み込まないかのどちらかになる。
    - 採らなかった案: 読み込むと必ず置き換え、置き換えたくなければ読み込みそのものをキャンセルする（複数のモジュールのうち一部だけを読み込めない）。「別のモジュールとして足す」（新しい `id` を付ける）も選べるようにする。
  - `id` は違うが、読み込み先のフォルダに同じ名前のモジュールがある: 名前の最後に ` (2)` などを付けて、別のモジュールとして読み込む。選ばせない（2026-10-18）。読み込みのダイアログの行に、変わった後の名前を示す。今あるモジュールを置いている部品を新しい方へ切り替えたいときは、読み込んだあとにプロジェクトパネルの「別のモジュールに差し替える」（[計画 21](../project-panel/plan.md)）で行う。
    - 採らなかった案: その行で「名前を変えて読み込む」「差し替える」を選べるようにする（差し替えはあとからパネルでできるので、読み込みのダイアログでは選ばせない）。
- 読み込みの流れ（2026-10-18）: メニューの「回路を読み込む…」を押すと、読み込みのダイアログを開く。ダイアログの中の「ファイルを選ぶ」ボタンで、ブラウザのファイルを選ぶ画面を開いてファイルを選ぶ。選ぶまでは、読み込むモジュールの一覧は空で、「読み込む」は押せない。選んだあとは、ファイルの名前と中身（読み込むモジュールの一覧）を出し、ボタンで別のファイルに選び直せる。読めないファイルなら、ダイアログの中にその旨を出す（ダイアログは閉じない）。「読み込む」を押すと反映し（まとめて 1 回の編集）、「キャンセル」なら何も変えない。
  - 採らなかった案: 先にファイルを選ぶ画面を開き、選んだあとでダイアログを出す。
- 違う種類のファイル（プロジェクトファイル）を選んだときは、ダイアログの中に、種類が違うことと正しい操作（ヘッダーの「ファイル」の「開く…」。計画 21 で変わった）を出す（2026-10-18。[計画 19](../project-format/plan.md)と同じ考え方）。
- 1 回の読み込みで選べるファイルは 1 つだけ（2026-10-18）。採らなかった案: ダイアログで複数のファイルを追加していき、まとめて読み込む（複数のファイルに同じ `id` のモジュールが入っていたときの扱いが要り、複雑になる）。
- 「扱い」の列は、どのモジュールでも選べるようにし、どれにも「スキップ」（読み込まない）を置く（2026-10-18）。
  - ぶつかりのないモジュール: 「追加」（既定）か「スキップ」。採らなかった案: 選べずに「新しく読み込みます」と出す。
  - 同じ名前があるモジュール: 「追加（名前を変更）」（既定）か「スキップ」。
  - 同じ `id` のモジュールがあるもの: 「置き換える」（既定）か「スキップ」。
  - スキップしたモジュールは、プロジェクトでの名前の列を「—」にする。
  - ほかの読み込むモジュールが使っている（依存している）モジュールをスキップし、プロジェクトにもそのモジュールがないときは、読み込んだあと未解決のモジュールになる。そのときは、その行に知らせを出す（例: 「スキップすると未解決になります（全加算器が使っています）」）。スキップはできる（2026-10-18）。知らせは、スキップを選んだときだけ出す。
- 知らせ（ピンが変わること、スキップすると未解決になることなど）は、「扱い」の横のアイコン（⚠）で示し、アイコンにポインターを載せる（ホバー）か、押す（タップ）と内容を出す（2026-10-18）。押したときは、ダイアログを重ねずに、アイコンの横に小さな吹き出し（ポップオーバー）で出す。スマホではホバーができないため、押しても見えるようにする（[UI](../../docs/ui.md)の「ツールチップ」の「欠かせない説明は、ツールチップだけに頼らない」）。
  - 採らなかった案: 知らせを文で出す列（「注意」）を設ける（長い文で幅が足りなくなる）。アイコンとホバーだけにし、一覧の下にまとめの 1 行を出す（スマホでどのモジュールか分からない）。
- 読み込みのダイアログの「読み込むモジュール」の一覧は、回路ファイル上の名前と、プロジェクトでの名前（読み込んだあとの名前）を 2 つの列で並べる（2026-10-18）。同じ `id` で「スキップ」を選んだモジュールは、プロジェクトに入らないので、プロジェクトでの名前を横線（—）にする。名前が重なって ` (2)` などを付けるモジュールは、付けた後の名前を出す。
  - 判定の順: 同じ `id` を先に見る。同じ `id` のモジュールがあれば、名前やフォルダが違っても同じモジュール（の別の版）として、置き換えるかスキップかを選ぶ。名前を見るのは、同じ `id` のモジュールがないときだけ（`id` だけで識別すると決めたため）。
  - （古い案。上の、モジュールごとに選ぶ形（2026-10-18）に変わった）一度に複数がぶつかったときは、まとめて 1 回聞く。
- メイン回路は、モジュールとして書き出せない（2026-10-17）。メイン回路は `id` が `"main"` でどのプロジェクトでも同じなので、持ち込むと見分けられない。採らなかった案: 書き出せるようにし、持ち込むときに新しい `id` を付けてふつうのモジュールにする。
- 持ち込めるのは回路ファイルだけ（2026-10-17）。回路の形式だけのファイル（手で作ったものなど）は持ち込めない。採らなかった案: 回路の形式だけのファイルも、モジュール 1 つだけの束として持ち込めるようにする。
- 書き出しのダイアログ（2026-10-17）: 木の形の一覧（追加・読み込みと同じ部品）にモジュールも並べ、印を付けて選ぶ。フォルダに印を付けると中のモジュールをまとめて選べる。メイン回路は並べない。「依存モジュールを含める」（既定で印あり）と、書き出すものの一覧を出す。「ファイルに保存」を置く（文字列の欄とコピーは置かない。受け渡しはファイルだけにすると決めたため。[計画 19](../project-format/plan.md)、2026-10-18）。保存は、プロジェクトの書き出しと同じく、使えるブラウザでは保存場所を選ぶ画面（`showSaveFilePicker`）を出し、使えなければ `<a download>` で保存する（計画 19）。1 つも選んでいなければ押せない。開き方は、下の「計画 21 のあとで決めたこと」。
- 回路ファイルの形式の目印は `"format": "sazanka-circuits"`。保存するファイル名は `circuits-YYYY-MM-DD.sazanka.json`（端末の日付）（2026-10-17）。採らなかった案: `sazanka-circuits-YYYY-MM-DD.json`。回路が 1 つのときは、下の「計画 21 のあとで決めたこと」。

- 読み込みのダイアログの細かいところ（2026-10-18）:
  - ぶつかりは、ダイアログの中の「読み込むモジュール」の一覧の「扱い」で選ぶ。既定の選択は、ぶつかりのないものが「追加」、同じ名前があるものが「追加（名前を変更）」、同じ `id` があるものが「置き換える」（改版を持ち込むことが多いと考えるため）。知らせは「扱い」の横のアイコンで出す。ダイアログを重ねない。
  - 置き換えたモジュールは、今あるモジュールのフォルダと名前のままにし、中身（回路、パッケージ、作者名など）だけを置き換える。選んだフォルダに入るのは、新しく足すモジュールだけ。フォルダと名前はプロジェクトの中での整理なので、読み込む側の都合を優先するため（例: プロジェクトで全加算器を「FA」に改名していたら、置き換えても「FA」のまま）。採らなかった案: 名前はファイルのものにする。
  - 文言: メニューの項目とダイアログの題名は「回路を読み込む…」（英語: Import modules）。プロジェクトの方は「開く…」（計画 24）で、取り違えないようにする。

## 問題点

- 置き換え（更新）でピンが変わると、置いた先の外側の配線が別のピンにつながったり、どこにもつながらなくなったりする。新しい形式で split もポート番号で決まるので、変わるのはポート番号・パッケージ・ピンの割り当てを変えたときに限られる。それでも、置き換える前に知らせる工夫が要る。
- 置き換えで、モジュールの中がまるごと入れ替わる。持ち込む前のモジュールを持ち込み先で直していたら、その変更は消える（元に戻すで戻せる）。

## 段階

実装は Skill の `modify` で進める。足りない回路があったときは、問題パネル（[計画 23](../problems-panel/plan.md)）に出る（計画 20）。

## 実装で変わったこと

- 持ち込むとモジュールの置き方が循環する（同じ ID の回路を、別のプロジェクトで逆向きに置いた版に置き換えるなど）ことがあるので、そうなる行に印を付け、循環があるうちは読み込めないようにする（エージェントが決めた。計画になかった）。
- 読み込むときは、モジュールの部品の名前と大きさの写しをいったんすべて残し、持ち込んだあとに、指す回路がある部品の写しを外す。今まで見つからなかったプロジェクトのモジュールも、持ち込んだ回路で見つかれば写しを外す。
- 回路ファイルの中の名前の重なりは断らない（持ち込むときに名前を変えるため）。
- 「読み込む」は、すべてをスキップしたときも押せない（読み込むものがないため。エージェントが決めた）。
- フォルダの行のメニューで、「フォルダを削除」の前に区切りの線を足した（回路の行と同じく、削除を分けるため）。
- 「スキップすると見つからないモジュールになります」の文の「未解決」は、計画 20 のあとの言い方（「見つからない」）にした。
