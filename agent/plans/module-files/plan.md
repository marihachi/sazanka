# モジュールのファイル（計画）

状態: **計画中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

モジュールをファイルに書き出し、別のプロジェクトに持ち込んで再利用できるようにする。

[プロジェクト管理機能](../project-management/plan.md)（計画 1）の下位の計画。前提は、[保存データをプロジェクトとモジュールに分ける](../project-format/plan.md)（計画 19）、[未解決のモジュール](../unresolved-module/plan.md)（計画 20）、[プロジェクトパネル](../project-panel/plan.md)（計画 21。書き出しと持ち込みの操作はパネルに置く）。

## 前提

- モジュールは `id` だけで識別する。`id` は UUID の形で、プロジェクトをまたいでも重ならない。同じ `id` なら同じモジュール（の別の版）と見分けられる。
- 計画 19 の新しい形式では、プロジェクトは要素（フォルダのパスと、中に持つモジュール）の並びと、フォルダの一覧を持つ。部品は `moduleId` と名前の写し `moduleName` でモジュールを指す。モジュールの形式は `format: "sazanka-module"` と版を持つ。
- プロジェクト全体の書き出しと読み込みは、今の共有用 JSON（ヘッダーの「書き出し」「読み込み」）。読み込むとプロジェクトを丸ごと置き換える。手元のファイルの保存と選択は `file/localFile.ts` が使える。

## 決めたこと

開発者が決めたこと（2026-10-17。もとは計画 1 で決めたもの）。

- 書き出せる単位は、プロジェクト全体（今の共有用 JSON）、モジュール 1 つ、複数のモジュール。それぞれ 1 ファイルで書き出す。
- モジュールを書き出すファイルは、1 つでも複数でも、いつも「モジュールの束」の形式にする（例: `"format": "sazanka-modules"`）。数でファイルの形が変わるとややこしいため。メイン回路は持たない。
- 束はフォルダを持たない。中身は、モジュールのデータ（モジュールの形式そのまま）の平らな並び（2026-10-17）。フォルダは置き先のプロジェクトが決めるもので、持ち込むときに、持ち込み先のフォルダを指定できれば足りるため。
  - 持ち込み先は、読み込みのダイアログで選ぶ。ダイアログでファイルと持ち込み先のフォルダを選んで「読み込む」を押すと、束のモジュールがすべてそのフォルダに入ってプロジェクトの並びに加わる（2026-10-17）。
  - 持ち込み先のフォルダは、木の形の一覧で選ぶ（新しいモジュールの追加と同じ部品。[計画 21](../project-panel/plan.md)）。
  - ダイアログの中で、新しいフォルダを作ってから、それを選べる（2026-10-17）。作ったフォルダは、その時点でプロジェクトにできるので、読み込まずに閉じても残る（空のフォルダとして残せる。計画 19）。新しいモジュールの追加のダイアログ（[計画 21](../project-panel/plan.md)）と同じ扱い。
  - 採らなかった案: プロジェクトパネルでフォルダを選んでからボタンを押し、選んでいるフォルダに入れる（ダイアログは出さない）。
  - 採らなかった案: 束の中身を、プロジェクトの要素と同じ形（パスとインラインのモジュール）にして、フォルダも持ち運ぶ。
  - 採らなかった案: 1 つのときはモジュールの形式（`"sazanka-module"`）そのままで書く。プロジェクトの形式で、メイン回路なしを許す。
- 束の形式は、プロジェクトとモジュールの形式とは別に v1 から数える。新しい種類を足すだけなので、ほかの形式の版には響かない。
- 追加: 今の「+」（空のモジュールを作る）に加えて、モジュールのファイルを選んでプロジェクトに足せるようにする（持ち込み）。操作はプロジェクトパネルに置く。

- 書き出すモジュールが中で使っているモジュール（入れ子を含む）を、画面では「依存モジュール」と呼ぶ。書き出しのダイアログの選択は「依存モジュールを含める」（英語: Include dependencies）（2026-10-17）。[用語](../../docs/glossary.md)にも足す。
  - 採らなかった案: 「使っているモジュールも入れる」。

叩き台:

```json
{
  "format": "sazanka-modules",
  "version": 1,
  "modules": [
    { "format": "sazanka-module", "version": 1, "id": "7b3e…", "name": "全加算器", ... },
    { "format": "sazanka-module", "version": 1, "id": "c91a…", "name": "半加算器", ... }
  ]
}
```

- 依存モジュール: 書き出すときに、依存モジュールを含めるかを選べるようにする（既定は含める）。含めないと、持ち込み先で足りなければ未解決のモジュールになる（2026-10-17）。採らなかった案: いつも含める。
- 持ち込んだときのぶつかり（2026-10-17）:
  - `id` が同じモジュールがすでにある（同じモジュールの別の版）: 利用者に聞く。「置き換える（更新）」「持ち込まない」を選べる。置き換えでピンが変わるとき（ポート番号やパッケージが違うとき）は、そのことを知らせる。
  - `id` は違うが、持ち込み先のフォルダに同じ名前のモジュールがある（名前は同じフォルダの中で重ならない決まり。[計画 21](../project-panel/plan.md)）: 「足す」（持ち込むモジュールの名前の最後に ` (2)` などを付ける。既定）と、「差し替える」（持ち込むモジュールを足し、今あるモジュールを置いている部品をそちらへ差し替える。計画 21 の「別のモジュールに差し替える」と同じ動き）を選べる。採らなかった案: 聞かずに ` (2)` を付けて足すだけにする。
  - 一度に複数がぶつかったときは、まとめて 1 回聞く（一覧で見せて、全部置き換える・全部やめるを選ぶ）。
- メイン回路は、モジュールとして書き出せない（2026-10-17）。メイン回路は `id` が `"main"` でどのプロジェクトでも同じなので、持ち込むと見分けられない。採らなかった案: 書き出せるようにし、持ち込むときに新しい `id` を付けてふつうのモジュールにする。
- 持ち込めるのは束のファイルだけ（2026-10-17）。モジュールの形式だけのファイル（手で作ったものなど）は持ち込めない。採らなかった案: モジュールの形式だけのファイルも、モジュール 1 つだけの束として持ち込めるようにする。
- 書き出しのダイアログ（2026-10-17）: 木の形の一覧（追加・読み込みと同じ部品）にモジュールも並べ、印を付けて選ぶ。フォルダに印を付けると中のモジュールをまとめて選べる。メイン回路は並べない。「依存モジュールを含める」（既定で印あり）と、書き出すものの一覧を出す。今のプロジェクト全体の書き出しと同じく、文字列の欄に中身を出し、「コピー」と「ファイルに保存」を置く。1 つも選んでいなければ押せない。開き方は、プロジェクトパネルの上の「⋯」の「モジュールを書き出す…」と、行のメニューの「書き出す…」（計画 21）。
- 束の形式の目印は `"format": "sazanka-modules"`。保存するファイル名は `modules-YYYY-MM-DD.sazanka.json`（端末の日付。モジュールの数によらず同じ）（2026-10-17）。採らなかった案: `sazanka-modules-YYYY-MM-DD.json`。モジュールが 1 つならそのモジュールの名前にする。

## 決めてほしいこと

開発者があとで聞くと言ったもの（2026-10-17）。

1. 読み込みのダイアログの細かいところ（持ち込み先の決め方は「決めたこと」）
   - ファイルを選ぶ所: 推す案は、今の共有用 JSON の読み込みのダイアログと同じく、ダイアログの中にファイルを選ぶボタンを置く（ファイルを選ぶまで「読み込む」は押せない）。
   - `id` が同じモジュールを置き換える（更新する）ときは、選んだフォルダではなく、今あるモジュールのフォルダのままにする（推す案）。置き換えは中身の更新で、置き場所は変えないため。
   - 文言: ヘッダーの「読み込み」（プロジェクト全体を置き換える）と同じ言葉だと取り違えやすい。推す案: パネルのボタンとダイアログの題名は「モジュールを読み込む」（英語: Import modules）。

## 問題点

- 置き換え（更新）でピンが変わると、置いた先の外側の配線が別のピンにつながったり、どこにもつながらなくなったりする。新しい形式で split もポート番号で決まるので、変わるのはポート番号・パッケージ・ピンの割り当てを変えたときに限られる。それでも、置き換える前に知らせる工夫が要る。
- 置き換えで、モジュールの中がまるごと入れ替わる。持ち込む前のモジュールを持ち込み先で直していたら、その変更は消える（元に戻すで戻せる）。

2. 画面: プロジェクトパネルの書き出しと持ち込みの操作、ぶつかったときの確認、ピンが変わるときの知らせ。
