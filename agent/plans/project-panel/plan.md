# プロジェクトパネル（計画 21）

状態: **計画中**

用語（2026-10-20）: 定義は「回路」、置いたものは「モジュール」と呼び分けることにした（[用語](../../docs/glossary.md)）。この文書の操作やファイル、形式の名前は新しい言い方に直した。それ以外で「モジュール」が定義を指している所は、「回路」と読み替える。

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

プロジェクトの中の回路（メイン回路とモジュール）を一覧して管理する「プロジェクトパネル」を作る。回路を開く・追加・改名・プロジェクトから削除し、フォルダで整理する。あわせて、タブバーを「開いている回路だけを並べる」形に変える。

解きたい課題: 今はモジュールがタブとパレットに散らばっていて、モジュールが増えると管理しにくい。

[プロジェクト管理機能](../project-management/plan.md)（計画 1）の下位の計画。前提は、[保存データをプロジェクトと回路に分ける](../project-format/plan.md)（計画 19。プロジェクトの要素の並びとフォルダのパス）、[メイン回路をほかの回路と同じに扱う](../main-as-module/plan.md)（計画 18。回路設定）、[未解決のモジュール](../unresolved-module/plan.md)（計画 20。未解決のモジュールと、使われているモジュールの削除）。回路ファイルの書き出しと持ち込みは、このあとの[回路ファイル](../module-files/plan.md)（計画 22）で、このパネルに足す。

## 前提

- 今のタブバー（`modules/TabBar.tsx`）: 回路をすべてタブに並べ、クリックで開く、「+」でモジュールを追加、ダブルクリックで改名、ドラッグで並べ替え（回路の並びそのもの。元に戻せる）。メイン回路は先頭に固定。
- 今のパレット（`palette/Palette.tsx`）: 左のサイドパネル。モジュールのグループもある。
- 計画 19 のあと、回路の並びはプロジェクトの要素の並びで、要素はフォルダのパスを持つ（フォルダの部分だけ。`""` はフォルダなし）。プロジェクトはフォルダの一覧（`folders`）も持ち、空のフォルダも残せる。アプリの中では、回路（`CircuitDef`）が `path` を持ち、`Project` が `folders` を持つ。

## 決めたこと

開発者が決めたこと（2026-10-17。もとは計画 1 で決めたもの）。

- 管理する場所は、プロジェクトパネルにする。プロジェクトにある回路（メイン回路とモジュール）の一覧を出し、開く・追加・プロジェクトから削除・書き出し（計画 22）をする。どのモジュールがどこで使われているかも見られるようにする（未解決のモジュールは問題パネル。下の「行に出すもの」）。
- プロジェクトパネルは、左のサイドパネル（今のパレットの場所）に置き、パレットと表示を切り替える。
  - 採らなかった案: パレットとは別のパネルとして左の端に並べる（横幅を取る）。右側に置く。
  - 切り替えは、サイドパネルのさらに左に置く、アイコンだけの細い列で行う。並びは上から「プロジェクト」「部品」。採らなかった案: サイドパネルの上にタブを 2 つ置く。
  - 最後に選んでいた方を覚える（パレットの折り畳みと同じく localStorage に保存する）。
  - パレットの「モジュール」グループは残す。切り替えるとパレットとプロジェクトを同時に見られないので、モジュールを置く操作は今までどおりパレットでもできるようにする。
  - 初めて開いたとき（保存した画面の状態がないとき）は、タブを 1 つも開かずに起動し、サイドパネルは「プロジェクト」を出す。メイン回路を開くと、タブが開き、サイドパネルは「部品」に移る。
  - プロジェクトパネルから回路を開き、それで新しくタブが開いたときは、いつもサイドパネルを「部品」に移す（開いた回路にすぐ部品を置けるように）。すでに開いているタブに切り替えただけなら移らない。
  - 今の利用者も、更新したあとに初めて開いたときは、開いていたタブの記録がないので、タブなしで起動し、「プロジェクト」を出す（今までと同じ見た目で始めるための特別な扱いはしない）。
- タブバーは、開いている回路だけを並べる。プロジェクトパネルで回路を開くとタブに並び、タブで開いている回路の間を行き来する（エディタと同じ形）。
  - メイン回路のタブも、ほかの回路と同じく閉じられる。メイン回路は、プロジェクトから削除できない。
  - タブを全部閉じたら、「表示するものがない」状態にする。シートは描かず、シートの所に短い文（例: 「開いている回路はありません」）を出す。シートのツールバーのボタンは押せない。シミュレーションは止める。最後のタブを閉じられないようにはしない。
  - タブに閉じるボタン（「×」）を付ける。
  - タブの並びは、開いた順。ドラッグで並べ替えられる。並びは保存データには入れず、画面の状態として localStorage に保存する（再読み込みのあとも、開いていたタブと並びが残る）。元に戻す対象にもしない。
  - 回路の並び（プロジェクトの要素の並び）は、プロジェクトパネルの並びとして扱い、保存データに残す。
  - タブでできるのは、開く・閉じる・並べ替えだけ。改名と追加（今の「+」）は、プロジェクトパネルに移す。
  - プロジェクトから削除したモジュールのタブは閉じる。
- プロジェクトから削除する操作は、プロジェクトパネルにだけ置く。シートのツールバーの「モジュールを削除」ボタンはなくす。[計画 18](../main-as-module/plan.md)で「回路設定」の右に場所を空けて置くと決めたボタンなので、なくすときに、空けていた場所の扱いも直す。
- 新しいモジュールの追加（今のタブバーの「+」をパネルに移したもの）では、名前と一緒に、追加先のフォルダを選ぶか、新しいフォルダを作れるようにする（2026-10-17）。モジュールの読み込み（[計画 22](../module-files/plan.md)）のダイアログとそろえる。
  - 開いたときに選ばれているフォルダは、パネルで選んでいるフォルダ（モジュールの行を選んでいれば、そのモジュールのフォルダ。何も選んでいなければフォルダなし）にする。
  - フォルダを作るときは、ダイアログの中でフォルダを作ってから、それを選ぶ（2026-10-17）。作ったフォルダは、その時点でプロジェクトにできる（空のフォルダとして残せるため）。追加せずにダイアログを閉じても、作ったフォルダは残る。フォルダを作るのは、その時点で 1 回の編集にする（履歴に積む）。モジュールを追加すれば、それも 1 回の編集で、元に戻す 2 回でどちらも戻る（2026-10-17）。
  - 採らなかった案: 名前だけを入れ、フォルダはあとでパネルで動かす。
- パネルの操作は、パネルの上の「⋯」（3 点）のアイコンを押して出すメニューにまとめる（2026-10-17）。ボタンを並べない。採らなかった案: ハンバーガーアイコン（≡）。操作のボタンをパネルの上に並べる。
- 追加と読み込みのダイアログで、フォルダを選ぶ所は木の形の一覧（ツリービュー）にする（2026-10-17）。プロジェクトパネルとダイアログで、木を描く部品を分け合い、パネルではフォルダとモジュールを、ダイアログではフォルダだけを並べる。ダイアログでは、フォルダの作成は一覧の中の入力欄で行う（ダイアログを重ねない。[UI](../../docs/ui.md)の「ダイアログ」）。
  - 採らなかった案: フォルダを選ぶ所を選択欄（ドロップダウン）にする。
- モジュールをフォルダで整理する。フォルダのパスはプロジェクトの要素が持ち、名前はモジュールのデータが持つ（計画 19）。


画面の構想（2026-10-17。開発者が、狭い画面のほかは構想どおりでよいとした）:

```
┌──────────────────────────────────────────────────────────────────────────┐
│ ✿  新規作成  読み込み  書き出し  元に戻す  やり直し              ⚙  ⓘ │ ← ヘッダー
├──┬───────────────────────┬────────────────────────────────────────────────┤
│📁│ プロジェクト       [⋯]│ [メイン ×] [全加算器 ×] [カウンタ ×]           │ ← タブ（開いている回路だけ）
│  │───────────────────────│────────────────────────────────────────────────│
│🔧│   ★ メイン            │ 選択 配線 分割 | 回転 | ⏸ ⏮ ⏭     [回路設定] │ ← シートのツールバー
│  │ ▾ adders              │────────────────────────────────────┬───────────│
│  │     全加算器       [⋯]│                                    │プロパティ │
│  │     半加算器          │            シート                  │           │
│  │ ▾ lib                 │                                    │           │
│  │   ▸ gates             │                                    │           │
│  │     7セグデコーダ     │                                    │           │
│  │   カウンタ            │                                    │           │
│  │───────────────────────│                                    │           │
│  │ 全加算器              │                                    │           │
│  │ 使われている所:       │                                    │           │
│  │  メイン (2)、カウンタ (1)                                  │           │
├──┴───────────────────────┴────────────────────────────────────┴───────────┤
│ ヒント…                                                                  │ ← ステータスバー
└──────────────────────────────────────────────────────────────────────────┘
```

- 一覧: フォルダを木の形で見せ、折り畳める（折り畳みは画面の状態として localStorage に保存する）。フォルダの中は、子のフォルダを先に、そのあとにモジュールを並べる（フォルダの並びは `folders` の順、モジュールの並びはプロジェクトの要素の順）。採らなかった案: フォルダとモジュールを混ぜて並べる（混ぜた順を保存する仕組みが要る）。
- メイン回路も、ほかのモジュールと同じく、並べ替えられ、フォルダにも入れられる（2026-10-17。整理の問題なので、ほかと分けない）。プロジェクトから削除と改名ができないことだけが違う。★ の印で見分ける。
  - 採らなかった案: いちばん上に固定し、フォルダに入れられない。並べ替えだけでき、フォルダには入れない（フォルダを畳むとメイン回路が見えなくなるのを避ける案だった）。
- 新規作成と、プロジェクトを読み込んだあとは、タブをすべて閉じ、どの回路も開かない。サイドパネルは「プロジェクト」にする（2026-10-18）。初めて開いたときと同じ状態から始める。採らなかった案: メイン回路のタブだけを開き、サイドパネルを「部品」にする（今のアプリはメイン回路を開く）。
- 新規作成したときは、元に戻す・やり直しの履歴を消す（2026-10-18）。履歴はプロジェクトごとのもので、別のプロジェクトを開けば、前のプロジェクトの履歴はなくなるのが当然、という考え方による（開発者が決めた）。新規作成は元に戻せなくなる。今は、新規作成も元に戻す対象（`commit`）で、確認の文に「元に戻すで戻せます」と書いてあるので、確認の文を「元に戻せません」に直す（[編集と元に戻す](../../docs/editing.md)の表も直す）。この確認は、[計画 24](../project-file/plan.md)で「保存してから続ける」「保存しない」「キャンセル」を選ぶ確認に置き換わり、ファイルに保存していない変更があるときだけ出すことになる。プロジェクトを読み込んだときも、履歴を消す（[計画 19](../project-format/plan.md)で、読み込みを作り直すときに当てはめる）。
  - 採らなかった案: 今と同じく、新規作成も元に戻せるようにする。
- 行を 1 回押すと選ぶ（パネルの下に使われている所を出す）。ダブルクリックか Enter で開く。行のメニューの「開く」でも開く（2026-10-18）。開くとサイドパネルが「部品」に移るので、選ぶだけの操作と分ける。採らなかった案: 1 回押すと開く。
- 改名は、行のメニューの「名前を変える」か、行を選んで F2 を押すと始める。その行が、その場で入力欄に変わる（今のタブの改名と同じ。Enter で確定、Esc で取り消し、欄を離れると確定）（2026-10-18）。モジュールとフォルダのどちらも同じ。メイン回路は改名できない。同じフォルダに同じ名前があれば断る（決めたとおり）。採らなかった案: 名前を入れるダイアログを出す。
- プロジェクトパネルからシートへのドラッグでモジュールを置く操作は、今回は作らない（2026-10-18）。パレットの「モジュール」グループで置ける。必要になったら足す。
- 行に出すもの: 名前、メイン回路の印（★）。未解決のモジュール（計画 20）は、プロジェクトパネルには出さず、[問題パネル](../problems-panel/plan.md)（計画 23）に「見つからない回路」として出す（2026-10-17）。採らなかった案: パネルのいちばん下に「見つからない回路」のまとまりを出す。パネルにも問題パネルにも出さず、ステータスバーで知らせるだけにする。行を選ぶと、使われている所（回路の名前と数）をパネルの下に出す。
- パネルの上の「⋯」のメニュー（パネル全体に効く操作）: 新しい回路…、新しいフォルダ…、回路を読み込む…（計画 22）、回路を書き出す…（計画 22）、新規作成…、開く…、上書き保存（対応しているブラウザだけ）、名前を付けて保存…（開くと保存はアプリのダイアログを出さず、ブラウザの保存場所・ファイルを選ぶ画面を出す。[計画 19](../project-format/plan.md)）。プロジェクトの操作の名前は[計画 24](../project-file/plan.md)で決めた（パネルの中なので「プロジェクトを」は付けない）。計画 24 より前にこの計画を進めるなら、上書き保存はなく、開くと名前を付けて保存は今の読み込みと書き出しの動き。
  - プロジェクト全体の書き出しと読み込みは、ヘッダーからなくし、このメニューに移す（2026-10-18）。プロジェクトの中のものを扱う操作を、パネルにまとめるため。採らなかった案: 今までどおりヘッダーに置き、パネルには置かない。
  - 新規作成も、ヘッダーからなくし、このメニューに移す（「新規作成…」。確認を出すので「…」を付ける。名前は計画 24 で決めた）（2026-10-18）。プロジェクト全体の操作をパネルにまとめるため。採らなかった案: 新規作成はヘッダーに残す。
  - ヘッダーには、元に戻す、やり直し、環境設定、このアプリについてが残る（と、[計画 24](../project-file/plan.md)で決める、今開いているファイルの名前）。
- 行のメニュー（右クリック、スマホの長押し、行の右端の「⋯」で開く。「⋯」は、行にポインターを載せたときと、選んでいる行に出す）:
  - モジュールの行: 開く、名前を変える、フォルダを変える…、書き出す…（計画 22。その行のモジュールに印が付いた状態で開く）、別のモジュールに差し替える…、プロジェクトから削除…（計画 20）。メイン回路の行では、名前を変える・別のモジュールに差し替える・プロジェクトから削除を出さない。
  - フォルダの行: 新しい回路…、新しいフォルダ…（どちらもそのフォルダの中に作る）、名前を変える、書き出す…（そのフォルダの中のモジュールすべてに印が付いた状態で開く）、フォルダを削除。
  - 採らなかった案: パネルの上の「⋯」に、選んでいる行への操作も全部入れる。選んだ行に効くボタンをパネルの上に並べる。
- モジュールを差し替える操作を足す（2026-10-17）。行のメニューの「別のモジュールに差し替える…」で差し替え先を木の形の一覧から選ぶと、元のモジュールを置いている部品が、すべて差し替え先を指すようになる（部品の `circuitId` を書き換える）。
  - 使う場面: 改版を別のモジュール（複製など。`id` が違う）として作ったときに、置いている部品をまとめて新しい方へ切り替える。未解決のモジュール（[計画 20](../unresolved-module/plan.md)）の部品を、手元の別のモジュールにつなぎ直す。
  - 差し替えたあと、元のモジュールをプロジェクトから削除するかを選べる。
  - ピンの数や並び（パッケージ、ポート番号、ピンの割り当て）が違うときは、配線が外れたり別のピンにつながったりすることを、差し替える前に知らせる。
  - 1 回の編集にする（元に戻す 1 回で戻る）。
  - メイン回路は差し替え先に選べない（ほかの回路に置けないため）。メイン回路の行には、この操作を出さない。
  - 同じモジュールを直した改版（`id` が同じ）は、この操作ではなく、回路ファイルの持ち込みで「置き換える（更新）」を選べば足りる（[計画 22](../module-files/plan.md)）。
  - 採らなかった案: モジュールをフォルダと名前の組で識別し、同じフォルダと名前に置けば差し替わるようにする（改名や移動で参照が切れ、プロジェクトをまたぐと別物が黙って置き換わる。`id` だけで識別すると決めたことを作り直すことになる）。
- フォルダとモジュールは、パネルでのドラッグで並べ替えられる（2026-10-17）。元に戻す対象にする（今のタブの並べ替えと同じ）。並びは保存データに残る（フォルダは `folders` の並び、モジュールはプロジェクトの要素の並び。計画 19 の形式のまま足せる）。
  - ドラッグは、落とす場所で意味を分ける。フォルダの行の上に落とすと、そのフォルダの中へ移す。行と行の間に落とすと、その位置へ並べ替える（間が別のフォルダの中なら、移しながら並べ替える）。落とす位置には線を出し、フォルダの中へ入るときはフォルダの行に色を付ける。
  - フォルダはフォルダどうし、モジュールはモジュールどうしの中で並べ替える（フォルダの中は、子のフォルダが先、モジュールがあと）。メイン回路もモジュールとして並べ替えられる。
  - スマホでは、長押しのメニューと区別するため、少し動かしてからドラッグとして扱う。
  - 採らなかった案: 並べ替えはできず、名前の順に並べる。
- モジュールをフォルダへ動かすのは、パネルでのドラッグと、行のメニューの「フォルダを変える…」（フォルダを木の形の一覧で選ぶ）。タブにはモジュールの名前を出す（フォルダは出さない）。
- モジュールの名前は、同じフォルダの中では重ならないようにする（ファイルの置き場所と同じ考え方）。追加・フォルダの移動・持ち込みで重なったら ` (2)` などを付け、改名では断る。採らなかった案: プロジェクト全体で重ならないようにする。重なってもよい（今の改名と同じ）。
- フォルダの作成・改名・削除: 「新しいフォルダ…」で空のフォルダを作れる。フォルダの改名は、中のモジュールと入れ子のフォルダのパスもまとめて変える。フォルダの削除は、空のときだけできる（中にモジュールがあれば、先に動かすか削除してもらう）。どれも元に戻す対象にする。採らなかった案: 中にモジュールがあるフォルダも削除でき、中のモジュールは 1 つ上のフォルダへ移る。
- 追加と読み込みのダイアログで、フォルダを選ぶ・作る部品は同じものを使い、開いたときに選ばれているフォルダも同じ決め方にする（パネルで選んでいるフォルダ。モジュールの行を選んでいればそのモジュールのフォルダ。何も選んでいなければフォルダなし）。
- タブを全部閉じたときは、シートの所に「開いている回路はありません」と出し、シートのツールバーのボタンは押せない。

- パレットのモジュールのグループは、フォルダごとにまとめない（名前の順に並べたまま）（2026-10-17）。パレットは部品を置くための一覧で、整理はプロジェクトパネルで行うため。採らなかった案: フォルダごとにまとめる。
- 狭い画面での、アイコンの列とサイドパネルの扱いは、今のところ考えない（2026-10-17。開発者が決めた）。今のサイドパネル（パレット）と同じ扱いのままにする。必要になったら決め直す。

## 段階（案）

実装の前に細かく書く。実装は Skill の `modify` で進める。

1. サイドパネルの切り替え（アイコンの列）と、プロジェクトパネルの一覧（木を描く部品、開く、並び、使われている所）。
2. タブバーを、開いている回路だけを並べる形にする（閉じる、並べ替え、タブなしの状態、localStorage）。
3. パネルの「⋯」のメニューと行のメニュー。ヘッダーの「新規作成」「書き出し」「読み込み」をなくし、新規作成とプロジェクト全体の書き出し・読み込みをパネルの「⋯」に移す。追加（フォルダを選ぶ・作るダイアログ）・改名・プロジェクトから削除をパネルに移し、ツールバーの「モジュールを削除」をなくす。アプリの中で「先頭の回路がメイン回路」を前提にしている所（回路が見つからないときに先頭を開く所、`project.ts` の `moveCircuit` がメイン回路を先頭に固定する所など）を、`id` で探す形に直す。
4. フォルダ（作成・改名・削除、移す操作、名前の重なり）と、ドラッグでの並べ替え。
5. 別のモジュールに差し替える操作。
- 確かめること: ブラウザで、各段階の操作と、元に戻す、再読み込みで状態が残ること、狭い画面。ドキュメント（[UI](../../docs/ui.md)、[画面操作](../../docs/interaction.md)、操作マニュアル、[用語](../../docs/glossary.md)）。
