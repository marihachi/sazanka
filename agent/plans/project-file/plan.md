# 保存していない変更の表示と確認（計画 24）

- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

プロジェクトをファイルとして開き、編集し、保存する使い方で、ファイルに保存していない変更があることを分かるようにし、保存し忘れたまま別のプロジェクトに入れ替えないようにする。アプリの中には「今開いているプロジェクト」が 1 つだけあり、複数のプロジェクトは、手元のフォルダにファイルとして置いて管理する（エディタやお絵かきアプリと同じ使い方）。

解きたい課題: 今は、新規作成やプロジェクトを開くと、今のプロジェクトはファイルに保存していなければなくなる（アプリが覚えておけるプロジェクトは 1 つだけ）。保存したかどうかも画面から分からない。

前提は[保存データをプロジェクトと回路に分ける](../project-format/plan.md)（計画 19。プロジェクトファイルの形式と、ファイルだけの書き出し・読み込み）。

## 前提

- プロジェクトの「開く…」と「名前を付けて保存…」は、ヘッダーの「ファイル」のメニューにあり、アプリのダイアログを出さずにファイルだけで行う。保存は、`showSaveFilePicker` が使えるブラウザ（Chrome、Edge など Chromium のもの）では保存場所とファイル名を選ぶ画面を出し、使えないブラウザ（Firefox、Safari）では `<a download>` で保存する。開くのは `<input type="file">`。開くことと新規作成では、元に戻す・やり直しの履歴を消す（履歴はプロジェクトごとのもの）。
- 保存の既定のファイル名は `project-YYYY-MM-DD.sazanka.json`。
- localStorage に、変わるたびにプロジェクトを自動で保存している（`sazanka.project`）。

## 決めたこと

開発者が決めたこと（2026-10-18。2026-10-24 に見直した）。

- 今開いているプロジェクトを、ファイルから開き、変更し、ファイルとして保存する。複数のプロジェクトは、手元のファイルとして管理する。
  - 採らなかった案: アプリの中（localStorage など）に複数のプロジェクトを保存し、一覧から選ぶ（保存の仕組み、一覧の画面、プロジェクトの名前、画面の状態をプロジェクトごとに分けることが要る）。
- 上書き保存（開いたファイルに、保存先を選ばずにそのまま書き込む）は足さない（2026-10-24）。開いたファイルへの書き戻し（`showOpenFilePicker` とファイルへの書き込み）は、安全な接続（https か localhost）でしか使えないため。ファイルへの保存は「名前を付けて保存…」だけ。
- localStorage への自動保存は残す。作業中の控えとして、ページを閉じたり再読み込みしたりしても、作業を失わないようにするため。ファイルへの保存は、利用者が選んだときだけ行う。
  - 採らなかった案: 自動保存をやめる（再読み込みで、保存していない作業が消える）。
- ファイルに保存していない変更があることを、画面に出す。localStorage への自動保存は続けるので、閉じても作業は消えないが、ファイルとしては保存していないことが分かるようにする。
  - ヘッダーの真ん中に、今開いているファイルの名前を出す。ファイルに保存していない変更があれば、名前の横に印（●）を付ける。開いたとき・保存したときから変えたかどうかを覚える。ファイルを開いていないとき（新規作成したあとなど）は、名前の代わりに「（未保存）」と出す（英語は叩き台で「(Unsaved)」）。
  - ファイルの名前は、開いたファイルの名前。名前を付けて保存したあとは、保存したファイルの名前（保存の画面を使えるブラウザでは、選ばれた名前。ダウンロードで保存するブラウザでは、名前を知る手段がないので、既定の名前）。
  - ● にポインターを載せるか押すと「ファイルに保存していない変更があります（作業中の内容は、このブラウザに自動で保存されています）」と出す。
  - 保存していない変更があるかどうかも、ファイルの名前と一緒に localStorage に覚えておき、ページを開き直したあとも ● をそのまま出す。
  - ページを閉じるときのブラウザの確認（`beforeunload`）は出さない。自動保存があるので閉じても作業は消えず、ブラウザの確認の文（「保存されない可能性があります」）と実際の動きが食い違うため。スマホでは出ないことも多い。
  - 採らなかった案: 自動保存をやめ、閉じるときの確認で保存し忘れを防ぐ（確認が出ない場面で作業が消える。確認に「保存する」ボタンを置けない）。自動保存は残し、閉じるときの確認も出す。
- 名前を付けて保存の既定のファイル名は、開いたファイルがあればその名前、なければ `project-YYYY-MM-DD.sazanka.json`。
- 開く前と新規作成の前の確認:
  - 今のプロジェクトを保存するか破棄するかを聞く。選べるのは「保存してから続ける」「保存しない」「キャンセル」。「保存してから続ける」は名前を付けて保存になる。
  - 確認は、ファイルに保存していない変更があるときだけ出す。何も変えていないとき（空のプロジェクトを含む）は出さない。
  - 開くときは、今のプロジェクトについての処理（確認と保存）と、開くプロジェクトの処理（ファイルを選んで読み込む）の 2 段階に分け、それぞれ独立したものとして扱う（開発者が決めた）。先に確認を出し、そのあとファイルを選ぶ画面を開く。ファイルを選ぶ画面で取り消しても、1 段階目でしたこと（保存など）は取り消さない。
  - 「保存しない」を選んだあと、ファイルを選ぶ画面で取り消したときは、今のプロジェクトをそのまま出しておく（元に戻す・やり直しの履歴も残す）。破棄は、別のプロジェクトに入れ替えたときに起きるものとして扱い、入れ替えなければ何も消さない。採らなかった案: 1 段階目で破棄して空のプロジェクトにする。
  - 「保存してから続ける」を選び、保存の画面で取り消したとき: Chrome、Edge では、開くことと新規作成も取りやめる。Firefox、Safari では、保存は `<a download>` のダウンロードで、取り消したかどうかをアプリが知る手段がないので、保存を始めた時点で保存したものとして進める。
- 操作の名前は「新規作成…」「開く…」「名前を付けて保存…」。英語は New…、Open…、Save as…。置き場所はヘッダーの「ファイル」のメニュー。
  - 「プロジェクトを」は付けない（開発者が決めた）。回路のインポートとエクスポートは、別の「回路」のメニューにある（計画 22）ので、取り違えない。
  - 「新規作成…」と「開く…」は、確認を出すので「…」を付ける。
  - 採らなかった案: 「新しいプロジェクト…」「プロジェクトを開く…」。
- キーボード: `Ctrl+O` で開く、`Ctrl+Shift+S` で名前を付けて保存。ブラウザの同じキーの操作より、アプリの操作を優先する。`Ctrl+S` は割り当てない（上書き保存のキーという印象が強いため。ブラウザのページの保存のまま）（2026-10-24）。

## 実装で変わったこと

- ファイルの名前は、ヘッダー全体の真ん中ではなく、左右の操作のあいだの空いている所の真ん中に置く（2026-10-24、開発者が決めた）。
- ● の場所はいつもとっておき、付いたり消えたりしても名前が動かないようにした（開発者が求めた）。
- 狭い画面で空きがなければ、名前は見えなくなり、● だけが残る（エージェントが決めた）。
- 保存していない変更は、編集した印ではなく、保存したときの中身との違いで決める（元に戻すで戻れば消える。エージェントが決めた）。
- 変更がないときは、新規作成の確認も出さない（今までは、いつも「今のプロジェクトは消えます」の確認を出していた。計画の「確認は、ファイルに保存していない変更があるときだけ出す」のとおり）。
- 「保存してから続ける」で開くとき、保存の画面がクリックの効力を使い切って、続けてファイルを選ぶ画面を開けない（Chrome、Edge）。そのときは「保存しました。開くファイルを選んでください。」と「ファイルを選ぶ」の確認を出す（2026-10-24、開発者が決めた。採らなかった案: 保存で止めてもう一度「開く…」を押してもらう、先にファイルを選ばせる）。開けるとき（ダウンロードで保存するブラウザ）は、そのまま開く。
