# プロジェクトをファイルとして開いて保存する（計画）

状態: **計画中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

プロジェクトを、手元のファイルとして開き、編集し、保存できるようにする。アプリの中には「今開いているプロジェクト」が 1 つだけあり、複数のプロジェクトは、手元のフォルダにファイルとして置いて管理する（エディタやお絵かきアプリと同じ使い方）。

解きたい課題: 今は、新規作成やプロジェクトの読み込みをすると、今のプロジェクトは書き出していなければなくなる（アプリが保存できるプロジェクトは 1 つだけ）。開いたファイルに書き戻す手段もない。

前提は[保存データをプロジェクトとモジュールに分ける](../project-format/plan.md)（計画 19。プロジェクトファイルの形式と、ファイルだけの書き出し・読み込み）。

## 前提

- 計画 19 のあと、プロジェクトの書き出しと読み込みは、アプリのダイアログを出さずにファイルだけで行う。書き出しは、`showSaveFilePicker` が使えるブラウザ（Chrome、Edge など Chromium のもの）では保存場所とファイル名を選ぶ画面を出し、使えないブラウザ（Firefox、Safari）では `<a download>` で保存する。読み込みは `<input type="file">`。読み込みと新規作成では、元に戻す・やり直しの履歴を消す（履歴はプロジェクトごとのもの）。
- ファイル名は `project-YYYY-MM-DD.sazanka.json`。
- localStorage に、変わるたびにプロジェクトを自動で保存している（`sazanka.project`）。
- ヘッダーの「新規作成」「書き出し」「読み込み」は、[計画 21](../project-panel/plan.md)でプロジェクトパネルの「⋯」に移す。

## 決めたこと

開発者が決めたこと（2026-10-18）。

- 今開いているプロジェクトを、ファイルから開き、変更し、ファイルとして保存できるようにする。複数のプロジェクトは、手元のファイルとして管理する。
  - 採らなかった案: アプリの中（localStorage など）に複数のプロジェクトを保存し、一覧から選ぶ（保存の仕組み、一覧の画面、プロジェクトの名前、画面の状態をプロジェクトごとに分けることが要る）。
- 上書き保存（開いたファイルに、保存先を選ばずにそのまま書き込む）は、対応しているブラウザ（Chrome、Edge など、`showOpenFilePicker` でファイルへの書き戻しができるもの）でだけ出す。Firefox と Safari では、上書き保存の機能はない（名前を付けて保存だけ）。
  - 上書きにならないのに「上書き保存」と出すと誤解を招くため。どのブラウザでも開くことと保存（名前を付けて保存）はできるので、「特定の環境を前提にしない」決まりとはぶつからない。
  - 採らなかった案: Firefox と Safari でも「上書き保存」を出し、押すとダウンロードにする。
- localStorage への自動保存は残す。作業中の控えとして、ページを閉じたり再読み込みしたりしても、作業を失わないようにするため。ファイルへの保存は、利用者が選んだときだけ行う。
  - 採らなかった案: 自動保存をやめる（再読み込みで、保存していない作業が消える）。開いたファイルにも自動で上書きする（思わぬ変更までファイルに書き込まれ、元に戻せない）。

- ファイルに保存していない変更があることを、画面に出す（2026-10-18）。localStorage への自動保存は続けるので、閉じても作業は消えないが、ファイルとしては保存していないことが分かるようにする。
  - ページを閉じるときのブラウザの確認（`beforeunload`）は出さない。自動保存があるので閉じても作業は消えず、ブラウザの確認の文（「保存されない可能性があります」）と実際の動きが食い違うため。スマホでは出ないことも多い。
  - 採らなかった案: 自動保存をやめ、閉じるときの確認で保存し忘れを防ぐ（確認が出ない場面で作業が消える。確認に「保存する」ボタンを置けない）。自動保存は残し、閉じるときの確認も出す。
- 操作の名前は「新規作成…」「開く…」「上書き保存」（対応しているブラウザだけ）「名前を付けて保存…」（2026-10-18）。英語は New…、Open…、Save、Save as…。置き場所はプロジェクトパネルの「⋯」（[計画 21](../project-panel/plan.md)）。計画 21 より前は、ヘッダーのボタンをこの名前と動きにする。
  - プロジェクトパネルの中なので、プロジェクトの操作だと分かる。「プロジェクトを」は付けない（開発者が決めた）。同じメニューのモジュールの操作は「モジュールを読み込む…」のように「モジュール」を付けるので、取り違えない。
  - 「新規作成…」と「開く…」は、確認（下に書く）を出すので「…」を付ける。
  - 採らなかった案: 「新しいプロジェクト…」「プロジェクトを開く…」。
- 開いたファイルへの手がかり（ファイルハンドル）を、ブラウザの中（IndexedDB）に覚えておく（2026-10-18。Chrome、Edge）。ページを開き直したあとも上書き保存できる。開き直したあとの最初の書き込みで、ブラウザが許可を聞く。覚えていた手がかりは、別のファイルを開いたときと、新規作成したときに入れ替える。
  - 採らなかった案: 覚えない（開き直したあとの最初の保存は、名前を付けて保存になる）。
- 名前を付けて保存の既定のファイル名は、開いたファイルがあればその名前、なければ `project-YYYY-MM-DD.sazanka.json`（2026-10-18）。
- ● にポインターを載せるか押すと「ファイルに保存していない変更があります（作業中の内容は、このブラウザに自動で保存されています）」と出す（2026-10-18）。
- 保存していない変更があるかどうかも、ファイルの名前と一緒に localStorage に覚えておき、ページを開き直したあとも ● をそのまま出す（2026-10-18）。手がかりを覚えられないブラウザ（Firefox、Safari）でも、ファイルの名前と ● は覚えて出す。
- 開く前と新規作成の前の確認（2026-10-18）:
  - 今のプロジェクトを保存するか破棄するかを聞く。選べるのは「保存してから続ける」「保存しない」「キャンセル」。
  - 確認は、ファイルに保存していない変更があるときだけ出す。何も変えていないとき（空のプロジェクトを含む）は出さない。
  - 開くときは、今のプロジェクトについての処理（確認と保存）と、開くプロジェクトの処理（ファイルを選んで読み込む）の 2 段階に分け、それぞれ独立したものとして扱う（開発者が決めた）。先に確認を出し、そのあとファイルを選ぶ画面を開く。ファイルを選ぶ画面で取り消しても、1 段階目でしたこと（保存など）は取り消さない。
  - 「保存しない」を選んだあと、ファイルを選ぶ画面で取り消したときは、今のプロジェクトをそのまま出しておく（元に戻す・やり直しの履歴も残す）。破棄は、別のプロジェクトに入れ替えたときに起きるものとして扱い、入れ替えなければ何も消さない。採らなかった案: 1 段階目で破棄して空のプロジェクトにする。
  - 「保存してから続ける」を選び、保存の画面で取り消したとき: Chrome、Edge では、開くことと新規作成も取りやめる。Firefox、Safari では、保存は `<a download>` のダウンロードで、取り消したかどうかをアプリが知る手段がないので、保存を始めた時点で保存したものとして進める。
- キーボード（2026-10-18）: `Ctrl+O` で開く、`Ctrl+S` で上書き保存（対応していないブラウザでは名前を付けて保存）、`Ctrl+Shift+S` で名前を付けて保存。ブラウザの同じキーの操作（ページを開く、ページを保存）より、アプリの操作を優先する。
- ファイルに保存していない変更の見せ方（2026-10-18）: ヘッダーの真ん中に、今開いているファイルの名前を出す。ファイルに保存していない変更があれば、名前の横に印（●）を付ける。開いたとき・保存したときから変えたかどうかを覚える。ファイルを開いていないとき（新規作成したあとなど）は、名前の代わりに「（未保存）」と出す（英語は叩き台で「(Unsaved)」）。● の説明と開き直したあとの扱いは、下に書く。

## 気になるところ

- `showOpenFilePicker` と、ファイルへの書き込みの許可は、Chromium のブラウザでも、安全な接続（https か localhost）でしか使えない。公開先（GitHub Pages）は https なので使える。
- 開き直したあとの上書き保存で、覚えていた手がかりのファイルが、ほかで動かされたり消されたりしていると、書き込みに失敗する。そのときは名前を付けて保存に切り替える。
