# ピンどうしを直接つなぐ（計画 30）

状態: **進行中**

- 保存データの形式を変えないので、ベースブランチは `main`（[作業の進め方](../../docs/workflow.md)の「ブランチ」）。

- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

部品のピンの先どうしが同じ点に重なったら、配線がなくてもつながるようにする。例: INPUT の出力のピンの先と NOT の入力のピンの先が重なるように並べると、線なしでつながる。今は、ピンの線が端どうしで接していて、つながっているように見えるのに、つながらない。

開発者が求めた。

## 決めたこと

以下は開発者と決めた。

- 配線のつながり方は今のまま（配線の端がピンの先かほかの配線の上にあればつながる。配線の途中がピンの先を通るだけではつながらない）。
- 足すのは、ピンの先どうしのつながりだけ。
- 保存データの形（JSON の項目や値）は変わらないので、形式の版は変えない。変わるのは同じデータの読み取り方で、今までピンの先どうしが重なっているだけだった所は、つながるようになる。
  - 採らなかった案: 回路の形式 v2（公開前）に入れて版を変える。v1 の意味を保つために、変換で重なっている部品をずらす（部品が動き、別の所がずれるおそれがある）。
- ピンどうしがつながっている所に、印は付けない。ピンの線が端どうしで接しているので、つながっていることは見て分かる。ピンの線は値の色で描くので、つながれば入力側のピンも色が変わる。
  - 採らなかった案: 分岐の印（`junction`）と同じ丸を付ける。
- つながり方の決まりは保存データで決めることではないので、形式の文書には書かず、[つながり](../../docs/nets.md)に書く（形式の文書からは、回路の形式 v2 から外した）。

- 出力どうしがぶつかっているネットは、配線だけでなく、ピンの線も赤くする（配線がある場合も、ない場合も）。ピンだけでつながる所でも、どこがぶつかっているかがシートで見えるようにするため。
  - 採らなかった案: 今のまま配線だけを赤くする（ピンだけのぶつかりは、問題パネルで部品を選ばないと見つからない）。
- 部品をぴったり重ねて置くと、ピンの先がすべて重なり、出力どうしもつながってぶつかりのエラーになる。それでよいとする（重ねた部品は見分けにくく、気付くきっかけになる）。
  - 採らなかった案: 本体が重なっている部品どうしは、ピンが重なってもつながない（判定が増える）。

## 今のコードと、変えるところ

- つながり（ネット）は `geometry/net.ts` の `computeNets` が配線から作る。配線が 1 本もないピンは、どのネットにも入らない（`Nets.nets` は「配線が 1 本以上あるネット」）。
- ネットを使うところ: シミュレーションの展開（`simulation/flatten.ts`）、問題パネル（`problems/problems.ts`）、シートの描画（`sheet/Sheet.tsx`）、`app/App.tsx`、`editing/edit.ts`。ネットの作り方を直せば、シミュレーション、モジュールの展開、出力どうしのぶつかりのエラー、問題パネルにも効く見込み。配線のないネットができることで、`wireNet` や分岐の印、配線の色など、配線があることを前提にした所が崩れないかを、実装のときに確かめる。
- ぶつかりの見せ方: 今は、ぶつかっているネットの配線を赤くする（`sheet/Sheet.tsx`、`isConflict`）。ピンの線（`SheetPart.tsx` の `PinLeads`）にも、ぶつかっているかを渡して赤くする。ピンの描き直しを省く比べ方（`samePinLeads`）にも足す（[描画の重さ](../../docs/performance.md)）。
- 変えること: `computeNets` で、ピンの先の位置が同じピンどうしを同じネットにまとめる（配線がなくても）。3 つ以上重なっても同じネット。出力どうしが重なれば、配線のときと同じく値がぶつかるエラー（`isConflict`）。
