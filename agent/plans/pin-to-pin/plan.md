状態: **計画中**

## 目的

部品のピンの先どうしが同じ点に重なったら、配線がなくてもつながるようにする。例: INPUT の出力のピンの先と NOT の入力のピンの先が重なるように並べると、線なしでつながる。今は、ピンの線が端どうしで接していて、つながっているように見えるのに、つながらない。

開発者が求めた。

## 決めたこと

以下は開発者と決めた。

- 配線のつながり方は今のまま（配線の端がピンの先かほかの配線の上にあればつながる。配線の途中がピンの先を通るだけではつながらない）。
- 足すのは、ピンの先どうしのつながりだけ。
- 保存データの形（JSON の項目や値）は変わらないので、形式の版は変えない。変わるのは同じデータの読み取り方で、今までピンの先どうしが重なっているだけだった所は、つながるようになる。
  - 採らなかった案: 回路の形式 v2（公開前）に入れて版を変える。v1 の意味を保つために、変換で重なっている部品をずらす（部品が動き、別の所がずれるおそれがある）。

## 今のコードと、変えるところ

- つながり（ネット）は `geometry/net.ts` の `computeNets` が配線から作る。配線が 1 本もないピンは、どのネットにも入らない（`Nets.nets` は「配線が 1 本以上あるネット」）。
- ネットを使うところ: シミュレーションの展開（`simulation/flatten.ts`）、問題パネル（`problems/problems.ts`）、シートの描画（`sheet/Sheet.tsx`）、`app/App.tsx`、`editing/edit.ts`。ネットの作り方を直せば、シミュレーション、モジュールの展開、出力どうしのぶつかりのエラー、問題パネルにも効く見込み。配線のないネットができることで、`wireNet` や分岐の印、配線の色など、配線があることを前提にした所が崩れないかを、実装のときに確かめる。
- 変えること: `computeNets` で、ピンの先の位置が同じピンどうしを同じネットにまとめる（配線がなくても）。3 つ以上重なっても同じネット。出力どうしが重なれば、配線のときと同じく値がぶつかるエラー（`isConflict`）。

## 決めてほしいこと

1. ピンどうしがつながっている所に、印を付けるか。
   - 推す案: 付けない。ピンの線が端どうしで接しているので、つながっていることは見て分かる。ピンの線は値の色で描くので、つながれば入力側のピンも色が変わる。
   - ほかの案: 分岐の印（`junction`）と同じ丸を付ける。
2. 形式の文書の直し方。回路の形式 v1 は公開済みで、文書の冒頭に「今ある項目や値は変えない」とある。読み取り方を足すので、v1 の文書に「version 1 の中で変えたもの」の節を作って書く案を推す。`format-next` にある回路の形式 v2 の文書（`docs/format/circuit/v2.md`）にも、同じことを書く必要がある（`main` から取り込んでも、v2 の文書には入らないため）。v2 の文書は `format-next` に直接コミットしてよいか。

## 段階

1. つながりの決まりを直す。
   - `computeNets` で、ピンの先が同じ点のピンどうしを同じネットにまとめる。テストを書く（2 つのピンが重なるとつながる、3 つ以上、出力どうしのぶつかり、配線とピンの先の重なりとの組み合わせ、モジュールのピン、回した部品）。
   - シミュレーション（`sim.test.ts` など）で、線なしでつないだ INPUT → NOT → OUTPUT が動くことを確かめるテストを書く。
   - 形式の文書（回路の形式の「つながりの決め方」）と、[シミュレーション](../../docs/simulation.md)など、ネットの作り方を書いているドキュメントを直す。
   - 確かめること: 整形、Lint、型、テスト、ビルド。ブラウザで、INPUT と NOT と OUTPUT を線なしで並べると動くこと、出力どうしを重ねるとエラーになること、モジュールのピンどうしもつながること、部品を動かして離すとつながりが切れること。フレームレート（ネットは編集のたびに作り直すので、部品の多い回路で、ドラッグ中に重くならないか。変える前と比べる）。
