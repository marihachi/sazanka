# メイン回路の INPUT / OUTPUT もポートと呼ぶ（計画）

状態: **完了**

- 実装は、開発者の合図を受けてから始める（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

INPUT / OUTPUT に付ける名前を、画面とドキュメントで「ラベル」と呼ぶのをやめ、「ポート名」にそろえる。

- 「ラベル」は、配線と配線を名前でつなぐ機能（ネットラベル。[バス配線](../bus/plan.md)の計画でも触れている）の名前として空けておきたい。
- メイン回路の INPUT / OUTPUT も、モジュールの中と同じくポートと呼ぶ。HDL でいちばん外側のモジュールの入出力をポートと呼ぶのと同じ考え方。
- メイン回路もポートを持つことにしておくと、メイン回路を外から見る機能（入出力をまとめたグラフィカルな表示など）を足すときに、モジュールと同じ扱いで済む。

## 前提

- 今、プロパティ欄の INPUT / OUTPUT の名前の欄は、モジュールの中では「ポート名」、メイン回路では「ラベル」と出る（`src/app/PropertyPanel.tsx` の `LabelField`。`inModule` で分けている）。
- 番号の表示「ポート番号: 入力 1」は、メイン回路でもモジュールの中でも同じ。
- 用語集では、「ポート」をモジュールの中の INPUT / OUTPUT、「ラベル」を `Part.label` と定めている。
- 同じ名前のポートを付けられない決まり（`otherLabels`）は、メイン回路でもすでに効いている。エラーの文言も「ほかのポートと同じ名前は付けられません」。

## 決めたこと

開発者が決めたこと:

- メイン回路の INPUT / OUTPUT もポートと呼ぶ。名前の欄は、メイン回路でも「ポート名」にする。
  - 採らなかった案: メイン回路だけ「名前」「信号名」「入出力名」にする（ポートをモジュールの入出力に限る考え方。上の「目的」の理由でポートにそろえた。「信号名」は、ネットラベルの機能と名前を取り合うおそれもあった）。
- 番号の表示「ポート番号: 入力 1」は変えない。
  - 採らなかった案: メイン回路では「番号: 入力 1」と出す（ポートをモジュールに限る場合の案）。「ピン番号」と呼ぶ（モジュールの外側のピン番号 `Part.pinNumber` と取り違える）。
- この計画では、保存データのキー `label` は変えない。キーの `portName` への改名は、[保存データの version 4](../format-v4/plan.md) で、ほかの形式の変更とまとめて行う。形式を上げずにキーだけを変えることはできないため。

エージェントが決めたこと:

- コードの `Part.label`、`setLabel`、`findDuplicateLabels`、`applyModuleSettings` の `labels` などは、この計画では名前を変えない。保存データのキーと対応させておくため。version 4 でキーを改名するときに、一緒に改名する。
  - 採らなかった案: この計画で先に改名する（version 4 までの間、保存データのキーとコードの名前がずれる）。
- 画面の部品だけは名前を変える。`PropertyPanel.tsx` の `LabelField` を `PortNameField` にする。
- `PropertyPanel` の `inModule` は、欄の名前を分けるためだけに使っているので、なくす（`App.tsx` から渡すのもやめる）。
- 文言は、モジュールの中で使っている `property.portLabel` / `property.noPortLabel` にそろえ、使わなくなる `property.label` / `property.noLabel` は消す（ja / en とも）。

### 文言

| 場所                          | 今（メイン回路）       | 新（メイン回路。モジュールの中と同じ） |
| ----------------------------- | ---------------------- | -------------------------------------- |
| 名前の欄の名前                | ラベル / Label         | ポート名 / Port name                   |
| 名前の欄のプレースホルダー    | ラベルなし / No label  | 名前未設定 / No name                   |

ヘルプの文言「モジュールの中では、ピンの名前になります」（`property.labelHelp`）は変えない。

## 段階

1 つの段階で行う。

1. 画面の文言とドキュメントを変える。
   - コード: `src/app/PropertyPanel.tsx`、`src/app/App.tsx`、`src/i18n/ja.ts`、`src/i18n/en.ts`。
   - ドキュメント:
     - [用語](../../docs/glossary.md): 「ポート」の意味を「INPUT / OUTPUT。モジュールの中では外側のピンになる」とし、メイン回路もポートと呼ぶ理由を添える。「ラベル」の行は「ポート名」（`Part.label`）に書き換える。英語の表の「ラベル / Label」を消す。
     - [UI](../../docs/ui.md)、[編集と元に戻す](../../docs/editing.md)、[画面操作](../../docs/interaction.md)、[操作マニュアル](../../../docs/manual/README.md)、[形式の文書 v3](../../../docs/format/v3.md) の説明文の「ラベル」を「ポート名」にする。`docs/format/archive/` は過去の版の記録なので直さない。
     - コードのコメント（`src/circuit/part.ts`、`src/editing/edit.ts` など）の「ラベル」も「ポート名」にする。テストの名前も同じ。
   - 確かめること: `npm run format`、`npm run lint`、`npx tsc -b`、`npm test`、`npx vite build`。ヘッドレスブラウザで、メイン回路とモジュールの中のそれぞれで INPUT / OUTPUT を選び、欄の名前とプレースホルダーが日本語・英語とも新しい文言になっていること、名前を入れるとシートに出ること、重なる名前でエラーが出ることを確かめる。

実装は Skill の `modify` で進める（画面の文言が変わるため）。

## 進み具合

- 段階 1: 済み。
  - 計画にないもので直したもの: `agent/docs/screenshot.md` の「ポート番号とラベル」（計画のあとに足された記述）。`PropertyPanel.tsx` で、入力欄の説明のコメントが `ReadOnlyRow` の上にずれていたので、`PortNameField` の上に移した。
  - ブラウザで確かめたこと（日本語・英語）: メイン回路の INPUT / OUTPUT とモジュールの中の INPUT で、欄の名前が「ポート名」/ "Port name"、プレースホルダーが「名前未設定」/ "No name" になる。名前を入れるとシートに出る。重なる名前でエラーが出る。荒い操作（長い文字列、欄にフォーカスしたままの選び替え、元に戻すの連打、再読み込み）でエラーは出ない。
  - フレームレート（ビルドしたもの、CPU 4 倍遅く、CLOCK 15 個、INPUT を選んでプロパティ欄を出した状態）: 変更前・後とも、CLOCK が動いているだけのときとドラッグ中のどちらも 60 fps、longtask は 0ms。
