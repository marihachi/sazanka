# モジュール設定のポートの並び（計画）

状態: **計画中**

- 段階ごとに、開発者の合図を受けてから実装する（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

モジュール設定のダイアログで、ポートの一覧とピンの割り当ての選択肢を、ポート番号の順に並べる。

解きたい課題（不具合）: 今は、ポートをシート上の位置の順に並べている。見出しはポート番号（「入力 1」など）なので、置いた位置と番号の順が違うと、番号が飛び飛びに並ぶ。

## 再現する手順

1. モジュールの中に、入力 1 を下、入力 2 を上、入力 3 を真ん中に置く。出力 1 を下、出力 2 を上に置く。
2. シートのツールバーの「モジュール設定」を開く。
3. 「ポート」の一覧が「入力 2、入力 3、入力 1、出力 2、出力 1」の順に並ぶ。パッケージが DIP / QFP なら、ピンの割り当ての選択肢と「割り当てのないポート」の並びも同じ順になる。

2026-10-14 に、開発用のサーバーで再現した（DIP 8 ピン）。

## 原因

- ダイアログ（`modules/ModuleSettingsDialog.tsx`）は、ポートの並びを `circuit/module.ts` の `listPortsInPositionOrder`（入力を上から、続けて出力を上から）で 1 つだけ作り、次のすべてに使っている。
  1. 「ポート」の一覧の行の並び。
  2. ピンの割り当ての選択肢の並び。
  3. 「割り当てのないポート」の並び。
  4. split から DIP / QFP に変えたときと、「上から順に割り当て直す」で、番号を振る順（`assignInOrder`）。
  5. 開いたときに、同じピン番号のポートが 2 つ以上あれば、どれを残すか（`initialNumbers`。並びの先頭のものを残す）。
- 位置の順は、もともと 4 のために作ったもの。表示（1〜3）の順を決めた記録は、計画にもドキュメントにもない。
- 同じ原因でほかに壊れているところ: なし。位置の順を使うほかの所（split のピンの順、ポート番号の付け直し）は、位置で決まることそのものが仕様。

## 決めたこと

開発者が決めたこと（2026-10-14）。

- 表示はポート番号の順にする。入力を番号の順に並べ、続けて出力を番号の順に並べる。上の 1〜3 が当たる。
- 番号を振る順（上の 4）は、今の位置の順のまま。「上から順に割り当て直す」は、名前のとおり上から振る。
- 開いたときに同じピン番号のポートが 2 つ以上あれば、ポート番号の順で先のもの（一覧の並びで先のもの。入力と出力が重なったときは入力）を残す（上の 5。今は位置の順で先のもの）。一覧の並びと、残る方を一致させる。
  - 起きるのは、外から来たデータだけ。アプリの操作（置く、貼り付け、モジュール設定の適用）では、重ならないように番号を付ける（`assignPinNumbers`、`applyModuleSettings`）。保存データや共有用 JSON を手で書き換えたものなどは、読み込みで断らない（形式の文書の「読み込むときの検証」）ので、重なったまま開く。そのときは、重なったポートがどちらも外側のピンに出ず、シート上で赤い「?」が付く。
  - 採らなかった案: 今のまま、位置の順で先のものを残す（割り当ての結果を変えずに済むが、一覧の並びと合わない）。
- 実装は、`main` から分けたブランチで行う。
- 採らなかった案: パッケージで分ける（split は位置の順、DIP / QFP は番号の順）。split では外側のピンの並びと一覧の並びがそろう利点があるが、パッケージを切り替えると並びが変わる。

## エージェントが決めること（案）

- `circuit/module.ts` に、ポートを番号の順に並べる関数 `listPortsInNumberOrder(def)` を足す。入力を `portNumber` の順、続けて出力を `portNumber` の順にする。
  - 番号がない・重なるポートは、読み込み（`fillPortNumbers`）と置く操作（`assignPortNumbers`）で付け直すので、ダイアログを開く時点では起きない。それでも並びが決まるよう、番号が同じなら位置の順、番号のないものは最後にする。
  - 採らなかった案: `listPortsInPositionOrder` の並びを変える。番号を振る順（上の 4）まで変わってしまう。
- ダイアログでは、表示と重なりの扱い（上の 1〜3 と 5）に使う並び（番号の順）と、番号を振る用の並び（上の 4。位置の順）を別々に持つ。

## 段階

1 つの段階で行う。小さな修正で、途中で止めて確かめるところがないため。

1. 修正
   - 先に、`listPortsInNumberOrder` のテストを書く（`circuit/module.test.ts`。位置と番号の順が違うポートで、番号の順に並ぶこと。番号が同じときとないときの並び）。
   - `listPortsInNumberOrder` を作り、ダイアログの表示（一覧、選択肢、割り当てのないポート）と、開いたときの重なりの扱い（`initialNumbers`）をそれに替える。
   - [UI](../../docs/ui.md)の「モジュール設定」に、一覧と選択肢の並び（番号の順）と、番号を振る順（位置の順）を書く。操作マニュアルは並びに触れていないので直さない。
   - 確かめること: `npm run format`、`npm run lint`、`npx tsc -b`、`npm test`、`npx vite build`。ブラウザで、上の再現の手順で一覧と選択肢と割り当てのないポートが番号の順に並ぶこと、「上から順に割り当て直す」と split から DIP に変えたときは今までどおり上から番号が振られること、同じピン番号のポートが 2 つあるデータ（保存データに直接書く）で開くと、ポート番号の小さい方に番号が残ること、名前の入力と適用が今までどおり動くこと（[UI](../../docs/ui.md)の「触ったら確かめること」のモジュール設定）。ダイアログ（`.tsx`）を変えるので、ピン数の多いモジュール（128 ピン）で、名前の入力と割り当ての変更が重くなっていないかも見る。

実装は Skill の `modify` で進める。
