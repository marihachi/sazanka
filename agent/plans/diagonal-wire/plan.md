# 45 度の配線（計画 32）

状態: **中止**（2026-10-31。平行に配線したときに斜めの間隔が細くなり、見た目が良くない。斜めの配線自体の重要度も低い。段階 2 まで実装したが、PR #43 はマージしなかった。以下は中止にした時点の記録）

- 保存データの形式（回路の形式 v2 で、斜めの区間を許す）を変えるので、ベースブランチは `format-next`（[作業の進め方](../../docs/workflow.md)の「ブランチ」）。
- 開始の合図を受けたら、段階の区切りで止めずに最後の段階まで進める。迷うことがあれば止めて聞く（[作業の進め方](../../docs/workflow.md)の「実装を始める合図」）。
- 決まったことや変わったことがあれば、その都度この文書を直す（[ドキュメントの書き方](../../docs/documentation.md)の「計画の文書」）。

## 目的

配線を、縦と横だけでなく、斜め 45 度にも引けるようにする。

開発者が求めた。

## 決めたこと

以下は開発者と決めた。

- 引き方: 配線モードでは、いつでも 8 方向（縦、横、斜め 45 度）のうち、ポインターに近い向きに伸ばす。縦横で引きたいときに、ポインターが少し斜めに寄っただけで 45 度にならないよう、縦横の判定の幅を広めにとる（幅は実装のときに試して決める）。
  - 採らなかった案: Shift を押している間だけ 45 度にする（スマホでは引けない）。ツールバーか環境設定で切り替える（切り替えの手間がある）。
- 保存データ: 回路の形式 v2（公開前）で、配線の区間に斜め 45 度（x と y の変わる量が同じ）を許す。今のアプリ（v1）は斜めの区間を読み込みで断るが、v2 は版が上がるので、もともと古いアプリでは開けない。
- 斜めの端のドラッグ: 端の区間が斜めなら、斜めの向きにだけ動かす。ポインターの形は `nesw-resize` / `nwse-resize`。
- 平行な斜めの線の間隔: グリッドの点だけでは、1 マス間隔で並ぶ 2 本を同じ所で斜めに曲げると、斜めの間隔が 1 マスの 0.7 倍（1/√2）になる。そのままにし、引く人に任せる（外側を 1 マス先で曲げれば 1.4 倍になる）。グリッドで点を置く回路図のアプリ（KiCad の回路図など）も同じ扱い。
  - 採らなかった案: 平行な斜めの区間を見た目だけずらして描く（つながりと見た目がずれる）。斜めの区間に半マスの点を許す（基板のアプリの考え方。形式とつながりの決まりが複雑になる）。

## 今のコードと、変えるところ

- 保存データの検証: `circuit/circuit.ts` の `isWire`（`isAxisAligned`）が、縦か横でない区間を断る。45 度も許す。型の説明（`Wire`）も直す。
- 描く: `geometry/layout.ts` の `wireStepTo` が、動いた量の大きい方に縦か横へ伸ばす。8 方向に広げる（45 度の先は、x と y を同じ量だけ動かした、グリッドの上の点）。
- 端のドラッグ: `layout.ts` の `dragWireEnd` が、端の区間の向き（縦か横）にだけ動かす。斜めにも広げる。ポインターの形は `Sheet.tsx`。
- 余分な点を省く: `layout.ts` の `simplifyWire` が、縦か横の直線の途中の点だけを省く。斜めの直線の途中の点も省く。
- つながり: `geometry/net.ts` の `computeNets` が、点を通る配線を、横線は y、縦線は x ごとに分けて探す。斜めの区間は、x − y（右下がり）と x + y（右上がり）ごとに分けて探せるようにする。点が区間の上にあるかの判定（`onSegment`）は、もともと斜めにも対応している。
- 2 本が 1 本に見える点の印: `net.ts` の `findWireJoints` が、区間が横か縦かで印の向きを決める（`horizontal`）。区間の向きを渡し、印を区間と直角に描く。
- 角を丸める描き方: `sheet/wirePath.ts` の `wirePath`。直角の角を前提にしていないかを確かめ、45 度と 135 度の角でも描けるようにする。
- 分割（`findSplitTarget`）、結合（`mergeWiresAt`）、回転、範囲選択、シートに収める処理: 斜めでも崩れないかを確かめる。
- 回路の形式 v2 の文書（`docs/format/circuit/v2.md`、`format-next`）の「配線」を直す。

## 段階

   - 回路の形式 v2 の文書、[つながり](../../docs/nets.md)、[画面操作](../../docs/interaction.md)など、縦横を前提に書いた所を直す。
   - テスト: 斜めの区間の上（端、途中）のピンの先と配線の端がつながる、斜めどうし・斜めと縦横の途中の交差はつながらない、斜めの直線の途中の点を省く、45 度でない斜めは検証で断る。
   - 確かめること: 整形、Lint、型、テスト、ビルド。ブラウザで、保存データに書いた斜めの配線が読み込めて、つながり、角を丸めても描けること。
2. 描く操作。
   - 配線モードで 8 方向に伸ばす。端のドラッグを斜めにも広げる。ヒントと操作マニュアルを直す。
   - 確かめること: 整形、Lint、型、テスト、ビルド。ブラウザで、45 度に引ける、縦横で引くときに斜めになりにくい、斜めの端のドラッグ、回す、分割、結合、範囲選択、つながり。荒い操作（素早い描画、ドラッグ中の Esc）。フレームレート（描画とつながりの計算を変えるため。変える前と比べる）。

実装は Skill の `modify` で進める。

## 進み具合

- 段階 1: 終えた。PR #43（ドラフト）。整形、Lint、型、テスト（552 件）、ビルドが通る。
  - 検証は `isOctilinear`（縦、横、x と y の変わる量が同じ斜め）。余分な点を省く処理は、外積と内積で、どの向きの直線の途中の点も省く。
  - つながりの計算は、斜めの区間を、右下がりは x − y、右上がりは x + y ごとに分けて探す（`computeNets`）。
  - 2 本の端が合わさる点の印と、分割モードの印は、区間の向き（`segmentDirection`。x と y が -1、0、1）を渡し、区間と直角に描く（`findWireJoints` の `horizontal` を `direction` に変えた。エージェントが決めた）。
  - 角を丸める描き方（`wirePath`）は、もともと角の向きによらない作りだったので、説明だけ直した。
  - 回路の形式 v2 の文書は、配線の説明、検証、「version 1 からの変更」を直した。
  - ブラウザで確かめた: 保存データに書いた斜めの配線（分岐、折れる点、分かれ目）が読み込め、つながって出力が点く。角を丸めても丸めなくても描ける。分割モードの印が斜めの区間と直角に出る。エラーは出ない。
- 段階 2: 終えた。整形、Lint、型、テスト（558 件）、ビルドが通る。
  - 縦横の判定の幅: 動いた量の小さい方が大きい方の 0.6 倍以上（約 31 度より斜め）なら斜め（`layout.ts` の `DIAGONAL_RATIO`。エージェントが決めた）。8 方向の真ん中で分けると 0.414（22.5 度）。
  - 向きは、グリッドに合わせる前のポインターの位置で決める。合わせた後で決めると、1 マスほど動かしたときに縦横のつもりが斜めになりやすいため（`wireStepTo` に、グリッドに合わせる前の位置とシートを渡すようにした。エージェントが決めた）。斜めの先は、グリッドに合わせた点までの x と y の量の小さい方だけ進んだ点（グリッドの上で、シートの中に来る）。
  - 端のドラッグは、ポインターを端の区間の向きに写した長さ（斜めなら x と y の平均）をグリッドに合わせる。伸ばせる長さは、動く軸ごとのシートの端までの長さの小さい方（`dragWireEnd`）。
  - ポインターの形は、端の区間の軸（`Sheet.tsx` の `endAxis`。横、縦、右下がり、右上がり）ごとのクラスで付ける。
  - ブラウザで確かめた: 8 方向に引ける。横寄り（傾き 0.4、0.5）や 1 マス弱の動きは縦横になる。斜めの端の印でポインターが `nwse-resize` / `nesw-resize` になり、ドラッグ中もシート全体で保つ。斜めの端のドラッグ（伸ばす、区間が 1 つなら 1 マスで止まる）。回す。斜めの途中で分割し、端を戻すと結合して途中の点が消える。範囲選択。斜めの配線で INPUT と OUTPUT をつなぎ、出力が点く。荒い操作（素早い描画と Esc、端のドラッグ中の Esc と Ctrl+Z のあと元に戻す 1 回で戻る、再読み込み）でエラーは出ない。
  - フレームレート（ビルドしたもの、CPU 4 倍遅く、CLOCK 14 個）: 計画の前（`format-next`）と後で、どちらも何もしないとき 60 fps、部品のドラッグ中 60 fps（長い処理 52〜56ms で同じ）。
